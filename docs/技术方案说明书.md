## 三、分层架构

**Controller → Service → Repository/DAO 严格分层：**

- **ERP.Domain**：纯 POCO 实体（继承 `BaseEntity` 审计基类）+ 枚举，无任何依赖。
- **ERP.Application**：定义 `IErpDbContext` 数据访问抽象接口（解耦）、`IAuthService`/`IDocumentNumberService`/`IGenericService<>`/`IReportService` 服务接口及其实现，统一响应 `ApiResponse<T>`、错误码、业务异常。
- **ERP.Infrastructure**：`ErpDbContext : DbContext, IErpDbContext` 具体实现，`JwtTokenService`，`SeedData` 种子数据，`DependencyInjection` 注册。
- **ERP.Api**：RESTful 控制器（含 `BaseCrudController<>` 泛型 CRUD 基类、`DocumentControllerBase<>` 单据基类），全局异常中间件、操作日志中间件。

## 四、统一接口规范

所有 API 统一响应 `{ code, message, data }`；分页 `{ items, total, page, pageSize, totalPages }`。

- `customers` 客户、`suppliers` 供应商、`employees` 员工、`expense-accounts` 费用科目、`warehouses` 仓库、`products` 商品、`other-infos` 其他资料（币种/港口/货代/唛头等）
- `customers` 客户资料支持可选「指定货代」（ERP-036）：复用「其他资料」中 `InfoType = Forwarder` 的字典项，
  仅存引用 Id（`ForwarderId`）+ 服务端写入的名称快照（`ForwarderName`），刻意不建外键、不做生产回填；
  下拉选项由 `GET /api/base/customers/forwarder-options` 提供（只返回未删除、已启用、类型为 Forwarder 的字典项），
  新增 / 更换引用时服务端校验字典项有效性并覆盖客户端提交的自由文本；字典项后来被停用 / 删除时，
  客户列表与详情仍显示当时的名称快照，并以 `ForwarderAvailable = false` 标注「已停用/不可用」（不可再被新选中）。
  该字段仅作主数据指引：不会自动写入订舱 / 装柜 / 报关 / 费用单据，也不涉及任何外部货代系统。

## 八、单据状态机

所有业务单据统一状态：`待提交(Pending) → 已提交(Submitted) → 已审核(Approved)`，另有 `已驳回(Rejected)`、`已完成(Completed)`、`已取消(Cancelled)`。状态流转通过 `DocumentControllerBase` 统一封装。

## 九、测试方案

**单元测试（xUnit + EF InMemory）覆盖：**
1. 密码哈希/校验（PBKDF2）
2. 单据号生成（前缀 + 日期 + 流水号递增）

## 十、前端交互组件

前端为原生 HTML/CSS/JS（无构建工具），静态资源位于 `src/ERP.Api/wwwroot`，随发布产物一同输出到 `deploy/wwwroot`。

**日期选择器（`js/datepicker.js` + `css/datepicker.css`）**

| 项目 | 说明 |
|---|---|
| 目的 | 替换浏览器原生 `<input type="date">` 外观，统一为符合 UI 设计规范的日历浮层 |
| 接入方式 | 页面加载后自动接管所有 `input[type=date]`；弹窗/侧滑面板等动态渲染的表单由 `MutationObserver` 自动接管，业务代码零改动 |
| 取值约定 | 输入框 `value` 始终保持 `yyyy-MM-dd` 文本，`saveForm`/`saveBill` 仍按原逻辑拼接 `T00:00:00` 提交 |
| 功能 | 日/月/年三级视图切换、上下年月导航、今天·本月初·本月末快捷、清空、周一为周起始、今天与选中态高亮、`min`/`max` 范围禁用 |
| 键盘操作 | `↑/↓` 增减一天，`PageUp/PageDown` 增减 30 天，`Enter` 确认并规范化，`Esc` 收起 |
| 手工录入 | 兼容 `2026-8-6`、`2026/8/6`、`20260806` 等写法，失焦自动规范化；非法输入回退为上一次有效值 |
| 对外 API | `window.ErpDatePicker.{enhance, enhanceAll, open, close, format, parse}` |

> 若后续新增页面使用日期输入，只需照常写 `<input type="date">` 即可自动获得该样式与交互。

## 十一、自动化开发控制层（.ai + scripts）

| 项 | 说明 |
|---|---|
| 控制模型 | GPT 对话为控制面，仓库文件为事实源：任务（`.ai/tasks`）、状态（`.ai/PROJECT_STATE.json`）、结果（`.ai/results`）、证据（`.ai/evidence`）、决策（`.ai/decisions`）、审计（`.ai/audit.jsonl`） |
| 任务生命周期 | `pending → in_progress → 工程验证 → code_ready → completed → Git checkpoint → push`；`depends_on` 组成校验过的无环图，队首非终态任务阻塞队列，禁止隐式跳过 |
| 滚动队列 | `rolling_queue.batch_size = 4`、低水位 2，由 GPT 从 `.ai/FUNCTION_BACKLOG.md` 补充下一批；队列清空时进入 `replenishing` 等待新批次 |
| 验证档 | `safe`（Release build + `ERP.UnitTests`，默认）、`build_only`、`integration`（数据库集成）、`ui`（Edge UI）；本文档补正任务 ERP-017 使用 `build_only` |
| 完成模式 | 业务任务默认 `completion_mode: browser`；开发阶段浏览器门禁按 `defer_browser_during_development` 延后并记 `browser_deferred`（延后到 `FINAL-UI-ACCEPTANCE`）；仅控制层任务可用 `control_plane` |
| Human Gate | 生产库 / SQL / `SchemaUpgrader` / `SeedData` / 部署发布 / 不可逆操作需人工批准；L3/L4 永不自动批准 |
| 保护路径 | `.env*`、`src/ERP.Api/appsettings*.json`、`deploy/**`、`release/**`、`checkpoints/**`、`user_input_files/**`、`logs/**`、`**/*.sql`、`SchemaUpgrader.cs`、`SeedData*.cs` |
| 运行命令 | `scripts/status-ai.ps1` 查看状态；`scripts/run-ai.ps1` / `scripts/run-pipeline.ps1` 执行；`scripts/resume-pipeline.ps1` 续跑；`py -3 scripts/ai_pipeline.py queue` 查看队列；常驻控制台 `start_agent.bat` |
| 证据要求 | 浏览器验收须产出 TRX + `browser-session.json` + 截图 + SHA-256 清单；开发阶段延后不等于放弃，最终 UI 验收阶段必须补齐 |
