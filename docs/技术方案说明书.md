## 三、分层架构

**Controller → Service → Repository/DAO 严格分层：**

- **ERP.Domain**：纯 POCO 实体（继承 `BaseEntity` 审计基类）+ 枚举，无任何依赖。
- **ERP.Application**：定义 `IErpDbContext` 数据访问抽象接口（解耦）、`IAuthService`/`IDocumentNumberService`/`IGenericService<>`/`IReportService` 服务接口及其实现，统一响应 `ApiResponse<T>`、错误码、业务异常。
- **ERP.Infrastructure**：`ErpDbContext : DbContext, IErpDbContext` 具体实现，`JwtTokenService`，`SeedData` 种子数据，`DependencyInjection` 注册。
- **ERP.Api**：RESTful 控制器（含 `BaseCrudController<>` 泛型 CRUD 基类、`DocumentControllerBase<>` 单据基类），全局异常中间件、操作日志中间件。

## 四、统一接口规范

所有 API 统一响应 `{ code, message, data }`；分页 `{ items, total, page, pageSize, totalPages }`。

**错误码规划：**

| code | 含义 | HTTP |
|---|---|---|
| 0 | 成功 | 200 |
| 1000 | 通用业务错误 | 400 |
| 1001 | 参数校验失败 | 400 |
| 1002 | 数据不存在 | 404 |
| 1003 | 数据已存在/重复 | 409 |
| 1004 | 业务规则冲突 | 409 |
| 2000 | 未认证 | 401 |
| 2001 | 用户名或密码错误 | 401 |
| 2002 | 权限不足 | 403 |
| 2003 | 令牌过期 | 401 |
| 2004 | 账号被禁用 | 403 |
| 5000 | 服务器内部错误 | 500 |

## 五、API 接口清单（8 大模块）

### 认证
- `POST /api/auth/login` 登录
- `GET /api/auth/profile` 当前用户信息（角色/权限/菜单树）
- `POST /api/auth/change-password` 修改密码

### 系统设置（/api/sys）
- `users` 用户管理（含重置密码、分配角色）
- `roles` 角色管理（含分配菜单）
- `menus` 菜单管理（树形）
- `parameters` 系统参数
- `document-number-rules` 单据号规则
- `client-limits` 客户端限制
- `logs` 系统日志

### 基础资料（/api/base）
- `customers` 客户、`suppliers` 供应商、`employees` 员工、`expense-accounts` 费用科目、`warehouses` 仓库、`products` 商品、`other-infos` 其他资料（币种/港口/货代/唛头等）

### 询价管理（/api/inquiries）
- 询价单 CRUD + 提交/审核/取消 + 导出

### 订单管理
- `/api/sales-orders` 销售订单 CRUD + 提交/审核/取消 + 导出
- `/api/purchase-orders` 采购订单 CRUD + 提交/审核/取消 + 导出

### 物流管理
- `/api/stock-ins` 采购入库（审核后增加库存）
- `/api/stock-outs` 销售出库（审核后校验并扣减库存）
- `/api/stocks` 库存查询

### 装柜管理（/api/container）
- `receiving-plans` 收货计划、`bookings` 订柜信息、`pre-loadings` 预装柜单、`loading-lists` 装柜清单

### 账务管理（/api/finance）
- `deposit-applies` 定金申请、`payment-applies` 货款申请、`payments` 付款单、`container-settlements` 装柜结算、`bulk-settlements` 散货结算、`receipts` 收款单、`complaints` 客诉单

### 报表管理（/api/reports）
- `product-sales-ranking` 商品销量排名榜
- `order-profit` 订单利润暂估表
- `customer-shipment` 客户出货量统计表
- `salesman-output` 业务员产值报表
- `balance-sheet` 资产负债表
- `income-statement` 利润表
- `cash-flow` 现金流量表

### 单据通用能力（/api/v2/bills，第四阶段）
| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v2/bills/{billType}` | GET | 分页查询（关键字=单据号、状态筛选） |
| `/api/v2/bills/{billType}/navigate?oid=&direction=` | GET | 首张/上一张/下一张/末张导航 |
| `/api/v2/bills/{billType}/{oid}` | GET | 详情（主表 + 副表明细） |
| `/api/v2/bills/{billType}/save` | POST | 新增/保存（Oid=0 为新增，自动取单据号） |
| `/api/v2/bills/{billType}/{oid}/{op}` | POST | 状态流转：`audit` 审核、`unaudit` 销审、`void` 作废、`restore` 还原、`delete` 删除 |
| `/api/v2/bills/{billType}/{oid}/logs` | GET | 单据操作日志（按单据号追溯；oid=0 查询该单据类型全部日志） |
| `/api/v2/bills/{billType}/export` | GET | 导出 Excel（关键字/状态/日期范围） |
| `/api/v2/bills/{billType}/import-template?withSample=` | GET | 下载导入模板（withSample=true 附带示例行） |
| `/api/v2/bills/{billType}/import` | POST | 上传 Excel 逐行导入（逐行调用存储过程 Save，返回成功/失败明细） |

> ⚠️ 状态流转路由变量为 `{op}`：MVC 中 `action` 属保留路由值，使用 `{action}` 会导致 405。

### 打印设计（/api/sys/print-templates，第四阶段）
| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/sys/print-templates?billType=` | GET | 模板列表 |
| `/api/sys/print-templates/{billType}` | GET | 取默认模板（无模板时返回内置默认配置） |
| `/api/sys/print-templates` | POST | 新增/更新模板（同类型同名唯一；设默认时自动取消其它默认） |
| `/api/sys/print-templates/{id}` | DELETE | 软删除模板 |

### 基础资料导入导出（/api/base/io，第四阶段）
| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/base/io/{resource}/export` | GET | 导出全部记录（resource：customers/suppliers/employees/expense-accounts/warehouses/products/other-infos） |
| `/api/base/io/{resource}/import-template` | GET | 下载导入模板 |
| `/api/base/io/{resource}/import` | POST | 上传 Excel 导入（编码重复逐行拦截） |

### 系统日志（/api/sys/logs，第四阶段增强）
- 支持 `module`、`userName`、`billNo`、`start`、`end`、`keyword`（模糊匹配路径/单据号/用户/动作/模块）筛选。

## 七、开发辅助脚本（tools/）

## 八、单据状态机

所有业务单据统一状态：`待提交(Pending) → 已提交(Submitted) → 已审核(Approved)`，另有 `已驳回(Rejected)`、`已完成(Completed)`、`已取消(Cancelled)`。状态流转通过 `DocumentControllerBase` 统一封装。

## 十、前端交互组件

前端为原生 HTML/CSS/JS（无构建工具），静态资源位于 `src/ERP.Api/wwwroot`，随发布产物一同输出到 `deploy/wwwroot`。

**日期选择器（`js/datepicker.js` + `css/datepicker.css`）**

| 项目 | 说明 |
|---|---|
| 目的 | 替换浏览器原生 `<input type="date">` 外观，统一为符合 UI 设计规范的日历浮层 |
| 接入方式 | 页面加载后自动接管所有 `input[type=date]`；弹窗/侧滑面板等动态渲染的表单由 `MutationObserver` 自动接管，业务代码零改动 |
| 取值约定 | 输入框 `value` 始终保持 `yyyy-MM-dd` 文本，`saveForm`/`saveBill` 仍按原逻辑拼接 `T00:00:00` 提交 |
| 功能 | 日/月/年三级视图切换、上下年月导航、今天·本月初·本月末快捷、清空、周一为周起始、今天与选中态高亮、`min`/`max` 范围禁用 |
| 键盘操作 | `↑/↓` 增减一天，`PageUp/PageDown` 增减 30 天，`Enter` 确认并规范化，`Esc` 收起 |
| 手工录入 | 兼容 `2026-8-6`、`2026/8/6`、`20260806` 等写法，失焦自动规范化；非法输入回退为上一次有效值 |
| 对外 API | `window.ErpDatePicker.{enhance, enhanceAll, open, close, format, parse}` |

> 若后续新增页面使用日期输入，只需照常写 `<input type="date">` 即可自动获得该样式与交互。
