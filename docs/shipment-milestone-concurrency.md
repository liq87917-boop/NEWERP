# 装柜出运里程碑证据的实时授权与串行化（ERP-365）

> 阶段 3 · 装柜（container）核心闭环收口 · 复用既有 ERP-058 里程碑登记册、ERP-362 出运引用授权口径与行锁

## 1. 目标

把既有装柜出运里程碑证据（`ContainerShipmentMilestone`，`api/container/shipment-milestones`）的**每一个路由**
都纳入与 ERP-057 / ERP-362 一致的实时授权、客户数据范围与**行锁串行化**护栏：

1. **登记**：在**父引用行锁**（`UPDLOCK, HOLDLOCK`，与 ERP-362 修订 / 作废同一把）与**源记录行锁**内完成
   「父引用资格（存在 / 未删除 / 未作废）→ 既有源模块菜单 → 权威客户数据范围 → 父引用**源记录**资格
   （存在 / 未删除 / 未取消）→ 同父 + 同类型 + 同时间有效唯一性 → 插入证据行」，同一父记录 + 类型 + 时间的
   并发登记只能成功一条；
2. **作废**：在**里程碑行锁**内串行化，重复作废被明确拒绝，原始事件类型 / 事件时间 / 来源说明 / 记录人与
   作废原因全部保留可读，作废后同一父记录 + 类型 + 时间可重新登记一条新的有效证据；
3. **读取**：台账 / 详情 / 父记录候选全部先授权，受限账号的既有源模块菜单与客户数据范围
   **在计数与分页之前**下推到数据库；父出运引用或源记录不可用时历史里程碑仍保留可读，只是显式标注不可用。

只复用既有分层架构、既有权限模型与既有单据流转，**不新增**用户授权、表 / 列 / 菜单、外部系统调用，
也不改写源记录（订柜信息 / 预装柜单 / 装柜清单）、父出运引用与库存、财务、单证等任何下游数据。

## 2. 口径

| 项 | 口径 |
|---|---|
| 身份 | 每次请求按 `ClaimTypes.NameIdentifier` 解析：缺失 / 非正整数 → `2000` 未认证；账号不存在或已 `IsDeleted` → `2000`；`Status != Enabled` → `2002` 权限不足 |
| 源模块菜单 | 按**父出运引用持久化**的源记录类型判定（`booking` 订柜信息 / `pre-loading` 预装柜单 / `loading-list` 装柜清单，与 `SeedData` 同源）；**非特权账号**必须显式具备该类型的既有菜单，撤销后下一次请求立即收敛；**特权账号**继承既有全部三种 |
| 数据范围 | 复用 `SalespersonDataScopeService`（ERP-097 唯一权威口径）；客户归属取**源记录的权威客户**（订柜信息 / 装柜清单取本单 `CustomerId`，预装柜单取所链接订柜信息的客户）；未映射业务员与无权威客户归属的孤儿源记录一律 fail closed，**绝不**降级为全局 / 管理员可见 |
| 关联方式 | 里程碑只按**持久化的父出运引用 Id** 关联，父引用的源记录只按**持久化的类型 + Id** 读取：**绝不**按柜号 / S/O / B/L / 单号等自由文本匹配，也绝不改派父记录 |
| 父引用资格 | 新登记要求父出运引用存在、未删除且未作废；不存在 → `1002`；已删除 / 已作废 → `1004`；历史里程碑照常可读并显式标注不可用 |
| 源记录资格 | 新登记还要求父引用的源记录**存在、未删除、未取消**（与 ERP-057 登记口径同源）；不存在 → `1002`；已删除 / 已取消 → `1004`；历史里程碑照常可读 |
| 有效唯一性 | 同一父记录 + 事件类型 + 事件时间最多 1 条有效证据（库侧过滤唯一索引 `UX_ContainerShipmentMilestones_ActiveIdentity` 兜底）；已作废行不占额度，作废后可重新登记 |
| 登记串行化 | 同一可序列化事务内先对**父引用行**加锁（`SELECT Id FROM db_owner.ContainerShipmentReferences WITH (UPDLOCK, HOLDLOCK) WHERE Id = @id`），再对**源记录行**加锁（`db_owner.ContainerBookings` / `ContainerPreLoadings` / `ContainerLoadingLists`，只 `SELECT Id`） |
| 作废串行化 | 同一可序列化事务内先对**里程碑行**加锁（`SELECT Id FROM db_owner.ContainerShipmentMilestones WITH (UPDLOCK, HOLDLOCK) WHERE Id = @id`） |
| 作废 | 必填原因，置 `Status = 2` 并记录 `VoidedAt` / `VoidReason`；原始事件类型 / 事件时间 / 来源说明 / 备注 / 记录人 / 登记时间全部保留；重复作废 → `1004` |
| 失败即回滚 | 校验全部先于写入；即便发生部分写入，`catch` 中 `RollbackAsync` 保证不留下半条证据 |
| 审计 | `CreatedBy` / `UpdatedBy` 记录真实登录用户 Id；不新增审计表 / 列，不新增任何用户授权 |

## 3. 路由矩阵（全部先授权）

| 路由 | 授权 | 数据范围 | 事务 / 行锁 |
|---|---|---|---|
| `GET api/container/shipment-milestones` | ✅ | ✅ 数据库侧（先于计数 / 分页） | — |
| `GET api/container/shipment-milestones/parent-candidates` | ✅ | ✅ 数据库侧（先于 `Take`） | — |
| `GET api/container/shipment-milestones/{id}` | ✅（按父引用源类型） | ✅ 单条 | — |
| `POST api/container/shipment-milestones` | ✅（按父引用源类型） | ✅ 源记录客户 | ✅ 父引用行锁 + 源记录行锁 + `Serializable` |
| `POST api/container/shipment-milestones/{id}/void` | ✅（按父引用源类型） | ✅ 单条 | ✅ 里程碑行锁 + `Serializable` |

非关系型提供程序（内存库 / 单元测试）无法执行表提示，`IsRelational()` 为假时跳过加锁 ——
事务语义在这些测试里等价「无事务」，真实串行化由 SQL Server 集成测试覆盖。

## 4. 并发协同

### 4.1 同一父记录 + 类型 + 时间的并发登记（create / create）

1. 事务外先解析身份 / 账号状态 / 既有源模块菜单 / 客户数据范围（fail closed 时不进事务、不加锁、不写库）；
2. 开启 `IsolationLevel.Serializable` 事务；
3. 对**父引用行**加 `UPDLOCK/HOLDLOCK`（与 ERP-362 的修订 / 作废同一把锁），再对父引用指向的**源记录行**加锁；
4. 锁内复核父引用资格（存在、未删除、未作废）、既有源模块菜单、客户数据范围与**源记录**资格；
5. 锁内查询同父 + 同类型 + 同时间的有效证据：有 → 明确 `1003` 重复；
6. 写入证据行并提交，失败即回滚。

因此「两条独立连接同时登记同一父记录 + 类型 + 时间」只能成功一条：后到者在锁内看到已登记的有效证据并被
明确拒绝，库中始终只有一条有效证据（过滤唯一索引 `UX_ContainerShipmentMilestones_ActiveIdentity` 作为第二道防线）。

### 4.2 父引用作废（ERP-362）竞争里程碑登记

父引用作废在 ERP-362 中同样先取**父引用行锁**。两方在同一把锁上串行化后只有两种一致结果：

- 登记先赢：里程碑已写入，随后父引用被作废 → 历史里程碑照常可读，列表显式标注「父出运引用已作废」，
  且不能再新增；
- 作废先赢：后到登记在锁内看到父引用已作废 → 明确 `1004`，一条证据都不落库。

绝不出现「父引用已作废之后仍成功登记新证据」的结果。

### 4.3 同一里程碑的并发作废（void / void）

作废在可序列化事务内先锁**里程碑行**：两个独立连接同时作废同一行时，前者成功、后者在锁内看到
`Status = 2` 并收到 `1004`；原始事件 / 时间 / 来源 / 记录人与作废原因绝不被第二次作废改写。

## 5. 错误信息（API 直接返回）

| 场景 | 业务码 | 说明 |
|---|---|---|
| 未登录 / 身份非法 / 账号不存在或已删除 | `2000` | 一律 fail closed，绝不猜测身份 |
| 账号已禁用 | `2002` | 禁用账号不执行任何读取与写入 |
| 父引用源类型无既有菜单 / 未映射业务员 / 客户范围外 / 父引用缺失（受限账号） | `2002` | fail closed，不泄露范围外证据 |
| 父出运引用不存在（新登记） | `1002` | 历史里程碑仍可读 |
| 父出运引用已删除 / 已作废（新登记） | `1004` | 历史里程碑仍可读，不能新增 |
| 父引用源记录不存在（新登记） | `1002` | 历史里程碑仍可读 |
| 父引用源记录已删除 / 已取消（新登记） | `1004` | 历史里程碑仍可读，不能新增 |
| 同一父 + 类型 + 时间已有有效证据 | `1003` | 提示先核对或显式作废后重新登记 |
| 重复作废 | `1004` | 已作废证据只读，**不**提供重写与硬删除 |
| 事件类型 / 事件时间 / 文本长度非法 | `1001` | 校验先于写入，不落任何证据 |

集成测试目标口径（安全护栏在**任何数据库访问之前**生效）：

- 实例必须为 `(localdb)\NEWERP_AutoAcceptance`，库名必须以 `NEWERP_AUTOTEST` 开头，必须集成安全；
- 每次运行只创建**全新 GUID 后缀库**，发现同名库已存在立即拒绝；
- **绝不** drop / reset / 复用任何数据库，也绝不读取 appsettings / .env / 生产凭据；
- 连接串只来自进程环境变量 `ERP_ConnectionStrings__Default`（若存在）或专用 localdb 默认值。

> 构建通过不等于阶段验收：本模块的证据链（单元 + 真实 SQL 竞争 + 文档）齐备后才视为收口；
> 构建 / 测试完成只表示实现已提交，**不等于阶段验收通过**。

## 7. 边界

- 只读写 `ContainerShipmentMilestones` 一张表（读取时只读父出运引用与源记录资格快照，加锁只 `SELECT Id`）；
- **不**改写父出运引用（不新增修订 / 作废留痕）与源记录（订柜信息 / 预装柜单 / 装柜清单）任何列、状态与工作流；
- **不**写销售订单、采购订单、库存与库存成本、库存流水、单证中心、发票、费用与分摊、收付款、税务与结算记录；
- **不**按柜号 / S/O / B/L / 单号等自由文本匹配父记录或源记录（显式 Id 是唯一关联方式）；
- **不**新增用户授权、表 / 列 / 菜单 / 权限模型，**不**做匿名 / 管理员回退，**不**调用承运人 / 海关 / 货代等外部系统；
- 里程碑始终是用户录入的**仓库操作性证据**：不是承运人 / 海关 / 货代确认，不代表放行或允许出运。
