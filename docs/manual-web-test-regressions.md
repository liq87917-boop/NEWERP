# NEWERP 网页手工测试回归修复说明（ERP-469）

> 阶段 3 · 手工网页测试（`NEWERP网页测试错误.xlsx`）逐项收口 · 复用既有授权 / 校验 / 事务 / 审计路径

## 1. 目标

把手工网页测试记录的 **7 项离散回归** 全部修掉，且**不削弱任何既有 ERP 控制**：

| # | 手工测试发现 | 处理口径 |
|---|---|---|
| 1 | 新建询价单必须手工录入汇率 | 新建表单改为读取**既有（参数授权）默认值端点** `GET /api/v2/bills/{billType}/defaults`；只有既有 `DefaultCurrency` / `ExchangeRate` 合法时才回填 |
| 2 | 有效期（天）出现小数 | 有效期是**整数天**：`step=1` / `min=0` 整数步长 + 前端整数校验（服务端校验仍为权威） |
| 3 | 标签栏第 4 个及以后页面被挤掉；切页签丢未保存内容 | 取消标签数量上限；切页签在**浏览器会话内存**中保留该页未保存的**非敏感**界面状态，关闭页签即丢弃 |
| 4 | 询价单新建无法完成 | 新建入口走既有渲染 / 保存路径（`{billType}/save`），只补充默认值、整数天与清空重填 |
| 5 | 询价单 / 销售订单导出没有「先搜索再下载」 | 两个导出视图都提供可见的 **🔍 搜索 / 预览**；预览与下载使用**同一组**筛选参数（日期 / 状态 / 关键字） |
| 6 | 打开一个全新单据时悄悄沿用上一次表单值 | 新建单据只从**文档化默认值**开始（日期 = 当天、其余为空），并丢弃该页签此前保存的未保存状态 |
| 7 | 表单没有一键清空 | 新建表单提供 **🧹 清空重填**：一次性恢复文档化默认值（并重新取既有系统默认币种 / 汇率） |

**未新增**：外部汇率查询、SQL / 表 / 列 / 权限 / 菜单、生产数据访问、特权兜底。
用户录入值始终可编辑，**服务端裁决始终是权威**。

## 2. 服务端口径（`BillProcController`）

| 路由 | 口径 |
|---|---|
| `GET {billType}/defaults` | 先复用既有读侧门禁（实时身份 + 该族既有功能菜单 + 业务员客户数据范围），再读取 `db_owner.SysParameters` 的 `DefaultCurrency` / `ExchangeRate`（未删除行）。**两者缺一不可且必须合法**，否则返回既有受控失败信封（HTTP 200 + `1001`），**绝不回退美元 / 1，绝不臆造汇率** |
| `POST {billType}/save` | 用户传来的合法币种 / 汇率优先；为空 / 非法时才读系统参数，参数不可用时同样 fail closed：**不调用 `sp_Biz_*`、不占用单号、不写日志、不发通知** |
| `GET {billType}/export` | **新增**既有读侧门禁（此前只有 `[Authorize]`）：未授权即不打开数据连接、不返回任何行；`dateField` 只接受该族**已登记导出列**（白名单），不再把请求参数拼进 SQL |
| `GET {billType}/export-preview` | **新增**导出前预览：与导出**完全相同的授权与筛选条件**（关键字 / 状态 / 日期范围），只返回命中计数与最多 20 行预览；只读、零写入 |

取值护栏复用既有 `SystemParameterAuthorizationRules`：
`IsSupportedCurrencyCode`（CNY / USD / EUR / HKD / GBP / JPY）与 `IsPositiveExchangeRate`（正的可解析十进制数），
并新增纯函数 `ResolveBillCurrencyDefaults`（缺失 / 非法一律抛既有 `1001`）。

## 3. 前端口径

### 3.1 标签栏（`app.js`）

| 项 | 口径 |
|---|---|
| 页签数量 | **不再驱逐**：`addTab` 只做「同编码去重 + 最新排最前」，第 4 个及以后页面保留 |
| 未保存状态 | 切页签 / 从菜单离开页面前把 `#content`、`#modal` 内**非敏感**字段值 / 勾选状态存入内存 `TAB_FORM_STATE`；切回时回填 |
| 关闭页签 | `closeTab` 立即 `dropTabState(code)`：状态**丢弃、绝不复活**；关闭当前页签时切到仍打开的页签（全部关闭则回首页） |
| 敏感字段 | `password` / `hidden` / `file` 与 id / name / autocomplete 命中 `pass|secret|token|credential|authorization|authcode|captcha|jwt|otp|session` 的字段**既不采集也不回写** |
| 持久化 | 只存在浏览器会话内存：**不写 localStorage、不发服务端**，因此不序列化令牌、授权判定结果或已落库的单据变更 |

### 3.2 新建单据（`bill-v2.js`，`bill-v2-form.js` 弹层同口径）

| 项 | 口径 |
|---|---|
| 新单据隔离 | 「+ 新增」走 `startNewBillForm()`：丢弃该页签未保存状态 → 既有渲染路径新建 → 只保留文档化默认值（日期 = 当天） |
| 默认币种 / 汇率 | `loadAuthorizedBillDefaults()` 调用既有端点；服务端返回值经 `billDefaultsIntoFields` 校验：**币种必须是正整数枚举值、汇率必须是正数**，否则保持为空并显式提示 |
| 有效期（天） | `billIntegralDays` 只接受非负整数（空 = 交服务端裁决）；小数回落为整数并提示，负数 / 文本 / 科学计数法一律拒绝；控件 `step=1` / `min=0` + `oninput` / `onchange` / `onwheel` 归整 |
| 清空重填 | `clearBillFormFields()` / `clearBillModalFields()`：主表恢复文档化默认值、明细恢复一条空行，再重新取既有系统默认币种 / 汇率 |
| 编辑 / 复制 | 编辑（`editBillRow`）仍按 Oid 载入持久化值；复制（`copyBill`）保留既有显式、带标注行为，仅补齐整数天控件 —— 默认值填充**只对新建生效** |

### 3.3 导出（`bill-export.js`）

| 项 | 口径 |
|---|---|
| 显式搜索 / 预览 | 导出视图新增可见按钮 **🔍 搜索 / 预览**（回车亦可）：按日期 / 状态 / 关键字搜索并展示命中条数与预览表 |
| 同一组参数 | `billExportParams` → `billExportQuery` 由预览与下载**共用**，因此下载文件的筛选条件与预览完全一致 |
| 预览数据源 | 询价单：新增 `{billType}/export-preview`（与导出同一授权与筛选）；销售订单 / 采购订单：既有已授权 JSON 导出接口 `GET /api/sales-orders/export`、`GET /api/purchase-orders/export`（日期服务端过滤，状态 / 关键字按同一参数等价过滤）——**不新增任何权限或数据范围旁路** |
| 下载闸门 | 条件变更即让预览失效；未预览（或预览后改过条件）直接导出会被拒绝并提示先搜索 |

## 4. 控制不变量

- 默认值与保存路径仍然只走既有服务端**校验 / 授权 / 事务 / 审计**：`Save` 仍先过 `GuardLegacyMutationAsync`，
  参数不可用时在上游拒绝，不调用存储过程、不占单号、不写操作日志、不发钉钉。
- 导出 / 预览**逐次**实时校验既有读侧门禁（缺失 / 非法 / 已删除身份按未认证，禁用按权限不足，
  缺少该族既有功能菜单按权限不足，受限账号按客户数据范围收敛）；`*-export` 导出菜单绝不顶替功能菜单。
- 前端不执行任意 SQL（预览与导出只调用既有接口），不内置美元 / 汇率 1 兜底，不臆造任何业务值。

## 6. 环境受限说明（不声称浏览器验收通过）

- 本任务为 `browser_acceptance.required = false`：未执行真实浏览器 / 样式 / 端到端验收，
  上述结论全部来自可离线执行的单测与源码契约断言。
- 真实 SQL Server 上的导出 / 预览 SQL（列白名单与参数化）由既有 SQL 测试环境覆盖；
  本任务未连接生产数据库、未使用生产凭据。
- 若某环境未维护系统参数 `DefaultCurrency` / `ExchangeRate`，新建单据会**显式报错并保持为空**
  （这是本次要求的口径：fail closed 而不臆造汇率）；此时应由管理员在既有「系统参数」中维护合法取值，
  或由用户在表单中手工录入币种与汇率后保存（保存仍走既有服务端校验）。
