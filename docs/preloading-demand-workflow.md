# 预装柜「需求来源」业务界面工作流（ERP-372）

## 1. 背景与目标

ERP-368 已在领域与接口层提供**权威需求计划证据**：预装柜明细
（`ContainerPreLoadingDetail.SourceSalesOrderDetailId`）可显式链接到一条**已审核、未删除**的销售订单明细，
并给出只读有界候选接口（`sales-order-candidates`）与链接指派接口（`sales-order-links`）。
但**业务界面此前没有任何入口**：预装柜单列表行操作只有物流 / 出运 / 时间线，单据编辑器也没有需求来源列，
用户无法在业务界面完成「这条预装行计划满足哪一条销售订单明细」的显式登记。

ERP-372 补齐**业务界面闭环**（不新增表 / 列 / 菜单 / 权限）：

| 位置 | 入口 | 行为 |
| --- | --- | --- |
| 预装柜单列表 · 行「更多」 | **需求来源**（`modules-doc2.js` → `openPreLoadingDemandLinks`） | 打开需求来源工作台（`preloading-demand-links.js`） |
| 单据编辑器明细行（`bill-edit.js`，预装柜单） | **需求来源** 只读列 + 行内按钮 | 只读展示持久化链接；未保存单据按钮禁用（先保存） |
| `index.html` | `<script src="/js/preloading-demand-links.js">` | 工作台脚本注册（与既有装柜脚本同一加载区） |

## 2. 工作台交互（显式、可追溯、可恢复）

打开后按**服务端持久化结果**渲染：

1. 读取单据（`GET /api/container/pre-loadings/{id}`）拿到**服务端明细行 Id** 与状态；
2. 读取**全部明细行的显式链接状态**（`GET /api/container/pre-loadings/{id}/sales-order-links`，
   含「已链接 / 未链接 / 来源不可用」证据文案）；
3. 读取**有界授权候选**（`GET /api/container/pre-loadings/{id}/sales-order-candidates?keyword=&take=`，
   `take` 钳制 1..200），列表展示 **订单明细 Id / 订单号 / 客户 / 商品 / 规格 / 基础单位 / 剩余可链接数量**。

逐行**显式选择**需求来源：

- 选择器只接受**服务端候选的销售订单明细 Id** 或「未链接（清除）」；空值 = 显式未链接；
- **绝不按订单号 / 商品 / 规格 / 文本相似度猜测来源**，也绝不为未保存单据臆造行 Id；
- 提交只发送**真正变化**的行（`PreLoadingSalesOrderLinkAssignRequest.Links`），清空发送 `null`；
- 提交成功后**重新加载服务端持久化结果**回显（不是本地草稿）。

### 2.1 关键守卫

| 场景 | 行为 |
| --- | --- |
| 未保存单据（无服务端行 Id） | 拒绝打开并提示「请先保存该预装柜单」；编辑器行内按钮 `disabled` |
| 已提交 / 已审核 / 已取消 / 已完成 / 已驳回 | **只读**（选择器不可写、提交按钮禁用），服务端同样 fail closed |
| 双击 / 重复提交 | `submitting` 闸门阻断（按钮禁用 + 提前 return） |
| 明细在别处被重新加载后仍按旧行集提交 | 陈旧选择被标记，必须先「重新加载服务端结果」并重新确认 |
| 明细行被别处删除 / 替换 | 重新加载时剔除对应未提交选择并提示，**不修改**仍存在行的链接 |
| 授权被撤销 / 越权客户 / 商品或单位不一致 / 容量不足 / 状态已变 / 网络失败 | **保留全部草稿输入**，显式展示服务端失败原因；不静默回退、不静默清除 |
| 历史 `null` 链接 | 显式显示「未链接（历史 / 未登记需求来源；保持显式未链接，绝不回填）」 |
| 来源已不可用（明细删除 / 订单取消 / 撤销审核） | 显式显示「来源不可用…原链接原样保留，绝不静默清除」，原 `SourceSalesOrderDetailId` 一并回显 |

## 3. 接口（复用 ERP-368，新增一个只读回显）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `api/container/pre-loadings/{id}/sales-order-candidates?keyword=&take=` | 只读有界候选（ERP-368） |
| GET | `api/container/pre-loadings/{id}/sales-order-links` | **ERP-372 新增只读回显**：全部明细行的链接状态 + 可用性文案（`SourceAvailable` / `SourceAvailabilityText`） |
| POST | `api/container/pre-loadings/{id}/sales-order-links` | 指派 / 清除（ERP-368）：先整体校验再改写，同一可串行化事务提交 |

三个接口都复用既有「预装柜单」（`pre-loading`）与「销售订单」（`sales-order`）菜单授权与实时客户数据范围
（ERP-097 / ERP-363）：**不新增任何用户授权、不提供匿名 / 管理员降级**。读取链接状态时，
若单据**存在显式链接**则额外要求既有「销售订单」菜单授权（不暴露任何订单数据给无授权账号）。

## 4. 服务端权威与「保留」语义

- 状态只读、客户范围、商品 / 基础单位一致、容量累计、唯一性等判定全部由服务端在**同一事务**内复核；
  界面永不作为判定权威（页面被篡改也只会被拒绝）。
- **主表单独更新**（请求未携带明细，如业务界面侧栏编辑主表）视为「仅更新主表」：既有明细与其
  `SourceSalesOrderDetailId` **原样保留**，绝不因主表编辑而静默清空需求来源证据；
  请求**携带明细**时保持既有「整体替换」语义（替换前仍统一校验全部拟议链接）。
- 明细编辑器（`bill-edit.js`）只读展示持久化链接，并把持久化链接随行携带、保存时原样回传。

## 5. 边界（需求计划证据，不是库存预留 / 出运）

- 本工作台是**需求计划 / 追溯证据**入口：不锁库、不预留库存、不生成库存流水 / 费用 / 单证，
  不改写商品 / 客户 / 销售订单 / 订柜信息主数据，不重写历史预装数量与状态，不删除任何审计证据；
- 物理出运证据由装柜清单明细 → 已审核销售出库明细链接（ERP-366）单独认定，两套证据互不替代；
- 不新增表 / 列 / 菜单 / 权限模型；生产库结构变更仍由 `SchemaUpgrader` 幂等补齐。

## 6. 验证

- **可执行 JS 交互单测** `tests/automation/preloading-demand-links.test.js`（`node` 直接运行）：
  状态只读口径、未保存闸门、草稿初值、选择归一化（拒绝文本 / 0 / 负数 / 小数）、变更集精确性、
  陈旧选择检测、重新加载剔除、证据文案、提交闸门（阻断双击）、候选文案与匹配、安全转义、
  前端接线契约（不执行任意 SQL、不从文本解析 Id）。
- **单元测试** `ERP.UnitTests/PreLoadingDemandWorkflowTests.cs`：业务界面接线契约（行操作 / 脚本注册 /
  编辑器列 / 自动化脚本存在）、服务端链接状态回显（历史未链接、来源不可用且不清除）、
  指派 ↔ 清除精确往返、批量拒绝零改动、已审核 / 已取消只读、主表单独更新与明细携带均保留链接、
  受限账号既有菜单授权正向往返与无「销售订单」菜单 fail closed。
- **SQL 集成测试** `ERP.IntegrationTests/PreLoadingDemandWorkflowSqlServerTests.cs`：真实控制器 + 真实
  SQL Server 的新增带链接 → 编辑改派 → 明细替换 / 主表更新 → 清除全链路往返、批量拒绝零改动，
  以及**两条独立连接竞争**（同单据两行并发指派、同一行并发指派到不同来源只保留一个一致结果）。
- **安全口径**：真实 SQL 只允许 `(localdb)\NEWERP_AutoAcceptance` + `Integrated Security` +
  全新 GUID 后缀 `NEWERP_AUTOTEST` 库；访问数据库之前先拒绝非专用目标（复用 ERP-368 专用 Fixture 与护栏），
  绝不 drop / reset / 复用既有库，绝不读取 `appsettings*` / `.env` / 生产凭据。
- **浏览器验收**：本任务未开启真实浏览器验收（`browser_acceptance.required = false`）；
  界面逻辑由上述可执行 node 交互单测与源码契约测试覆盖，真实浏览器工作流可在显式 opt-in 后补录。
- 构建通过与单测通过**不代表**阶段验收完成。
