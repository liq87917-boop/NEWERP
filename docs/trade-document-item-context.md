# 单证明细行编辑上下文绑定（ERP-396）

## 1. 目标与范围

单证中心「商品明细行」对话框（`js/trade-doc-items.js`）在打开 / 切换单证、关闭 / 重开或重新读取时，**必须把每一次读取 / 保存 / 删除
绑定到捕获到的单证 Id、对话框代际与编辑身份**，使任何陈旧异步响应都不能：

- 覆盖当前单证数据、渲染旧单证或触发错误刷新；
- 清空 / 覆盖用户尚未提交的输入；
- 提示「陈旧动作成功」（切换单证后旧请求返回的保存 / 删除成功提示）；
- 在确认期间或切换之后按旧上下文再发一次变更请求；
- 因重复点击产生第二次提交。

本功能**只改前端对话框的上下文绑定**：不改写服务端权限 / 状态口径，不新增用户授权、无匿名 / 管理员兜底，
不发明客户端权威（行金额仍由服务端按「数量 × 单价」与币种精度计算），不改写商品资料、销售订单、采购订单、装柜清单、
库存与库存流水、发票、退税、费用或财务记录，也不回写单证表头金额。

## 2. 问题（改造前的竞态）

改造前 `TDI` 只有 `{docId, data, editing}` 三项全局状态，`tdiReload()` 直接把 `await` 结果写入全局：

| 场景 | 改造前的后果 |
|---|---|
| 打开 A 后立即切换到 B，A 的读取后到 | A 的数据 / 行覆盖 B，对话框渲染成 A |
| 同一单证两次重新读取乱序返回 | 旧读取覆盖新读取 |
| 保存 / 删除在途时切换单证 | 成功提示仍出现，并按当前全局状态刷新成另一张单证 |
| 保存 / 删除在途时关闭对话框 | 迟到响应重新打开对话框并渲染旧数据 |
| 重复点击保存 / 删除 | 产生第二次提交请求 |

## 3. 代际与身份模型（`TDI`）

| 字段 | 含义 |
|---|---|
| `docId` | 当前对话框绑定的单证 Id |
| `gen` | **对话框代际**：每次打开 / 切换单证 / 关闭自增；异步响应必须连同代际校验，代际不符一律丢弃 |
| `loadGen` | **重新读取序号**：同一代际内只有最后一次读取可以落地（乱序响应丢弃） |
| `editingGen` | 进入编辑动作时的代际（编辑身份绑定） |
| `open` | 对话框是否仍在打开：关闭后旧响应不得重新打开 / 渲染 / 覆盖 |
| `pending` | 进行中的一次行变更提交（单飞闸门：同一时刻只允许一次） |
| `editingDraft` | 成功刷新时若用户已改指另一行，保留其尚未提交的表单输入 |

核心判定：`tdiCapture()` 捕获 `{docId, gen, open, editingId, editingGen}`；`tdiIsCurrent(ctx)` 要求
**仍打开 + 仍是同一张单证 + 仍是同一代际**。所有 `await` 之后的落地都必须先过这道闸门。

## 4. 各动作的绑定规则

| 动作 | 绑定规则 |
|---|---|
| 打开 / 切换（`manageTradeDocumentItems`） | 代际自增、清空数据与编辑身份与在途提交；旧代际所有在途响应立即失效 |
| 重新读取（`tdiReload`） | 捕获 `docId + gen`，取 `loadSeq`；仅当仍为当前上下文**且** `loadSeq` 是最新序号才落地 / 渲染 |
| 保存（`tdiSaveForm`） | 请求前捕获上下文与编辑身份；**URL / 方法 / payload 单证 Id 与行 Id 全部取自捕获上下文**（`ctx.docId` / `itemId`），`await` 之后不再读取全局状态；成功后仅在仍当前时提示并刷新**仍激活的那张单证** |
| 删除（`tdiDeleteItem`） | `confirm` 前按当前已加载清单校验行归属并捕获单证 / 行 Id；`confirm` 返回后与请求返回后都再次校验上下文，陈旧一律不发 / 不提示 / 不刷新 |
| 关闭（`tdiClose` / 全局 `closeModal` 包装） | 代际自增 + 清空状态；迟到响应不得重新打开对话框 |

**失败口径**：保存 / 删除失败时**保留编辑身份与表单输入**（不重渲染、不刷新）；陈旧失败同样不提示、不清空。

**去重口径**：`pending` 单飞闸门存在期间，第二次保存 / 删除被显式拒绝（提示「正在提交」），不产生第二个请求。

**输入保留**：成功保存 / 删除后如果需要刷新，而用户已改指另一行，则先把当前表单采集为草稿（`editingDraft`），
刷新渲染时**仅当仍在编辑同一行**才回填（`tdiApplyDraft`），绝不用旧草稿覆盖另一个编辑目标。

## 5. 前端接线

- 对话框「关闭」按钮改为 `tdiClose()`（先失效代际再关闭）；
- 首次渲染时**只安装一次**对全局 `closeModal` 的包装（`tdiEnsureCloseHook`），任何关闭路径都让当前代际失效，
  且只在明细行对话框打开 / 有在途提交时才清状态，不影响其它对话框；
- `modules.js` 的行操作入口 `manageTradeDocumentItems(单证Id)` 不变。

1. **A→B 切换**：B 先回、A 后回 → 不覆盖 / 不渲染 A，行 Id 仍是 B 的；
2. **乱序重新读取**：同一单证两次读取，新请求先回、旧请求后回 → 只有最新一次读取落地；
3. **关闭 / 重开同一 Id**：关闭后迟到读取不落地、不重新打开；重开使用新代际并正常渲染；
4. **保存进行中改指另一行编辑目标**：不改编辑身份、成功后只刷新仍激活的单证、刷新渲染保留未提交输入（数量 77 不丢）；

6. **确认期间切换单证**：删除请求不再按旧上下文发出、无陈旧删除成功提示；
7. **失败的变更**：显式提示服务端原因、保留编辑身份与数量输入、不重渲染、不刷新、释放单飞闸门；
8. **重复点击保存**：只产生一次请求；断言 POST URL 精确绑定当前单证、数量提交、可选箱数 / 净重 / 毛重留空即 `null`
   （绝不臆造 0）、单价留空按 0、**提交体不含行金额 / 金额 / 币种**；
9. **静态接线契约**：代际失效、单飞闸门、关闭先失效、乱序序号、无任意 SQL、无文本 Id 解析、无金额 / 币种提交；
10. **金额 / 数量语义**：未登记值显示「—」、行金额只展示服务端返回值（前端不重算）。

### 6.1 真实 SQL 与竞态测试

「真实 SQL 必须指向 `(localdb)\NEWERP_AutoAcceptance` + `Integrated Security` + 新建 GUID 独占 `NEWERP_AUTOTEST` 库」

## 7. 边界与证据保留

- 使用**既有** ERP 认证与权限（`doc-center` 等既有菜单 + 服务端实时授权），**不新增用户授权，无匿名 / 管理员降级**；
- 服务端仍按实时身份、数据范围、单证状态（准备状态才可维护）与类型白名单决定能否读写，前端**不假装拥有客户端权威**；
- 行金额一律服务端计算：前端只提交数量与单价（留空重量 / 箱数即 `null`），**不提交金额与币种、不重算金额**；
- 保留单据来源审计与既有失败日志，不改写任何历史证据；
- **构建完成不等于阶段验收**：本任务验收证据为上述前端单测、全量安全档单元测试与 Release 构建；
  真实浏览器场景与 SQL 竞态（若后续任务适用）必须真实执行通过才算验收。
