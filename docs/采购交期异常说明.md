# 采购交期异常工作台说明（ERP-099）

## 1. 定位

采购订单页新增一个**只读派生**的「采购交期异常」工作台，用既有的要求交期（订单交货日期
`PurchaseOrder.DeliveryDate`）、供应商确认交期（`PurchaseOrder.SupplierConfirmedDate`）与
「以本单为来源、未删除、已审核」的采购入库收货证据，按一个显式的 **as-of 基准日**派生每张订单的
交期状态，帮助运营一眼看出哪些订单逾期、即将到期、被供应商晚确认或已收齐。

> **边界（重要）**：本工作台是采购订单的**运营交期视图**，不是排产系统、不是催货 / 交期承诺系统。
> 它不写任何表、不执行迁移 / 生产 SQL / 真实数据库操作 / 部署，也**不改写**订单上任何已登记进度
> （`ArrivalProgress`、`QcStatus`、`SettlementProgress` 等）。缺日期或收货证据不完整一律按「未知」呈现，
> 绝不当作 0 或正常。

## 2. 接口

- `GET /api/purchase-orders/delivery-exceptions?supplierId=&asOfDate=&keyword=&page=&pageSize=`
  - 有界分页（`pageSize` 1~200，默认 50），稳定排序（供应商 → 订单日期 → 单据 Id）。
  - `asOfDate` 为显式基准日，缺省今天；用于判定「已过 / 临近 / 未到」。
  - `supplierId` / `keyword`（采购单号 / 合同号 / 归属销售订单号）可选筛选。
  - 固定次数数据集访问（无逐单查库）；收货数量复用 ERP-026 的同一套权威批量派生。

## 3. 交期状态口径（后端、前端与测试同源）

| 状态值 | 含义 | 判定 |
| --- | --- | --- |
| `received` | 已收齐 | 已审核且未删除入库收齐（`ReceiptStatus == complete` 且未命中派生上限） |
| `late_confirmation` | 晚确认 | 供应商确认交期晚于要求交期；或要求交期已过 as-of 却仍未确认 |
| `overdue` | 逾期 | 交期（确认交期优先，缺省回落要求交期）已过 as-of 且未收齐 |
| `due_soon` | 即将到期 | 交期落在 as-of 后 7 天内且未收齐 |
| `on_schedule` | 在途正常 | 交期未到、未收齐但尚未进入异常窗口 |
| `unknown` | 未知 | 要求交期与确认交期都缺失，或收货证据超过单次派生上限 |

判定顺序固定：**已收齐 → 缺日期未知 → 晚确认 → 逾期 / 即将到期 / 在途**。部分收货（`partial`）仍视为
未收齐、继续按日期判定；`over_received`（超收）也不视为已收齐，仅在收货状态列单独标出。

## 4. 收货证据口径（复用 ERP-026，不引入第二套算法）

- 已收数量只统计「`StockIn.PurchaseOrderId` 指向本单、主表未删除、明细未删除、且 `Status == Approved`」的
  入库明细数量（明细数量已折算基础单位，与订单明细同口径直接比较）。
- 待提交 / 已提交入库单列为待审数量（`PendingQuantity`），不计入已收；已驳回 / 已取消不计。
- 一页多张订单命中批量派生上限（2000 张入库单）时，无法把截断归因到具体订单，该页相关订单的收货数量与
  收货状态按「未知」返回，绝不静默给出不完整数量。

## 5. 界面

采购订单页工具栏「🚚 交期异常」打开工作台：供应商 / 基准日 as-of / 关键字 / 每页条数筛选，
KPI（逾期 / 即将到期 / 晚确认 / 已收齐 / 未知本页计数）、订单明细表（要求交期、供应商确认交期、
已收 / 已订、未收、收货状态、最近入库、交期状态、说明）与 CSV 导出。未知值在表格与导出中原样显示「未知」。

## 6. 测试

`src/ERP.UnitTests/PurchaseOrderDeliveryExceptionTests.cs` 覆盖：交期状态派生（逾期 / 即将到期 / 在途 /
已收齐）、晚确认两种情形、部分收货仍为未收齐、仅已审核未删除入库计入已收、缺日期未知、只读不写库、
分页有界与稳定排序、供应商 / 关键字筛选、批量取数（固定次数数据集访问、无逐单查库）、接口端点与前端接线契约。
全部使用内存数据库，不连接 SQL Server、不启动 API、不执行任何 SQL 或 seed。
