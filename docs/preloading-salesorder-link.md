# 预装柜明细 → 已审核销售订单需求计划证据链接（ERP-368）

## 1. 背景与目标

预装柜单明细（`ContainerPreLoadingDetail`）此前只有 `ProductId` 与 `Quantity`，**没有**指向真实销售订单需求的
显式来源：`BookingId` 只能解析到订柜信息的客户，无法回答「这条预装行计划满足哪一张销售订单的哪一条明细」。
阶段 3 库存闭环在既有领域实体上**只新增一个可空证据列**，把每条预装柜明细与
**已审核、未删除的销售订单明细**显式链接起来，并在审核时以「来源订单明细数量」为容量上限做累计校验。

## 2. 数据与结构（可空留痕，不回填）

| 项目 | 内容 |
| --- | --- |
| 列 | `db_owner.ContainerPreLoadingDetails.SourceSalesOrderDetailId`（`BIGINT NULL`） |
| 语义 | 指向该预装行认定的**已审核、未删除、未取消**销售订单明细；`NULL` = **显式未链接**（历史 / 无需求来源） |
| 外键 | **刻意不建**：来源销售订单软删除 / 取消后，历史需求证据仍必须可读 |
| 索引 | `IX_ContainerPreLoadingDetails_SourceSalesOrderDetailId`（过滤 `IsDeleted = 0 AND SourceSalesOrderDetailId IS NOT NULL`，读取侧有界检索） |
| 升级 | `SchemaUpgrader` 第 29.8 / 29.9 段以 `IF OBJECT_ID(...) IS NOT NULL AND COL_LENGTH(...) IS NULL` 幂等加列，索引**独立成批**创建（避免同批引用新列触发错误 207） |

**历史明细一律保持 `NULL`**：不按订单号 / 金额 / 相似度猜测来源、不做任何回填，
未链接数量既不计入「已链接需求」，也不占用来源容量。

## 3. 权威来源与客户范围

显式链接必须构成**权威需求来源**，任一不满足即 fail closed（保存 / 提交 / 审核前）：

1. 来源销售订单明细**存在且未删除**；
2. 父销售订单**存在、未删除、状态为已审核**（已取消 / 未审核 / 待提交 / 已提交一律拒绝）；
3. 预装柜明细商品与来源订单明细**商品一致**；
4. **基础单位语义一致**：订单明细单位为空或等于商品基础单位（商品未维护基础单位时 fail closed）；
5. 订单客户必须等于本预装柜单的**权威订柜客户**（`BookingId` → `ContainerBooking.CustomerId`，
   未关联订柜或无权威客户时 fail closed，绝不降级为「任意客户」）；
6. 新链接的预装数量必须为**正数**。

## 4. 容量口径（审核，原子提交）

审核时**按来源销售订单明细逐条**聚合：

```
累计已链接预装数量（其它已审核预装柜 + 本次）
    ≤ 来源销售订单明细数量
```

- 每条来源明细商品唯一，因此天然**不跨商品合计、不混合单位与币种**（只比较基础单位数量，绝不涉及金额 / 汇率）；
- 重复预装行先聚合再判定；
- **已取消 / 未审核**的预装柜单不计入已链接占用 → 取消即时释放**规划容量**，但链接与历史数量**原样保留**；
- 判定与状态变更在**同一可串行化事务**内完成，任一步失败整体回滚：**明细、状态、历史零改动**；
- 预装柜审核**不**锁库、**不**过账库存、**不**改财务、**不**生成出运单 / 单证。

## 5. 并发与锁序

审核 / 链接的确定性锁序固定为：

```
上游销售订单行（SalesOrderId 升序，UPDLOCK, HOLDLOCK）
    → 订柜信息行（既有 ERP-353 锁）
    → 预装柜单行（UPDLOCK, HOLDLOCK）
```

上游订单行锁与既有销售订单工作流共用同一把来源行锁，保证并发下只出现一致结果。
两条已链接预装柜竞争同一来源容量时只放行合法总量；同一单据双连接并发审核只成功一次。
既有 **ERP-353**（预装柜 ↔ 订柜信息）与 **ERP-348**（装柜清单衔接预装柜、累计超装）护栏全部保留。

## 6. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `api/container/pre-loadings/{id}/sales-order-candidates?keyword=&take=` | **只读、有界**候选证据：返回权威订柜客户下「已审核、未删除」销售订单明细，并显式回传父 `SalesOrderId` / 商品 / 客户 / `RemainingBaseQuantity`（返回条数钳制在 1..200） |
| POST | `api/container/pre-loadings/{id}/sales-order-links` | 指派 / 清除显式链接：**先整体校验全部拟议链接，再改写任何一行**；同一可串行化事务内提交，仅「待提交」状态可维护 |

两个接口都复用既有「预装柜单」（`pre-loading`）与「销售订单」（`sales-order`）菜单授权、
当前用户与实时客户数据范围（ERP-097 / ERP-363），**不新增任何用户授权、不提供匿名 / 管理员降级**。

## 7. 边界（需求计划证据，不是库存预留 / 出运）

- 本链接是**需求计划 / 追溯证据**：只说明该预装行计划满足哪一条已审核销售订单明细，
  **不是库存预留、不是出运凭证** —— 不锁库、不生成库存流水、不改财务、不生成单证；
- 物理出运证据由**装柜清单明细 → 已审核销售出库明细**链接（ERP-366）单独认定，两套证据互不替代；
- 不改写商品 / 客户 / 销售订单 / 订柜信息主数据，不重写历史预装柜明细数量与状态，不删除任何审计证据；
- 不新增表 / 菜单 / 权限模型（只新增一个可空证据列与其读取侧过滤索引）；
- 生产库结构变更仍由 `SchemaUpgrader` 幂等补齐，人工高风险 Gate 不变。

## 8. 验证

- **单元测试** `ERP.UnitTests/PreLoadingSalesOrderLinkTests.cs`：候选证据有界查询与容量扣减、链接校验
  （非审核 / 已删除 / 错商品 / 错客户 / 单位不兼容 / 非正数量）、历史未链接保持、审核逐条累计容量、
  取消释放容量但保留历史、审核不过账、菜单与客户范围 fail closed、控制器授权仅继承基类。
- **SQL 集成测试** `ERP.IntegrationTests/PreLoadingSalesOrderLinkSqlServerTests.cs`：真实控制器 + 真实 SQL Server，
  覆盖幂等结构升级、来源撤销、错商品 / 错客户 / 非审核订单、重复行聚合、溢出原子失败、取消释放，
  以及**两条独立连接竞争**（同源容量竞争、同单并发审核）。
- **安全口径**：真实 SQL 只允许 `(localdb)\NEWERP_AutoAcceptance` + `Integrated Security` +
  全新 GUID 后缀 `NEWERP_AUTOTEST` 库；访问数据库之前先拒绝非专用目标，绝不 drop / reset / 复用既有库，
  绝不读取 `appsettings*` / `.env` / 生产凭据。构建通过与单测通过**不代表**阶段验收完成。
