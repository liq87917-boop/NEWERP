# 客户销项发票登记说明（ERP-055）

## 1. 背景与定位

出口 / 内销销售业务中，企业会向客户开具**普通发票（普票）**、**增值税专用发票（专票）**或**出口发票**。
系统原本只有销售订单、出货进度与客户收款引用（ERP-053），无法登记
「这张订单到底开没开票、票面金额多少、对应哪几张销售订单」，也无法在出现错票 / 重开时留下可追溯的更正痕迹。

本次（ERP-055）新增**客户销项发票证据登记册**：

- 登记发票证据本身：发票类型、发票代码（专票必填）、发票号码、开票日期、客户、币种、不含税金额、税额、含税总额、备注；
- 可（可选、显式）把含税总额的**全部或一部分**分摊到既有销售订单，并显式展示**已分摊 / 未分摊金额**；
- 分摊只按**权威一致性**（同客户 + 同币种、订单未取消）建立，**不按单号相似度、金额相近、开票日期接近猜测订单**；
- 登记（记录）后证据**冻结**，更正走**显式作废**（保留身份 / 金额 / 分摊 / 审计历史），不删除、不静默改写。

定位：**操作性的销项发票证据台账**。它**不是**发票开具系统（不连税务局、**不调用任何开票 / 税务服务**）、
**不是**税务申报与销项税金计算、**不是**应收账款台账或余额、**不是**收款核销、**不是**客户对账单，
也**不构成**任何开票、纳税或债权结论。

> 登记 / 记录 / 作废都**不会开具或作废任何真实发票**、**不会改写销售订单状态 / 出货进度 / 金额与明细**、
> **不会改写客户信用状态与信用额度、收款单与其引用行、库存与库存成本、装柜与单证记录、佣金 / 回佣、
> 费用与退税记录**，也**不记账、不生成凭证 / 收款 / 付款 / 结算单**。

> 本说明对应改动**不含**任何历史数据回填，也**不新增或修改客户、销售订单、收款单、单证表的任何列**；
> 新增的只有 `CustomerSalesInvoiceEvidences` 与 `CustomerSalesInvoiceAllocations` 两张表
> （幂等建表 + 索引，见第 10 节）。

## 2. 发票字段与校验口径

| 字段 | 口径 |
|---|---|
| 发票类型 | `普票` / `专票` / `出口发票`（其它取值一律拒绝，不做隐式兜底） |
| 发票代码 | 专票**必填**、普票与出口发票可选；去首尾空白，长度 ≤ 50 |
| 发票号码 | **必填**，长度 ≤ 50（一张发票登记一条，不支持多号码拼接） |
| 开票日期 | 必填（留空按当天）；不改写任何既有单据日期 |
| 客户 | 必须**存在、未删除且启用**；客户编码 / 名称由服务端写成**快照**（客户端提交值不被采信） |
| 币种 | 系统支持币种：`CNY / USD / EUR / HKD / GBP / JPY`（与销售订单币种同源）；未知币种一律拒绝 |
| 金额 | 不含税金额（净额）、税额、含税总额（价税合计），均以**原币**存储，`DECIMAL(18,2)` |
| 备注 | 有界（≤ 500 字符），只作为登记说明，不参与任何金额派生 |
| 状态 | `0` 草稿 / `1` 已登记 / `2` 已作废（常量见 `CustomerSalesInvoiceEvidenceRules`） |

客户停用 / 删除后**历史证据照常可读**，只是显式标注为不可用（`客户已停用 / 已删除（历史快照仍可读…）`），
绝不回填、绝不静默改成空值。

## 3. 金额等式与币种精度

**金额等式（服务端权威校验）**：

```
含税总额（价税合计） = 不含税金额（净额） + 税额
```

- 三项均按**币种精度**四舍五入后必须**严格相等**：JPY / KRW / VND / IDR 为 0 位小数，其余（含未知币种口径）为 2 位；
  取整一律 0.5 进位（`MidpointRounding.AwayFromZero`，不使用银行家舍入）；
- 含税总额必须**大于 0**，三项均不得为负；税额允许为 0（不征税 / 免税 / 出口免税票）；
- 系统**不按税率反推金额**、**不自动调整差额**、不做汇率换算、不跨币种合并。

> 金额等式不成立时接口直接拒绝并给出差额，界面只做提示，**不会**替用户改写金额。

币种精度口径与装柜费用分摊（ERP-042）、供应商发票（ERP-043）、供应商付款引用（ERP-049）、
客户收款引用（ERP-053）共用同一权威实现 `CurrencyAmountRules`，系统中不存在第二套取整规则。

## 4. 有效身份唯一（重复登记被拒绝）

唯一身份 = **客户 + 发票类型 + 规范化发票代码 + 规范化发票号码**：

- 规范化 = 去首尾空白、去掉所有空白与连字符（`-`、`－`、`—`、`_`）后**大写**；
  因此 `036-0021 / 8800 1` 与 ` 0360021 / 88001` 被视为**同一张发票**；
- 只在**未作废且未删除**的记录范围内唯一：重复请求一律**拒绝**（不静默合并、不覆盖原记录）；
- 不同客户、不同发票类型的同一号码各自独立（身份包含客户与类型）；
- 已**作废**的记录**保留可读**，但**不占用身份**：作废后可以用同一身份重新登记新发票（历史与新记录并存可查）。

## 5. 销售订单分摊口径

一张发票可以把含税总额分摊到**一张或多张**销售订单（草稿期维护，整体替换保存）：

| 规则 | 口径 |
|---|---|
| 订单可用性 | 必须存在、未删除、**未取消**（已取消订单不参与发票证据分摊） |
| 权威一致性 | 订单**客户**必须与发票客户一致；订单**币种**必须与发票币种一致（**不做汇率换算**，不跨币种改派） |
| 分摊金额 | 原币，按**币种精度取整后必须大于 0**；同一发票内**合计不得超过含税总额** |
| 重复分摊 | 同一张销售订单在同一张发票内**只能分摊一次**（重复提交直接拒绝，不静默合并） |
| 未分摊金额 | 含税总额 − 已分摊金额（下限 0）；**绝不被猜测到任何订单**，也不代表应收未收余额、未开票税金或催收依据 |
| 订单快照 | 订单号 / 订单日期 / 订单状态 / 订单币种 / 客户编码与名称（服务端写入） |
| 登记前复核 | 登记前重新校验已持久化分摊行仍权威可分摊（订单未删除 / 未取消、客户与币种一致、合计不超上限），不满足即拒绝登记且不改写既有分摊行 |

分摊状态：`linked` 已全额分摊 / `partial` 部分分摊 / `unlinked` 未分摊（依据**持久化分摊行合计**派生），
台账与详情页都直接展示中文文案（已分摊 / 未分摊金额一并显式列出）。

可分摊销售订单候选（只读、有界，单次最多 200 条，`take` 超出即截断）只列出**同客户 + 同币种**的未删除订单：
已取消订单照实列出并标注**不可分摊**，每行附带订单总额、本发票已分摊、其他有效发票已分摊与剩余未被发票证据
覆盖的金额（派生值，**不是**应收余额、账龄或收款依据）。

## 6. 状态机、冻结与作废保留

| 状态 | 可编辑 | 可维护分摊 | 可登记 | 可作废 |
|---|---|---|---|---|
| `0` 草稿 | ✅ | ✅（整体替换） | ✅ | ✅（一次） |
| `1` 已登记 | ❌（证据冻结） | ❌ | ❌（重复登记拒绝） | ✅（一次） |
| `2` 已作废 | ❌ | ❌ | ❌（作废不可恢复） | ❌（重复作废拒绝） |

- **登记（记录）**只把状态改为已登记并写入登记时间：**不开票、不报税、不记账**，也不改写任何其它记录；
- **作废必须填写原因**（≤ 500 字符，空值 / 超长一律拒绝）：保留发票身份、三个金额、分摊行、作废时间与原因，
  **不物理删除、不静默改写、不重写已作废证据**；
- 编辑草稿时若**已存在分摊行**，**不允许更换客户或币种**（会破坏分摊口径，需先清空分摊再改）；
  其它字段（号码、日期、金额、备注、单证交叉引用）可改，改金额后分摊合计仍受上限约束（保存时按当前上限校验）。

## 7. 与单证中心商业发票的分离与显式交叉引用

单证中心的**商业发票 CI**（`TradeDocument` 中 `DocType = 商业发票`，权威常量
`TradeDocumentItemRules.CommercialInvoiceDocType`）是**出口报关用的单证快照**，
本登记册登记的是**账务 / 税务口径的发票证据**。两者**刻意分离**：

- 系统**不会**把单证转换成本登记册记录、**不会**替换或覆盖单证、**不会**自动建立任何链接；
- 只允许**显式**的有界交叉引用（可选）：
  - `TradeDocumentId`：显式选择一张**存在、未删除且类型为商业发票**的单证；
    服务端校验通过后只写入**单证号 / 单证类型快照**，**不读取单证金额**、不参与金额派生；
    类型不符（如装箱单）拒绝并说明原因，引用已删除 / 不存在的单证返回「数据不存在」；
  - `CommercialInvoiceReference`：人工留痕文本（≤ 100 字符），系统绝不据此自动匹配或链接任何单证或订单；
- 被引用单证之后被删除 / 改名：历史引用快照照常可读，只是显式标注不可用；
- 候选接口 `GET /api/customer-sales-invoices/commercial-invoice-candidates`（只读、有界，单次最多 200 条）
  只列出既有、未删除的商业发票，供**显式选择**使用。

## 8. 非变更边界（本模块不改写什么、不做什么）

| 对象 | 本模块的行为 |
|---|---|
| 真实开票 | **不**开具、**不**作废任何真实发票；**不**连接税务局 / 任何开票平台；**不**提交任何票面数据 |
| 税务 | **不**计算销项税金、**不**生成税务申报数据、**不**判断税率或免税成立与否 |
| 销售订单 | **不**改写状态 / 出货进度 / 金额与明细 / 交期 / 合同字段；分摊只是证据行 |
| 客户 | **不**改写信用状态与信用额度、账期、佣金比例；只保存编码 / 名称快照 |
| 收款 | **不**生成 / 改写收款单，**不**改写 ERP-053 收款引用行，**不**做收款核销 |
| 库存 | **不**改写库存数量、库存成本、库存流水 |
| 装柜与单证 | **不**改写装柜清单、单证中心任何单证；只允许显式交叉引用留痕 |
| 财务 | **不**记账、**不**生成凭证 / 结算单 / 费用单，**不**改写费用与退税记录 |
| 历史数据 | **不**做任何请求期或生产回填；既有客户 / 销售订单 / 单证在没有发票证据时行为与历史完全一致 |

## 9. 接口与界面

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/customer-sales-invoices` | 台账分页（可按客户 / 类型 / 状态 / 币种 / 开票日期区间 / 分摊状态 / 销售订单 / 关键字过滤；默认含已作废历史） |
| `GET` | `/api/customer-sales-invoices/{id}` | 详情（含分摊行、已分摊 / 未分摊金额与可用性标注） |
| `GET` | `/api/customer-sales-invoices/commercial-invoice-candidates` | 可显式交叉引用的商业发票候选（只读、有界） |
| `GET` | `/api/customer-sales-invoices/{id}/order-candidates` | 可分摊销售订单候选（只读、有界，同客户 + 同币种） |
| `POST` | `/api/customer-sales-invoices` | 新增草稿（金额等式 / 身份唯一 / 客户启用 / 可选单证交叉引用校验） |
| `PUT` | `/api/customer-sales-invoices/{id}` | 修改草稿（已登记 / 已作废拒绝；已有分摊时不允许换客户或币种） |
| `POST` | `/api/customer-sales-invoices/{id}/allocations/preview` | 分摊预览（**只读，不写库**，与保存共用同一校验口径） |
| `POST` | `/api/customer-sales-invoices/{id}/allocations` | 保存分摊（草稿专用，整体替换） |
| `POST` | `/api/customer-sales-invoices/{id}/record` | 登记（草稿 → 已登记，登记前复核分摊） |
| `POST` | `/api/customer-sales-invoices/{id}/void` | 作废（必填原因，保留历史） |

界面：`wwwroot/js/customer-sales-invoices.js`（`openCustomerSalesInvoiceRegister`），
入口在**销售订单模块工具栏**（`🧾 销项发票`）与**销售订单行操作**（按该单预筛选台账），
页面内提供台账 / 草稿表单 / 详情 / 分摊 / 作废五个视图，全部文案与服务端规则同源
（含「不是开票系统 / 税务申报 / 应收账款台账 / 收款核销」与「与单证中心商业发票刻意分离」声明）。

**查询有界**：台账分页（默认 50、上限 200），映射时按页**批量**装载分摊行 / 销售订单 / 客户 / 单证，
**无逐行数据库查询**；候选接口单次最多 200 条。

## 10. 幂等结构与索引

`SchemaUpgrader` 第 37 段（`// 37. 客户销项发票证据登记`）为本模块**唯一**的结构变更：

- 只建两张表：`CustomerSalesInvoiceEvidences`（发票证据）与 `CustomerSalesInvoiceAllocations`（分摊行），
  金额列均为 `DECIMAL(18,2)`，全部语句都是 `IF OBJECT_ID(...) IS NULL` / `IF NOT EXISTS(...)` 幂等写法；
- 索引：`UX_CustomerSalesInvoiceEvidences_ActiveIdentity`（客户 + 类型 + 规范化代码 + 规范化号码，
  过滤 `IsDeleted = 0 AND Status <> 2`）、`IX_CustomerSalesInvoiceEvidences_CustomerId_Status`、
  `IX_CustomerSalesInvoiceEvidences_Status_InvoiceDate`、
  `IX_CustomerSalesInvoiceEvidences_NormalizedInvoiceNumber`、
  `UX_CustomerSalesInvoiceAllocations_InvoiceOrder`（发票 + 销售订单，过滤 `IsDeleted = 0`）、
  `IX_CustomerSalesInvoiceAllocations_SalesOrderId`；
- **刻意不建任何外键、也不加导航属性**（与 ERP-049 / ERP-053 的登记册口径一致）：
  本段**不含任何既有表结构变更语句**（`ALTER TABLE`）、不含 `UPDATE / INSERT / DELETE`、
  不含任何开票 / 报税 / 记账语句；
- 客户 / 销售订单 / 收款单 / 单证表**一行数据、一列结构都不会被本段改动**。

  采购发票 / 退税 / 费用 / 库存流水 / 变更申请 / 附件引用单据；

真实浏览器（Edge）验收按项目策略在开发期记录为 **browser_deferred**，将在 `FINAL-UI-ACCEPTANCE` 阶段执行：
场景一「创建发票证据 → 部分分摊到多个兼容销售订单 → 校验已分摊 / 未分摊金额持久化且订单与真实开票状态未变」，
场景二「重复发票与客户 / 币种不匹配分摊被拒绝 → 作废已登记发票 → 证据与分摊仍可读且与单证中心商业发票保持分离」。



## 12. 订单侧只读证据视图（ERP-056）

ERP-055 只提供了登记册（发票维度 + 台账）。ERP-056 在同一份持久化证据行与被分摊行之上补上**销售订单维度**的
只读证据视图：让使用者从订单出发就能看到「哪些既有销项发票把含税总额的多少钱分摊到了本单」，
同时**不引入第二套匹配、分桶或对账算法**（复用的正是 ERP-055 的 `CustomerSalesInvoiceEvidenceRules`
权威资格判定与持久化行）。

### 12.1 派生口径（与 ERP-055 / ERP-054 同源）

- 全部金额只按 `CustomerSalesInvoiceEvidences` 与其 `CustomerSalesInvoiceAllocations` 的**未删除持久化行**派生，
  且只有**已登记（未作废）**发票下的行计入有效合计；
- 逐行分桶（`SalesOrderInvoiceEvidenceSemantics.SupportedBuckets`）：
  `recorded`（有效：发票已登记、行未删除、客户 / 币种 / 订单币种快照自相一致、金额等式成立、订单可用且与发票同客户同币种）、
  `draft`（发票仍为草稿：分摊只是工作数据，未形成登记证据）、
  `voided`（发票已作废：历史证据保留可读）、
  `invalid`（客户 / 币种 / 订单币种快照 / 金额等式不一致或状态码无法识别：**不换算、不合并、不改派**）、
  `unavailable`（发票证据或销售订单不存在 / 已删除：有效性无法确认）；
- 金额等式校验复用 ERP-055 的口径与 `CurrencyAmountRules` 币种精度（含税总额 = 净额 + 税额，取整后严格相等、
  含税总额 > 0、税额不得为负），**不重算、不改写**持久化金额；
- 证据结论短标签 / 状态键：`有销项发票证据` / `recorded`、`仅有草稿 / 作废 / 无效销项发票证据` / `historical_only`、
  `无销项发票证据` / `none`、`未知（超出有界读取上限）` / `unknown`；
- 上下文金额（**均不是应收余额 / 未开票金额 / 应交税金**）：
  `recordedInvoiceGrossAmount` = 参与有效证据的发票含税总额快照合计（按发票去重）、
  `unreferencedInvoiceAmount` = 前者 − 本订单有效已分摊金额（下限 0，表示这些发票中**未指向本订单**的部分）、
  `invoiceUnreferencedOrderAmount` = 订单金额 − 有效已分摊金额（下限 0，表示订单金额中**没有有效发票证据分摊到**的部分）。

### 12.2 接口与有界读取

| 接口 | 说明 |
| --- | --- |
| `GET /api/sales-orders/{id}/invoice-evidence` | 单张订单的销项发票证据详情（汇总 + 有界逐条证据 500 条 + 口径 / 边界 / 登记口径 / 金额等式文案） |
| `GET /api/sales-orders/invoice-evidence-summaries?ids=1,2,3` | 列表页有界批量汇总（去重保序、单次 ≤ 200 张；未知订单也返回「订单不可用 + 金额未知」而不是丢行） |

- 固定 4 次数据集访问（订单 + 持久化分摊行 + 发票证据 + 发票侧未删除分摊合计），与订单张数 / 行数无关，**绝无逐行查库**；
- 命中上限（列表 5,000 条分摊行 / 详情 500 条 / 报表聚合 500 张订单）时金额与计数一律按**未知**（`null`）返回，
  **不给部分合计**，明细只显示已读取部分；
- 全程只读（`AsNoTracking`、无 `SaveChanges`），不改写发票证据、分摊行、销售订单、客户、收款单与其引用行、
  库存与库存成本、装柜与单证、佣金 / 回佣、费用与退税记录，也不开票、不报税、不记账。
