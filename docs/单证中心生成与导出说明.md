# 单证中心：由销售订单 / 装柜清单生成单证与 Excel 导出（ERP-019）

> 本文件说明 ERP-019 交付的「单证中心台账自动化」：**由销售订单与装柜清单生成 / 带入预填单证**，以及**单证台账 Excel 导出**；
> ERP-030 交付**单证共享打印**（打印预览 / 直接打印 / 打印设计，见第 10 节）；
> ERP-052 交付**生成 / 导出 / 打印消费商品明细行快照**（见第 11 节）。
> 参考实现：`src/ERP.Api/Controllers/TradeDocumentGeneration.cs`（共享逻辑）、`TradeDocumentController`、`SalesOrderController`、`ContainerLoadingListController`、`src/ERP.Application/Services/TradeDocumentLineSnapshotRules.cs`、`src/ERP.Api/wwwroot/js/trade-doc-gen.js`、`src/ERP.Application/Interfaces/TradeDocumentPrintDtos.cs`、`src/ERP.Api/wwwroot/js/trade-doc-print.js`。

## 1. 背景与缺口

ERP-006「全仓功能审计」把「单证中心」判为 **partial**：台账、状态跟踪（待制作 → 已制作 → 已提交客户 → 已使用）与菜单（`doc-center`）已可用，但

1. 只能**手工登记**，没有「由装柜清单 / 销售订单自动生成」；
2. 没有 **Excel 导出**（附件仍是 `FileNote` 文本）。

ERP-019 只补这两个缺口，**不新增任何数据库结构**（`TradeDocument` 实体、`SchemaUpgrader.cs`、`deploy/**`、任何 `.sql` 均未修改）。

## 2. 可用字段与来源留痕口径

单证台账既有字段（`src/ERP.Domain/Entities/TradeDocument.cs`）与两路来源的映射：

| 单证字段 | 销售订单来源 | 装柜清单来源 |
|---|---|---|
| `DocNo` | `{类型前缀}-{订单号}`，冲突自动追加 `-2/-3…` | `{类型前缀}-{装柜清单号}`，同上 |
| `DocType` | 用户勾选（默认 商业发票 + 装箱单） | 用户勾选（默认 装箱单） |
| `IssueDate` | 生成当天 | 装柜日期 |
| `SalesOrderNo` | **来源订单号（留痕）** | 空（清单未关联订单号） |
| `RefNo`（柜号/订舱号） | 空，装柜后人工回填 | **来源柜号（留痕）** |
| `DeclareNo` | 空，报关后人工回填 | 空，报关后人工回填 |
| `CustomerId` / `CustomerName` | 订单客户 + 客户档案名称（无档案时留空） | 清单客户 + 客户档案名称 |
| `Amount` | 订单总额 `TotalAmount` | `0`（装柜阶段金额未定，人工填写） |
| `Currency` | 订单币种枚举名（USD/CNY/EUR/…） | 客户档案币种，为空时 `USD` |
| `DeparturePort` | 空（订单无起运港字段） | 装柜清单 → 预装柜单 → **订柜信息 `DeparturePort`**，缺失留空 |
| `DestinationPort` | 订单目的港文本 → 客户档案目的港 | 订柜信息目的港 → 客户档案目的港 |
| `IssuedBy` / `Copies` | 按类型默认（报关单：报关行·1；产地证：贸促会/海关·2；CI/PL/BL：3…） | 同左 |
| `Status` | 固定 `待制作`（人工确认后才流转） | 固定 `待制作` |
| `FileNote` | 空 | 空 |
| `Remark` | `来源：销售订单 {订单号} ｜ 客户 PO ｜ 合同号 ｜ 贸易条款 ｜ 目的港 ｜ 交货日期 ｜ 定金比例` | `来源：装柜清单 {清单号} ｜ 柜号 ｜ 唛头 ｜ 箱数 ｜ 毛重 ｜ 体积 ｜ 装柜日期 ｜ 装柜备注` |

字段统一按目标列长截断（`MaxLength` 超长不会写入失败）。备注前缀同时也是重复生成守卫的判定依据，**修改文案需同步**。

| 装箱单 | `PL` | 订舱确认 | `BK` |

## 5. 重复生成守卫（不产生重复单证）

- **销售订单来源**：同一 `SalesOrderNo` + 同一 `DocType` 视为已生成；
- **装柜清单来源**：同一柜号 `RefNo` **或**备注留痕指向同一装柜清单号，命中同一 `DocType` 即视为已生成（一柜一类单证只应有一份）；
- 批量生成时**任一类型已生成即整体拒绝**（错误码 `RuleConflict`，提示「该…已生成「商业发票」（单证编号 CI-…），不能重复生成」），不会写入半成品数据；
- 已**软删除**的单证不参与判定（删除后可重新生成）；
- 「带入预填」不落库，因此重复校验时机在落库接口上；对话框同时把已生成类型置灰并取消勾选（前端防重）。

其他守卫：来源单据已作废 → `RuleConflict`；未选择类型 → `InvalidParameter`；不在该来源可生成清单内的类型 → `InvalidParameter`（提示可生成类型）；生成后的单证状态为 `待制作`，仍可在单证中心编辑（金额/份数/制作人/备注/状态），**来源留痕保留**。

### 10.3 打印字段口径与缺值语义

字段键与实体属性同名（camelCase），因此「样式设计」勾选顺序（`FieldKeys`）可直接驱动打印顺序，无需二次映射；模板中出现但不属于台账打印字段的键（如 `customerId`）直接忽略。

| 字段键 | 打印页标签 | 取值 / 缺值语义 |
|---|---|---|
| `docNo` | 单证编号 | 台账 `DocNo`（裁剪首尾空白）；无值 → 空白 |
| `docType` | 单证类型 | 原样输出；无值 → 空白 |
| `status` | 状态 | 中文业务状态原样（待制作 / 已制作 / 已提交客户 / 已使用），**不做状态码映射** |
| `issueDate` | 出具/签发日期 | `yyyy-MM-dd`；无值 → 空白 |
| `customerName` | 客户名称 | **仅取台账冗余名称**；历史数据只有 `CustomerId` 时留空，不回查客户档案 |
| `salesOrderNo` | 关联销售订单号 | 来源留痕（见 §2）；无值 → 空白 |
| `refNo` | 关联柜号/订舱号 | 台账 `RefNo`；无值 → 空白（不按单证号推测柜号） |
| `declareNo` | 关联报关单号 | 台账 `DeclareNo`；无值 → 空白 |
| `amount` | 单证金额 | `0.00` 两位小数；`Amount = 0` 视为**未填写金额**（报关单 / 装箱单等本就不含金额口径）→ 空白，不打印 `0.00` |
| `currency` | 币种 | 原样输出；无值 → 空白 |
| `departurePort` | 起运港 | 原样输出；无值 → 空白 |
| `destinationPort` | 目的港 | 原样输出；无值 → 空白 |
| `issuedBy` | 制作人/出证机构 | 原样输出；无值 → 空白 |
| `copies` | 份数 | 正整数；`Copies <= 0` 视为未填写 → 空白（与金额同一口径） |
| `fileNote` | 附件说明/存放位置 | 原样输出；无值 → 空白 |
| `remark` | 备注 | 原样输出；无值 → 空白 |

字段顺序：未保存打印模板时按上表顺序；已保存模板时按模板 `FieldKeys` 顺序（模板中未知键忽略、模板外字段按默认顺序补齐），模板关闭「打印备注」时字段表同步去掉备注列。

## 11. ERP-052：生成 / 导出 / 打印消费商品明细行快照（2026-09-25）

### 11.1 目标与边界

- **目标**：让 ERP-051 落库的 `TradeDocumentItems`（商业发票 / 装箱单的行级快照）真正进入业务链路 ——
  ① 由销售订单 / 装柜清单**生成 / 预填**时按来源明细写入行快照；② 单证中心 **Excel 导出**可按明细行输出（含行合计）；
  ③ **共享打印**输出类型适配的明细表与合计；④ 生成前在对话框**预览**将带入的行。
- **边界（重要）**：
  - 只读写「单证台账 + 明细行 + 只读來源明细 / 商品资料」：**不**改写销售订单、装柜清单、商品资料、库存与库存流水、
    发票、退税、费用或财务记录；**不**回写单证表头金额（行合计与表头金额差异只提示）；
  - **不做价格推断**：不按商品资料现价补价、不做汇率换算、不跨币种合并合计；
  - **不臆造缺值**：来源没有的箱数 / 净重 / 毛重一律留空（`null`），UI / Excel / 打印都留空，绝不写 0；
  - **无生产回填**：既有单证不会自动补明细行；老单证照常导出与打印（明细区为空）。

### 11.2 来源明细 → 行快照映射口径（`TradeDocumentLineSnapshotRules`）

| 维度 | 销售订单来源 | 装柜清单来源 |
|---|---|---|
| 适用单证类型 | 商业发票（含价格口径）、装箱单 | 装箱单（清单不生成商业发票） |
| 商品名称 | 订单明细 `ProductName`（为空回退商品资料名称） | 清单明细 `ProductName`（为空回退商品资料名称） |
| 商品编码 / 英文名称 | 来源无此列 → 引用商品资料时取**商品资料权威快照**，否则留空 | 同左 |
| 规格 / 单位 | 订单明细 `Spec` / `Unit`（为空回退商品资料） | 清单明细**无该列** → 引用商品资料时有值，否则留空（不按文本猜测） |
| 数量 | 订单明细 `Quantity`（必须 > 0 且 ≤ 4 位小数，否则**拒绝生成**） | 清单明细 `Quantity`（同上） |
| 单价 / 行金额 | 单价取订单明细 `UnitPrice`（不能为负），行金额 = 数量 × 单价按**币种精度**服务端计算 | 清单明细无单价列、装箱单不含价格口径 → 单价与金额恒为 0 |
| 箱数 | **留空**（订单明细没有箱数列） | 清单明细 `Cartons`：仅**整数**且 ≤ 1,000,000 时写入；来源 0（= 未登记）或非整数一律留空（**不四舍五入**） |
| 净重 | **留空**（订单没有重量证据） | **留空**（清单明细没有净重列，绝不推断） |
| 毛重 | **留空** | 清单明细 `Weight`：> 0 时写入（来源 0 = 未登记 → 留空），精度收敛到 4 位 |
| 币种 | 与单证台账同口径（商业发票须在系统币种内，不做汇率换算） | 同左 |
| 行序 | 按来源明细顺序 1..N（基准 = 来源明细 Id 升序） | 同左 |
| 行备注 | 来源明细 `Remark`（纯文本、有界） | 同左 |

**文本安全（写入即清洗）**：`<` / `>`、控制字符被剔除，换行 / 制表符折叠为空格，并按列长截断
（商品编码 50 / 名称与规格 200 / 单位 20 / 备注 500）——因此界面（`escapeHtml`）、Excel（NPOI 字符串单元格）与打印
输出的都是**纯文本**，既不会被当作标记执行，也不会成为公式载荷。

**有界与 fail-closed（不静默丢弃来源明细）**：来源明细单次读取上限 = 200 行（`Take(201)` 判定越界）；
数量非正 / 超精度、单价为负、既无商品引用又无商品名称与编码、来源明细超过 200 行 → 生成与预填**明确拒绝**
（错误码 `RuleConflict`，提示先修正 / 拆分来源单据），**不写任何半成品单证或明细行**。

### 11.3 Excel 明细行导出（`layout=lines`）

`GET /api/trade/documents/export-excel?...&layout=lines`（大小写不敏感；其余取值保持既有表头导出）：

| 列 | 说明 |
|---|---|
| `行类型` | `明细行` / `行合计` / `箱数/重量合计` / `无明细行` / `导出截断说明` |
| 单证表头列 | 单证编号 · 单证类型 · 状态 · 出具/签发日期 · 客户名称 · 关联销售订单号 · 关联柜号/订舱号 |
| 明细列 | 行序 · 商品编码 · 商品中文名称 · 商品英文名称 · 规格型号 · 数量 · 单位 · 单价 · 行币种 · 行金额 · 箱数 · 净重kg · 毛重kg · 行备注 |

- **顺序**：单证（按筛选顺序，同列表导出的 Id 倒序）→ 该单证明细行（按行序）→ 行合计 → 下一张单证；

- **老单证照常导出**：无明细行的单证输出一行 `无明细行`（表头字段照常，明细列留空，备注说明不做任何合计）；
- **有界**：单次导出明细行上限 5000 行，命中上限时末尾追加 `导出截断说明` 行（不静默丢失、不把截断当完整导出）；
- **缺值一律留空**（`null` → 空白单元格），**不写成 0**；文本写入字符串单元格（不是公式）。

### 11.5 事务与守卫

- **生成 = 单证表头 + 明细行快照的同一次事务写入**（`IErpDbContext.Database.BeginTransactionAsync`）：
  先构造并**完整校验**全部草稿与行快照（此时未写库），再在同一事务内两次 `SaveChanges`（先表头取 Id、再写明细行），
  任一步失败整体回滚 → 不留「没有明细的半成品单证」，也不留孤儿明细行；
- 守卫顺序：来源合法性 → 未选择 / 不支持的类型 → **来源明细校验（数量 / 单价 / 商品身份 / 有界行数）** → 重复生成；
- 重复生成守卫仍为权威口径（同一来源 + 同一单证类型只允许一张；批次中任一类型已生成即整体拒绝），
  重试不会追加明细行、也不会覆盖已生成 / 人工维护的单证；
- 计数字段（`decimal`）统一经 `CurrencyAmountRules` 按币种精度取整（0.5 进位，确定性）；
- 单元测试使用内存库：EF 把「内存库不支持事务」按异常处理，测试工厂 `TestDbFactory` 显式忽略
  `InMemoryEventId.TransactionIgnoredWarning`（内存库下事务等价于无事务，业务校验与写入语义不变；生产 SQL Server 走真实事务）。
