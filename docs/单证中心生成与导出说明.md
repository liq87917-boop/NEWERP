# 单证中心：由销售订单 / 装柜清单生成单证与 Excel 导出（ERP-019）

> 本文件说明 ERP-019 交付的「单证中心台账自动化」：**由销售订单与装柜清单生成 / 带入预填单证**，以及**单证台账 Excel 导出**。
> 参考实现：`src/ERP.Api/Controllers/TradeDocumentGeneration.cs`（共享逻辑）、`TradeDocumentController`、`SalesOrderController`、`ContainerLoadingListController`、`src/ERP.Api/wwwroot/js/trade-doc-gen.js`。

## 1. 背景与缺口

ERP-006「全仓功能审计」把「单证中心」判为 **partial**：台账、状态跟踪（待制作 → 已制作 → 已提交客户 → 已使用）与菜单（`doc-center`）已可用，但

1. 只能**手工登记**，没有「由装柜清单 / 销售订单自动生成」；
2. 没有 **Excel 导出**（附件仍是 `FileNote` 文本）。

ERP-019 只补这两个缺口，**不新增任何数据库结构**（`TradeDocument` 实体、`SchemaUpgrader.cs`、`deploy/**`、任何 `.sql` 均未修改）。

## 2. 可用字段与来源留痕口径

单证台账既有字段（`src/ERP.Domain/Entities/TradeDocument.cs`）与两路来源的映射：

| 单证字段 | 销售订单来源 | 装柜清单来源 |
|---|---|---|
| `DocNo` | `{类型前缀}-{订单号}`，冲突自动追加 `-2/-3…` | `{类型前缀}-{装柜清单号}`，同上 |
| `DocType` | 用户勾选（默认 商业发票 + 装箱单） | 用户勾选（默认 装箱单） |
| `IssueDate` | 生成当天 | 装柜日期 |
| `SalesOrderNo` | **来源订单号（留痕）** | 空（清单未关联订单号） |
| `RefNo`（柜号/订舱号） | 空，装柜后人工回填 | **来源柜号（留痕）** |
| `DeclareNo` | 空，报关后人工回填 | 空，报关后人工回填 |
| `CustomerId` / `CustomerName` | 订单客户 + 客户档案名称（无档案时留空） | 清单客户 + 客户档案名称 |
| `Amount` | 订单总额 `TotalAmount` | `0`（装柜阶段金额未定，人工填写） |
| `Currency` | 订单币种枚举名（USD/CNY/EUR/…） | 客户档案币种，为空时 `USD` |
| `DeparturePort` | 空（订单无起运港字段） | 装柜清单 → 预装柜单 → **订柜信息 `DeparturePort`**，缺失留空 |
| `DestinationPort` | 订单目的港文本 → 客户档案目的港 | 订柜信息目的港 → 客户档案目的港 |
| `IssuedBy` / `Copies` | 按类型默认（报关单：报关行·1；产地证：贸促会/海关·2；CI/PL/BL：3…） | 同左 |
| `Status` | 固定 `待制作`（人工确认后才流转） | 固定 `待制作` |
| `FileNote` | 空 | 空 |
| `Remark` | `来源：销售订单 {订单号} ｜ 客户 PO ｜ 合同号 ｜ 贸易条款 ｜ 目的港 ｜ 交货日期 ｜ 定金比例` | `来源：装柜清单 {清单号} ｜ 柜号 ｜ 唛头 ｜ 箱数 ｜ 毛重 ｜ 体积 ｜ 装柜日期 ｜ 装柜备注` |

字段统一按目标列长截断（`MaxLength` 超长不会写入失败）。备注前缀同时也是重复生成守卫的判定依据，**修改文案需同步**。

## 3. 单证编号规则

| 单证类型 | 前缀 | 单证类型 | 前缀 |
|---|---|---|---|
| 报关单 | `CD` | 提单 | `BL` |
| 装箱单 | `PL` | 订舱确认 | `BK` |
| 商业发票 | `CI` | 外汇核销单 | `VR` |
| 形式发票 | `PI` | 其他 | `TD` |
| 产地证 | `CO` | | |

编号形如 `CI-SO202609230001`（可读、可回溯来源）。与历史人工台账冲突时自动追加 `-2`、`-3`…（最多 200 次），保证 `DocNo` 唯一。

## 4. 接口清单

| 用途 | 方法与路径 | 说明 |
|---|---|---|
| 销售订单带入预填 | `GET /api/sales-orders/{id}/trade-documents/prefill` | 返回**未落库**草稿（5 类）+ `generatedDocTypes`（已生成类型）；不写库、不占用编号 |
| 销售订单生成单证 | `POST /api/sales-orders/{id}/trade-documents` | Body `{ "docTypes": ["商业发票","装箱单"] }`，为空时用默认类型 |
| 装柜清单带入预填 | `GET /api/container/loading-lists/{id}/trade-documents/prefill` | 同上（4 类可生成类型） |
| 装柜清单生成单证 | `POST /api/container/loading-lists/{id}/trade-documents` | 同上 |
| 单证导出（列表） | `GET /api/trade/documents/export-excel?keyword=&docType=&status=&start=&end=` | 关键字命中单证编号/客户/柜号/订单号/报关单号；xlsx 附件 |
| 单证导出（单条） | `GET /api/trade/documents/export-excel?id={id}` | 单条导出，文件名 `TradeDocument_{id}_{时间戳}.xlsx` |

响应契约：`TradeDocPrefillResult`（`sourceType/sourceId/sourceNo/sourceRefNo/documents/generatedDocTypes/defaultDocTypes/supportedDocTypes`）、`TradeDocGenerateResult`（`sourceType/sourceId/sourceNo/documents[{id,docNo,docType,status}]`）；JSON 一律 camelCase（与 `Program.cs` 一致）。

## 5. 重复生成守卫（不产生重复单证）

- **销售订单来源**：同一 `SalesOrderNo` + 同一 `DocType` 视为已生成；
- **装柜清单来源**：同一柜号 `RefNo` **或**备注留痕指向同一装柜清单号，命中同一 `DocType` 即视为已生成（一柜一类单证只应有一份）；
- 批量生成时**任一类型已生成即整体拒绝**（错误码 `RuleConflict`，提示「该…已生成「商业发票」（单证编号 CI-…），不能重复生成」），不会写入半成品数据；
- 已**软删除**的单证不参与判定（删除后可重新生成）；
- 「带入预填」不落库，因此重复校验时机在落库接口上；对话框同时把已生成类型置灰并取消勾选（前端防重）。

其他守卫：来源单据已作废 → `RuleConflict`；未选择类型 → `InvalidParameter`；不在该来源可生成清单内的类型 → `InvalidParameter`（提示可生成类型）；生成后的单证状态为 `待制作`，仍可在单证中心编辑（金额/份数/制作人/备注/状态），**来源留痕保留**。

## 6. 前端入口（`src/ERP.Api/wwwroot`）

| 位置 | 入口 | 行为 |
|---|---|---|
| 销售订单页（`modules-doc.js` 的 `rowActions`） | 「生成单证」/「预填单证」 | 打开对话框（默认勾选商业发票 + 装箱单）→ 生成所选单证 / 带入预填到单证中心新增表单 |
| 装柜清单页（`modules-doc2.js` 的 `rowActions`） | 「生成单证」/「预填单证」 | 同上（默认勾选装箱单） |
| 单证中心页（`modules.js` 的 `extraActions`） | 「📤 导出 Excel」 | 导出对话框（单证类型 / 状态 / 出具日期区间 / 关键字）→ 下载 xlsx |
| 单证中心页（`rowActions`） | 「导出该单证」 | 单条导出为 `单证_{单证编号}.xlsx` |

脚本 `trade-doc-gen.js` 在 `index.html` 中随 `sales-pi.js` 之后加载；生成成功后自动跳到单证中心列表，用户可立即看到新生成的单证。

## 9. 已知限制与后续建议

1. **无附件管理**：单证扫描件仍只能记在 `FileNote`（文本），附件中心为独立缺口（Backlog §2 #20）；
2. **单证版式打印**：本任务只做 Excel 导出，未做 PDF/版式打印；如需可复用共享打印设计（`print-design.js`）另立任务；
3. **金额与明细**：单证台账为单表，不含商品明细（装箱单明细仍需人工或另立主子表任务）；
4. **装柜清单 → 销售订单关联**：`ContainerLoadingDetail` 无订单号，故装柜清单来源的 `SalesOrderNo` 留空，靠柜号留痕；
5. **报关单号 / 柜号回填**：销售订单来源的 `RefNo`/`DeclareNo` 由人工在单证中心补录（不引入新字段）。
