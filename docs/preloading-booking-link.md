# 预装柜单衔接待审核订柜信息（ERP-353）

## 1. 目标

让**既有**预装柜单上游的 `ContainerPreLoading.BookingId` 成为**受校验的权威引用**：只要显式填写，
创建 / 修改 / 提交 / 审核任一环节都必须重新解析出一条仍然有效的订柜信息（存在、未删除、已审核），
并且落在当前账号既有的「预装柜单」菜单授权与客户数据范围之内；订柜信息取消与预装柜单审核在同一把
订柜行锁 + 可串行化事务内协同，避免「上游已取消、下游已审核」的失效履约证据。

只复用既有分层架构与既有单据流转（创建 / 修改 / 提交 / 审核 / 取消），不做报表、不做 Agent、
不做界面视觉 / 样式 / 导出打磨，不写库存 / 财务，也不调用任何外部跟踪系统。

## 2. 口径

| 项 | 口径 |
|---|---|
| 来源链接 | `ContainerPreLoading.BookingId`（可空，刻意不建外键） |
| 权威来源 | 订柜信息存在、未删除且 `Status = Approved`；已删除 / 未审核 / 已取消 / 已驳回 / 待提交 / 已提交 / 已完成一律拒绝 |
| 未关联历史 | `BookingId = null` 的历史预装柜单**不做来源校验**（仍校验身份 / 菜单），行为与改造前完全一致，不强制补链接、不回填 |
| 授权 | 操作要求当前账号具备既有「预装柜单（pre-loading）」菜单授权（特权账号继承既有全部访问）；取消订柜信息要求既有「订柜信息（booking）」菜单授权 |
| 数据范围 | 预装柜单自身没有客户字段 → 以**订柜信息的归属客户** `ContainerBooking.CustomerId` 参与既有业务员客户数据范围判定；范围外订柜一律拒绝（fail closed） |
| 校验时点 | 创建 / 修改 / 提交 / 审核**每一路由**都重新解析，绝不信任客户端提交的状态与快照 |
| 审核原子性 | 审核在 `IsolationLevel.Serializable` 事务内先对订柜信息行加 `UPDLOCK/HOLDLOCK`，锁内重新加载本单与订柜信息后才置为已审核 |

### 2.1 字段推导边界（只认订柜信息上实际存在的权威字段）

订柜信息（`ContainerBooking`）的权威字段只有：订柜号、状态、客户、供应商、柜型、船公司 / 物流公司、
航次、开船日、起运港、目的港，以及 ERP-040 的外贸与物流跟踪列（出运方式、B/L、S/O、中转港、
ETD / ETA / ATD / ATA、拖车、报关行、查验与放行）。

订柜信息**没有柜号、没有封条号、没有参与方字段** —— 因此：

- 预装柜单的 `ContainerNo` / `SealNo` 始终是**本单自己的运行记录**（由操作员显式录入），
  **绝不**从订柜信息推导、**绝不**改写 / 清空，也**绝不**臆造封条号；
- **绝不**把客户 / 参与方归属从订柜信息写回预装柜单（预装柜单没有客户列，也不新增）；
- 跟踪值仍是**只读回显**（ERP-040）：按 `BookingId` 解析订柜信息原样返回，没有第二份跟踪值，
  不按柜号等自由文本兜底匹配。

## 3. 权威柜号链接冲突判定

同一订柜信息（一票订柜 = 一个柜）下，如果还存在**其他仍然有效**的预装柜单（未删除且未取消 / 未驳回）
且申报了**不同**柜号，则两者的柜号主张互相冲突 → 拒绝保存 / 审核，错误信息指出冲突单据号与柜号：

- 本单未申报柜号（空串）= 无柜号主张，不参与冲突判定，也不反向推导柜号；
- 与本单柜号一致（忽略大小写与首尾空白）视为同一柜号主张，允许；
- 已取消 / 已驳回 / 已删除的预装柜单不构成冲突，不阻断；
- 由客户端自由文本比较得出，**不写任何列**。

## 4. 订柜取消与预装柜审核的并发协同

`ContainerPreLoadingController.Approve` 与 `ContainerBookingController.Cancel` 按如下顺序执行，整体包在
`IsolationLevel.Serializable` 事务内，并**共用同一把订柜信息行锁**
（`SELECT Id FROM db_owner.ContainerBookings WITH (UPDLOCK, HOLDLOCK) WHERE Id = @id`）：

1. 预装柜单按主键读取本单头（取 `BookingId`）；
2. 开启可串行化事务；
3. 对**来源订柜信息行**加 `UPDLOCK/HOLDLOCK`（未关联不加锁；非关系型提供程序跳过）；
4. 锁内重新加载本单 / 订柜信息，校验当前状态（预装柜单必须是 `Submitted`）；
5. `PreLoadingBookingLinkRules.ValidateApprovalAsync` / `ValidateBookingCancellationAsync` 做权威判定；
6. 置为已审核 / 已取消并提交事务。

`ValidateBookingCancellationAsync`（订柜取消）在锁内拒绝两类有效下游引用：

- 「以本订柜为权威来源、未删除、已审核」的**预装柜单**；
- 历史数据不一致时仍以本订柜下预装柜单为来源的**已审核装柜清单**。

已取消 / 已驳回 / 待提交 / 已提交 / 已删除的预装柜单不算有效引用，不阻断取消。
解除**只走既有显式取消流程**：先取消装柜清单（ERP-348 护栏）→ 再取消预装柜单 → 最后取消订柜信息。
任何一步失败即回滚：订柜信息与预装柜单的状态、柜号、封条号与明细都保持不变，且**不写库存 / 财务 / 外部系统**。

并发下「订柜取消」与「预装柜审核」抢同一把订柜行锁，只能成功其一：

- 取消先提交 → 预装柜审核在锁内看到订柜信息已取消，fail closed 拒绝；
- 审核先提交 → 订柜取消在锁内看到已审核预装柜单，fail closed 拒绝。

## 5. 错误信息（API 直接返回）

全部通过既有 `BusinessException` 抛给既有异常中间件：

- 非正订柜 Id：`订柜信息 Id 必须为正整数`（1001 参数校验失败）；
- 不存在 / 已删除：`订柜信息不存在或已删除，不能作为预装柜单的权威来源`（1004 规则冲突）；
- 已取消：`订柜信息 [DG...] 已取消，不能作为预装柜单的权威来源`；
- 未审核：`订柜信息 [DG...] 未审核，不能作为预装柜单的权威来源`；
- 范围外：`当前账号的客户数据范围不包含该订柜信息的客户：拒绝关联（fail closed，不泄露范围外单据）`（2002 权限不足）；
- 柜号冲突：`订柜信息已由预装柜单 [YZ...] 关联柜号 [CTN-A]：本单柜号 [CTN-B] 与同一订柜信息下的权威柜号链接冲突，不能保存`；
- 订柜取消受阻：`存在已审核且未取消的预装柜单 [YZ...] 引用本订柜信息：请先按既有流程取消预装柜单，再取消订柜信息`；
- 无身份 / 无菜单：`请先登录后再操作预装柜单`（2000）/ `当前账号没有「预装柜单」（pre-loading）模块授权...`（2002）。

## 6. 不改写项

- 不新增表列 / 外键 / schema，不改 `SchemaUpgrader` 与种子数据；不重写历史预装柜单的柜号、封条号、
  明细与原始数量，也不为历史单据补链接或回填跟踪值；
- 不新增权限、菜单、报表、Agent、前端页面；数据范围沿用既有 ERP-097 口径，不扩权；
- 不写库存 / 库存流水 / 财务 / 结算记录，不产生装柜清单、单证、费用或任何下游单据；
- 不调用船公司、海关、报关行、货代或任何跟踪 / 订舱服务，不做 EDI / API 对接；
- 不按订柜号 / 柜号等自由文本猜测链接，不由审核推断开船 / 离港，不由订柜信息臆造封条号与参与方。

## 8. 真实 SQL 夹具安全口径

- 目标必须为专用 localdb 实例 `(localdb)\NEWERP_AutoAcceptance`，库名前缀 `NEWERP_AUTOTEST`，
  且 `Integrated Security=true`，护栏在**任何数据库访问之前**校验失败即中止；
- 每次运行创建**全新的 GUID 后缀库**，发现同名库已存在立即拒绝，绝不 drop / reset / 复用任何数据库；
- 不读取 `appsettings` / `.env` / 生产凭据；连接串只来自进程环境变量或专用 localdb 默认值；
- 测试种子一律使用 SQL Server 自增主键（不显式指定 Id），保留完整日志输出。
