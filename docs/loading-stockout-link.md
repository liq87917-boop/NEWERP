# 装柜明细 → 已审核销售出库证据链接（ERP-366）

## 1. 背景与目标

装柜清单明细（`ContainerLoadingDetail`）此前只有 `ProductId` 与 `Quantity`，**没有**指向真实销售出库的显式来源：
ERP-348 只按「预装柜单」做累计超装护栏，物理出运证据（已审核销售出库明细）与装柜数量彼此脱节。

本任务（阶段 3 库存闭环）在既有领域实体上**只新增一个可空证据列**，把每条装柜明细与
**已审核、未删除的销售出库明细**显式链接起来，并在审核时以「来源出库数量 − 已生效退货」为容量上限做累计校验。

## 2. 数据与结构（可空留痕，不回填）

| 项目 | 内容 |
| --- | --- |
| 列 | `db_owner.ContainerLoadingDetails.SourceStockOutDetailId`（`BIGINT NULL`） |
| 语义 | 指向该装柜行认定的**已审核、未删除**销售出库明细；`NULL` = **显式未链接**（历史 / 无证据） |
| 外键 | **刻意不建**：来源出库单软删除 / 取消后，历史装柜证据仍必须可读 |
| 索引 | `IX_ContainerLoadingDetails_SourceStockOutDetailId`（过滤 `IsDeleted = 0 AND SourceStockOutDetailId IS NOT NULL`，读取侧有界检索） |
| 升级 | `SchemaUpgrader` 第 29 段以 `IF OBJECT_ID(...) IS NOT NULL AND COL_LENGTH(...) IS NULL` 幂等加列，索引**独立成批**创建（避免同批引用新列触发错误 207） |

**历史明细一律保持 `NULL`**：不按出库单号 / 金额 / 相似度猜测来源、不做任何回填，
未链接数量既不计入「已证明出运」，也不占用来源容量。

## 3. 权威来源与客户范围

显式链接必须构成**权威来源**，任一不满足即 fail closed（保存 / 提交 / 审核前）：

1. 来源销售出库明细**存在且未删除**；
2. 父销售出库单**存在、未删除、状态为已审核**（已取消 / 未审核 / 已删除一律拒绝，构成「来源撤销」护栏）；
3. 装柜明细商品与来源出库明细**商品一致**；
4. **基础单位语义一致**：出库明细单位为空或等于商品基础单位（商品未维护基础单位时 fail closed）；
5. 出库单客户属于本装柜清单的**权威客户范围**（兼容 `CustomerId` + 全部「启用、未删除」参与方客户；
   一柜多客户必须逐客户匹配）；
6. 新链接的装柜数量必须为**正数**。

## 4. 容量口径（审核，原子提交）

审核时按「**来源出库单 + 商品**」聚合：

```
累计已链接装柜数量（其它已审核装柜清单 + 本次）
    ≤ 来源出库明细数量（同商品重复行聚合） − 已生效（已审核、未删除）销售退货数量
```

- 销售退货**缺明细 Id**，因此退货按商品**保守聚合**（单位可折算为基础单位时按基础单位，无法折算按原始数量计入，
  绝不忽略退货）；绝不猜测退货归属到哪一条出库明细；
- 跨商品不合计；历史未链接数量不参与（既不计为已证明出运，也不占用容量）；
- 重复装柜行 / 重复来源明细行先聚合再判定；
- 判定与状态变更在**同一可串行化事务**内完成，任一步失败整体回滚：**明细、状态、历史零改动**；
- 装柜审核**不**二次过账库存、**不**改财务、**不**生成任何库存流水 / 费用。

## 5. 并发与锁序

审核 / 链接的确定性锁序固定为：

```
上游销售出库单行（StockOutId 升序，UPDLOCK, HOLDLOCK）
    → 来源预装柜单行（既有 ERP-348 锁）
    → 装柜清单行（UPDLOCK, HOLDLOCK）
```

上游出库行锁与「销售退货审核 / 销审 / 来源出库取消」共用同一把来源行锁，保证并发下只出现一致结果。
两条已链接装柜竞争同一来源容量时只放行合法总量；同一单据双连接并发审核只成功一次。

## 6. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `api/container/loading-lists/{id}/stock-out-candidates?keyword=&take=` | **只读、有界**候选证据：返回权威客户范围内「已审核、未删除」出库明细，并显式回传父 `StockOutId` / `SalesOrderId` / 商品 / 客户 / `RemainingBaseQuantity`（返回条数钳制在 1..200） |
| POST | `api/container/loading-lists/{id}/stock-out-links` | 指派 / 清除显式链接：**先整体校验全部拟议链接，再改写任何一行**；同一可串行化事务内提交，仅「待提交」状态可维护 |

两个接口都复用既有「装柜清单」与「销售出库」菜单授权、当前用户与实时客户数据范围（ERP-097 / ERP-364），
**不新增任何用户授权、不提供匿名 / 管理员降级**。

## 7. 边界

- 不改变库存成本口径（移动加权平均）、不改写商品 / 客户 / 销售订单 / 出库单主数据；
- 不重写历史装柜明细数量与状态、不删除任何审计证据；
- 不新增表 / 菜单 / 权限模型（只新增一个可空证据列与其读取侧过滤索引）；
- 生产库结构变更仍由 `SchemaUpgrader` 幂等补齐，人工高风险 Gate 不变。
