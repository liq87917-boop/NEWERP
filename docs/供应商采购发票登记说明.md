# 供应商采购发票登记说明（ERP-043，ERP-065 扩展）

## 1. 背景与定位

出口 / 内销采购业务中，供应商会开具**普通发票（普票）**、**增值税专用发票（专票）**，
进口业务则取得**进口发票 / 海关进口增值税专用缴款书**。系统原本只有采购订单与执行进度，
无法登记「这批货款到底有没有票、票面金额多少、对应哪几张采购订单、票面到期日与付款条件是什么」，
也无法在出现错票 / 重开时留下可追溯的更正痕迹。

本次（ERP-043 建立登记册，ERP-065 扩展类型与到期日 / 付款条件证据）**供应商采购发票登记册**：

- 登记发票证据本身：发票类型（普票 / 专票 / 进口）、发票代码（专票必填）、发票号码、开票日期、
  **可选到期日**、**可选付款条件**、供应商、币种、不含税金额、税额、含税总额、备注；
- 可（可选、显式）把含税总额的**全部或一部分**关联到既有采购订单，并显式展示**已关联 / 未关联金额**；
- 关联只按**权威一致性**（同供应商 + 同币种、订单未取消）建立，**不按单号相似度、金额相近、开票日期接近猜测订单**；
- 登记（记录）后证据**冻结**，更正走**显式作废**（保留身份 / 金额 / 关联 / 审计历史），不删除、不静默改写。

定位：**操作性的发票证据台账**。它**不是**应付账款台账、**不是**税务申报系统、**也不是**付款授权机制，
不引入第二套账务引擎（不记账、不生成凭证 / 收款 / 付款 / 结算单）。

## 2. 发票字段与校验口径

| 字段 | 口径 |
|---|---|
| 发票类型 | `普票` / `专票` / `进口`（其它取值一律拒绝；客户销项侧的「出口发票」与单证商业发票类型刻意不受支持） |
| 发票代码 | 专票**必填**、普票与进口票可选（票面无发票代码时留空，系统不臆造代码）；去首尾空白，长度 ≤ 50 |
| 发票号码 | **必填**，长度 ≤ 50（一张发票登记一条，不支持多号码拼接） |
| 开票日期 | 必填（留空按当天）；登记时按日期存储，不改写任何既有单据日期 |
| 到期日 | **可选、显式证据**（ERP-065）：留空 = **未知**；填写只取日期部分且**不得早于开票日期** |
| 付款条件 | **可选、显式证据**（ERP-065）：有界文本快照（≤ 200 字符，去首尾空白），留空 = **未提供** |
| 供应商 | 必须**存在、未删除且启用**；供应商编码 / 名称由服务端写成**快照**（客户端提交值不被采信） |
| 币种 | 系统支持币种：`CNY / USD / EUR / HKD / GBP / JPY`（与采购订单币种同源）；未知币种一律拒绝 |
| 金额 | 不含税金额（净额）、税额、含税总额（价税合计），均以**原币**存储，DECIMAL(18,2) |

**金额等式（服务端权威校验）**：

```
含税总额（价税合计） = 不含税金额（净额） + 税额
```

- 三项均按**币种精度**四舍五入后必须**严格相等**：JPY / KRW / VND / IDR 为 0 位小数，其余（含未知币种口径）为 2 位；
  取整一律 0.5 进位（不使用银行家舍入）；
- 含税总额必须**大于 0**，三项均不得为负；税额允许为 0（不征税 / 免税票）；
- 系统**不按税率反推金额**、**不自动调整差额**、不做汇率换算、不跨币种合并。

> 金额等式不成立时接口直接拒绝并给出差额，界面只做提示，**不会**替用户改写金额。

币种精度口径与装柜费用分摊（ERP-042）共用同一权威实现（`CurrencyAmountRules`），系统中不存在第二套取整规则。

## 3. 有效身份唯一（重复登记被拒绝）

唯一身份 = **供应商 + 发票类型 + 规范化发票代码 + 规范化发票号码**：

- 规范化 = 去首尾空白、去掉所有空白与连字符（`-`、`－`、`—`、`_`）后**大写**；
  因此 `0440-3190 / 8800 1` 与 ` 04403190 / 88001` 被视为**同一张发票**；
- 只在**未作废且未删除**的记录范围内唯一：重复请求一律**拒绝**（不静默合并、不覆盖原记录）；
- 已**作废**的记录**保留可读**，但**不占用身份**：作废后可以用同一身份重新登记新发票（历史与新记录并存可查）。

## 4. 采购订单关联口径

一条发票可以把含税总额关联到**一张或多张**采购订单（草稿期维护，整体替换保存）：

| 规则 | 口径 |
|---|---|
| 订单可用性 | 必须存在、未删除、**未取消**（已取消订单不参与发票证据关联） |
| 供应商一致 | 订单 `SupplierId` 必须与发票供应商**完全相同**（按 Id 判定，不按名称模糊匹配） |
| 币种一致 | 订单币种必须与发票币种**完全相同**（**不做汇率换算**） |
| 金额 | 每行按币种精度取整后必须**大于 0**；**合计不得超过发票含税总额** |
| 重复 | 同一张采购订单在同一张发票内**只能关联一次**（重复行直接拒绝，不合并金额） |
| 未关联 | 发票允许**部分或全部未关联**：未关联金额保留为「未关联」，**不会**被猜测到任何订单 |
| 数量上限 | 单张发票最多关联 50 张采购订单（有界） |

保存关联时服务端写入的是一份**快照**：采购单号、订单日期、订单币种、供应商编码 / 名称，
以及关联金额；采购订单后续改名 / 改币种 / 被取消**不会**破坏历史关联的可读性（只会显式标注不可用）。

关联保存在草稿期是**整体替换**语义（提交即当前完整清单，可提交空清单 = 清空全部关联），
并在**同一次 `SaveChanges`** 内完成：校验失败不会留下部分关联行。登记后关联即冻结。

## 5. 状态机与证据冻结

| 状态 | 可编辑发票头 | 可维护关联 | 可登记 | 可作废 | 说明 |
|---|---|---|---|---|---|
| 草稿（0） | 是 | 是 | 是 | 是 | 工作数据；可反复修改 |
| 已登记（1） | 否 | 否 | 否（重复登记被拒绝） | 是 | 证据冻结，保留可读 |
| 已作废（2） | 否 | 否 | 否 | 否（重复作废被拒绝） | 历史证据保留，可读 |

登记（`POST /{id}/record`）前会**复核**已持久化关联行仍然权威可关联：关联订单存在且未删除、未取消、
供应商与币种一致、关联合计不超过含税总额；不满足时**拒绝登记**（不会静默丢弃关联行，也不改写采购订单）。

修改草稿时如已有采购订单关联，**不允许更换供应商或币种**（会破坏关联口径）：必须先清空关联再修改。

## 6. 更正：作废而不是删除

- `POST /{id}/void` 把发票状态改为「已作废」并记录**作废原因（必填）**与时间；
- **保留**发票身份、金额、币种、供应商快照、**全部关联行**与审计历史；**不物理删除**、**不改写**已登记证据；
- 不产生任何收款 / 付款 / 结算 / 记账动作；
- 作废后同一「供应商 + 类型 + 代码 / 号码」可以重新登记新发票，旧记录仍可在台账中按「已作废」筛选查看。

## 7. 台账读取与关联展示

- 台账（`GET /api/purchase-invoices`）为**分页 + 有界**（默认 50 条 / 页，上限 200），可过滤：
  供应商、发票类型、状态（草稿 / 已登记 / 已作废）、币种、开票日期区间、关联状态（`linked` 已全额关联 /
  `partial` 部分关联 / `unlinked` 未关联）、关键字（发票号码 / 代码 / 供应商编码与名称）；
  默认**包含已作废历史**；分页参数被钳制到合法范围；
- 关联状态过滤与分页口径**一致**：先按持久化关联行派生每张发票的已关联金额再过滤，
  因此「只看未关联」不会因分页漏行；
- 每张发票显式给出：`linkedAmount`（已关联）、`unlinkedAmount`（未关联）、`allocationCount`、`linkageStatus`、
  `linkageText`（中文口径文案）、`supplierAvailable` / `supplierAvailabilityText`（供应商停用 / 删除后照实说明，历史可读）；
- 每条关联行显式给出：订单快照（单号 / 日期 / 币种 / 供应商）与 `orderAvailable` / `orderAvailabilityText`
  （订单已取消 / 已删除时历史关联仍可读）；
- 可关联订单候选（`GET /{id}/order-candidates`，只读有界，最多 200 条）：只返回**同供应商 + 同币种**订单
  （含已取消订单并标注不可关联），并派生订单总额、本发票已关联、其他**有效**发票（非作废）已关联、
  以及「剩余未被发票证据覆盖」金额（下限 0）。该派生值只按持久化关联行计算，
  **不是**应付余额、账龄或付款依据；
- 关联预览（`POST /{id}/allocations/preview`）为**只读**：逐行给出订单快照、资格文案与拟关联金额，
  以及保存后的已关联 / 未关联金额；预览与保存共用同一校验入口，**预览所示即保存结果**；
- 台账与详情映射按页**批量装载**关联行 / 订单 / 供应商（无逐行数据库查询）。

## 8. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/purchase-invoices` | 台账分页（供应商 / 类型 / 状态 / 币种 / 开票日期 / 关联状态 / 关键字过滤） |
| GET | `/api/purchase-invoices/{id}` | 详情（含关联行、已关联 / 未关联金额与可用性标注） |
| POST | `/api/purchase-invoices` | 新增草稿（校验类型 / 代码 / 号码 / 供应商 / 币种 / 金额等式与重复身份） |
| PUT | `/api/purchase-invoices/{id}` | 修改草稿（已登记 / 已作废拒绝；有联更换供应商 / 币种拒绝） |
| GET | `/api/purchase-invoices/{id}/order-candidates` | 可关联采购订单候选（同供应商 + 同币种，有界，只读） |
| POST | `/api/purchase-invoices/{id}/allocations/preview` | 关联预览（只读，不写库） |
| POST | `/api/purchase-invoices/{id}/allocations` | 保存关联（草稿专用，整体替换，事务性） |
| POST | `/api/purchase-invoices/{id}/record` | 登记（草稿 → 已登记，登记前复核关联） |
| POST | `/api/purchase-invoices/{id}/void` | 作废（原因必填；保留历史与关联） |
| GET | `/api/purchase-invoices/reconciliation` | **供应商采购发票对账报表（ERP-044，只读派生）**：按供应商 + 币种核对订单金额 / 已开票金额 / 未开票余额与未关联金额，支持证据状态（含已作废历史）与关联状态筛选，见 §10 |

前端入口：采购订单模块工具栏与行操作「🧾 供应商发票」（`wwwroot/js/supplier-purchase-invoices.js` +
`modules-doc.js`）。从行操作进入时会按该采购订单的**供应商与币种**预筛选 / 预填（只允许关联同供应商 + 同币种的订单）。
对账报表入口：采购订单模块工具栏「📑 发票对账报表」（`wwwroot/js/supplier-invoice-reconciliation.js`，见 §10）。

## 9. 边界（明确不做的事）

- **不是应付账款台账 / 账龄表**：不创建应付记录、不推算账期与到期日、不做账龄分摊；
- **不是税务申报系统**：不做进项认证、不做税负计算、不生成申报表；
- **不是付款授权机制**：登记 / 作废发票都不触发付款、不改变付款状态、不生成付款申请 / 付款单 / 结算单；
- 不改写**采购订单**：状态、到货进度、已收数量、归属客户 / 销售订单、金额与明细一律不变；
- 不改写**库存与库存成本**（`Stocks`）、**库存流水**（`StockMovements`）、**退税记录**（`BaseTaxRefunds`）、
  **供应商主数据**（余额 / 结算方式 / 开票能力）与**收付款记录**（`FinancePayments` / `FinanceReceipts`）；
- 不做历史数据回填：既有供应商与采购订单在没有任何发票数据时行为**完全不变**；
- 不按单号相似度、金额相近、开票日期接近或备注文本猜测采购订单；未关联金额永远保持「未关联」。

## 10. 供应商采购发票对账报表（ERP-044，只读派生）

采购订单模块工具栏「📑 发票对账报表」入口（`wwwroot/js/supplier-invoice-reconciliation.js`）调用
`GET /api/purchase-invoices/reconciliation`（`SupplierInvoiceReconciliation.ForQueryAsync`）。
该报表**只读派生**：不落库、不改发票 / 采购订单 / 收货进度 / 库存与库存成本 / 付款 / 费用 / 退税记录，
也不新增或修改任何表列。

> **与应付账款台账 / 付款授权 / 税务申报 / 账龄表的边界（重要）**：本报表是**运营性的采购发票对账视图**，
> 不是发票口径的应付账款台账、不是付款授权、不是税务申报报表，也不是账龄表 —— 不推算账期与到期日、
> 不做账龄分摊、不做进项认证与税负计算、**不判断是否已付款**；「未关联金额」只是发票尚未按持久化关联行
> 归属到采购订单的金额，「未开票余额」只是订单尚未被有效发票证据覆盖的金额，**两者都不得当作应付余额、
> 不得据以付款，也不代表欠款已逾期**。

**派生口径**

- 分组 = **供应商 + 币种**：不同币种分别成行，绝不合并为一个金额、也不做汇率换算；报表不存在任何跨币种总额字段；
- 发票侧（本页入选发票）：
  - `grossAmount` 取发票已落库含税总额，`linkedAmount` **只按该发票的 ERP-043 持久化关联行**合计，
    `unlinkedAmount` = 含税总额 − 已关联金额（下限 0），`linkageStatus` = `linked` / `partial` / `unlinked`；
  - **部分关联与整笔未关联的金额只作单列**，系统绝不按单号、金额或日期相似度把它归到任何采购订单；
  - 每张发票的订单行只来自该发票的持久化关联行；未关联发票不会出现在任何订单行下；
- 订单侧（本页有效发票涉及的订单，按订单去重后汇总）：
  - `orderedAmount` 取采购订单已落库总额；`invoicedAmount` 只统计**未作废且未删除**发票的持久化关联行
    （与本页发票日期筛选无关，因此「未开票余额」不随筛选漂移）；
  - `remainingUninvoicedAmount` = 订单金额 − 已开票金额（逐单下限 0），**只在订单金额已知且订单未取消时计算**；
  - `coverageStatus` = `fully_invoiced` / `partially_invoiced` / `not_invoiced` / `unknown`；
  - 订单**不存在 / 已删除**时：订单金额与未开票余额为**未知（null）**，已关联金额仍如实列出（不按 0 处理）；
  - 订单**已取消**时：订单金额仅作历史参考，未开票余额与覆盖状态按**未知**显示；
- 收货数量与结算金额复用**「采购订单执行进度（ERP-026）」的同一套权威口径**（已审核入库单 / 付款单 →
  货款申请单 → 归属销售订单）；链接不唯一、无可用引用或命中批量上限时一律为 **null（未知显示为「未知」）**，
  绝不用 0 顶替，也不代表已付款或已结清。

**证据状态与已作废历史**

| `evidenceStatus` | 口径 |
|---|---|
| `recorded`（默认） | 只统计**已登记且未作废**发票 = 登记证据；草稿（工作数据）与已作废历史都不进入报表 |
| `draft` | 只看草稿（工作数据） |
| `voided` | 只看已作废历史证据（仅历史核对） |
| `all` | 全部状态；**已作废金额仍单独成列**（`voidedGrossAmount` / `voidedOrderAllocatedAmount`），永不并入任何有效合计 |

**筛选与分页（有界）**

- 筛选：供应商、币种、**订单日期**（依据关联行的订单日期快照，故只会返回已关联发票）、**开票日期**、
  关联状态（`linked` / `partial` / `unlinked`）、证据状态、关键字（发票号码 / 代码 / 供应商编码与名称 /
  关联行的采购单号快照）；非法取值直接拒绝，不静默忽略筛选条件；
- 分页按「供应商 + 币种 + 开票日期（倒序）+ 发票 Id（倒序）」**稳定排序**，每页默认 50、上限 200；
  分组与币种汇总**只统计本页**（页脚与接口 `scopeNote` 均如实说明）；
- 查询次数固定（计数 + 分页 + 本页发票 + 本页关联行 + 本页订单 + 订单关联行 + 关联发票状态 + 供应商名 +
  收货 2 次 + 结算 3 次共 12 次数据集访问），与页大小、单据数量无关（无逐行查库 / 无 N+1）；全程只读。

## 12. 采购订单发票证据视图（ERP-048，只读派生）

ERP-048 在**既有采购订单列表 / 详情工作流**中暴露只读的发票证据汇总（详见 `docs/采购订单发票证据说明.md`）：

- `GET /api/purchase-orders/{id}/invoice-evidence`：单张订单的发票证据详情；
- `GET /api/purchase-orders/invoice-evidence-summaries?ids=…`：列表用有界批量汇总（≤ 200 张订单，固定 3 次数据集访问，无逐行查库）。

口径与 ERP-043 / ERP-044 **同源**（不引入第二套算法）：

- 已开票金额只按本登记册的**持久化关联行**派生，且只统计**已登记且未作废**发票；草稿、已作废、
  供应商 / 币种不一致的无效证据与无法确认证据（发票或订单已删除）分别单独分桶，**绝不计入已开票金额**；
- 覆盖状态与订单可用性文案**复用 ERP-044 的同一套常量与文案**，订单供应商 / 币种校验**复用 ERP-043 的
  权威资格判定**（`PurchaseInvoiceRules.EvaluateOrderEligibility`，不做汇率换算）；
- 该视图**只读**：不写本登记册的任何记录、不自动建立 / 修改 / 作废 / 改派关联，
  也不改写采购订单状态 / 到货进度 / 结算进度文本、库存、收付款、供应商余额、费用或退税记录；
- 该视图**不是**应付余额、付款授权、税务申报判断或结算状态；金额未知（`null`）一律显示「未知」，绝不用 0 顶替。

## 13. 付款引用证据与对账报表第三类证据（ERP-050，只读派生）

ERP-050 把 ERP-049 的**持久化付款引用行**以只读方式暴露为**第三类独立证据**（与订单金额、已开票金额**分别标注**，
详见 `docs/采购订单付款证据说明.md`）：

- `GET /api/purchase-orders/{id}/payment-evidence`：单张订单的付款引用证据详情；
  `GET /api/purchase-orders/payment-evidence-summaries?ids=…`：列表用有界批量汇总（≤ 200 张订单，固定 4 次数据集访问，无逐行查库）；
- **ERP-044 对账报表**（`GET /api/purchase-invoices/reconciliation`）在订单行 / 分组 / 币种汇总上新增
  `paymentReferenceAmount`（付款引用金额）、`paymentReferenceOrderCount` / `noPaymentReferenceOrderCount` /
  `unknownPaymentReferenceOrderCount`（有 / 无 / 未知付款引用证据的订单张数）与 `historicalPaymentAllocationCount`
  （已作废 / 无效 / 无法确认的历史引用行数），报告级同时给出 `paymentEvidenceRule` 与 `paymentEvidenceBoundary` 文案；
- 口径与 ERP-049 **同源**（不引入第二套算法）：有效已引用金额只按**有效（未作废）**引用行派生，
  资格判定复用 `SupplierPaymentAllocationRules.EvaluateOrderEligibility`，供应商 / 币种不一致按**无效历史证据**单列
  （不换算、不合并、不改派），付款单已删除按**无法确认**单列，已作废历史证据**绝不并入有效合计**；
- 该视图**只读**：不写引用行、不改写付款单与采购订单、不改写发票与发票关联、库存、收付款、费用或退税记录；
- 该视图**不是**银行付款凭证、**不是**应付余额、**不是**发票核销、**不是**结算结果与账龄表：
  没有付款引用行时只显示「无付款引用证据」，绝不被推断为未付款、已付款、已结清、逾期或欠款。

## 14. 进口发票与到期日 / 付款条件证据（ERP-065）

ERP-065 把登记册的**类型覆盖**扩展到进口业务，并补齐票面上与付款相关、但**只能由用户显式提供**的两类证据。

**支持的发票类型（服务端 `PurchaseInvoiceRules.SupportedInvoiceTypes`，未知类型一律拒绝）**

| 类型 | 说明 | 发票代码 |
|---|---|---|
| `普票` | 增值税普通发票 | 可选（票面无代码时留空） |
| `专票` | 增值税专用发票 | **必填** |
| `进口` | 进口发票 / 海关进口增值税专用缴款书 | 可选（进口缴款书通常没有发票代码） |

> 「出口发票」属于**客户销项发票证据**（ERP-055），单证中心的**商业发票**属于贸易单证；
> 两者与供应商采购发票登记册**刻意分离**：不转换、不替换、不自动链接，也不因号码或金额相同而合并。

**到期日（`DueDate`）与付款条件（`PaymentTerms`）**

| 规则 | 口径 |
|---|---|
| 来源 | 只来自授权用户在登记 / 修改草稿时**显式提交**的值（服务端不做任何补值） |
| 到期日留空 | `null` = **未知**：`dueDateKnown = false`，`dueDateText` 明确显示「未知」，并声明系统不按供应商默认账期、付款条件、备注或历史发票推算 |
| 到期日填写 | 只保留日期部分，且**不得早于开票日期**（明显录入错误的到期日直接拒绝，不静默改写） |
| 付款条件 | 有界文本快照（去首尾空白，≤ 200 字符）；留空 = **未提供**（`paymentTermsText` 明确显示「未提供」） |
| 不使用场景 | 不据此计算账龄 / 逾期 / 现金折扣 / 付款义务，不写入账龄表，也不是付款授权 |
| 生命周期 | 草稿可反复修改或清空；**登记后冻结**（与身份 / 金额 / 关联一样只读）；**作废保留**原值与历史 |

**接口与界面**

- 接口字段与 ERP-043 完全同源（`POST /api/purchase-invoices`、`PUT /api/purchase-invoices/{id}`）：
  请求新增可选 `dueDate` / `paymentTerms`；台账 / 详情响应新增 `dueDate`、`dueDateKnown`、`dueDateText`、
  `paymentTerms`、`paymentTermsText`、`evidenceTermsRuleText`（口径与边界文案）与 `invoiceCodeRuleText`（按类型的代码要求）；
- 界面（`wwwroot/js/supplier-purchase-invoices.js`）：类型下拉新增「进口」并逐类型提示代码要求；
  表单新增「到期日（可选）」「付款条件（可选）」，留空即未知 / 未提供（**不会**自动预填默认账期）；
  台账新增「到期日 / 付款条件」列，未登记到期日的行显示「到期日未知」；详情页显式列出到期日、付款条件与口径文案。

**数据库与测试**

- 结构：第 31 段建表已含 `DueDate DATETIME2 NULL` 与 `PaymentTerms NVARCHAR(200) NOT NULL DEFAULT N''`；
  既有库由**同一第 31 段末尾**的 `IF COL_LENGTH(...) IS NULL` **幂等加列**（无新表 / 新索引 / 无回填；
  刻意留在第 31 段内，避免破坏第 37 段及以后模块段落「只建表 / 建索引、不改既有表」的既有契约），生产库执行仍受 Human Gate 控制；

  留空保持未知且不按备注或默认账期推算、到期日早于开票日期被拒（等于开票日期允许）、付款条件超长被拒与边界长度可保存、
  草稿可更新 / 清空但登记后冻结、作废保留到期日 / 付款条件 / 关联历史且不硬删除、
  写入到期日与付款条件不改写订单与供应商且与客户销项发票证据 / 单证商业发票刻意分离；
