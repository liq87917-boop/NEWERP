# 供应商采购发票登记说明（ERP-043）

## 1. 背景与定位

出口 / 内销采购业务中，供应商会开具**普通发票（普票）**或**增值税专用发票（专票）**。系统原本只有采购订单与执行进度，
无法登记「这批货款到底有没有票、票面金额多少、对应哪几张采购订单」，也无法在出现错票 / 重开时留下可追溯的更正痕迹。

本次（ERP-043）新增**供应商采购发票登记册**：

- 登记发票证据本身：发票类型、发票代码（专票必填）、发票号码、开票日期、供应商、币种、不含税金额、税额、含税总额、备注；
- 可（可选、显式）把含税总额的**全部或一部分**关联到既有采购订单，并显式展示**已关联 / 未关联金额**；
- 关联只按**权威一致性**（同供应商 + 同币种、订单未取消）建立，**不按单号相似度、金额相近、开票日期接近猜测订单**；
- 登记（记录）后证据**冻结**，更正走**显式作废**（保留身份 / 金额 / 关联 / 审计历史），不删除、不静默改写。

定位：**操作性的发票证据台账**。它**不是**应付账款台账、**不是**税务申报系统、**也不是**付款授权机制，
不引入第二套账务引擎（不记账、不生成凭证 / 收款 / 付款 / 结算单）。

## 2. 发票字段与校验口径

| 字段 | 口径 |
|---|---|
| 发票类型 | `普票` / `专票`（其它取值一律拒绝） |
| 发票代码 | 专票**必填**、普票可选；去首尾空白，长度 ≤ 50 |
| 发票号码 | **必填**，长度 ≤ 50（一张发票登记一条，不支持多号码拼接） |
| 开票日期 | 必填（留空按当天）；登记时按日期存储，不改写任何既有单据日期 |
| 供应商 | 必须**存在、未删除且启用**；供应商编码 / 名称由服务端写成**快照**（客户端提交值不被采信） |
| 币种 | 系统支持币种：`CNY / USD / EUR / HKD / GBP / JPY`（与采购订单币种同源）；未知币种一律拒绝 |
| 金额 | 不含税金额（净额）、税额、含税总额（价税合计），均以**原币**存储，DECIMAL(18,2) |

**金额等式（服务端权威校验）**：

```
含税总额（价税合计） = 不含税金额（净额） + 税额
```

- 三项均按**币种精度**四舍五入后必须**严格相等**：JPY / KRW / VND / IDR 为 0 位小数，其余（含未知币种口径）为 2 位；
  取整一律 0.5 进位（不使用银行家舍入）；
- 含税总额必须**大于 0**，三项均不得为负；税额允许为 0（不征税 / 免税票）；
- 系统**不按税率反推金额**、**不自动调整差额**、不做汇率换算、不跨币种合并。

> 金额等式不成立时接口直接拒绝并给出差额，界面只做提示，**不会**替用户改写金额。

币种精度口径与装柜费用分摊（ERP-042）共用同一权威实现（`CurrencyAmountRules`），系统中不存在第二套取整规则。

## 3. 有效身份唯一（重复登记被拒绝）

唯一身份 = **供应商 + 发票类型 + 规范化发票代码 + 规范化发票号码**：

- 规范化 = 去首尾空白、去掉所有空白与连字符（`-`、`－`、`—`、`_`）后**大写**；
  因此 `0440-3190 / 8800 1` 与 ` 04403190 / 88001` 被视为**同一张发票**；
- 只在**未作废且未删除**的记录范围内唯一：重复请求一律**拒绝**（不静默合并、不覆盖原记录）；
- 已**作废**的记录**保留可读**，但**不占用身份**：作废后可以用同一身份重新登记新发票（历史与新记录并存可查）。

## 4. 采购订单关联口径

一条发票可以把含税总额关联到**一张或多张**采购订单（草稿期维护，整体替换保存）：

| 规则 | 口径 |
|---|---|
| 订单可用性 | 必须存在、未删除、**未取消**（已取消订单不参与发票证据关联） |
| 供应商一致 | 订单 `SupplierId` 必须与发票供应商**完全相同**（按 Id 判定，不按名称模糊匹配） |
| 币种一致 | 订单币种必须与发票币种**完全相同**（**不做汇率换算**） |
| 金额 | 每行按币种精度取整后必须**大于 0**；**合计不得超过发票含税总额** |
| 重复 | 同一张采购订单在同一张发票内**只能关联一次**（重复行直接拒绝，不合并金额） |
| 未关联 | 发票允许**部分或全部未关联**：未关联金额保留为「未关联」，**不会**被猜测到任何订单 |
| 数量上限 | 单张发票最多关联 50 张采购订单（有界） |

保存关联时服务端写入的是一份**快照**：采购单号、订单日期、订单币种、供应商编码 / 名称，
以及关联金额；采购订单后续改名 / 改币种 / 被取消**不会**破坏历史关联的可读性（只会显式标注不可用）。

关联保存在草稿期是**整体替换**语义（提交即当前完整清单，可提交空清单 = 清空全部关联），
并在**同一次 `SaveChanges`** 内完成：校验失败不会留下部分关联行。登记后关联即冻结。

## 5. 状态机与证据冻结

| 状态 | 可编辑发票头 | 可维护关联 | 可登记 | 可作废 | 说明 |
|---|---|---|---|---|---|
| 草稿（0） | 是 | 是 | 是 | 是 | 工作数据；可反复修改 |
| 已登记（1） | 否 | 否 | 否（重复登记被拒绝） | 是 | 证据冻结，保留可读 |
| 已作废（2） | 否 | 否 | 否 | 否（重复作废被拒绝） | 历史证据保留，可读 |

登记（`POST /{id}/record`）前会**复核**已持久化关联行仍然权威可关联：关联订单存在且未删除、未取消、
供应商与币种一致、关联合计不超过含税总额；不满足时**拒绝登记**（不会静默丢弃关联行，也不改写采购订单）。

修改草稿时如已有采购订单关联，**不允许更换供应商或币种**（会破坏关联口径）：必须先清空关联再修改。

## 6. 更正：作废而不是删除

- `POST /{id}/void` 把发票状态改为「已作废」并记录**作废原因（必填）**与时间；
- **保留**发票身份、金额、币种、供应商快照、**全部关联行**与审计历史；**不物理删除**、**不改写**已登记证据；
- 不产生任何收款 / 付款 / 结算 / 记账动作；
- 作废后同一「供应商 + 类型 + 代码 / 号码」可以重新登记新发票，旧记录仍可在台账中按「已作废」筛选查看。

## 7. 台账读取与关联展示

- 台账（`GET /api/purchase-invoices`）为**分页 + 有界**（默认 50 条 / 页，上限 200），可过滤：
  供应商、发票类型、状态（草稿 / 已登记 / 已作废）、币种、开票日期区间、关联状态（`linked` 已全额关联 /
  `partial` 部分关联 / `unlinked` 未关联）、关键字（发票号码 / 代码 / 供应商编码与名称）；
  默认**包含已作废历史**；分页参数被钳制到合法范围；
- 关联状态过滤与分页口径**一致**：先按持久化关联行派生每张发票的已关联金额再过滤，
  因此「只看未关联」不会因分页漏行；
- 每张发票显式给出：`linkedAmount`（已关联）、`unlinkedAmount`（未关联）、`allocationCount`、`linkageStatus`、
  `linkageText`（中文口径文案）、`supplierAvailable` / `supplierAvailabilityText`（供应商停用 / 删除后照实说明，历史可读）；
- 每条关联行显式给出：订单快照（单号 / 日期 / 币种 / 供应商）与 `orderAvailable` / `orderAvailabilityText`
  （订单已取消 / 已删除时历史关联仍可读）；
- 可关联订单候选（`GET /{id}/order-candidates`，只读有界，最多 200 条）：只返回**同供应商 + 同币种**订单
  （含已取消订单并标注不可关联），并派生订单总额、本发票已关联、其他**有效**发票（非作废）已关联、
  以及「剩余未被发票证据覆盖」金额（下限 0）。该派生值只按持久化关联行计算，
  **不是**应付余额、账龄或付款依据；
- 关联预览（`POST /{id}/allocations/preview`）为**只读**：逐行给出订单快照、资格文案与拟关联金额，
  以及保存后的已关联 / 未关联金额；预览与保存共用同一校验入口，**预览所示即保存结果**；
- 台账与详情映射按页**批量装载**关联行 / 订单 / 供应商（无逐行数据库查询）。

## 8. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/purchase-invoices` | 台账分页（供应商 / 类型 / 状态 / 币种 / 开票日期 / 关联状态 / 关键字过滤） |
| GET | `/api/purchase-invoices/{id}` | 详情（含关联行、已关联 / 未关联金额与可用性标注） |
| POST | `/api/purchase-invoices` | 新增草稿（校验类型 / 代码 / 号码 / 供应商 / 币种 / 金额等式与重复身份） |
| PUT | `/api/purchase-invoices/{id}` | 修改草稿（已登记 / 已作废拒绝；有联更换供应商 / 币种拒绝） |
| GET | `/api/purchase-invoices/{id}/order-candidates` | 可关联采购订单候选（同供应商 + 同币种，有界，只读） |
| POST | `/api/purchase-invoices/{id}/allocations/preview` | 关联预览（只读，不写库） |
| POST | `/api/purchase-invoices/{id}/allocations` | 保存关联（草稿专用，整体替换，事务性） |
| POST | `/api/purchase-invoices/{id}/record` | 登记（草稿 → 已登记，登记前复核关联） |
| POST | `/api/purchase-invoices/{id}/void` | 作废（原因必填；保留历史与关联） |

前端入口：采购订单模块工具栏与行操作「🧾 供应商发票」（`wwwroot/js/supplier-purchase-invoices.js` +
`modules-doc.js`）。从行操作进入时会按该采购订单的**供应商与币种**预筛选 / 预填（只允许关联同供应商 + 同币种的订单）。

## 9. 边界（明确不做的事）

- **不是应付账款台账 / 账龄表**：不创建应付记录、不推算账期与到期日、不做账龄分摊；
- **不是税务申报系统**：不做进项认证、不做税负计算、不生成申报表；
- **不是付款授权机制**：登记 / 作废发票都不触发付款、不改变付款状态、不生成付款申请 / 付款单 / 结算单；
- 不改写**采购订单**：状态、到货进度、已收数量、归属客户 / 销售订单、金额与明细一律不变；
- 不改写**库存与库存成本**（`Stocks`）、**库存流水**（`StockMovements`）、**退税记录**（`BaseTaxRefunds`）、
  **供应商主数据**（余额 / 结算方式 / 开票能力）与**收付款记录**（`FinancePayments` / `FinanceReceipts`）；
- 不做历史数据回填：既有供应商与采购订单在没有任何发票数据时行为**完全不变**；
- 不按单号相似度、金额相近、开票日期接近或备注文本猜测采购订单；未关联金额永远保持「未关联」。

## 10. 数据库与验证

- 结构由 `SchemaUpgrader` 第 31 段幂等补齐：`IF OBJECT_ID(...) IS NULL` 建
  `PurchaseInvoices` / `PurchaseInvoiceAllocations` 两张表与索引 / 外键；**不含任何 `UPDATE` / `INSERT` 回填语句**；
- 唯一索引：`UX_PurchaseInvoices_ActiveIdentity`（过滤 `IsDeleted = 0 AND Status <> 2`）、
  `UX_PurchaseInvoiceAllocations_InvoiceOrder`（过滤 `IsDeleted = 0`）；EF 模型同名同过滤条件；
- 关联行唯一外键是「关联行 → 发票」；**刻意不建**到采购订单 / 供应商的外键，采购订单侧不新增任何列；
- 单元测试：`ERP.UnitTests/PurchaseInvoiceTests.cs`（45 例，覆盖发票类型与代码要求、金额等式与币种精度、
  供应商可用性、重复身份与规范化、草稿编辑与冻结、关联资格与金额上限、部分 / 全额 / 未关联、
  整体替换、预览只读、候选派生金额、登记 / 作废与历史保留、登记前关联复核、非变更边界、
  台账过滤与分页、模型 / 幂等结构与前端接线契约）；默认安全档（Release build + `ERP.UnitTests`）通过；
- **生产库执行、部署与发布仍受 Human Gate 控制**；本说明不声明生产库已升级；
- 浏览器（Edge）验收按项目策略记录为 `browser_deferred`，延后到 `FINAL-UI-ACCEPTANCE` 阶段执行。
