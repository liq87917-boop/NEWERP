# 装柜费用分摊批次与来源留痕说明（ERP-042）

## 1. 背景与定位

一柜多客户（拼柜）场景下，柜级费用（报关费 / 拖车费 / THC …）需要按体积 / 重量 / 箱数 / 金额分摊到各参与客户。
系统原本已能用「拼柜分摊」预览并生成费用单，但生成结果**没有批次与来源留痕**：事后无法回答「这一批费用单是谁按什么口径、
按哪条来源费用生成的」，出现错误时也只能删除记录，历史随之丢失。

本次（ERP-042）在**既有费用单与既有分摊口径之上**补一层**可追溯的批次与来源留痕**：

- 分摊结果**仍然落在既有费用单**（`FinanceExpenses`，一参与方一行，沿用金额 / 币种 / 汇率 / 归属 / 分摊基数 / 比例 / 分摊金额字段）；
- 额外记录**批次**（批次号 / 来源费用 / 装柜清单 / 柜号 / 方法 / 基数 / 合计 / 状态）与**逐行留痕**
  （参与方客户 / 方法 / 基数种类与来源 / 基数值 / 比例 / 分摊金额 / 生成的费用单号）；
- 更正走**显式作废**（保留批次与逐行历史），而不是删除记录。

定位：**操作性分摊留痕**。它不是应收应付台账、不是记账凭证、不是结算单，也不产生任何收付款动作。

## 2. 支持的分摊方法与基数口径

| 方法 | 比例口径 | 基数来源 |
|---|---|---|
| 按体积 | 按各参与方体积占比 | **用户确认的请求值**（服务端校验：非负、必须逐个显式填写、合计大于 0） |
| 按重量 | 按各参与方重量（kg）占比 | 同上 |
| 按箱数 | 按各参与方箱数占比 | 同上 |
| 按金额 | 按各参与方金额占比 | 同上 |
| 整柜 | 恒为 100%（全额归唯一参与方） | **持久化装柜证据**：装柜清单持久化的总箱数 / 总毛重 / 总体积，请求须显式指定其中一种 |

口径要点：

- **不猜测**：参与方基准值缺失（未提交或为空）一律拒绝，服务端不会按体积经验值、历史比例、主参与方或列表顺序推断；
- **要求完整**：逐行基准法必须覆盖该装柜清单**全部启用参与方**，提交本柜以外的参与方（含停用 / 已删除 / 属于其他柜）一律拒绝；
- **合计必须大于 0**：全部基准值为 0 时拒绝（缺少可用证据）；某参与方显式填 0 表示「不承担本次分摊」，其比例为 0、金额为 0；
- **整柜法**：必须显式指定唯一目标参与方（仅当该柜恰好只有一条启用参与方时可省略）；若所选持久化基数为 0 / 缺失，
  一律拒绝（不按经验推断）；
- **停用参与方不参与分摊**：停用 / 客户不可用的历史参与方照常只读展示，但不进入分摊范围。

## 3. 精度与余差（确定性规则）

- 金额按**币种精度**四舍五入（0.5 进位，不使用银行家舍入）：JPY / KRW / VND / IDR 为 **0 位**，其余（含未知币种）为 **2 位**；
- 比例固定 **4 位小数**；
- **余差归属**：四舍五入产生的余差归「基准值最大」的参与方；基准值并列时归**参与方 Id 较小者**——
  该规则与列表顺序、提交顺序、主参与方标记均无关，因此结果稳定可复现；
- **各行合计恒等于来源费用金额**（预览与生成共用同一计算入口，预览所示即生成结果）。

> 逐行基准法示例：来源金额 100.00 CNY，三方等权 → 33.33 / 33.33 / 33.34，合计 100.00（余差 0.01）。

## 4. 可分摊来源费用（资格判定）

候选来源费用必须同时满足（全部依据**持久化字段**）：

1. 存在且未删除；
2. 归属类型是**柜级**（整柜 / 拼柜 / 散货）——「订单 / 客户 / 不分摊」归属不能作为来源；
3. 归属单号与装柜清单的**柜号一致**（去空白后不区分大小写；不一致直接拒绝，不按单号相似度匹配）；
4. 金额大于 0（原币）；
5. 尚未属于任何分摊批次（`AllocationBatchNo` 为空）；
6. 本身不是历史分摊生成的明细行（带分摊基数且比例 / 分摊金额大于 0 的行 = 旧接口生成的分摊结果，不能再次分摊）。

不满足时接口返回明确的**不可分摊原因**，界面逐行展示，用户据此改选柜级总额费用单。

## 5. 批次留痕与重复防护

- **批次号**：`EAB-yyyyMMdd-序号`（批次表唯一）；
- **逐行留痕**：批次的每个参与方一行，含来源费用、装柜清单 / 柜号、参与方客户（编码 / 名称快照）、方法、基数种类、
  基数来源、基数值、比例、分摊金额与**生成的费用单号**；
- **费用单行留痕**：生成行写入批次号与来源费用 Id / 单号（`AllocationBatchNo`、`AllocationSourceExpenseId`、`AllocationSourceExpenseNo`）；
- **重复防护**：同一「来源费用 + 装柜清单」最多只有**一条有效批次**（**不区分分摊方法**，避免同一笔柜级费用被重复分摊到客户），
  重复请求返回「不能重复生成」，并提示先作废原批次；数据库过滤唯一索引（含方法）作为并发兜底；
- **事务性**：批次 + 逐行留痕 + 既有费用单行在**同一次 `SaveChanges`** 内提交，
  校验或持久化失败**不会留下部分行**。

## 6. 更正：作废而不是删除

- `POST /api/finance/expenses/allocation-batches/{id}/void` 把批次状态改为「已作废」并记录**作废原因**（必填）与时间；
- **不删除**批次、逐行留痕与已生成的费用单行；**不改写**来源费用单与已生成行（金额 / 归属 / 付款状态一律不变）；
- 不产生任何收款 / 付款 / 结算 / 记账动作；重复作废被拒绝；
- 作废后同一来源费用可在同一柜重新生成新批次（历史批次保留并可在台账中按「仅已作废」过滤查看）。

## 7. 历史数据的只读辨识（不做回填）

既有费用单（含旧「拼柜分摊」接口生成的行）的留痕列为空，读取侧显式标注三类口径（**只读，不写库**）：

| 留痕分类 | 判定 | 文案示例 |
|---|---|---|
| `Batch` 批次留痕 | `AllocationBatchNo` 非空 | 批次留痕：EAB-20260925-001（有效批次），来源费用 EXP-20260925-001 |
| `Legacy` 历史分摊 | 无批次号，但带分摊基数且比例 / 分摊金额大于 0 | 历史分摊（无批次留痕：……仅作只读辨识，不做任何回填） |
| `None` 未分摊 | 其余 | 未分摊（柜级 / 客户级费用行，未参与任何分摊批次） |

批次状态未知时照实说明（不假定为有效）；已作废批次的生成行标注为「已作废批次」但**保持可读**。

## 8. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/finance/expenses/allocation-context?loadingListId=` | 只读上下文：装柜清单与（含停用的）参与方、持久化装柜总量、该柜费用单资格与留痕分类、现存有效 / 已作废批次、支持的方法与余差规则 |
| POST | `/api/finance/expenses/allocation-preview` | 只读预览：参与方、方法、基数种类与来源、基数值、比例、分摊金额、余差归属（**不写库**） |
| POST | `/api/finance/expenses/allocation-generate` | 生成批次（事务性）：写入批次 + 逐行留痕 + 既有费用单行 |
| GET | `/api/finance/expenses/allocation-batches` | 批次台账（分页；可按来源费用 / 装柜清单 / 状态 / 关键字过滤，默认含已作废历史） |
| GET | `/api/finance/expenses/allocation-batches/{id}` | 单个批次台账（含逐行留痕） |
| POST | `/api/finance/expenses/allocation-batches/{id}/void` | 作废批次（必须填写作废原因；保留历史） |

费用单列表（`GET /api/finance/expenses`）为当前页附带 `allocationLineage` / `allocationLineageText` 只读标注。
前端入口：费用单模块工具栏「🧾 分摊批次」与行操作「分摊批次」（`wwwroot/js/expense-allocation-batch.js`）。

## 9. 边界（明确不做的事）

- 不引入第二套账务引擎：不记账、不生成凭证、不生成收款 / 付款 / 结算单，不改写付款状态；
- 不改写来源费用单（金额 / 币种 / 汇率 / 归属 / 付款状态一律不变）；
- 不改写装柜清单与装柜明细（数量 / 箱数 / 重量 / 体积）、参与方身份与主参与方标记；
- 不改写订柜外贸与物流跟踪值、单证 `TradeDocuments`、库存 `Stocks` / 库存流水 `StockMovements`、采购订单、销售订单；
- 不做历史数据回填：历史分摊行只做只读辨识。

## 10. 数据库与验证

- 结构由 `SchemaUpgrader` 第 30 段幂等补齐：`COL_LENGTH(...) IS NULL` 补 3 个可空留痕列、
  `IF OBJECT_ID(...) IS NULL` 建 `FinanceExpenseAllocationBatches` / `FinanceExpenseAllocationLines` 与索引、外键；
  **不含任何 `UPDATE` / 回填语句**；
- 单元测试：`ERP.UnitTests/ContainerExpenseAllocationTests.cs`（25 例）；
- 生产库执行、部署与发布仍受 Human Gate 控制；浏览器（Edge）验收按项目策略记录为 `browser_deferred`，
  延后到 `FINAL-UI-ACCEPTANCE` 阶段执行。
