# 装柜出运里程碑证据说明（ERP-058）

> 任务：`ERP-058` 在 ERP-057 **出运引用登记册**（`ContainerShipmentReferences`）之下，登记用户录入的
> **只追加里程碑证据**（实际开船 / 实际到港 / 查验 / 放行），并支持显式作废（必填原因，保留原始证据）。
> 范围：`src/ERP.Domain`、`src/ERP.Application`、`src/ERP.Infrastructure`、`src/ERP.Api`、
> `src/ERP.UnitTests`、`docs/**`、`.ai/**`。
> 不改动任何 `.sql` 脚本、`deploy/**`、`release/**`、`checkpoints/**`、`SeedData*.cs`；
> **生产库执行、外部承运商 / 海关 / 货代对接、正式部署与发布仍由 Human Gate 控制**。
> 本次未启动 API、未连接 SQL Server、未执行任何 `.sql` / seed / 部署动作、未联系任何外部系统。

## 1. 背景与审计结论（为什么挂在出运引用之下）

ERP-057 已经建立了**唯一权威**的出运引用登记册：每种装柜链路记录（订柜信息 / 预装柜单 / 装柜清单）
最多一条有效出运引用，承载出运方式、S/O、B/L、港口、计划时间、承运人与报关行快照。
ERP-040 在订柜信息上另有本套跟踪值的**权威单值列**（`Etd` / `Eta` / `Atd` / `Ata` /
`InspectionDate` / `CustomsReleaseDate`）。

因此 ERP-058 的审计结论是：**不新建出运或跟踪主数据、不在装柜三单与出运引用上加列**，
而是新增**一套**只追加的里程碑留痕表，**按显式的父出运引用 Id** 挂在 ERP-057 登记册之下：

| 表 | 作用 |
|---|---|
| `ContainerShipmentMilestones` | 里程碑证据（父出运引用 + 事件类型 + 事件时间 + 来源说明 / 备注 / 记录人 + 状态 / 作废留痕） |

口径差异（重要）：ERP-040 的订柜跟踪列是**单值**快照（一票货一个 ATD / ATA），
本模块是**可重复追加**的操作性事件留痕（例如多次查验、重新登记更正后的时间），
并且**只登记用户录入的证据**：登记 / 作废里程碑都不会回写订柜跟踪列。

`ERP.UnitTests/ContainerShipmentMilestoneTests.cs` 的
`ERP058审计_里程碑只挂在ERP057出运引用之下_不改写任何既有记录` 用源码 / 反射方式锁定该结论
（`IErpDbContext` 里只有一套里程碑模型、装柜三单与出运引用没有新增任何里程碑列、
服务只按 `AsNoTracking` 读取父出运引用、不引用装柜三单、不引用 `Atd` / `Ata` / 查验 / 放行列）。

## 2. 字段口径（`ContainerShipmentMilestones`）

| 项 | 口径 |
|---|---|
| `ContainerShipmentReferenceId` | 父出运引用 Id（必填）：必须是存在、未删除、未作废的 ERP-057 出运引用；**刻意不建外键**，父记录被删除 / 作废后历史里程碑照常可读 |
| `EventType` | 显式 allowlist：`actual-departure`（实际开船 / 离港）/ `actual-arrival`（实际到港 / 抵达）/ `inspection`（查验）/ `customs-release`（放行）；其他取值一律拒绝 |
| `EventAt` | 事件发生时间（**必填**且有界：2000-01-01 ~ 2100-01-01）；**绝不**由计划开船 / 计划到港时间、单据状态或自由文本推断 |
| `SourceDescription` | 来源说明（用户录入 ≤ 200 字符，空 = 未知，如「船公司网站截图」「货代邮件」）；**不是**承运人 / 海关 / 货代回执 |
| `Notes` | 备注（≤ 500 字符，空 = 无；不参与任何派生） |
| `RecordedBy` | 记录人（用户录入 ≤ 100 字符，空 = 未知，不按登录用户强行推断） |
| `RecordedAt` | 登记时间（服务端写入，登记后不因作废而改写） |
| `Status` | `1` 已登记（有效证据，可作废）/ `2` 已作废（只读，保留原始证据与作废原因） |
| `VoidedAt` / `VoidReason` | 作废时间与必填原因（≤ 500 字符） |

**未知口径（贯穿全模块）**：未填写的选项一律保持空串并显示「未知」，
**绝不**按计划时间、单据状态、父出运引用的承运人 / 港口 / 备注或任何自由文本补全；
历史遗留的异常事件类型 / 异常状态照实回显为「未知（原值）」，不做静默修正。

事件类型 allowlist 与文案同源：`ContainerShipmentMilestoneRules.EventTypeText`、
`ContainerShipmentMilestoneRules.EvidenceCategoryText`（查验 / 放行类事件显式标注
「不是海关决定、不是查验或放行结论、也不代表允许出运」）。

## 3. 登记口径（只追加）

| 场景 | 结果 |
|---|---|
| 父出运引用存在、未删除、未作废 + 事件类型在 allowlist + 事件时间合法 | 正常登记，事件时间与登记时间由服务端权威写入 |
| 未选择父出运引用（Id ≤ 0） | 400 参数校验失败（不按柜号 / 单号兜底匹配） |
| 父出运引用不存在 | 404 数据不存在，不产生任何写入 |
| 父出运引用已软删除 / 已作废 | 400 规则冲突（历史里程碑仍可读，但不能新增） |
| 事件类型为空 / 自由文本 / 不在 allowlist | 400 参数校验失败（不静默忽略） |
| 事件时间为空 / 越界 | 400 参数校验失败（不按计划时间推断） |
| 同一父记录 + 事件类型 + 事件时间再次登记 | 400 重复：提示先核对或显式作废，**绝不静默合并或覆盖** |
| 同类型不同时间 / 同时间不同类型 / 不同父记录 | 允许（不按文本相似度去重） |
| 已作废行 | 不占用「同父 + 类型 + 时间」的有效额度：作废后可重新登记，新旧并存可查 |

## 4. 作废与历史（可审计的留痕）

1. **作废**（`POST /{id}/void`，必填原因 ≤ 500 字符）：只改状态与作废留痕，**保留**原始事件类型、
   事件时间、来源说明、备注、记录人与登记时间；**重复作废被拒绝**；**不提供硬删除**，
   也不提供任何修改已作废证据的接口（控制器只暴露 `GET` / `POST`，没有 `PUT` / `PATCH` / `DELETE`）。
2. **历史视图**：台账默认包含已作废历史（可按 `status=1` / `status=2` 过滤），
   已作废证据保留原值可读，而不是被删除或「修好」。
3. **父记录可用性**：父出运引用被软删除 / 物理缺失时，里程碑仍可读并显式标注不可用
   （`ParentAvailable = false` + 说明文案），**绝不**回填快照或改派到别的出运引用；
   父出运引用已作废时标注「父出运引用已作废」，并拒绝新增里程碑。
4. **历史异常数据**：事件类型或状态不在当前取值域内的历史行照实可读
   （事件类型文案显示「未知（原值）」、状态文案显示「未知（原值）」），
   但筛选条件仍然严格：未知事件类型 / 未知状态一律 400，不静默忽略。

## 5. API（`api/container/shipment-milestones`）

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/container/shipment-milestones` | 台账（分页）：可按父出运引用、事件类型、状态、事件时间区间、关键字过滤 |
| `GET` | `/api/container/shipment-milestones/{id}` | 详情：当前证据 + 父记录可用性 + 证据性质 / 边界文案 |
| `GET` | `/api/container/shipment-milestones/parent-candidates` | 可挂里程碑的出运引用候选（只读、有界；标注已有里程碑条数） |
| `POST` | `/api/container/shipment-milestones` | 登记里程碑证据（父记录 / 事件类型 / 事件时间校验、重复拒绝） |
| `POST` | `/api/container/shipment-milestones/{id}/void` | 作废（必填原因，保留历史，无硬删除） |

**读取性能口径**：台账按页返回（默认 50 / 上限 200，参数越界自动收敛）；
单页内父记录信息（源记录类型 / 单号 / 柜号 / 状态 / 可用性）一次**批量装载**；
父记录候选按 `take` 有界（上限 200）并用**两次分组查询**统计里程碑条数 / 有效条数；
全程**无逐行数据库访问**（单元测试用只读计数代理断言访问次数与页大小无关）。

## 7. 边界（本任务明确不做的事）

1. **不改写装柜链路与出运引用**：不改订柜信息 / 预装柜单 / 装柜清单 / 出运引用的任何列、状态与工作流，
   不推进装柜、报关或出运状态。
2. **不自动推进业务单据**：登记 / 作废里程碑不会改变销售订单、采购订单、库存与库存成本、库存流水、
   单证中心、发票、费用与分摊、收付款、税务与结算记录。
3. **不触达外部系统**：不轮询船公司、海关、报关行、货代或任何跟踪 / 订舱服务，也不做 EDI / API 对接。
4. **不做生产回填 / 迁移**：不为历史出运引用补里程碑，不迁移历史数据
   （历史记录保持可读，可直接登记新证据）。
5. **不新建出运 / 跟踪主数据**：不复制 ERP-040 的订柜跟踪列，不建第二套时间线主表（审计结论见第 1 节）。
6. **不做推断与派生**：不由计划时间、单据状态、父出运引用内容或自由文本推断事件时间与事件类型；
   不由柜号 / S-O / B-L 等文本匹配父记录。
7. **不提供硬删除与静默改写**：更正只走显式作废（必填原因，保留原始证据）。
8. **不把查验 / 放行当作权威结论**：查验 / 放行只是用户录入的仓库操作性证据，
   不是海关决定、不是放行结论，也不代表「允许出运」。
