# 装柜结算单生命周期与来源装柜清单完整性（ERP-384）

## 1. 目标

把**既有**装柜结算单（`api/finance/container-settlements`）的**每一个读取与写入路由**都收敛到同一套实时授权口径，
并解决可空来源 `LoadingListId` 指向**范围外 / 已取消 / 已删除**装柜清单、以及**装柜清单取消导致已存在结算单悬空**的风险：

- 列表 / 详情 / 创建 / 修改 / 提交 / 审核 / 取消 / 删除 / 费用分摊证据读取都先校验**实时启用身份 + 既有「装柜结算单」
  （`container-settlement`）菜单授权 + 当前权威客户数据范围**（复用 ERP-097 / ERP-364 口径）；
- 可空 `LoadingListId` 按 **Id 精确解析**既有、未删除、未取消的装柜清单，结算客户必须是该清单的权威客户
  （多参与方时为有效参与方之一），且该清单的参与方 / 上游客户全部在当前账号范围内；
- 金额只按**既有存储精度**做正负校验（总金额 > 0，海运费 / 其他费用 >= 0），**不**发明换算、**不**跨币种聚合、
  **不**施加 `total = sum(costs)` 之类的公式；
- 只要仍存在**未删除且未取消**的装柜结算单引用某装柜清单，就拒绝取消该装柜清单，直到显式取消结算单释放。

复用既有分层架构与既有单据流转（创建 / 修改 / 提交 / 审核 / 取消 / 删除）、既有 ERP-364 装柜清单授权与
ERP-060 费用分摊证据只读视图；不做报表、不做界面视觉 / 样式打磨，不写库存 / 资金 / 会计，也不调用任何外部系统。

## 2. 口径

| 项 | 口径 |
|---|---|
| 适用路由 | 列表、详情、创建、修改、提交、审核、取消、删除、费用分摊证据 |
| 实时授权 | 每一路由先解析：身份缺失 / 非法 → 未认证；账号不存在 / 已删除 → 未认证；账号禁用 → 权限不足；非特权账号无既有 `container-settlement` 菜单 → 权限不足，一律 fail closed（绝不降级为匿名 / 管理员） |
| 数据范围 | 复用既有 ERP-097 `SalespersonDataScopeService`；特权账号（超级管理员 / 系统内置角色 / 显式特权角色）不受限、保留历史访问；未映射业务员的受限账号可见客户为空（fail closed） |
| 客户权威性 | 结算客户必须真实存在、未删除且启用；不存在 / 已删除 → 404，停用 → 规则冲突 |
| 来源清单（可空） | `LoadingListId == null` 保留历史「未关联来源」语义；提供 Id 时必须为正整数且解析到既有、未删除、**未取消**的装柜清单（悬空 / 已删除 → 404，已取消 → 规则冲突） |
| 来源归属一致 | 结算客户必须是该清单的权威客户：有有效参与方时须为其一；无有效参与方时按持久化 `CustomerId` 判定；字段非正视为无权威归属 fail closed |
| 来源清单范围 | 复用 ERP-364：受限账号必须对该清单**每一个有效参与方客户**与**显式上游（预装柜单 → 订柜信息）客户**都有权限 |
| 混合客户证据 | 费用分摊证据读取前，受限账号必须对该清单分摊行**每一个被显式引用的客户**都有权限（共享柜 fail closed） |
| 金额 | 既有存储精度 `decimal(18,2)`（2 位小数、0.5 进位）：总金额 > 0，海运费 / 其他费用 >= 0；结算单无币种字段，绝不换算 / 跨币种聚合 / 施加合计公式 |
| 列表范围 | 列表在 **SQL 侧**把客户范围下推到 `Count` 与分页之前，绝不先查全量再内存过滤 |
| 校验时点 | 创建 / 修改在**生成单号与写入之前**完成授权与校验（失败绝不消耗单号）；状态流转在**锁内重新加载后**复核范围 / 状态 / 金额 |
| 不猜测 | 只认显式 Id 与显式参与方 / 上游客户：绝不按柜号 / 单号等自由文本反查来源，不补链接、不回填、不臆造归属 |
| 并发 | 修改 / 提交 / 审核 / 取消 / 删除 / 创建都在事务内按既有锁序（来源装柜清单行 → 装柜结算单行）串行化 |

## 3. 权威客户归属与数据库侧范围

`FinanceContainerSettlementLifecycleRules`（ERP-384，纯只读判定 + 有界只读查询）提供以下入口：

1. `EnsureMenuAuthorizedAsync(db, userId)`：实时身份 → 账号状态 → 既有 `container-settlement` 菜单 → 返回数据范围；
2. `EnsureCustomerInScope(scope, customerId)` / `EnsureAuthorizedAsync`：客户权威性与数据范围 fail closed；
3. `EnsureCustomerAvailableAsync(db, customerId)`：客户存在 / 未删除 / 启用（Id 精确解析，不按文本猜客户）；
4. `ResolveEligibleLoadingListAsync(db, loadingListId)`：按 Id 精确解析可空来源装柜清单；
5. `EnsureSettlementCustomerMatchesLoadingListAsync` / `ResolveAndAuthorizeLoadingListAsync`：结算客户与清单权威客户一致 +
   ERP-364 参与方 / 上游客户范围；
6. `EnsureStoredSettlementScopeAllowedAsync`：已存储结算单的权威归属（读取 / 证据 / 状态变更 / 删除之前）；
7. `EnsureEvidenceCustomersInScopeAsync`：费用分摊行每一个客户的范围（混合客户证据护栏）；
8. `EnsureNoActiveSettlementForLoadingListAsync`：装柜清单取消前的结算占用护栏。

特权账号（`AllowedCustomerIds == null`）在上述入口中一律放行 —— 历史单客户、共享柜与未关联来源单据照常可读可流转，
既有行为保持不变。受限账号把结算单改派到范围外客户 / 来源清单、或引用范围外参与方，都会在写入前被拒绝。

## 4. 金额语义（无币种字段）

装柜结算单实体没有币种字段，因此本护栏**只**按既有存储精度（`decimal(18,2)`，2 位小数、`MidpointRounding.AwayFromZero`）做正负校验：

- `TotalAmount`：取整后必须 > 0（`0` / 负数 / 取整后为 0 一律 400）；
- `FreightCost` / `OtherCost`：取整后 >= 0（负数为 400）；
- 明确**不**校验 `TotalAmount == FreightCost + OtherCost`，也**不**引入任何汇率、折算或跨币种合计 ——
  金额语义保持「显式原值」。

创建 / 修改以取整后的值落库；提交 / 审核在锁内复核**持久化**金额仍满足既有口径（历史合法数据原样保留，绝不改写）。

## 5. 来源装柜清单精确解析与归属一致

- `LoadingListId` 为空 → 保留历史「未关联来源」语义（不补链接、不回填、不按柜号 / 客户推断）；
- 提供 Id → 必须为正整数，且解析到**既有、未删除、未取消**的装柜清单，否则 fail closed；
- 结算客户必须是该清单的**权威客户**：
  - 存在有效（启用、未删除）参与方 → 结算客户必须是其中一个有效参与方客户（复用 ERP-041 参与方口径）；
  - 无有效参与方 → 按持久化兼容客户字段 `ContainerLoadingList.CustomerId` 判定，字段非正视为无权威归属 fail closed；
- 受限账号还必须通过 ERP-364 的**清单范围**复核（参与方逐一 + 显式上游订柜客户）。

## 6. 锁定写路由与并发协同

修改 / 提交 / 审核 / 取消 / 删除统一按下列顺序执行：

1. 事务外先解析身份 / 账号状态 / 菜单 / 数据范围与请求金额（fail closed 时不进事务、不加锁、不写库）；
2. 读取本单当前持久化的 `LoadingListId`（仅用于确定要加锁的清单行；权威校验一律在锁内重做）；
3. 对**来源装柜清单行**按 Id 升序加更新锁（与装柜清单取消 / 参与方维护共用同一把清单行锁）；
4. 对**本装柜结算单行**加更新锁（审计时间戳刷新 + `RowVersion` 乐观并发，语义等价 `UPDLOCK, HOLDLOCK`）；
5. 锁内重新加载本单 → 复核权威客户范围 / 允许的状态 /（提交审核时）持久化金额 → 复核请求来源 / 客户资格；
6. 置状态 / 改写字段 / 软删除并提交事务；任一步失败即回滚，库中字段 / 状态 / 审计时间戳全部保持不变。

创建：事务外完成授权与全部校验（失败**绝不消耗单号**），事务内先取来源清单行锁，锁内再次解析并复核来源与客户，
之后才生成单号并落库。锁序固定为**「来源装柜清单行 → 装柜结算单行」**，任何流程都不反向持锁，因此不会形成锁环。
非关系型提供程序（内存库）没有行锁语义，加锁与事务等价无操作（单元测试不受影响）。

## 7. 装柜清单取消协同

`ContainerLoadingListController.Cancel` 在取到装柜清单行锁并复核范围后，调用
`EnsureNoActiveSettlementForLoadingListAsync`：只要仍存在**未删除且未取消**的装柜结算单以该清单为显式来源，即拒绝取消装柜清单
（规则冲突），直到显式取消结算单释放。取消只把状态置为「已取消」，**历史字段 / 来源链接与审计原样保留，绝不物理删除**。

由于装柜清单取消（`UPDLOCK` 清单行）与装柜结算单创建 / 状态变更（清单行锁）共用同一把清单行锁，二者必然串行：
要么取消先完成、随后创建被「已取消来源」拒绝；要么创建先完成、随后取消被「未取消结算单」阻断。

## 9. 不改写项

- **不新增用户授权 / 菜单 / 权限模型**：菜单与数据范围沿用既有 `SeedData` 与 ERP-097 口径，测试只用既有
  `container-settlement` / `loading-list` 菜单；
- **不新增表 / 列 / 外键 / schema**，不改 `SchemaUpgrader` 与种子数据；不需要数据库迁移；
- **不改写历史**：不重写历史装柜结算单的客户、来源、金额、状态与审计时间戳；不为历史单据补链接或回填；
- **保留来源单据审计与原始失败日志**：失败的创建 / 编辑 / 状态变更 / 删除只回滚，不产生半更新，也不清除既有审计痕迹；
- **不写库存 / 库存流水 / 资金 / 会计**：不产生收款、付款、核销、分摊入账、结算流水或对账结论；
- **不改写装柜清单 / 明细 / 参与方 / 订柜跟踪值 / 单证**，也不改写 ERP-042 费用分摊批次与分摊行证据；
- **不按柜号 / 单号等自由文本猜测来源**，不臆造客户或参与方。

## 11. 真实 SQL 夹具安全口径

- 目标必须为专用 localdb 实例 `(localdb)\NEWERP_AutoAcceptance`，库名前缀 `NEWERP_AUTOTEST`，且 `Integrated Security=true`；
  护栏在**任何数据库访问之前**校验失败即中止；
- 每次运行创建**全新的 GUID 后缀库**，发现同名库已存在立即拒绝，绝不 drop / reset / 复用任何数据库；
- 不读取 `appsettings` / `.env` / 生产凭据；连接串只来自进程环境变量 `ERP_ConnectionStrings__Default` 或专用 localdb 默认值；
- 测试种子一律使用 SQL Server 自增主键（不显式指定 Id），保留完整日志输出；
- 构建通过仅代表编译成功，**不代表本阶段验收通过**：真实 SQL 集成测试与阶段验收由调度器在专用目标上单独执行。

## 12. 边界说明

- 本任务的确定性交付门为「Release 构建 + `ERP.UnitTests` 全套通过」；真实浏览器验收未要求（`browser_acceptance.required = false`）。
- 装柜结算单**没有**币种字段，因此不存在跨币种聚合、汇率换算或合计公式；金额校验只覆盖既有存储精度下的正负语义。
- 费用分摊证据仍是**只读**视图（ERP-060）：本护栏只在读取前增加客户范围护栏，**不**改动证据内容与只读语义。
- 散货结算单（`api/finance/bulk-settlements`）不在本任务 `allowed_paths` / 验收范围内，其控制器行为保持不变。
