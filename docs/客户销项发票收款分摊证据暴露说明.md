# 客户销项发票收款分摊证据暴露（ERP-075）

## 1. 定位

ERP-073 已经建立了「客户收款单 → 客户销项发票」的显式收款分摊证据册
（`CustomerSalesInvoiceCollectionAllocations`）。ERP-075 **不新增任何表、列、存储过程或 SQL 脚本**，
只把这份既有证据**只读地暴露**到四处用户界面，让用户在发票与收款工作流里直接看到：

1. **客户销项发票详情**：显示「发票含税总额 / 已分摊收款 / 算术未分摊」三个**分开标注**的字段，
   以及有效 / 已作废分摊行条数与逐行明细（含收款单号、分摊金额、状态、可用性标注、作废原因）。
2. **客户销项发票台账**：每行附带**有界**的收款分摊汇总（已分摊金额 + 未分摊金额 + 有效行条数），
   一次分组聚合派生，**绝无逐行查库**。
3. **客户收款单工作流**：收款单台账行新增「收款分摊证据」入口，展示「本收款单分摊到哪些已登记销项发票」
   与**剩余收款证据**（收款金额 − 本维度有效已分摊），不改写、不复制既有的 `FinanceReceipt` 主记录。
4. **发票侧收款分摊工作台**（ERP-073 既有 `invoices/{id}/summary` 视图）：继续以「含税总额 / 已分摊 / 未分摊」
   分开展示，作为对账证据视图。

## 2. 关键口径（与 ERP-073 同源，绝不自造对账引擎）

- **有效已分摊** = ERP-073 分摊行中**未作废（Status=1）且未删除**的行合计；**已作废行**只作历史可读、
  不计入有效合计。
- **算术未分摊** = 发票含税总额 − 本维度有效已分摊（下限 0）。它只是**算术证据**，绝不代表
  已付 / 已结清 / 逾期 / 已确认收入 / 已记账状态或应收余额。
- **币种分组**：不同币种分别展示、绝不合并 / 换算 / 改派；不做任何汇率换算。
- **证据维度分离**：ERP-053（收款 → 销售订单）、ERP-055（发票 → 销售订单）、ERP-073（收款 → 发票）、
  ERP-071（收款 → 代理服务费对账单）是**互相独立**的证据维度，金额**绝不相加**。
- **缺失即「无 / 未知」**：没有收款分摊证据只表示尚未登记，绝不转换为已付、已结清、逾期或欠款。

## 3. 边界（重要）

本视图是**操作性证据视图**，不是总账、不是法定客户对账单、不是税务申报、不是付款授权，也不是结算确认。
读取该证据**只读**：不改写发票、分摊行、收款单、销售订单、客户、余额、财务或税务记录；
也不新增任何数据库结构（`SchemaUpgrader`、`ErpDbContext*`、`IErpDbContext` 与任何 `.sql` 均未改）。

## 4. 落点

- 应用层 DTO：`CustomerSalesInvoiceEvidenceDto` 追加 `ReceiptAllocatedAmount` / `ReceiptUnallocatedAmount` /
  `ReceiptAllocationCount` / `ReceiptVoidedAllocationCount` / `ReceiptAllocationStatus` /
  `ReceiptAllocationText` / `ReceiptAllocations`（复用 ERP-073 `CustomerSalesInvoiceCollectionAllocationDto`）。
- 应用层服务：`CustomerSalesInvoiceEvidenceService.MapManyAsync` 用**一次分组聚合**派生台账汇总、
  详情路径再装载**有界**逐行明细；`CustomerSalesInvoiceCollectionAllocationService.MapManyAsync` 改为公开以复用行映射。
- 前端：`js/customer-sales-invoices.js`（台账汇总列 + 详情收款分摊证据区）、
  `js/customer-sales-invoice-collection-allocations.js`（收款单侧只读视图）、
  `js/modules-finance.js`（收款单行「收款分摊证据」入口）。
