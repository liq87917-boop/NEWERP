# 装柜外贸与物流跟踪字段说明（ERP-040）

> 任务：`ERP-040` 在既有订柜信息（Container Booking）上补齐外贸与物流跟踪字段，并以订柜信息作为**唯一权威记录**，预装柜单 / 装柜清单只按持久化引用只读回显。
> 范围：`src/ERP.Domain`、`src/ERP.Application`、`src/ERP.Infrastructure`、`src/ERP.Api`、`src/ERP.UnitTests`、`docs/**`。
> 不改动任何 SQL 脚本、`deploy/**`、`release/**`、`checkpoints/**`、`SeedData*.cs`；**生产库执行、外部承运商 / 海关 / 货代对接、正式部署与发布仍由 Human Gate 控制**。本次未启动 API、未连接 SQL Server、未执行任何 `.sql` / seed / 部署动作。

## 1. 背景与结论

ERP-006 审计把「装柜外贸与物流跟踪字段」判为 **missing**：`ContainerBooking` / `ContainerPreLoading*` / `ContainerLoading*` 都缺少出运方式、提单号、订舱号、目的 / 中转港、ETD / ETA / ATD / ATA、拖车、报关行、查验与放行等列，原先还因「装柜单据走存储过程」而暂缓。

ERP-040 的落地口径：

1. **订柜信息是本套跟踪值的唯一权威记录**（`db_owner.ContainerBooking`）：预装柜单 / 装柜清单不新增任何跟踪列，只按持久化引用（`ContainerPreLoading.BookingId`、`ContainerLoadingList.PreLoadingId`）只读回显，避免出现第二份互相冲突的跟踪值。
2. **装柜三单（订柜信息 / 预装柜单 / 装柜清单）统一由 EF 主子表页面承载**，不再从菜单进入存储过程版单据页 —— 与 ERP-008 处理销售 / 采购订单的口径一致：存储过程版的 `INSERT/UPDATE` 使用固定列清单，无法保存新增列。`BILL_CONFIG` 中的 SP 版装柜配置**保留**（历史数据排查 / 回滚与打印设计仍可用），只是不再作为菜单入口。
3. **新列一律带安全默认值**（文本空串、日期与报关行 Id 可空、查验要求 `BIT NULL`）：历史订柜记录打开即为「未知 / 未填写」，**不做任何回填**，也不为任何单据臆造日期。
4. **未知、未填写、未关联一律显式呈现**：界面显示「未知」或「未关联」，绝不回落为空、0、今天，也不按柜号 / 提单号等自由文本去匹配订柜记录。
5. **结构升级幂等**：`SchemaUpgrader.EnsureUpgradedAsync` 第 28 段以 `COL_LENGTH` 逐列补齐；任一步都可重复执行。
6. **不触达外部系统**：不调用船公司、海关、货代或任何跟踪服务；也不写费用、单证、库存与历史单据。

## 2. 字段清单（`ContainerBooking`，共 14 列）

| 字段 | 类型 | 说明 |
|---|---|---|
| `ShipmentMode` | string(10) | 出运方式：`LCL` 拼箱 / `FCL` 整箱；空串 = 未指定（未知）。服务端忽略大小写与首尾空白，其他取值一律拒绝 |
| `BillOfLadingNo` | string(50) | 提单号 B/L |
| `ShippingOrderNo` | string(50) | 订舱号 / 托运单号 S/O |
| `TransitPort` | string(100) | 中转港（目的港沿用既有 `DestinationPort`，起运港沿用既有 `DeparturePort`） |
| `Etd` | datetime2? | 预计开船日（ETD） |
| `Eta` | datetime2? | 预计到港日（ETA） |
| `Atd` | datetime2? | 实际开船日（ATD） |
| `Ata` | datetime2? | 实际到港日（ATA） |
| `TruckerName` | string(200) | 拖车 / 集卡公司（自由文本，仅作联系记录） |
| `CustomsBrokerId` | bigint? | 报关行引用（`BaseOtherInfo` 中 `InfoType = CustomsBroker` 的字典项；可空，**不建外键**） |
| `CustomsBrokerName` | string(100) | 报关行名称快照（服务端按字典项权威写入） |
| `InspectionRequired` | bit? | 查验要求三态：`NULL` 未知 / `0` 不需要查验 / `1` 需要查验 |
| `InspectionDate` | datetime2? | 查验日期（可选） |
| `CustomsReleaseDate` | datetime2? | 海关放行日期（可选） |

只读标注（`[NotMapped]`，不落库）：`CustomsBrokerAvailable` = 报关行引用是否仍可选用（由服务端在列表 / 详情读取时标注）。

## 3. 报关行引用口径（复用「其他资料」字典项）

| 环节 | 口径 |
|---|---|
| 可选用判定 | 字典项存在、未删除（`IsDeleted = 0`）、已启用（`Status = 1`）、`InfoType = CustomsBroker`（类型比较忽略大小写与首尾空白） |
| 新增 / 更换引用 | 必须是可选用字典项，否则：不存在 → 404；已删除 / 类型不符 / 已停用 → 400；被拒绝时**不产生半更新**，也不占用单据号流水 |
| 名称快照 | 一律由服务端按字典项写入 `CustomsBrokerName`；客户端提交的 `CustomsBrokerName` 自由文本**不被采信**（只填名字、不填 Id 等于未指定） |
| 引用未变更 | 老订柜单保存其他字段时保留原引用；字典项仍可用则刷新快照（字典改名后同步），字典项已停用 / 删除则保留库中历史名称 |
| 历史引用可读 | 字典项被停用 / 删除 / 改类型后：历史订柜记录照常可读、名称照常显示，界面显式标注 `（已停用/不可用）`（与 `CustomerForwarderRules.UnavailableMark` 同一文案），但该字典项不能再被新选中 |
| 清空 | `CustomsBrokerId` 传 `null` / `0` 等同清空（两个字段一并清空），不影响任何其他单据 |
| 下拉选项 | `GET /api/container/bookings/customs-broker-options` 只返回未删除、已启用、类型匹配的字典项（数组形态的选项接口） |

## 4. 查验要求三态与日期口径

- `InspectionRequired`：`null` = **未知**（未标注）、`false` = **不需要查验**、`true` = **需要查验**。三者互不混淆，未填写一律落为 `null`，绝不回落为「不需要查验」。
- `InspectionDate`（查验日期）与 `CustomsReleaseDate`（海关放行日期）保持**可选**：
  - 「需要查验」或「未知」都不要求必须填日期（尚未查验时日期本就为空）；
  - 但明确「不需要查验」（`false`）时不允许填写查验日期（自相矛盾的记录直接拒绝：400）。
- 三态与日期都不会由自由文本解析或推断得出（例如不会因为备注里出现「已放行」就写 `CustomsReleaseDate`）。

## 5. 只读回显与未知口径（未关联 = 未知）

| 场景 | 结果 |
|---|---|
| 预装柜单 `BookingId` → 未删除的订柜记录 | `linked = true`，字段原样回显订柜信息（含报关行名称快照与可用性标注） |
| 预装柜单未填 `BookingId` | `linked = false`，全部跟踪字段为空 / `null`，`notLinkedReason` 说明「未关联」，界面显示「未知」 |
| `BookingId` 指向不存在或已软删除的订柜记录 | 同上（已删除记录不算权威引用） |
| 装柜清单 `PreLoadingId` → 预装柜单 → `BookingId` → 订柜记录 | `linked = true`，走**持久化引用链**回显 |
| 装柜清单未填 `PreLoadingId` / 指向不存在的预装柜单 / 预装柜单未关联订柜 | `linked = false`（链上任一环断裂即视为未关联） |

**绝不按文本匹配**：即使某张订柜记录的单号与预装柜单的柜号文本相同，只要没有持久化引用就仍然返回「未关联」。

## 6. 接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/container/bookings` | 订柜信息分页列表（含跟踪字段 + 报关行可用性标注，只读标注不写库） |
| `GET` | `/api/container/bookings/{id}` | 订柜信息详情（同上标注） |
| `POST` | `/api/container/bookings` | 新增订柜信息：先校验跟踪字段（不合格不占单据号）再落库 |
| `PUT` | `/api/container/bookings/{id}` | 更新订柜信息：跟踪字段先校验 / 规范化；报关行引用未变更时保留历史引用 |
| `GET` | `/api/container/bookings/customs-broker-options` | 报关行下拉选项（只读） |
| `GET` | `/api/container/pre-loadings/{id}/shipment-tracking` | 预装柜单的权威跟踪值（只读，未关联返回 `linked = false`） |
| `GET` | `/api/container/loading-lists/{id}/shipment-tracking` | 装柜清单的权威跟踪值（只读，按引用链；未关联返回 `linked = false`） |

## 7. 前端入口

- **订柜信息（模块 `booking`，菜单「装柜管理 → 订柜信息」）**：列表新增「出运方式 / 提单号 / 目的港 / ETD / ETA / 报关行 / 查验要求」等只读列（空值显示「未知」，报关行不可用时显示名称 + 标注）；表单可录入全部跟踪字段，其中「报关行」为字典项引用下拉、「查验要求」为三态下拉（提交 `null` / `false` / `true`）。
- **预装柜单（模块 `pre-loading`）**：表单新增「订柜信息（关联）」引用；行操作新增「🚢 物流跟踪」只读弹窗。
- **装柜清单（模块 `loading-list`）**：表单新增「预装柜单（关联）」引用；行操作新增「🚢 物流跟踪」（与 ERP-019 的「生成单证 / 预填单证」并存）。
- **只读弹窗**（`wwwroot/js/container-shipment-tracking.js`）：按当前模块调用对应 `shipment-tracking` 接口，展示 16 项跟踪值；未关联时顶部显示未关联原因、所有值显示「未知」；弹窗**不提供任何编辑入口**（不复制、不落库、不产生外部请求）。
- **菜单路由（`bill-v2.js` 的 `BILL_CODE_MAP`）**：`booking` / `pre-loading` / `loading-list` 三个编码已移除，菜单改为进入 EF 主子表页面；`receiving-plan`（收货计划）不受影响。SP 版页面定义（`bill-config3.js` 的 `BILL_CONFIG`）保留供历史排查与回滚参考。

## 8. 边界（本任务明确不做的事）

1. 不调用船公司、海关、报关行、货代或任何外部跟踪 / 订舱系统，也不做 EDI / API 对接。
2. 不自动改写货代、费用、单证中心（Trade Document）、库存（`StockMovements` / `Stocks`）与任何历史单据。
3. 不生产回填：不补历史订舱的 ETD / ETA / ATD / ATA / 查验 / 放行日期，不迁移历史单据。
4. 不给预装柜单 / 装柜清单新增跟踪列（避免第二份跟踪值）。
5. 不按柜号、提单号、订舱号等自由文本匹配订柜记录。
6. 不实现装载率、箱型用量、多柜合并、B/L 多份、附件扫描件等（装载率仍在报表侧，口径不变）。

## 9. 结构升级

- `SchemaUpgrader.EnsureUpgradedAsync` 第 28 段：对 `db_owner.ContainerBooking` 逐列 `IF COL_LENGTH(...) IS NULL → ALTER TABLE ADD ...`，只加列、只建列，不建表、不回填、不改写其他表；模型侧在 `ErpDbContext.Config` 中声明列长度与「不建外键」的设计理由。
- 生产库升级与部署属于 Human Gate 动作；本文档**不声明**生产库已升级。
