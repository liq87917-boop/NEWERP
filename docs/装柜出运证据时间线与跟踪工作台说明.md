## 1. 背景与审计结论（为什么是「只读呈现」而不是「第二套跟踪」）

| 已有权威记录 | 作用 |
|---|---|
| `ContainerShipmentReferences`（ERP-057） | 出运引用证据：出运方式 / S/O / B/L / 港口 / **计划开船·到港时间** / 承运人 / 货代 / 拖车 / 报关行快照 + 修订 / 作废留痕 |
| `ContainerShipmentMilestones`（ERP-058） | 里程碑证据：实际开船 / 实际到港 / 查验 / 放行（只追加，作废保留原值） |
| `ContainerBooking`（ERP-040） | 订柜信息上的本套跟踪值权威单值列（ETD / ETA / ATD / ATA / 查验 / 放行） |

ERP-059 的审计结论是：**不新建表、不新增列、不复制任何跟踪值**，只按显式 Id 读取上述两张登记册
并**派生呈现**：

- 计划时间只来自 ERP-057 出运引用的持久化计划值（`PlannedDepartureAt` / `PlannedArrivalAt`）；
- 实际事件只来自 ERP-058 里程碑（`EventAt` + `EventType` + 状态）；
- 两者**分开标注**、各自带来源标注，绝不互相替代、绝不互相推断。

`docs/装柜出运引用登记说明.md`（§10）与 `docs/装柜出运里程碑证据说明.md`（§10）此前已把本任务列为后续扩展，
本次即为该扩展的落地。

## 2. 关联口径（显式持久化链接，绝不按文本匹配）

| 入口 | 关联键 | 缺失时行为 |
|---|---|---|
| 订柜信息详情 | `SourceType = booking` + `SourceId = 订柜信息 Id` 的**当前有效**出运引用 | 返回「未关联」，证据显示「未知 / 无」 |
| 预装柜单详情 | `SourceType = pre-loading` + `SourceId = 预装柜单 Id` | 同上 |
| 装柜清单详情 | `SourceType = loading-list` + `SourceId = 装柜清单 Id` | 同上 |
| 工作台 / 详情（行入口） | 显式**出运引用 Id** | 不存在 → 404；已作废 → 历史呈现 |

- **不按柜号 / S/O / B/L / 承运人或任何自由文本**挑选、匹配或合并记录；
- 同一源记录存在多条有效引用的历史异常情况下，取 Id 最小的一条（与 ERP-057 的候选口径一致），
  且不做任何改写；
- 源记录被删除 / 不存在、源记录 Id 无效时显式标注「源记录不可用 / 链接无效」，
  历史证据按原值呈现，**绝不改派**到别的记录，也不回填任何快照。

## 3. 计划 vs 实际（分开标注，缺失即「无 / 未知」）

时间线固定包含两条**计划**条目与零到多条**实际**条目：

| 条目种类（Kind） | 来源 | 缺失时显示 |
|---|---|---|
| `planned-departure` | 出运引用 `PlannedDepartureAt`（计划开船 ETD） | 「未知（未登记该计划时间）」 |
| `planned-arrival` | 出运引用 `PlannedArrivalAt`（计划到港 ETA） | 同上 |
| `actual-departure` / `actual-arrival` / `inspection` / `customs-release` | ERP-058 已登记里程碑（`Status = 1`） | 「无（未登记）」 |

**绝不**发生以下事情（单元测试逐条锁定）：

1. 缺失的实际事件不会被计划时间补齐，也不会因此显示为「已开船 / 已到港 / 已清关 / 已放行」；
2. 计划时间已过、单据状态变化或自由文本都不会派生出「延误 / 逾期」结论；
3. 时间线上没有任何「业务状态」字段：只有「已登记 / 已作废」的证据状态与条目时间；
4. 查验 / 放行类事件一律附带「不是海关决定、不是查验或放行结论、也不代表允许出运」的证据性质文案；
   开船 / 到港类事件附「不是承运人确认或航行回执」文案。

## 4. 时间差（算术证据，仅在两条持久化时间戳可比时给出）

| 对比项 | 计划侧 | 实际侧 | 结果 |
|---|---|---|---|
| 开船时间差 | 计划开船 ETD（出运引用） | **最近一条有效**实际开船证据（里程碑） | 「实际比计划晚 / 早 X 天 Y 小时 Z 分钟」或「实际与计划一致」 |
| 到港时间差 | 计划到港 ETA | **最近一条有效**实际到港证据 | 同上 |

- 任一侧缺失 → `comparable = false`，文案显式说明「无法比较」以及**缺的是哪一侧**（不推断缺失的一侧）；
- 两侧 `DateTime.Kind` 语义不一致（例如一侧 Local、一侧 Unspecified）→ 同样「无法比较」，
  **不做任何时区换算、不假定可比**；两侧语义一致时按库中原值做减法，并保留 `DateTimeKind` 文案；
- 结果一律标注为**算术证据**：不是承运人 / 海关确认、不是合同 SLA 结论、不是延误责任或索赔依据；
- 已作废里程碑**不参与**时间差（从有效口径排除），只保留在历史视图中。

## 5. 历史与失效链接（可见、可查、不改写）

1. **有效时间线**只含计划条目与 `Status = 1`（已登记）里程碑；
2. 已作废里程碑（`Status = 2`）与**历史异常状态**行只出现在「已作废 / 历史异常状态视图」（按事件时间倒序、
   有界且显式说明截断），保留原始事件类型 / 时间 / 来源 / 备注 / 记录人 / 作废时间 / 作废原因；
3. 出运引用本身被作废时：整条记录仍可读（含作废原因），标注「出运引用已作废：只作历史呈现、不新增证据」；
4. 源记录被删除 / 不存在 / 源记录 Id 无效：显式标注不可用，历史证据按原值呈现，**绝不改派**；
5. 历史异常事件类型 / 状态照实回显（「未知（原值）」），筛选条件仍然严格：未知事件类型 / 未知状态一律 400。

## 6. API（只读）

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/container/shipment-timeline` | 跟踪工作台（分页，只读；显式字段筛选） |
| `GET` | `/api/container/shipment-timeline/sources/{sourceType}/{sourceId}` | 按显式源记录读取时间线（`booking` / `pre-loading` / `loading-list`） |
| `GET` | `/api/container/shipment-timeline/references/{referenceId}` | 按显式出运引用读取时间线（工作台行入口） |
| `GET` | `/api/container/bookings/{id}/shipment-timeline` | 订柜信息详情入口（只读） |
| `GET` | `/api/container/pre-loadings/{id}/shipment-timeline` | 预装柜单详情入口（只读） |
| `GET` | `/api/container/loading-lists/{id}/shipment-timeline` | 装柜清单详情入口（只读） |

工作台查询参数（全部为可选筛选，未知取值一律 400）：

| 参数 | 口径 |
|---|---|
| `page` / `pageSize` | 分页（默认 50，单次上限 200，越界自动收敛） |
| `sourceType` / `sourceId` | 源记录类型 allowlist / 正整数 Id |
| `status` | 出运引用状态（1 已登记 / 2 已作废；留空 = 全部，含已作废历史） |
| `sourceNo` / `containerNo` / `billOfLadingNo` / `shippingOrderNo` | **显式等值**筛选（去空白 + 统一大小写；不做相似度匹配） |
| `departurePort` / `transitPort` / `destinationPort` | **显式等值**筛选 |
| `plannedDepartureFrom` / `plannedDepartureTo` / `plannedArrivalFrom` / `plannedArrivalTo` | 只匹配**已持久化**的计划值（含端点当天；区间颠倒一律 400） |
| `eventType` / `eventDateFrom` / `eventDateTo` | 命中至少一条匹配里程碑证据（相关 `EXISTS`，不是逐行查库；区间颠倒一律 400） |
| `includeVoidedEvents` | 记录事件筛选是否显式包含已作废历史（默认 `false` = 只看有效证据） |
| `keyword` | 只命中显式列（源单号 / 柜号 / B/L / S/O / 承运人 / 目的港），长度上限 100 |

**读取性能口径**：单页内里程碑汇总（有效 / 已作废 / 异常状态条数、各事件类型最近一条有效证据）与源记录
可用性一律**批量装载**（分组查询 + 按源记录类型最多 3 次查询），**无逐行数据库访问**；
详情读取的查询次数与条目数无关（单元测试用只读计数代理断言「分页行数变化不改变访问次数」与「只读不写库」）。

## 8. 边界（本任务明确不做的事）

1. **只读**：不写任何表（服务层没有 `Add` / `Update` / `Remove` / `SaveChanges`），不改写订柜信息 /
   预装柜单 / 装柜清单 / 出运引用 / 里程碑的任何列、状态与工作流；
2. **不新建任何表 / 列**：无结构变更、无 `SchemaUpgrader` 改动、无任何回填（历史记录保持可读即可查看时间线）；
3. **不推断与派生**：不把计划时间当实际事件，不把缺失事件推断为已发生 / 已清关 / 延误 / 逾期，
   不做任何时区换算，不把时间差解释为 SLA 或索赔依据；
4. **不按文本匹配**：不按柜号 / S/O / B/L / 承运人等自由文本挑选或合并记录，也不跨客户 / 跨柜并行；
5. **不触达外部系统**：不轮询承运人、海关、报关行、货代或任何跟踪 / 订舱服务，也不做 EDI / API 对接；
6. **不改写下游**：不改写销售订单、采购订单、库存与库存成本、库存流水、单证中心、发票、费用与分摊、
   收付款、税务与结算记录。
