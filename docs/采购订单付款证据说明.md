# 采购订单付款引用证据说明（ERP-050）

## 1. 背景与定位

ERP-049 建立了**供应商付款引用（分摊）登记册**（`SupplierPaymentAllocations`），让「这张付款单把多少钱指向了哪几张采购订单」
可被显式登记与追溯；ERP-048 又在采购订单列表 / 详情上暴露了只读的**发票证据**汇总。但在采购与对账的实际操作里，
用户还需要在看到订单的**订单金额**与**已开票金额**的同时，看到**第三类完全独立的证据：付款引用证据**
（付款单金额指向本订单的引用行），而不是把三者混成一个「余额」。

本次（ERP-050）在**既有采购订单列表 / 详情工作流**与**ERP-044 供应商采购发票对账报表**上暴露只读的付款引用证据：

- 有效已引用金额 = **有效（未作废）**持久化引用行的合计（原币）；
- 付款单张数（按付款单去重）与引用行条数；
- 参与证据的付款单金额快照合计，以及其中**未指向本订单**的部分（可能指向其他采购订单）；
- 已作废历史证据、无效历史证据（供应商 / 币种或快照不一致）、无法确认证据（付款单已删除 / 不存在）
  **单独分桶列出并逐条给出原因**，绝不并入有效合计，也绝不换算、合并或改派到其他订单；
- ERP-044 对账报表中，**订单金额 / 已开票金额 / 付款引用金额**保持三个**分别标注**的字段。

定位：**采购订单维度的付款引用证据只读呈现**。它**不是**银行付款凭证、**不是**付款授权或付款状态、
**不是**应付账款台账或应付余额、**不是**发票核销或进项（税务）判断、**也不是**结算结果与账龄表。

> 本说明对应改动**不含**任何数据库结构变更（无新表 / 新列 / 新索引），也不含任何历史数据回填；
> 改动仅限只读派生、接口暴露、界面呈现、文档与单元测试。

## 2. 金额口径（唯一权威来源）

| 值 | 口径 |
|---|---|
| 有效已引用金额 | 只按 ERP-049 的**持久化引用行**合计，且只统计**有效（未作废、状态 = 1）**的行；已作废 / 无效 / 无法确认一律不计入 |
| 付款单张数 | 有有效引用行的付款单去重计数（同一付款单指向本订单只算一张） |
| 引用行条数 | 本次读取到的持久化引用行总条数（含历史 / 无效证据），用于「有证据 / 无证据」判定 |
| 参与证据的付款单金额快照合计 | 有有效引用行的付款单的**快照金额**去重求和（仅作上下文；不是应付余额，也不是银行付款金额） |
| 未指向本订单的金额 | 参与证据的付款单金额快照合计 − 本订单有效已引用金额（下限 0，仅作上下文；**可能指向其他采购订单**） |
| 币种与精度 | 复用 ERP-043 的 `CurrencyAmountRules`（JPY / KRW / VND / IDR 为 0 位小数，其余 2 位，0.5 进位）；**不同币种绝不合并、不做汇率换算** |
| 资格判定 | 复用 ERP-049 的权威规则 `SupplierPaymentAllocationRules.EvaluateOrderEligibility`（订单存在未删除、未取消、供应商一致、币种一致）与状态 / 可用性文案 |
| 订单可用性 | 复用 ERP-044 的 `available` / `cancelled` / `unavailable` 常量与文案 |

**金额直接取自持久化行**：本视图不重算付款金额、不按税率或比例反推、不调整差额、不做汇率换算、不跨币种合并，
也绝不因为「看起来像」就把未指向部分或历史证据改派给任何采购订单。

## 3. 证据分桶

一条持久化引用行（付款单 → 采购订单）在派生时只可能落进下列一个分桶：

| 分桶 | 命中条件 | 是否计入有效合计 |
|---|---|---|
| `recorded` 有效付款引用证据 | 引用行状态 = 有效，付款单存在且未删除，供应商与币种**都与付款单一致**，引用行订单币种快照自相一致，订单存在未删除、引用金额为正数，且订单供应商 / 币种与付款单一致（订单已取消时仍照实计入有效合计，但订单金额与结算上下文按未知 / 历史参考） | **是**（唯一计入的分桶） |
| `voided` 已作废历史证据 | 引用行状态 = 已作废（保留身份 / 金额 / 快照 / 作废原因） | 否 |
| `invalid` 无效历史证据 | 供应商不一致、币种不一致、订单币种快照自相矛盾、引用金额非正数，或状态码无法识别 | 否 |
| `unavailable` 无法确认的证据 | 引用行指向的付款单不存在 / 已删除，或采购订单不存在 / 已删除 | 否 |

汇总与详情都会给出各分桶的**金额与条数**，并在行说明中点名「为什么这些金额不计入有效合计」，
避免被读成「已经付款所以已经结算」。

## 4. 供应商 / 币种不一致：无效历史证据（绝不换算、合并或改派）

引用行写入时由 ERP-049 服务端保证权威一致；但付款单的供应商 / 币种或订单的供应商 / 币种后续可能被改动，
历史数据也可能出现自相矛盾的残留。以下情形一律落到 `invalid` 分桶：

1. **引用行供应商快照与付款单供应商不一致** → 原样说明两个供应商 Id；
2. **引用行币种与付款单币种不一致** → 明确「不做汇率换算、不合并为同一金额」；
3. **引用行订单币种快照与引用行币种不一致** → 快照自相矛盾，按无效证据处理；
4. **引用金额非正数或状态码无法识别** → 不能确认证据有效性，按无效证据处理；
5. **订单当前供应商 / 币种与付款单不一致**（订单资料被改动）→ 复用 ERP-049 判定文案，按无效证据处理。

处理原则：**显示为无效 / 不可确认的历史证据**，金额**原样保留**在该分桶中（不换算、不四舍五入改写），
**绝不**并入有效合计，也**绝不**改派到其他采购订单。

## 5. 有界读取与「未知」处理

| 入口 | 有界上限 | 说明 |
|---|---|---|
| 列表批量汇总 | 一次最多 **200 张**采购订单（超出直接拒绝，不静默截断） | 固定 **4 次**数据集访问：订单 + 持久化引用行（含 1 条溢出探测）+ 付款单 + 付款单侧有效引用合计（数据库侧分组聚合）；**无逐行查库** |
| 列表批量汇总 | 最多读取 **5000 条**引用行 | 命中上限时本次响应内**全部**订单的金额与计数按 `null`（未知）返回 |
| 单张订单详情 | 最多读取 **500 条**引用行 | 命中上限时金额与计数按 `null`（未知）返回，明细只显示已读取部分 |
| ERP-044 对账报表 | 一次最多聚合 **500 张**订单 | 超出时该批订单的付款引用金额与计数按未知（`null`）显示，报表不给部分合计 |

- 命中上限时**绝不报出部分合计**：接口返回 `truncated = true`，界面显示「未知（超出有界读取上限）」，
  并在说明中写清原因；报表侧则把该订单的付款引用字段置为 `null` 并计入 `unknownPaymentReferenceOrderCount`；
- 金额 / 计数为 `null` 一律显示为「**未知**」，**绝不用 0 顶替**；
- 订单**没有任何引用行**：证据短标签为「无付款引用证据」，明确提示
  「不代表未付款、已付款、已结清、逾期或欠款，也不构成应付余额、付款授权或结算依据」；
- 订单**只有历史 / 无效证据**：短标签为「仅有历史 / 无效付款引用证据」，有效合计为 0 但**不显示为未付款**；
- 订单**已取消**：有效合计照实列出（该引用行登记时有效），订单金额与结算上下文按未知显示，不推断付款或逾期。

## 6. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/purchase-orders/{id}/payment-evidence` | 单张采购订单付款引用证据详情（汇总 + 有界逐条明细 + 口径 / 边界文案）；订单不存在 / 已删除返回「数据不存在」 |
| GET | `/api/purchase-orders/payment-evidence-summaries?ids=1,2,3` | 列表用有界批量汇总：逗号分隔订单 Id（去重、保序，≤ 200 张），非法或超界一律拒绝；空 `ids` 返回空结果且**不访问数据库** |

返回内容（两接口同源）：有效已引用金额 / 付款单张数 / 引用行条数、参与证据的付款单金额快照合计与其中未指向本单部分、
已作废 / 无效 / 无法确认的金额与条数、订单金额与订单可用性文案、`truncated`、短标签 `evidenceLabel`、
行级 `evidenceNote`、逐条明细（付款单号 / 日期 / 状态 / 金额 / 引用金额 / 分桶 / 供应商快照 / 订单快照 / 登记与作废留痕 / 原因），
以及口径文案 `rule` / `scopeNote` / `boundary` 与 ERP-049 同源的 `linkageRule` / `allocationBoundary`。


## 7. 界面

- **采购订单列表新增派生列「付款引用证据」**（`virtual` 列，不落库、不改接口实体）：
  - 列渲染读取本页订单的汇总缓存；缓存缺失时**按页**发起有界批量请求（单次 ≤ 200 张，超出按 200 分批），
    到达后就地重渲染，同一页不重复请求，**绝不逐行查库**；
  - 徽标显示「付款引用 金额 · n 张付款单 · 未指向本单 金额」；只有历史 / 无效证据时显示
    「仅有历史 / 无效证据」，没有引用行时显示「无付款引用证据」，命中上限时显示「未知（超出有界读取上限）」；
  - 列表重新加载（翻页 / 搜索 / 操作后刷新）会使缓存失效并重新取数，避免展示过期证据。
- **行操作「付款引用证据」**：打开只读详情弹窗（汇总 + 逐条证据明细 + 口径 / 边界文案），
  已作废 / 无效 / 无法确认证据逐条给出原因，便于审计对照。
- **ERP-044 对账报表页面**：供应商 + 币种分组表、按币种汇总表与发票明细的关联订单行都新增独立的
  「付款引用金额 / 有·无·未知订单数 / 付款引用历史行数」列，页脚同时展示 `paymentEvidenceRule` 与
  `paymentEvidenceBoundary` 文案，确保**订单金额 / 已开票金额 / 付款引用金额**三类证据分别标注。
- 相关文件：`src/ERP.Api/wwwroot/js/purchase-order-payment-evidence.js`、
  `wwwroot/js/supplier-invoice-reconciliation.js`、`wwwroot/js/modules-doc.js`（列与行操作接线）、
  `wwwroot/index.html`（脚本注册）。界面与接口都显式声明「不是银行付款凭证、不是应付余额、不是发票核销、不是结算结果」。

## 8. 边界（明确不做的事）

- **只读**：派生过程只有 `AsNoTracking` 查询，**从不** `SaveChanges`；
- **不改写采购订单**：状态、到货进度、结算进度文本、金额与明细、归属客户 / 销售订单一律不变；
- **不改写付款单**：审批 / 执行状态、金额、币种、付款方式、银行账户、供应商与备注一律不变，
  也**不**执行付款、不移动资金、不生成付款或结算单；
- **不改写引用行**：不自动建立 / 修改 / 作废 / 改派任何引用行；历史证据只读；
- **不改写下游记录**：发票与发票关联、库存与库存成本、库存流水、退税记录、供应商余额、费用与收付款都不受影响；
- **不作财务判断**：不判断是否已付款、是否已结清、是否逾期，不推算账期与到期日、不做账龄分摊与税负计算；
- **无回填**：既有采购订单在没有付款引用行时显示「无付款引用证据」，行为与历史完全一致；
- **无结构变更**：不新增表 / 列 / 索引，`SchemaUpgrader` 不变；生产库执行、部署与发布仍受 Human Gate 控制。
