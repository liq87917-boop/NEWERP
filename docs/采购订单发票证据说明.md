# 采购订单发票证据说明（ERP-048）

## 1. 背景与定位

采购订单此前已经有「执行进度（ERP-026）」与「财务核对（ERP-028）」两个只读视图，ERP-043 又建立了供应商采购发票登记册
（`PurchaseInvoices` / `PurchaseInvoiceAllocations`）并支持把发票含税总额关联到既有采购订单。但在实际业务里，
采购员与跟单员仍需要在**采购订单自己的列表与详情**上直接看到「这张订单的发票证据覆盖到什么程度」。

本次（ERP-048）在**既有采购订单列表 / 详情工作流中暴露只读的发票证据汇总**：

- 已开票金额 = **已登记且未作废**发票的**持久化关联行**合计（原币）；
- 未开票金额 = 采购订单已落库总额 − 已开票金额（下限 0）；
- 发票张数（已登记去重）与覆盖状态（沿用 ERP-044 的同一套常量）；
- 草稿证据、已作废历史证据、无效历史证据（供应商 / 币种不一致）、无法确认证据（发票或订单已删除）
  **单独分桶列出**，绝不并入已开票金额。

定位：**采购发票证据的只读呈现**。它**不是**应付账款台账或应付余额、**不是**付款授权与付款状态、
**不是**税务（进项）申报或抵扣判断、**也不是**结算进度与账龄表。

> 本说明对应改动**不含**任何数据库结构变更（无新表 / 新列 / 新索引），也不含任何历史数据回填。

## 2. 金额与覆盖口径（唯一权威来源）

| 值 | 口径 |
|---|---|
| 已开票金额 | 只按 ERP-043 的**持久化关联行**合计，且只统计**已登记且未作废**的发票；草稿 / 已作废 / 无效 / 无法确认一律不计入 |
| 未开票金额 | 采购订单已落库总额 − 已开票金额（下限 0）；**仅在订单可用且未取消时给出**，否则为 `null`（未知） |
| 覆盖状态 | `fully_invoiced` / `partially_invoiced` / `not_invoiced` / `unknown`，复用 ERP-044 的常量与长文案；界面另加短标签 |
| 币种与精度 | 复用 ERP-043 的 `CurrencyAmountRules`（JPY / KRW / VND / IDR 为 0 位小数，其余 2 位，0.5 进位）；**不同币种绝不合并、不做汇率换算** |
| 订单供应商 / 币种校验 | 复用 ERP-043 的权威资格判定 `PurchaseInvoiceRules.EvaluateOrderEligibility`（订单存在未删除、未取消、供应商一致、币种一致） |
| 订单可用性 | 复用 ERP-044 的 `available` / `cancelled` / `unavailable` 常量与文案 |

**金额直接取自持久化行**：本视图不重算发票金额、不按税率反推、不调整差额、不做汇率换算、不跨币种合并，
也不因为「看起来像」就把未关联金额或历史证据改派给任何采购订单。

## 3. 证据分桶

一条持久化关联行（发票 → 采购订单）在派生时只可能落进下列一个分桶：

| 分桶 | 命中条件 | 是否计入已开票金额 |
|---|---|---|
| `recorded` 已登记证据 | 发票状态 = 已登记、未删除，关联行快照自相一致，且订单可用、供应商与币种**都与发票一致**（订单已取消时仍按已登记计入，但覆盖状态按未知） | **是**（唯一计入的分桶） |
| `draft` 草稿证据 | 发票仍是草稿（工作数据，尚未登记为证据） | 否 |
| `voided` 已作废历史证据 | 发票已作废（保留身份 / 金额 / 关联 / 作废原因） | 否 |
| `invalid` 无效历史证据 | 供应商不一致、币种不一致、关联行快照与发票自相矛盾，或关联金额非正数 | 否 |
| `unavailable` 无法确认的证据 | 关联行指向的发票不存在 / 已删除，或采购订单不存在 / 已删除 | 否 |

汇总与详情都会给出各分桶的**金额、条数与（发票身份可靠时的）发票张数**，并在备注中点名说明
「为什么这些金额不计入已开票金额」，避免被读成「已经开票所以已经付款」。

## 4. 供应商 / 币种不一致：无效历史证据（绝不换算、合并或改派）

关联行与发票在写入时由 ERP-043 服务端保证权威一致；但订单的供应商 / 币种后续可能被改动，
历史数据也可能出现自相矛盾的残留。以下四类一律落到 `invalid` 分桶：

1. **订单供应商与发票供应商不一致**（订单供应商被改动）→ 复用 ERP-043 判定文案，原样说明不一致的供应商 Id；
2. **订单币种与发票币种不一致** → 明确「不做汇率换算」，金额以原币保留在无效分桶；
3. **关联行快照与发票自相矛盾**（关联行供应商 Id / 币种与发票不一致）→ 按无效证据处理；
4. **关联行订单币种快照与发票币种不一致** → 按无效证据处理。

处理原则：**显示为无效 / 不可确认的历史证据**，金额**原样保留**在该分桶中（不换算、不合并、不四舍五入改写），
**绝不**并入已开票金额，也**绝不**改派到其他采购订单。

## 5. 有界读取与「未知」处理

| 入口 | 有界上限 | 说明 |
|---|---|---|
| 列表批量汇总 | 一次最多 **200 张**采购订单（超出直接拒绝，不静默截断） | 固定 **3 次**数据集访问：采购订单 + 持久化关联行（含 1 条溢出探测）+ 关联发票；**无逐行查库** |
| 列表批量汇总 | 最多读取 **5000 条**关联行 | 命中上限时本次响应内**全部**订单的金额与计数按 `null`（未知）返回 |
| 单张订单详情 | 最多读取 **500 条**关联行 | 命中上限时金额与计数按 `null`（未知）返回，明细只显示已读取部分 |

- 命中上限时**绝不报出部分合计**：接口返回 `truncated = true`，界面显示「未知（超出有界读取上限）」
  并在备注中说明原因；
- 金额 / 计数为 `null` 一律显示为「**未知**」，**绝不用 0 顶替**；
- 订单**不存在 / 已删除 / 已取消**：订单金额与未开票金额为 `null`（未知），绝不按 0 处理，也不推断付款或结算状态；
- 订单**没有任何登记发票关联行**：覆盖状态为 `not_invoiced`、界面显示「无发票证据」，
  明确提示「不代表未付款、已结清或逾期，也不构成应付余额或付款依据」；
- 订单**只有历史 / 无效证据**：覆盖状态仍为 `not_invoiced`，短标签显示「未开票（仅有历史 / 无效证据）」。

## 6. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/purchase-orders/{id}/invoice-evidence` | 单张采购订单发票证据详情（汇总 + 有界逐条明细 + 口径文案）；订单不存在 / 已删除返回「数据不存在」 |
| GET | `/api/purchase-orders/invoice-evidence-summaries?ids=1,2,3` | 列表用有界批量汇总：逗号分隔订单 Id（去重、保序，≤ 200 张），非法或超界一律拒绝；空 `ids` 返回空结果且**不访问数据库** |

返回内容（两接口同源）：已登记金额 / 张数、草稿 / 已作废 / 无效 / 无法确认金额与计数、关联行条数、订单金额、
未开票金额、覆盖状态（常量 + 长文案 + 短标签）、订单可用性文案、`truncated`、行级 `evidenceNote`、
逐条明细（发票身份 / 开票日期 / 状态 / 分桶 / 关联金额 / 发票供应商 / 关联行快照 / 不计入原因），
以及口径文案 `rule` / `scopeNote` / `boundary` 与 ERP-043 同源的 `amountEquation` / `linkageRule`。

## 7. 界面

- **采购订单列表新增派生列「发票证据」**（`virtual` 列，不落库、不改接口实体）：
  - 列渲染读取本页订单的汇总缓存；缓存缺失时**按页**发起有界批量请求（单次 ≤ 200 张，超出按 200 分批），
    到达后就地重渲染，同一页不重复请求，**绝不逐行查库**；
  - 徽标显示覆盖状态短标签 + 「已开票 / 未开票」金额；订单存在草稿 / 已作废 / 无效 / 无法确认证据时追加
    「⚠ 含历史证据」，并在悬停说明中给出完整口径与不计入原因；
  - 列表重新加载（翻页 / 搜索 / 操作后刷新）会使缓存失效并重新取数，避免展示过期证据。
- **行操作「发票证据」**：打开只读详情弹窗（汇总 + 逐条证据明细 + 口径 / 边界文案），
  历史与无效证据在明细中逐条给出原因，便于审计对照。
- 相关文件：`src/ERP.Api/wwwroot/js/purchase-order-invoice-evidence.js`、
  `wwwroot/js/modules-doc.js`（列与行操作接线）、`wwwroot/index.html`（脚本注册）。
  界面与接口都显式声明「不是应付余额、不是付款授权、不是税务申报、不是结算状态」。

## 8. 边界（明确不做的事）

- **只读**：派生过程只有 `AsNoTracking` 查询，**从不** `SaveChanges`；
- **不改写采购订单**：状态、到货进度、结算进度文本、金额与明细、归属客户 / 销售订单一律不变；
- **不改写发票与关联行**：不自动建立 / 修改 / 作废 / 改派任何关联；历史证据只读；
- **不改写下游记录**：库存与库存成本、库存流水、退税记录、供应商余额与付款状态、费用、收付款与结算单都不受影响；
- **不作财务判断**：不判断是否已付款、是否已结清、是否逾期；不推算账期与到期日、不做账龄分摊与税负计算，
  也不产生记账 / 凭证 / 收付款 / 结算单；
- **无回填**：既有采购订单在没有发票数据时显示「无发票证据」，行为与历史完全一致；
- **无结构变更**：不新增表 / 列 / 索引，`SchemaUpgrader` 不变。
