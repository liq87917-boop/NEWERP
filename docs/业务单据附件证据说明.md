# 业务单据附件证据说明（ERP-061 / ERP-062 / ERP-063 / ERP-064）

> 目标：为**既有**销售订单 / 采购订单（ERP-061）、**出口单证**（ERP-062）与**验货记录 / 样品记录**（ERP-063）
> 提供**唯一**的附件（二进制内容）证据能力：用户上传 PDF / PNG / JPEG 证据文件，服务端权威保存内容元数据
> （净化文件名快照 / 媒体类型 / 字节长度 / SHA-256 摘要 / 上传人 / 登记时间），并以「附件」方式安全下载；
> 更正走**显式作废**（必填原因），保留原始元数据与登记历史。

---

## 1. 定位与边界

| 项 | 口径 |
|---|---|
| 模块 | 业务单据附件**内容**证据册（`AttachmentEvidences` 一张表 + 唯一内容接缝 `IAttachmentContentStore`） |
| 归属（ERP-061） | 销售订单（`SalesOrder`）、采购订单（`PurchaseOrder`）：**显式**类型 + Id，必须存在且未删除 |
| 归属（ERP-062） | 出口单证（`TradeDocument`，单证中心台账）：同一模型、**显式**类型 + Id，单证必须存在且未删除；不新增第二张二进制表、不新增自由路径字段、不新增单证专用上传引擎 |
| 归属（ERP-063） | **验货记录**（`QualityInspection`）：权威记录是**既有采购订单上的 QC 字段**（`PurchaseOrders.QcStatus` 验货状态 + `ArrivalProgress` 到货进度）——本仓库**没有**独立验货 / 质检实体与表，因此不新建验货主数据、不新建第二张表；**样品记录**（`Sample`）：权威记录是**既有样品台账**（`Samples`）。两者都是同一模型上的**显式**类型 + **既有持久化 Id**（验货记录 = 采购订单 Id，样品记录 = 样品 Id），必须存在且未删除 |
| 允许内容 | 仅 `PDF`（`%PDF-`）、`PNG`（8 字节魔数）、`JPEG`（`FF D8 FF`），且**扩展名 / 声明 Content-Type / 文件签名三者一致** |
| 大小上限 | 单个内容 **20 MiB**（服务端实测；超限在读取时立即中止且不保存任何内容） |
| 更正方式 | **显式作废**（原因必填，≤500 字）：无硬删除、无二进制替换、无归属改派、无 `PUT` / `PATCH` / `DELETE` 接口 |
| 明确不是 | 不是报关 / 报税 / 银行 / 承运人 / 客户或任何第三方的确认或回执；不构成批准、付款、出运、清关或结算依据；不改写任何单据状态、金额、明细与库存 / 财务记录 |

## 2. 审计结论：为什么这是「唯一」附件内容模型

| 既有代码 | 事实 | 本任务处理 |
|---|---|---|
| `src/ERP.Infrastructure/Storage/OssStorageService.cs` | 仓库内**唯一**的文件 / 图片存储代码（阿里云 OSS V1 签名 PUT）；无接口、无下载、无删除；仅被商品图片上传使用 | **保持原样**：不修改、不新增调用、不注册新用途；生产 OSS 的凭据 / 桶配置 / 迁移与**激活**属生产 OSS Human Gate，本阶段**不存在、不注册、不激活** |
| `BaseProducts.Image1~3`（商品图片位） | 只保存图片 URL 字符串 | 保持原样：不导入、不改写、不作为附件证据 |
| `DocumentAttachmentReference`（ERP-045） | **仅元数据**的附件引用册（分类 / 显示名 / 不透明引用标识 / 大小 / 校验和），**不**上传 / 下载 / 预览任何文件 | 保持原样：两册职责互补；附件证据**不**自动导入引用行，也不把引用行当作已上传内容 |
| `TradeDocuments.FileNote` | 「附件说明 / 存放位置」自由文本 | 保持原样：**不解析成路径、不抓取其中的地址、不转成附件证据、不在请求时回填**（ERP-062 接入单证时同样如此；口径文案 `AttachmentEvidenceRules.LegacyFileNotePolicyText` 随 `metadata` 返回并由界面显示） |
| 验货 / 质检（全仓审计，ERP-063） | 全仓**不存在**独立验货 / 质检实体、表或端点：与验货相关的只有 `PurchaseOrders.QcStatus`（验货状态）+ `ArrivalProgress`（到货进度）；`docs/菜单与业务流程优化建议-20260918.md:28` 明确「验货单 QC ❌ 未实现，未立项 | 采购订单仅有 `QcStatus` 字段，无独立验货单与照片」 | ERP-063 **不**新建验货主数据、**不**新建第二张表：`OwnerType = QualityInspection` 的权威记录就是**该既有采购订单本身**（使用其**既有持久化 Id**），只读投影 `QcStatus` / `ArrivalProgress` 原文；上传 / 读取 / 下载 / 作废都**不**改写验货状态，也**不**推断合格 / 不合格、质量认证或出运许可 |
| `Sample`（样品管理，ERP-063） | 既有单表台账（`SampleNo` / `SampleDate` / `SampleType` / `SampleFee` / `FeeSettled` / `Result` 等），走通用 CRUD（`api/crm/samples`、菜单 `sample`、`modules.js`） | ERP-063 在同一模型上接入**同一**附件证据能力（`OwnerType = Sample`）：只读样品编号 / 样品类型 / 客户反馈原文，**不**改写样品台账、**不**新建样品主数据、**不**把上传当作样品批准或客户确认 |

因此本任务**不引入第二套文件存储**，而是建立唯一的内容访问接缝 `IAttachmentContentStore`：

```csharp
public interface IAttachmentContentStore
{
    string ProviderCode { get; }              // 隔离非生产本地存储 = "local-isolated"
    string ProviderText { get; }              // 与界面 / 接口同源的文案
    bool IsProductionProvider { get; }        // 生产对象存储 → true（写入被服务层拒绝）
    Task<string> SaveAsync(Stream content, string extension, CancellationToken ct = default);
    Task<Stream?> OpenReadAsync(string storageKey, CancellationToken ct = default);
    Task<long?> GetLengthAsync(string storageKey, CancellationToken ct = default);
}
```

| 提供程序 | 实现 | 状态 |
|---|---|---|
| `local-isolated`（缺省） | `IsolatedLocalAttachmentContentStore` | **开发 / 测试唯一启用**：写入应用目录之外的隔离根目录（缺省 `<应用目录>/var/attachment-evidence`，配置键 `Attachments:LocalRootPath`）；根目录解析后若位于任意 `wwwroot` 之内直接拒绝构造 |
| `oss` | **未实现** | `AttachmentContentStoreFactory` 在 `Attachments:Provider = oss` 时**显式抛错**（不静默降级），提示生产 OSS Human Gate |
| 其他取值 | 无 | 显式抛错（避免拼写错误悄悄退化成默认提供程序） |

## 3. 数据模型

| 项 | 口径 |
|---|---|
| 表 | `AttachmentEvidences`（内容本体**不在**数据库：只保存服务端生成的**不透明存储键**与内容元数据） |
| 列 | `OwnerType` NVARCHAR(30)（白名单 SalesOrder / PurchaseOrder / TradeDocument（ERP-062）/ QualityInspection / Sample（ERP-063））、`OwnerId` BIGINT、`OwnerNo` NVARCHAR(50) + `OwnerTypeText` NVARCHAR(30)（服务端快照）、`OriginalFileName` NVARCHAR(255)（净化后快照）、`MediaType` NVARCHAR(120)（按签名判定）、`SizeBytes` BIGINT（服务端实测）、`Sha256` NVARCHAR(64)（服务端计算，小写十六进制）、`Description` NVARCHAR(500)、`StorageKey` NVARCHAR(200)（服务端生成、**不经接口返回**）、`StorageProvider` NVARCHAR(30)、`UploadedBy` NVARCHAR(100)、`RecordedAt` DATETIME2、`Status` INT（0 有效 / 1 已作废）、`VoidedAt` DATETIME2、`VoidReason` NVARCHAR(500) + 审计基类字段 |
| 唯一索引 | **刻意不建任何唯一索引**：同一摘要的重复上传**不做内容寻址去重**，两次上传是两条各自独立的证据（各有 Id / 存储键 / 登记时间），绝不静默合并、覆盖或替换 |
| 普通索引 | `IX_AttachmentEvidences_Owner_Status_RecordedAt`（归属 + 状态 + 登记时间：单据详情有界清单与台账分页）、`IX_AttachmentEvidences_Sha256`（摘要人工比对，**不是**证据身份）、`IX_AttachmentEvidences_Status_RecordedAt`（状态台账），全部过滤 `IsDeleted = 0` |
| 外键 | **刻意不建**任何外键与导航属性：归属单据改名 / 软删除后历史证据必须始终可读，只由服务端显式标注不可用，**绝不改派**到别的单据 |

## 4. 上传：校验顺序（任一失败都不落盘、不落库）

1. **存储提供程序守卫**：`IsProductionProvider == true` → `RuleConflict`（生产 OSS 未激活，属 Human Gate）；
2. **归属单据类型白名单**：`SalesOrder` / `PurchaseOrder` / `TradeDocument`（大小写不敏感，服务端统一输出规范写法）；留空、其它类型（如装柜清单）一律拒绝；
3. **归属单据存在性**：Id 必须为正整数，单据必须存在且**未删除**（`NotFound`）；系统**不按号码或名称猜测归属**；
4. **有界读取内容**：声明长度超限 → 提前拒绝；实际内容超限 → 读取**到达上限立即中止**并抛错（不保存任何内容）；空内容 / 未收到内容拒绝；
5. **文件名与格式三重判定**（`AttachmentEvidenceRules.ValidateUpload`）：
   - 净化文件名（客户端路径忽略、控制字符丢弃、不安全字符替换、长度 ≤255 且保留扩展名）；
   - 扩展名白名单 `.pdf / .png / .jpg / .jpeg`；可执行 / 脚本 / 标记类扩展名（`.html/.svg/.js/.exe/.bat/.ps1/.zip` 等）给出**专门的拒绝提示**；
   - 声明 Content-Type 只接受 `application/pdf`、`image/png`、`image/jpeg`（`image/jpg` 归一化；允许 `; charset=` 参数）；
   - **文件签名判定**（只依赖内容本身）：无法识别 → 拒绝；扩展名 / 声明类型 / 签名不一致 → 拒绝（改名伪装与 Content-Type 欺骗一律无法通过）；
6. **内容落盘**：存储键由提供程序生成（`yyyyMMdd/{guid}{ext}`，与客户端输入无关）；
7. **元数据落库**：摘要（SHA-256）、实测字节长度、媒体类型、归属号码 / 类型快照、上传人（缺失记「未知用户」）、登记时间全部**服务端权威写入**。

> 客户端**无法提交**任何被信任的值：上传请求模型里没有 `Sha256` / `StorageKey` / `StorageProvider` / `OwnerNo` /
> `OwnerTypeText` / `MediaType` / `SizeBytes` / `UploadedBy` / `RecordedAt` / `Status` 字段（单测逐项断言）。

## 5. 下载：每次重新校验 + 完整性复核

`GET /api/attachment-evidences/{id}/content`（**要求认证**）：

1. 证据必须存在、未软删除、状态为**有效**（已作废 → `RuleConflict`：元数据仍可读但**不提供下载**）；
2. **归属单据仍存在且未删除**（权威复核，知道 Id 不能绕过；失败 → `RuleConflict`，且不改派）；
3. 存储对象长度必须等于登记长度（不一致 → 拒绝）；流可定位时再复核 **SHA-256 摘要**（被外部替换 → 拒绝）；
4. 以 `File(stream, mediaType, fileName, enableRangeProcessing: false)` 返回：`Content-Disposition: attachment`，
   并附带 `X-Content-Type-Options: nosniff`、`Content-Security-Policy: default-src 'none'; sandbox`、
   `Cache-Control: no-store`、`Pragma: no-cache`、`X-Download-Options: noopen`、`Referrer-Policy: no-referrer`；
   **不内联渲染、不转成标记、不暴露存储键 / 文件系统 / 对象存储路径**（DTO 只给出 API 相对地址）。

## 6. 作废（唯一更正方式）

| 项 | 口径 |
|---|---|
| 原因 | **必填**、≤500 字、拒绝控制字符与 HTML / 脚本 / 链接形态 |
| 保留 | 原始文件名快照、SHA-256 摘要、媒体类型、字节长度、存储键、归属类型 / Id / 号码、上传人、登记时间 |
| 不做 | 硬删除、软删除（`IsDeleted` 保持 0）、二进制替换、归属改派；重复作废 → `Duplicate` |
| 下载 | 作废后**不再提供下载**（内容本体仍保留在隔离存储中，便于事后取证与留痕） |

## 7. 读取口径与授权

| 接口 | 口径 |
|---|---|
| `GET /api/attachment-evidences` | 台账分页（默认 50、单次上限 200）；过滤归属类型 / 归属 Id / 状态 / 摘要前缀（8~64 位十六进制，仅人工比对）/ 关键字（≤100）；**默认包含已作废历史**；页内归属单据可用性**批量装载**（每类型最多一次查询，无逐行查库） |
| `GET /api/attachment-evidences/by-owner` | 指定归属的有界清单（默认与上限 200 条）；归属必须存在且未删除（否则 `NotFound`）——单证、销售订单、采购订单同一口径 |
| `GET /api/attachment-evidences/owner-summary` | **有界摘要**（ERP-062）：`ownerType` + `ids=1,2,3`（或重复 `ids` 参数，单次 ≤ `AttachmentEvidenceRules.MaxSummaryOwnerIds` = 200）一次批量返回这些单据的「证据总数 / 有效 / 已作废」计数与**归属可用性**（软删除单据照实标注不可用、号码照实显示、绝不改派）；一次分组查询 + 一次归属装载，**无逐行查库、不访问任何存储、不返回证据明细** |
| `GET /api/attachment-evidences/owner-options` | 归属单据候选（有界 ≤200）：只列未删除的销售订单 / 采购订单 / 出口单证，批量统计证据条数（含已作废历史）；单证状态取台账原文（只读标注）；仅用于**显式选择**归属 |
| `GET /api/attachment-evidences/metadata` | 白名单 / 上限 / 当前内容存储提供程序 / 全部口径文案（界面与接口同源，避免前端硬编码漂移） |
| `GET /api/attachment-evidences/{id}` | 详情（只读）：归属单据已删除 / 缺失时照实标注不可用，历史证据仍可只读查看 |
| 授权 | 全部接口（含内容下载与摘要）**类级 `[Authorize]`**，与销售订单 / 采购订单 / 单证中心工作流相同的 JWT 认证与模块授权；上传动作另加 `RequestSizeLimit`（内容上限 + 1 MiB 表单开销） |

界面入口：`wwwroot/js/attachment-evidences.js`（`index.html` 引入）：
销售订单 / 采购订单列表行操作「📎 附件证据」（`modules-doc.js`）、单证中心行操作「📎 附件证据」（`modules.js`）
均由 `CURRENT_MODULE_CODE` 推断归属类型（`doc-center` → `TradeDocument`）；单证中心工具栏另有「📎 附件证据概览」
（`openAttachmentEvidenceSummaryForCurrentPage`）：按**当前页**单据 Id 一次请求 `owner-summary` 显示有界计数，
不逐行请求、不访问存储，内容需在登记册里显式发起带认证的下载。所有动态文本经 `aeEsc` 转义，
**不生成链接、不嵌入图片 / 框架标签、不自行抓取、不计算摘要**；下载走带 Bearer 认证的 `fetch` + Blob 保存为附件。

## 8. 幂等数据结构（SchemaUpgrader 第 40 段）

`SchemaUpgrader` 第 40 段以 `IF OBJECT_ID('db_owner.AttachmentEvidences') IS NULL` 幂等建表，并建三个普通过滤索引：
**不含任何 `UPDATE` / `INSERT` / `DELETE` 回填语句**，不在订单表上加列或建外键，也不改写任何既有表。

**生产库执行、生产 OSS 变更、部署与发布仍由 Human Gate 控制**；本文档不声明生产库已升级或已执行任何脚本。

## 9. 非变更边界

上传、读取、下载与作废**只读写** `AttachmentEvidences` 一张表（读取时只读归属单据），**不**改写：

- 销售订单 / 采购订单的状态、金额、定金、明细、备注、唛头与出运字段；
- 库存与库存成本（`Stocks`）、库存流水（`StockMovements`）、出入库 / 盘点 / 调拨 / 退货单据；
- 单证中心（`TradeDocuments` 及其 `FileNote`、明细行）、发票证据；ERP-062 接入单证后同样只读单证台账的
  编号 / 类型 / 状态（明细行与「附件说明 / 存放位置」文本保持原样，不解析、不抓取、不回填）；
- 费用与分摊、收付款引用、税务与结算记录、客户与供应商主数据；
- ERP-045 附件引用册（`DocumentAttachmentReferences`）与商品图片位（`BaseProducts.Image1~3`）。

## 13. 附件中心工作台（ERP-064）

**目标**：在 ERP-061 / ERP-062 / ERP-063 交付的**同一**附件证据册之上，提供一个**有界且按既有权限收敛**的
只读清单工作台（`docs/业务单据附件证据说明.md` 本节口径与实现同源）。

### 13.1 定位与边界

| 项 | 口径 |
|---|---|
| 数据来源 | **同一张** `AttachmentEvidences` 表 + 同一 `IAttachmentContentStore` 接缝：不复制二进制、不复制元数据、**不新增**第二个附件登记册、不新增表 / 列 / 存储 |
| 只读 | 工作台只有 `GET`：不新增 / 不改写 / 不作废证据，不改写父单据、工作流状态、库存、出运、单证、发票、税务、财务、审批与结算记录 |
| 授权口径 | 复用**既有**「角色 → 菜单」授权（`SysUserRoles` → `SysRoleMenus` → `SysMenus.MenuCode`）；归属类型 → 所需菜单：销售订单 = `sales-order`、采购订单 = `purchase-order`、出口单证 = `doc-center`、验货记录 = `purchase-order`（权威记录是既有采购订单 QC 记录）、样品记录 = `sample` |
| fail closed | 无身份 / 无角色 / 无相关菜单授权 → 可见范围为空：不显示记录、不计入合计；显式传入未授权类型 → 空页（不抛错、不披露存在性）；详情 / 下载 → 按「不存在」拒绝（不披露证据 Id 与归属类型） |
| 未授权不披露 | 未授权类型的记录、计数、文件名、摘要与历史一律不返回（连计数行都不返回）；界面只显示「未授权 + 所需菜单」这一事实 |
| 可见历史 | 授权查看者照常看到归属已软删除 / 缺失的历史证据并标注「不可用」；**下载**按既有口径拒绝（`RuleConflict`），绝不改派、绝不静默修复 |
| 有效 / 已作废 | 分开标注（`有效` / `已作废` + 作废时间与原因）；已作废证据仍在历史中可读，但不再提供下载 |
| 筛选 | 只用**已持久化显式元数据**：归属类型 / 归属 Id / 归属号码快照 / 文件名快照 / 媒体类型 / 上传人 / 登记日期区间 / 状态；不扫描文件内容、不抓取远端地址、不做模糊跨记录匹配，也绝不按文件名或摘要合并记录 |
| 有界 | 分页默认 50、单次上限 200；摘要按授权类型分组**单次**查询；页内归属可用性按类型**批量**装载（无逐行查库）；列表 / 摘要 / 详情 **零存储访问** |
| 下载 | 工作台下载先重新校验归属类型授权，再复用既有口径（证据有效 + 归属存在且未删除 + 长度 / 摘要一致）；以「附件」方式流式返回并带 `nosniff` / `sandbox` / `no-store` 等防御性响应头；只有用户**显式**点击才读取内容 |
| 界面入口 | 复用既有页面与菜单注册：`index.html` 仍只注册 `js/attachment-evidences.js`；入口为**单证中心**（`doc-center`）工具栏「🗂 附件中心」（`openAttachmentCenterWorkspace()`），不新增菜单与菜单授权 |

### 13.2 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/attachment-evidences/center` | 工作台台账（分页、有界、只读）：只列当前账号已授权归属类型的权威元数据；支持上述全部显式字段筛选 |
| `GET` | `/api/attachment-evidences/center/summary` | 可见范围（含每个归属类型所需菜单与授权状态）+ **授权范围内**按状态拆分计数 + 筛选项白名单 + 全部口径文案 |
| `GET` | `/api/attachment-evidences/center/{id:long}` | 证据元数据 / 历史：读取时**重新校验**当前归属授权（未授权 → `NotFound`，fail closed） |
| `GET` | `/api/attachment-evidences/center/{id:long}/content` | 内容下载：先校验归属授权，再复用既有下载口径（归属删除 / 不可用 / 已作废 / 长度或摘要不一致一律拒绝） |

控制器仍为类级 `[Authorize]`、唯一路由 `api/attachment-evidences`，**不提供**任何 `PUT` / `PATCH` / `DELETE`、
匿名或生产存储端点；防御性下载响应头由既有下载与工作台下载**共用**同一私有方法（同一口径，不重复实现）。

### 13.3 工作台文案（接口与界面同源）

| 文案 | 要点 |
|---|---|
| `CenterReadOnlyNoticeText` | 只读视图：只按已持久化元数据列出 / 筛选，不改写任何证据与业务记录 |
| `CenterUntrustedEvidenceNoticeText` | 附件是仓库内**不可信文件证据**：不是批准或审核结论、不是验货合格 / 不合格判定、不是质量认证或第三方检验结论、不是报关或税务提交 / 受理结果、不是银行付款凭证或付款授权、不是结算 / 对账确认，也不构成出运许可 |
| `CenterUnauthorizedNoticeText` | 未授权归属类型不返回记录 / 计数 / 文件名 / 摘要，连计数行都不返回；撤销授权后立即从列表与计数中消失，详情 / 下载 fail closed |
| `CenterFilterPolicyText` | 只用显式元数据筛选：不扫描内容、不抓取远端地址、不做模糊跨记录匹配、不按文件名或摘要合并记录 |
| `CenterScopeText` / `CenterSummaryText` | 可见范围与摘要计数口径：空范围明确 `fail closed`，计数只统计已授权类型，未授权类型不计入合计 |
| `CenterBoundaryText` | 边界：不是批准 / 验货结论 / 报关税务 / 付款授权 / 结算确认 / 出运许可；工作台只读 |
