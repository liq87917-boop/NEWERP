# 供应商报价转采购订单转化漏斗（ERP-103）

## 1. 目的

为已持久化的采购报价（`PurchaseQuote`）提供一个**只读**的「转采购订单」转化漏斗工作台：按比价批次号
（`QuoteNo`）分组，逐批次展示 已报价 → 已选中 → 已批准 → 已转采购订单 的转化进展，并区分 已拒绝 / 未解决
两类侧枝证据，帮助采购人员看清哪些批次卡在哪一步，但**不转单、不创建订单、不改报价 / 审批决定**。

## 2. 边界（重要）

- **只读**：不写库、不改报价 / 采购订单 / 价格 / 审批 / 库存 / 收付款，不创建订单。
- **审批决定仅作证据**：来自 `PurchaseQuoteDecision`（ERP-095，append-only），绝不被本视图改写。
- **不凭 `RefOrderNo` 文本单独推断转换**：该列在转换前可表示关联销售订单号，转换后才写回生成的采购单号。

## 3. 漏斗阶段与计数规则

每个批次按**漏斗口径（累计）**统计六类证据，逐级为上一级的子集（已拒绝 / 未解决为侧枝）：

| 计数 | 判定 | 说明 |
|---|---|---|
| `quotedCount` 已报价 | 批次内全部未删除报价行 | 漏斗顶部 |
| `selectedCount` 已选中 | `IsSelected == true` | 人工勾选最终选用 |
| `approvedCount` 已批准 | 存在 `Approved` 审批决定 | append-only 决定 |
| `convertedCount` 已转采购订单 | 三重证据全部成立（见第 4 节） | 仅此计入「已转」 |
| `rejectedCount` 已拒绝 | 存在 `Rejected` 审批决定 | 侧枝 |
| `unresolvedCount` 未解决 | 状态已转采购订单，但链接缺失 / 订单删除 / 单号歧义 / 来源标记缺失 | 侧枝 |

行级钻取时，每行展示其**到达的最深阶段**（`quoted` / `selected` / `approved` / `converted` /
`rejected` / `unresolved`），未解决行同时给出显式 `stageReason`。

## 4. 转采购订单证据认定

比价行 → 采购订单的权威链接沿用转换留痕（ERP-020 / ERP-027），**三重证据必须同时成立**才认定「已转采购订单」：

1. 比价行状态 = `已转采购订单`（`PurchaseQuoteConversion.ConvertedStatus`）；
2. 比价行 `RefOrderNo` 能唯一定位到一张未删除的采购订单；
3. 该采购订单备注包含来源标记 `来源比价 {QuoteNo}（比价行 #{Id}）`（`PurchaseQuoteConversion.SourceMarker`）。

判定顺序（仅对状态已是「已转采购订单」的行执行）：

- `RefOrderNo` 为空 → **未链接**；
- 按单号找不到未删除采购订单 → **不存在或已删除**；
- 同一单号对应多张未删除订单 → **链接歧义**；
- 订单备注不含来源标记 → **陈旧链接**；
- 全部成立 → **已转采购订单**。

**绝不凭 `RefOrderNo` 文本单独推断转换**：状态不是「已转采购订单」的行，即使 `RefOrderNo` 有值（可能是
转换前保存的关联销售订单号），也只按 已报价 / 已选中 / 已批准 / 已拒绝 归类，不计入已转或未解决。

## 5. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/purchase/quotes/conversion-funnel` | 通用查询：按可选 `dateFrom` / `dateTo` / `supplierId` / `page` / `pageSize` 筛选比价批次并分组 |

接口行为：

- 排除软删除（`IsDeleted`）比价行 / 采购订单 / 审批决定；
- 筛选作用于报价行（日期区间 + 可选供应商），命中行按批次号分组；
- 稳定按「批次最早报价日期 + 批次号」排序；
- 分页有界（默认 50 个批次、上限 200），命中截断时显式返回 `truncated=true`；
- 无匹配时返回显式 `emptyText`。

## 6. 响应要点

- `totalBatchCount` / `totalLineCount`：符合筛选条件的批次总数 / 报价行总数（分页前）。
- `batches[]`：每个批次含 `quoteNo`、`quoteDate`（最早报价日期）、六类计数与 `lines[]` 行明细。
- 行明细含来源证据（供应商 / 商品 / 报价单价 / 选中 / 状态 / `refOrderNo`）、审批状态（Approved / Rejected / Pending）、
  到达阶段、未解决原因与已转采购订单号 / 订单 Id。
- `ruleText`：口径与边界说明（与后端 `PurchaseQuoteConversionFunnel.RuleText` 同源）。

## 7. 前端

- 供应商比价页新增「🔎 转单漏斗」（`modules.js` → `purchase-quote-conversion-funnel.js`），
  为批次级入口（列表工具栏），不属于行操作。
- 点击后调用 `GET /api/purchase/quotes/conversion-funnel`，在弹层中只读展示批次漏斗，支持日期区间 +
  可选供应商筛选与分页；每个批次可展开钻取行明细，未解决行显式标注原因，弹层不含任何转换 / 编辑 / 保存动作。

## 8. 验证

单元测试 `src/ERP.UnitTests/PurchaseQuoteConversionFunnelTests.cs`（内存数据库，不连接 SQL Server、不启动 API）覆盖：
多供应商批次六类证据计数、审批变化（已批准 / 已拒绝 / 待审批）、批次转换（三重证据）、陈旧链接、订单删除、
未链接、`RefOrderNo` 不单独推断转换、分页有界与截断、供应商 / 日期筛选、稳定排序、无写入语义、
日期区间参数校验、接口路由与前端接线契约。
