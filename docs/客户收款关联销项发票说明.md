# 客户收款关联销项发票（ERP-073）

## 1. 定位

在既有客户收款单（`FinanceReceipt`）与 ERP-055 客户销项发票证据（`CustomerSalesInvoiceEvidence`）之上新增
**唯一一张**显式分摊证据表 `CustomerSalesInvoiceCollectionAllocations`：一行 = 一张既有、未删除且未取消的收款单 →
一条**已登记**的销项发票证据 + 一个分摊金额。

它**不是**银行入账 / 到账凭证、**不是**应收账款台账或余额、**不是**货款核销、**不是**客户对账单、
**不是**收入确认、**不是**税务（销项）判断、**不是**结算确认，也**不是**会计凭证或记账分录；
登记 / 作废都不会收款、不付款、不记账、不核销、不催收或联系客户，也不改写收款单与发票证据的任何字段。

## 2. 证据维度分离（核心口径）

| 维度 | 模型 | 含义 |
|---|---|---|
| 收款单 → 销售订单（ERP-053） | `CustomerReceiptAllocations` | 「这笔收款指向哪几张订单」 |
| 销项发票 → 销售订单（ERP-055） | `CustomerSalesInvoiceAllocations` | 「这张发票分摊到哪几张订单」 |
| 收款单 → 代理服务费对账单（ERP-071） | `AgencyServiceFeeCollectionAllocations` | 「这笔收款分摊到哪几条服务费对账单」 |
| **收款单 → 销项发票（ERP-073，本册）** | **`CustomerSalesInvoiceCollectionAllocations`** | **「这笔收款分摊到哪几张已登记销项发票」** |

四个维度**互相独立**：金额含义、判定资格与模型都不同，系统**绝不**把四个维度的金额相加，
也不把它们当成几张不同的收款单；任意一个维度的变动都不影响其它维度的数值。

## 3. 命名口径

类型名与 DbSet 名采用 **`Collection`（收款）** 而不是 `Receipt`，与 ERP-071 同源：ERP-053 已审计锁定
「`IErpDbContext` 中名字同时含 `Receipt` 与 `Allocation` 的 DbSet **只能有一套**（`CustomerReceiptAllocations`）」。
本模型虽然同样以客户收款单为来源，但引用对象是**销项发票证据**而不是销售订单，属于另一套独立维度。

## 4. 权威资格与金额口径

- 发票证据必须**存在、未删除且已登记**（草稿 / 已作废拒绝）；收款单必须**存在、未删除且未取消**；
  客户必须存在、未删除且启用；两侧客户与币种必须**一致**（不做汇率换算、不跨客户合并）。
- 分摊金额只来自授权用户**显式提交**：按币种精度（`CurrencyAmountRules`，0.5 进位）取整后必须 > 0，
  且不得超过**收款单可分摊余额**（收款金额 − 本维度有效分摊）与**发票未分摊含税额**（含税总额 − 本维度有效分摊）。
- 有效行唯一：同一「发票证据 + 收款单」在未作废 / 未删除行内唯一
  （`UX_CustomerSalesInvoiceCollectionAllocations_InvoiceReceipt`，过滤 `IsDeleted = 0 AND Status <> 2`）；
  作废保留原始值与历史，作废后该组合可重新登记。

- 前端：`js/customer-sales-invoice-collection-allocations.js` + 发票详情「收款分摊」入口。

## 6. 数据库与幂等升级

`CustomerSalesInvoiceCollectionAllocations` 由三处保持一致：

1. **EF 模型**（`ErpDbContext.Config.cs`，ERP-073 段）：长度 / 精度（`DECIMAL(18,2)`）、
   过滤唯一索引 `UX_CustomerSalesInvoiceCollectionAllocations_InvoiceReceipt`；
2. **幂等升级**（`SchemaUpgrader.cs` 第 45 段）：`IF OBJECT_ID(...) IS NULL` 建表 +
   `IF NOT EXISTS (sys.indexes ...)` 建索引，**不含任何 UPDATE / INSERT / DELETE / ALTER TABLE**；
3. **DbSet 与接口**（`ErpDbContext.Entities.cs` / `IErpDbContext.cs`）各新增一个 `DbSet`。

**刻意不建**任何外键与导航属性：收款单 / 发票证据被取消、软删除、作废或改名后历史证据必须始终可读。
