# 散货结算单生命周期与客户 / 金额护栏（ERP-387）

## 1. 目标

把**既有**散货结算单（`api/finance/bulk-settlements`）的**每一个读取与写入路由**都收敛到同一套实时授权口径，
并解决列表全量可见、客户归属不明、金额未校验、并发改写丢失更新与状态可被绕过流转的风险：

- 列表 / 详情 / 创建 / 修改 / 提交 / 审核 / 取消 / 删除都先校验**实时启用身份 + 既有「散货结算单」
  （`bulk-settlement`）菜单授权 + 当前权威客户数据范围**（复用 ERP-097 口径）；
- 创建 / 修改校验**真实可用客户**（存在、未删除、启用），读取 / 状态变更 / 删除前复核**库中已存储**客户归属，
  受限账号对范围外 / 无权威归属 / 未知归属一律 fail closed；
- 金额只按**既有存储精度**做正负校验（总金额 > 0，海运费 >= 0），**不**发明换算、**不**跨币种聚合、
  **不**推断装运 / 订单来源；
- 修改 / 提交 / 审核 / 取消 / 删除在**同一事务内先取散货结算单行锁**，锁内重新加载权威单据并复核范围 / 状态 / 金额，
  失败整体回滚（状态、原始字段与审计不变）；创建在**生成单号与写入之前**完成全部校验（失败绝不消耗单号）。

复用既有分层架构与既有单据流转（创建 / 修改 / 提交 / 审核 / 取消 / 删除）；不做报表、不做界面视觉 / 样式打磨，
不写库存 / 资金 / 会计，也不调用任何外部系统。

## 2. 口径

| 项 | 口径 |
|---|---|
| 适用路由 | 列表、详情、创建、修改、提交、审核、取消、删除 |
| 实时授权 | 每一路由先解析：身份缺失 / 非法 → 未认证；账号不存在 / 已删除 → 未认证；账号禁用 → 权限不足；非特权账号无既有 `bulk-settlement` 菜单 → 权限不足，一律 fail closed（绝不降级为匿名 / 管理员） |
| 数据范围 | 复用既有 ERP-097 `SalespersonDataScopeService`；特权账号（超级管理员 / 系统内置角色 / 显式特权角色）不受限、保留历史访问；未映射业务员的受限账号可见客户为空（fail closed） |
| 客户权威性 | 创建 / 修改：结算客户必须真实存在、未删除且启用（不存在 / 已删除 → 404，停用 → 规则冲突），且在当前账号客户数据范围内（越界 / 无权威归属 → 权限不足）；读取 / 状态变更 / 删除：复核库中已存储客户归属 |
| 金额 | 既有存储精度 `decimal(18,2)`（2 位小数、0.5 进位）：总金额 > 0，海运费 >= 0；散货结算单无币种字段、无来源单据，绝不换算 / 跨币种聚合 / 施加 `total = freight` 公式 / 从文本推断装运或订单来源 |
| 列表范围 | 列表在 **SQL 侧**把客户范围下推到 `Count` 与分页之前，绝不先查全量再内存过滤 |
| 校验时点 | 创建在**生成单号与写入之前**完成授权与校验（失败绝不消耗单号）；修改 / 流转 / 删除在**锁内重新加载后**复核范围 / 状态 / 金额 |
| 并发 | 修改 / 提交 / 审核 / 取消 / 删除都在同一事务内先取**散货结算单行锁**串行化（散货结算单没有上游来源行，无跨表锁序） |
| 删除 | 仅待提交可删，且只置**软删除**标记；绝不物理删除任一历史记录 |
| 边界 | 不新增菜单 / 角色 / 用户授权或表结构；不写库存 / 资金 / 会计，不产生收款 / 付款 / 核销 / 分摊入账 / 流水 |

## 3. 生命周期护栏入口

`FinanceBulkSettlementLifecycleRules`（ERP-387，纯只读判定 + 有界只读查询）提供以下入口：

1. `EnsureMenuAuthorizedAsync(db, userId)`：实时身份 → 账号状态 → 既有 `bulk-settlement` 菜单 → 返回数据范围；
2. `EnsureCustomerInScope(scope, customerId)` / `EnsureAuthorizedAsync`：客户权威性与数据范围 fail closed
   （无权威归属 `<= 0` 与越范围一律拒绝）；
3. `EnsureCustomerAvailableAsync(db, customerId)`：客户存在 / 未删除 / 启用（Id 精确解析，不按文本猜客户）；
4. `EnsureStoredSettlementScopeAllowedAsync(scope, settlement)`：已存储结算单的权威归属（读取 / 状态变更 / 删除之前）；
5. `NormalizeTotalAmount` / `NormalizeCost` / `NormalizeAmounts`：既有存储精度下的金额纯校验；
6. `IsRelationalProvider(db)`：关系型后端判定（内存库跳过行锁语义）；
7. `LockSettlementRowAsync(db, id)`：在调用方事务内对结算单行取排它行锁（技术审计时间戳刷新式 UPDATE）。

特权账号（`AllowedCustomerIds == null`）在上述入口中一律放行 —— 历史单据照常可读可流转，既有行为保持不变。
受限账号把结算单落到范围外客户、或试图读取 / 流转范围外单据，都会在写入前被拒绝。

## 4. 金额语义（无币种字段）

散货结算单实体没有币种字段，因此本护栏**只**按既有存储精度（`decimal(18,2)`，2 位小数、
`MidpointRounding.AwayFromZero`）做正负校验：

- `TotalAmount`：取整后必须 > 0（`0` / 负数 / 取整后为 0 一律 400）；
- `FreightCost`：取整后 >= 0（负数为 400；`-0.001` 取整为 0，不视为负数）；
- 明确**不**校验 `TotalAmount == FreightCost`，也**不**引入任何汇率、折算、跨币种合计或来源推断。

## 5. 路由与校验时点

| 方法 | 路由 | 身份 / 菜单 / 范围 | 其它校验 | 事务 / 锁 |
|---|---|---|---|---|
| GET | `/api/finance/bulk-settlements` | 先校验，再在 SQL 侧范围过滤 + 计数 | 状态 / 关键字过滤 | 只读 |
| GET | `/api/finance/bulk-settlements/{id}` | 先校验 + 已存储客户范围复核 | 未找到 / 已删除 → 404 | 只读 |
| POST | `/api/finance/bulk-settlements` | 先校验 + 请求客户范围 + 真实启用客户 | 金额（>0 / >=0）、客户存在 / 未删除 / 启用 | 关系型：事务内锁内复核客户可用后才生成单号并写入 |
| PUT | `/api/finance/bulk-settlements/{id}` | 先校验 + 请求客户范围 + 真实启用客户 | 仅待提交；金额；锁内复核已存储范围与状态 | 事务 + 散货结算单行锁 |
| POST | `.../{id}/submit` | 先校验 | 待提交 → 已提交；锁内金额复核 | 事务 + 散货结算单行锁 |
| POST | `.../{id}/approve` | 先校验 | 已提交 → 已审核；锁内金额复核 | 事务 + 散货结算单行锁 |
| POST | `.../{id}/cancel` | 先校验 | 置已取消，幂等拒绝重复取消 | 事务 + 散货结算单行锁 |
| DELETE | `/api/finance/bulk-settlements/{id}` | 先校验 | 仅待提交；只置软删除 | 事务 + 散货结算单行锁 |

## 6. 并发与锁序

- 散货结算单**没有上游来源单据**，因此只对散货结算单行取更新锁（`UPDLOCK` / 乐观并发令牌），
  把同单并发的「修改 / 提交 / 审核 / 取消 / 删除」串行化在同一事务内，绝不反向获取其它锁；
- 行锁通过「技术审计时间戳刷新式 UPDATE」实现（`UpdatedAt` 不是商业字段），语义等价于
  `SELECT ... WITH (UPDLOCK, HOLDLOCK)`，随事务提交 / 回滚释放；
- 存在并发乐观令牌过期（`DbUpdateConcurrencyException`）时按规则冲突拒绝本次操作（不产生部分变更），
  由调用方刷新后重试；
- 每个被模拟的请求使用**独立 DbContext / 连接 / 事务**，绝不共享跟踪状态。

## 7. 状态流转

保持既有单据生命周期语义（与基类一致）：

- 提交：`Pending → Submitted`（其它源状态拒绝）；
- 审核：`Submitted → Approved`（其它源状态拒绝）；
- 取消：任意状态 → `Cancelled`，重复取消拒绝；
- 删除：仅 `Pending` 可删，且只做软删除。

失败整体回滚：状态、客户、金额、备注、删除标记与 `UpdatedAt` 审计时间戳一律不变。

## 8. 模块边界

- 不新增菜单 / 角色 / 用户授权或表结构，也不把空身份当作管理员；
- 不写库存 / 库存流水 / 资金 / 会计凭证，不产生收款、付款、核销、分摊入账或对账结论；
- 散货结算单没有币种字段与来源单据，因此不做汇率换算、不跨币种聚合、不推断装运 / 订单来源；
- 散货结算单的商业字段（日期 / 客户 / 金额 / 备注）与删除标记只在既有允许的状态流转下变更，
  绝不物理删除任一历史记录。
