# 代理服务费对账与账龄工作台（ERP-072）

> 任务：`ERP-072`「Add bounded agency fee reconciliation workspace」（依赖 ERP-070 / ERP-071；
> Human Gate L2 `not_required`；`validation_profile: safe`；`completion_mode: browser` 但本阶段浏览器验收按
> `browser_deferred` 延后到 `FINAL-UI-ACCEPTANCE`）。
>
> 定位：在 **ERP-070 的持久化代理服务费对账单证据** 与 **ERP-071 的持久化「客户收款 → 代理服务费对账单」分摊行**
> 之上，新增一个**只读的运营性对账与账龄视图**：按「客户 + 币种」列出
> ①对账单合计证据、②**有效**收款分摊证据、③两者相减的**算术剩余证据**，
> 并按**显式到期日**与**显式 as-of 日期**计算互斥账龄桶（未登记到期日的对账单进入独立的「未知到期日」分组）。
>
> 边界：它**不是**总账或应收账款余额、**不是**经审计的客户对账单或具有法律效力的对账确认、
> **不是**付款通知或催款函、**不是**收款授权与收款执行、**不是**收入确认、
> **不是**税务（销项）申报与开票判断、**不是**结算确认或核销结果，也**不是**任何形式的记账或凭证。
> 本模块**不新增 / 不修改任何表与列**、不做任何回填、**不写库**；不开票、不记账、不核销、不收款或付款、
> 不催收或联系客户、不调用任何外部服务。

## 1. 为什么需要本模块（既有模型审计）

| 既有模型 | 含义 | 是否满足需求 | 结论 |
|---|---|---|---|
| ERP-069 `AgencyServiceFeeAgreements` | 客户代理服务费的**商业条款证据**（费率 / 固定金额 / 生效区间 / 计费依据） | **否**：条款没有对账日期、服务期间、逐笔来源、行金额与合计，也没有收款分摊 | 只作只读身份留痕（协议号 / 协议可用性） |
| ERP-070 `AgencyServiceFeeStatements` / `...Lines` | 对账单**证据**：客户 / 币种 / 对账日期 / 可选到期日 / 服务期间 / 显式来源行 / **服务端合计** | **部分**：有合计与可选到期日，但**没有任何收款级引用**，也没有对账 / 账龄视图 | 本模块的**主证据来源**（只读） |
| ERP-071 `AgencyServiceFeeCollectionAllocations` | 「客户收款 → 代理服务费对账单」的**显式分摊证据**（含作废历史） | **部分**：有分摊金额与两侧快照，但只有台账与两侧汇总，**没有对账剩余证据与账龄** | 本模块的**分摊证据来源**（只读） |
| ERP-053 `CustomerReceiptAllocations` | 「收款单 → 销售订单」收款引用 | **否**：引用对象与金额含义都不同（**另一个证据维度**） | 绝不合并、绝不相加 |
| ERP-055 `CustomerSalesInvoiceAllocations` | 「销项发票 → 销售订单」分摊 | **否**：发票口径，不是服务费对账 | 绝不合并、绝不相加 |
| ERP-068 供应商对账与账龄工作台 | 供应商侧的只读对账与账龄派生 | **否**：供应商 / 采购发票口径 | 只借鉴「只读派生 + 互斥账龄桶 + 未知到期日独立成组 + 固定次数数据集访问」的同一套做法 |

**结论**：客户侧的代理服务费对账与账龄**没有可复用的既有派生**，因此本模块**新增一个只读派生视图**
（应用服务 + 控制器 + 前端页面），**不新增表、不新增列、不加外键、不做回填**，只在读取时组合既有持久化证据。

## 2. 派生口径（服务端权威，接口 / 界面 / 文档同源）

| 数字 | 口径 |
|---|---|
| 对账单合计证据 | ERP-070 持久化 `TotalAmount`（登记时由服务端按已校验行计算并冻结；本模块**不重算、不回写**） |
| **有效**已分摊 | ERP-071 分摊行中**未作废**且**来源仍可确认**的行合计：对账单存在、未删除且**仍为已登记**；快照客户与币种与对账单一致；收款单存在、未删除且**未取消** |
| 算术剩余证据 | 对账单合计 − 有效已分摊（**只有两侧都可确认时才给出**；仅当与源规则矛盾时按「无效证据」显示，**绝不轧为 0、绝不裁剪下限**） |
| 无效 / 无法确认 | 状态「有效」但来源已失效（收款单已删除 / 已取消、对账单已作废或已删除、快照客户 / 币种不一致）的行，以及状态非「有效 / 已作废」的未知状态行：**单独计数与单独成列**，绝不并入有效合计、绝不修复或改派 |
| 已作废历史 | ERP-071 状态「已作废」的行：**保留可见**（原始金额、双方快照、登记与作废留痕），但**永不并入**有效合计 |
| 草稿 / 已作废对账单 | 单独标注，且**排除**在有效对账合计与账龄桶合计之外；默认列表只返回已登记证据 |

**证据维度分离**：本工作台只使用「客户收款 → 代理服务费对账单」这一个维度；
ERP-053 的销售订单收款引用与 ERP-055 的销项发票分摊是另外两个独立维度，**三者绝不相加**，
也绝不被当成几张不同的收款单。

## 3. 账龄分桶（互斥且完整；只对显式到期日计算）

| 桶 | 取自 | 口径 |
|---|---|---|
| `not_due` 未到期 | as-of ≤ 到期日 | 逾期天数 = as-of − 到期日 ≤ 0（含恰好到期当天） |
| `overdue_1_30` | 逾期 1 ~ 30 天 | **边界取含**：30 天归入本桶，31 天起归入下一桶 |
| `overdue_31_60` | 逾期 31 ~ 60 天 | 边界取含 60 |
| `overdue_61_90` | 逾期 61 ~ 90 天 | 边界取含 90 |
| `overdue_over_90` | 逾期 90 天以上 | &gt; 90 天 |
| `unknown_due_date` | **独立分组、不是账龄桶** | 到期日为空 → 账龄**不计算**，绝不按客户账期、协议文字、对账日期或历史对账单推算 |

- as-of 日期是**显式参数**（默认当天，年份 &lt; 1900 直接拒绝并在界面回显）；
- 账龄桶合计只统计**已登记**（有效证据）且**登记了显式到期日**的对账单；
- 到期日区间筛选**只命中登记了到期日的对账单**（未知到期日的对账单既不落区间内、也不落区间外，属口径内行为）。

## 4. 币种隔离（绝无跨币种总额）

- 所有金额（对账单合计 / 有效已分摊 / 算术剩余 / 账龄分桶合计）一律按**原币**分别成行；
- 汇总维度为「客户 × 币种」与「币种」两层，**没有任何把多个币种相加的字段**（报表与币种汇总 DTO 上都没有
  跨币种总额属性，单元测试以反射锁定）；
- 不做汇率换算，也不使用当前或猜测汇率；币种筛选只返回该币种。

## 5. 筛选与分页（全部只用持久化字段）

| 筛选 | 说明 |
|---|---|
| 客户 / 币种 | 客户 Id 精确匹配；币种必须是受支持枚举（非法取值直接拒绝） |
| 对账单身份 / 协议身份 | 精确 `StatementId` / `AgreementId`（正数；非法取值直接拒绝） |
| 服务来源 | 复用 ERP-070 来源白名单（`sales-order` / `loading-list`），命中「至少一条对账单行引用该来源类型」（含软删除过滤） |
| 对账日期区间 | 含当天；起始晚于结束直接拒绝 |
| 显式到期日区间 | 含当天；**只命中登记了到期日的对账单** |
| 对账单状态 | `recorded`（默认）/ `draft` / `voided` / `all` |
| 分配状态 | `none` / `historical_only` / `partial` / `full`（数据集侧聚合比较，只用持久化行判定） |
| 关键字 | 对账单号 / 客户编码 / 客户名称 / 协议号 / 备注；长度 ≤ 100（超长拒绝） |
| 分页 | 页码从 1 开始；单页 1 ~ 200（超限截断），稳定排序：客户 → 币种 → 到期日（未知在前）→ 对账日期（倒序）→ 对账单 Id（倒序） |

**汇总范围**：分组汇总、账龄桶与币种汇总都只统计**本次返回页**的对账单；`total` 为符合筛选条件的未删除对账单总数。

## 6. 有界读取（固定次数数据集访问，无逐行查库）

本页对账单**非空**时固定 **8 次**数据集访问（与对账单张数与行数无关）：

1. 对账单数据集（筛选 + 计数 + 分页共用 1 次查询）；
2. 本页对账单实体一次批量装载；
3. 本页分摊行**按状态聚合**（张数 / 金额，含已作废与无效）；
4. 本页**有效**分摊聚合（张数 / 金额，资格在数据集侧判定）；
5. 本页有效分摊的（对账单, 收款单）组合（去重计数；单侧有效行 ≤ 50 故有界）；
6. 本页客户一次批量装载；
7. 本页关联协议一次批量装载；
8. 本页服务来源行（按类型计数与有界身份清单）。

**展示清单有界 = 合计仍然精确**：来源身份清单每行最多 5 条（超出只给计数并显式标注「计数完整」）；
明细页分摊行清单最多 100 条（超出标记 `AllocationsTruncated`），
但**金额与计数一律来自数据集侧聚合**，因此展示截断**不会**产生部分合计。

## 7. 明细授权（fail closed）

打开单张对账单明细（`GET /api/agency-service-fee-reconciliation/statements/{statementId}/detail`）时：

1. **重新校验登录身份**（未认证 → `2000` 未认证错误）；
2. **重新校验既有「角色 → 菜单」模块授权**（`SysUserRoles` → `SysRoleMenus` → `SysMenus.MenuCode`，
   忽略按钮型菜单与被删除角色 / 菜单；本轮要求既有菜单码 `customer`「客户资料」，**不新增菜单或权限模型**）；
   无该授权 → `2002` 权限不足；每次请求都重新查询，因此撤销授权后立即收敛；
3. **重新读取权威来源**：对账单必须存在且未删除，否则 `1002` 不存在；
4. 任何一种拒绝都**不返回任何证据、不返回部分金额**，也不做来源修复或改派；
5. 返回行与列表行**完全同源**（同一派生方法），界面在列表与明细之间不会出现两套口径。

## 8. 非变更边界（本模块不改写什么、不做什么）

- **只读**：不新增 / 不修改任何表与列、不迁移、不回填、**不写库**（服务源码中没有任何 `SaveChanges` 或写库调用，
  单元测试以源码断言锁定）；控制器只有 `[HttpGet]`，没有任何写入口；
- **不改写**：ERP-070 对账单证据（含合计 / 到期日 / 服务期间 / 状态 / 行清单 / 登记与作废留痕）、
  ERP-071 分摊行（含状态 / 金额 / 快照 / 作废原因）、客户收款单（含状态 / 金额 / 币种 / 付款方式 / 银行账户）、
  ERP-069 协议证据、客户主数据（含账期 / 信用）、销售订单、装柜与装柜清单、单证中心、客户销项发票证据、
  ERP-053 收款引用行、ERP-055 发票分摊、库存与库存成本、库存流水、费用与分摊、退税、结算与余额记录；
- **不做**：不开票 / 不作废发票、不记账或生成凭证、不核销、不收款或付款、不催收或联系客户、
  不判断是否欠款 / 是否逾期已确认 / 是否已结清、不产生任何结算或余额记录、不调用任何外部服务；
- 客户停用 / 删除、协议作废 / 删除、收款单取消 / 删除后，**历史快照照常可读**并显式标注不可用，
  系统**不回填、不修复、不改派、不合并**；
- 已删除对账单不进入本工作台列表（其分摊证据仍可在 ERP-071 登记册中按原口径查看）；
  本模块**不做任何生产回填**、也不「修复」历史数据。

## 10. 导出（与屏幕完全同源）

前端 CSV 导出（`exportAgencyServiceFeeReconciliationCsv`）使用**同一份筛选与同一分页结果**：

- 分三段：账龄分桶（按币种）/ 未知到期日独立分组 / 对账单级证据（按客户 + 币种）；
- **不含任何跨币种总额**，也不写「应收 / 欠款 / 逾期确认 / 已对账」等法律或账务断言；
- 到期日未知显式写「未知」，剩余证据无效显式写「无效证据」，与屏幕逐字一致。
