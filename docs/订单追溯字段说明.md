# 销售订单 / 采购订单追溯字段说明（ERP-008）

> 任务：`ERP-008` 完整化销售订单与采购订单追溯（外销合同 + 来源单据 + 采购执行）。
> 范围：`src/ERP.Domain`、`src/ERP.Application`、`src/ERP.Infrastructure`、`src/ERP.Api`、`src/ERP.UnitTests`、`src/ERP.IntegrationTests`。
> 不改动任何 SQL 脚本、`deploy/**`、`release/**`、`checkpoints/**`、`SeedData*.cs`；生产库、生产 OSS、正式部署与不可逆数据操作仍由 Human Gate 控制。

## 1. 背景与结论

ERP-006 审计把「销售订单（外销合同）」「采购订单」判为 **partial**：字段与页面都缺少外贸合同、来源追溯与采购执行所需的列，且采购单无法归属客户 / 销售订单（代理出口无法核算单客户毛利）。

ERP-008 的落地口径：

1. **销售订单与采购订单统一由 EF 主子表承载**（`db_owner.SalesOrders` / `db_owner.PurchaseOrders`，与报表 `ReportService` 读取的表一致），不再从菜单进入存储过程版单据页（`sp_Biz_SalesOrder` / `sp_Biz_PurchaseOrder` 的 `BILL_CONFIG` 页仍保留定义，供历史数据排查与回滚参考）——这样新增列不需要 `DROP/CREATE` 生产存储过程。
2. **新列一律带安全默认值**（空串 / 0 / 0 位），历史单据可正常打开、列表与打印不受影响。
3. **结构升级幂等**：`SchemaUpgrader.EnsureUpgradedAsync` 第 22 段以 `OBJECT_ID + COL_LENGTH` 双保险补齐缺列，表不存在时不会中断服务启动。

## 4. 页面与打印 / 导出

- 「订单管理 → 销售订单」「订单管理 → 采购订单」由 `modules-doc.js` 的模块配置驱动 `crud.js` 主子表页面：客户 / 供应商 / 业务员为**引用字段**（可搜索选择），币种 / 价格条款 / 出口方式 / 业务性质 / 是否含税 / 到货与结算进度为**下拉选择**，多行文本字段（Consignee / Notify / 唛头 / 验货 / 包装要求）为 textarea；明细行「数量 × 单价 = 金额」自动计算并汇总。
- 行操作「打印预览」经 `sales-pi.js` 的 `SALES_DOC_PRINT` 配置渲染单据，新增字段与唛头 / 验货 / 包装要求区块一并输出；打印模板类型沿用 `sales-order` / `purchase-order`（打印设计页可用）。
- 「订单管理 → 销售订单导出 / 采购订单导出」菜单改调 EF 的 `export-excel`，状态筛选口径为订单状态（待提交 / 已提交 / 已审核 / 已取消），导出列包含全部新增字段。
- **来源单据带入（ERP-010）**：报价单 / PI 列表的「更多」菜单提供两个动作——「带入预填销售订单」（按来源单据打开销售订单新增表单，字段与明细已带入，可继续编辑，保存走 `/api/sales-orders`）与「转销售订单」（服务端一次生成，来源自动留痕）。带入后 `来源报价单 ID / 号`、`来源 PI ID / 号` 字段会随表单提交写入，重新打开该订单即可看到追溯链。
- **比价选中行带入采购订单（ERP-020）**：「供应商与采购 → 供应商比价」列表中**状态为「已选中」**的行会在「更多」菜单显示「生成采购订单」与「预填采购订单」两个动作（未选中 / 已放弃行不显示，服务端仍二次校验）。「预填」切到采购订单页并打开已带入的新增表单（不落库、不占用单据号），保存走 `/api/purchase-orders`；「生成」由服务端一次落库，并在比价行留下来源痕迹：状态置 `已转采购订单`、`RefOrderNo` 写回生成的采购单号，采购订单备注追加 `来源比价 <比价批次号>（比价行 #<Id>）`。

| `OrderDate` | — | 生成当天 |
| `SupplierId` | `SupplierId` | **必填**：比价行未维护供应商时拒绝转换 |
| `Currency` | `Currency` | 币种文本按枚举名不区分大小写解析（`USD`/`usd` 均可），无法识别回退 `CNY` |

| `DeliveryDate` / `SupplierConfirmedDate` | `DeliveryDays` | 今天 + 交期天数（`DeliveryDays ≤ 0` 时两者留空；比价交期本身即供应商承诺，故回签交期同口径） |

### 4.2 采购执行进度派生（ERP-026）

采购订单列表行操作新增「执行进度」（`modules-doc.js` → `purchase-order-progress.js`），调用 `GET /api/purchase-orders/{id}/progress`（`PurchaseOrderProgress.ForPurchaseOrderAsync`）。该接口**只读派生**：不落库、不改单据状态、不新增或修改任何表列；界面把「派生值」与「人工登记值」并列展示，二者互不覆盖。同一页面的「执行时间线」由 ERP-022 提供（`GET /api/purchase-orders/{id}/timeline`）。

**收货数量（`StockIn` + `StockInDetail`，来源引用 `StockIn.PurchaseOrderId`）**

| 输出 | 口径 |
|---|---|
| `orderedQuantity` | 采购订单未删除明细的数量合计 |
| `receivedQuantity` | 以本单为来源、未删除、**状态 = 已审核**的入库明细数量合计（ERP-023 起入库明细已折算基础单位，与订单明细同口径比较） |
| `pendingQuantity` | 同口径但状态为**待提交 / 已提交**（未审核，单列、不计入已收） |
| `outstandingQuantity` | Σ 订单行未收数量 = Σ max(0, 订单数量 − 已冲抵已收数量) |
| `matchedReceivedQuantity` / `unmatchedReceivedQuantity` | 已冲抵订单明细的已收数量（含超收）/ 订单外商品（订单明细中不存在该商品）的已收数量；两者之和 = `receivedQuantity` |
| 行 `overReceivedQuantity` | 订单行超收部分；同一商品多行时由该商品的**最后一行**吸收剩余数量 |
| `receiptStatus` | `none` / `partial` / `complete` / `over_received`（整体与逐行同一词表） |

- **不计入已收**：已驳回 / 已取消入库单、软删除入库单、以其它采购订单为来源的入库单；采购退货与库存调整单不冲减已收数量（另行核算）。
- `arrivalProgressConsistent`：把人工登记的到货进度（未到货 / 部分到货 / 已到货）与派生状态比对；文本为空或不在词表内时为 `null`（无法判定），不猜测、不改写字段。
- 结果同时列出收货来源入库单引用（单号 / 日期 / 状态 / 数量 / 是否计入），便于逐单核对。

**结算金额（只在既有引用可用时暴露）**

- 既有结构中**不存在**「采购订单 ↔ 付款单」的直接引用：`FinancePayment` 只记录供应商（另有可空 `PaymentApplyId`），`FinancePaymentApply` 只引用销售订单。因此只有下面这条链完整且唯一时才算「引用可用」：
  `FinancePayment.SupplierId = 本单供应商` 且 `FinancePayment.PaymentApplyId → FinancePaymentApply.SalesOrderId = 本单归属销售订单 Id`，且该归属销售订单下**只有本单一张未删除采购订单**。
- `linkStatus = linked` 时才给出金额：`settledAmount`（已审核且**币种与本单一致**的付款单合计）、`outstandingAmount`（= 订单总额 − 已结算，最小 0）、`submittedAmount`（已提交 / 待提交，同口径）；`overSettled` 标记超付。引用成立但找不到货款申请单时，已结算按 0、未结算按订单总额返回（引用成立，不是猜测）。
- `linkStatus = ambiguous`：归属销售订单下存在多张采购订单，付款单无法唯一归属到本单 → 金额一律 `null`。
- `linkStatus = unavailable`：本单未关联归属销售订单，或未维护供应商 → 金额一律 `null`，`linkReason` 说明缺什么。
- 币种不一致的付款单只列出（`counted = false`）且**不做汇率换算**；供应商不符、未引用货款申请单的付款单不列入；**按供应商汇总、或按备注 / 事由文本匹配都不作为本单结算依据**。`null` 表示未知，界面显示「未知」，绝不显示为 0。
- `recordedProgress` 原样回显订单已落库的结算进度文本（人工维护的字段），派生结果不写回该字段。

**查询有界**：固定 1 次订单（含明细）+ 1 次入库主表 + 1 次入库明细 + 1 次归属销售订单下采购订单计数 + 1 次货款申请单 + 1 次付款单，各集合按 200 条上限截断，无 N+1，与订单 / 单据数量无关。

## 5. 校验规则

- 销售订单：`CommissionRatio` 必须在 0~100（越界抛 `InvalidParameter`，事务内不落库）。
- 采购订单：`TaxRate` 必须在 0~100。
- 比价 → 采购订单资格（ERP-020，服务端唯一权威）：`IsSelected = true` 且状态不为 `已放弃` / `已转采购订单`，供应商必须已维护，需求数量必须 > 0、报价单价不得为负；违反时分别抛出 `RuleConflict` / `InvalidParameter`，且**不落库、不改来源单据**。
- 比价 → 采购订单重复守卫（两道，全部只读既有列、不新增结构）：① 比价行 `RefOrderNo` 指向的未删除采购订单（人工把状态改回「已选中」也不会重复生成）；② 采购订单备注中的来源标记（防止人工清空 `RefOrderNo` 后再次生成）。生成过的采购订单被软删除后允许重新生成（与「报价单 / PI 转销售订单」同一口径）。
- 定金比例沿用既有口径（总额 × 比例），明细金额与订单总额、定金由服务端重算。
