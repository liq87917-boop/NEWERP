# 销售订单 / 采购订单追溯字段说明（ERP-008）

> 任务：`ERP-008` 完整化销售订单与采购订单追溯（外销合同 + 来源单据 + 采购执行）。
> 范围：`src/ERP.Domain`、`src/ERP.Application`、`src/ERP.Infrastructure`、`src/ERP.Api`、`src/ERP.UnitTests`、`src/ERP.IntegrationTests`。
> 不改动任何 SQL 脚本、`deploy/**`、`release/**`、`checkpoints/**`、`SeedData*.cs`；生产库、生产 OSS、正式部署与不可逆数据操作仍由 Human Gate 控制。

## 1. 背景与结论

ERP-006 审计把「销售订单（外销合同）」「采购订单」判为 **partial**：字段与页面都缺少外贸合同、来源追溯与采购执行所需的列，且采购单无法归属客户 / 销售订单（代理出口无法核算单客户毛利）。

ERP-008 的落地口径：

1. **销售订单与采购订单统一由 EF 主子表承载**（`db_owner.SalesOrders` / `db_owner.PurchaseOrders`，与报表 `ReportService` 读取的表一致），不再从菜单进入存储过程版单据页（`sp_Biz_SalesOrder` / `sp_Biz_PurchaseOrder` 的 `BILL_CONFIG` 页仍保留定义，供历史数据排查与回滚参考）——这样新增列不需要 `DROP/CREATE` 生产存储过程。
2. **新列一律带安全默认值**（空串 / 0 / 0 位），历史单据可正常打开、列表与打印不受影响。
3. **结构升级幂等**：`SchemaUpgrader.EnsureUpgradedAsync` 第 22 段以 `OBJECT_ID + COL_LENGTH` 双保险补齐缺列，表不存在时不会中断服务启动。

## 2. 字段清单

### 2.1 销售订单 `SalesOrder`（外销合同与来源追溯）

| 字段 | 类型 | 说明 |
|---|---|---|
| `CustomerPoNo` | string(50) | 客户 PO 号（买方订单号，对账与报关核对） |
| `ContractNo` | string(50) | 外销合同号 |
| `TradeTerms` | string(50) | 价格条款 / 贸易术语（FOB / CIF / CFR / EXW / DDP…） |
| `DestinationPort` | string(100) | 目的港文本（与 `PortId` 港口字典并存，便于合同与提单直接打印） |
| `Consignee` | string(300) | 收货人（提单用） |
| `NotifyParty` | string(300) | 通知人（提单用） |
| `ShippingMarks` | string(500) | 唛头 Shipping Marks（多行） |
| `SourceQuotationId` / `SourceQuotationNo` | long? / string(50) | 来源报价单（报价单 → 销售订单追溯） |
| `SourcePiId` / `SourcePiNo` | long? / string(50) | 来源形式发票 PI（PI → 销售订单追溯） |
| `ExportMode` | string(20) | 出口方式（0110 一般贸易 / 1039 市场采购 / 9610 跨境电商 / 9710 B2B） |
| `CommissionRatio` | decimal(18,4) | 佣金 / 回佣比例（%，校验 0~100） |
| `BusinessNature` | string(20) | 业务性质（自营出口 / 代理出口 / 内销） |
| `SplitShipment` | bit | 是否分批出货 |
| `InspectionRequirement` | string(500) | 验货要求（SGS / 客户验货 / 免验） |
| `PackagingRequirement` | string(500) | 包装要求（如 12 pcs/箱 彩盒） |

### 2.2 采购订单 `PurchaseOrder`（归属与采购执行）

| 字段 | 类型 | 说明 |
|---|---|---|
| `OwningCustomerId` / `OwningCustomerName` | long? / string(200) | 归属客户（代理出口按客户核算毛利） |
| `OwningSalesOrderId` / `OwningSalesOrderNo` | long? / string(50) | 归属销售订单 |
| `AdvanceOnBehalf` | bit | 是否代垫货款 |
| `SupplierConfirmedDate` | datetime2? | 供应商确认交期（区别于订单要求的交货日期） |
| `TaxRate` | decimal(18,4) | 税率（%，校验 0~100） |
| `TaxIncluded` | bit | 单价是否含税 |
| `ArrivalProgress` | string(50) | 到货进度（未到货 / 部分到货 / 已到货） |
| `QcStatus` | string(30) | 验货状态（未验货 / 验货中 / 合格 / 不合格 / 免验） |
| `ContractNo` | string(50) | 采购合同号 |
| `SettlementProgress` | string(50) | 结算进度（未结算 / 部分结算 / 已结算） |

## 3. 接口（`SalesOrderController` / `PurchaseOrderController`）

| 方法 | 路由 | 说明 |
|---|---|---|
| GET | `/api/sales-orders?keyword=&status=` | 列表；关键字匹配 **订单号 / 客户 PO 号 / 合同号** |
| GET | `/api/sales-orders/{id}` | 详情（含明细） |
| POST/PUT | `/api/sales-orders[/{id}]` | 新增 / 修改（待提交状态可改；金额与定金由后端重算） |
| GET | `/api/sales-orders/{id}/print` | 打印数据（主表 + 明细，供打印预览 / 批量打印） |
| GET | `/api/sales-orders/export-excel` | Excel 导出（列含全部新增字段） |
| GET | `/api/purchase-orders?keyword=&status=` | 列表；关键字匹配 **采购单号 / 合同号 / 归属销售订单号** |
| GET | `/api/purchase-orders/{id}` `/print` `/export-excel` | 详情 / 打印 / Excel 导出（同理） |

## 4. 页面与打印 / 导出

- 「订单管理 → 销售订单」「订单管理 → 采购订单」由 `modules-doc.js` 的模块配置驱动 `crud.js` 主子表页面：客户 / 供应商 / 业务员为**引用字段**（可搜索选择），币种 / 价格条款 / 出口方式 / 业务性质 / 是否含税 / 到货与结算进度为**下拉选择**，多行文本字段（Consignee / Notify / 唛头 / 验货 / 包装要求）为 textarea；明细行「数量 × 单价 = 金额」自动计算并汇总。
- 行操作「打印预览」经 `sales-pi.js` 的 `SALES_DOC_PRINT` 配置渲染单据，新增字段与唛头 / 验货 / 包装要求区块一并输出；打印模板类型沿用 `sales-order` / `purchase-order`（打印设计页可用）。
- 「订单管理 → 销售订单导出 / 采购订单导出」菜单改调 EF 的 `export-excel`，状态筛选口径为订单状态（待提交 / 已提交 / 已审核 / 已取消），导出列包含全部新增字段。

## 5. 校验规则

- 销售订单：`CommissionRatio` 必须在 0~100（越界抛 `InvalidParameter`，事务内不落库）。
- 采购订单：`TaxRate` 必须在 0~100。
- 定金比例沿用既有口径（总额 × 比例），明细金额与订单总额、定金由服务端重算。

## 6. 测试

- 单元测试（safe 档，`ERP.UnitTests`，新增 `OrderTraceabilityTests`）：新字段创建 / 回读 / 修改 / 清空、历史单据安全默认值、关键字检索命中新列、打印数据、Excel 导出字节流、越界校验、以及前端报文（布尔 + 枚举名）反序列化契约。
- 真实浏览器验收（`ERP.IntegrationTests`，`Collection=UiTests`，Microsoft Edge，新增 `OrderTraceabilityUiTests`）：销售订单在页面填写外贸合同 / 来源追溯字段与明细后保存 → 重新打开核对回显 → 打印预览含新字段 → Excel 导出可用；采购订单关联归属客户与归属销售订单、填写采购执行与结算字段后保存 → 重新打开核对 → 打印预览可用；订单列表渲染新增追溯列、导出菜单为订单状态口径，且全流程无 JS / 接口失败（截图证据 10 张，含每张单据的保存 / 重开 / 打印 / 导出）。

## 7. 边界与未做项

- **持久化前提**：订单表沿用 EF 模型生成的 `db_owner.SalesOrders` / `db_owner.PurchaseOrders`（本应用任何一次由 `EnsureCreated` 初始化的库都具备；`SchemaUpgrader` 第 22 段用 `OBJECT_ID` 守卫，表缺失时只跳过补列、不中断启动）。如遇从未由本应用初始化过的库，需要先按既有交付方式初始化 EF 表结构（`EnsureCreated` 或部署文档「方式二：EF Core 迁移脚本」）。
- 未执行任何生产 / 业务库操作，未执行 SQL 脚本、seed、部署；`deploy/**`、`release/**`、`checkpoints/**`、`logs/**`、SQL 文件、`SeedData*.cs` 均未改动。
- 存储过程版订单页（`sp_Biz_SalesOrder` / `sp_Biz_PurchaseOrder` + `BILL_CONFIG`）不再从菜单进入，历史 SP 表数据不迁移（如需迁移应另开受门禁的数据库变更任务）。
- 仍未实现（属后续任务范围）：订单变更申请、订单执行跟踪时间轴、附件、报价 / PI「一键生成销售订单」（本次仅提供来源报价 / PI 字段与追溯）、采购订单与比价 `PurchaseQuote.IsSelected` 的下游联动。
- 打印与导出中的 `supplierId` 等引用字段仍按 ID 输出（本次未引入名称冗余列）；如需打印名称可后续补 `SupplierName` 冗余列。
