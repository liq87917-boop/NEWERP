# 库存单据与库存成本说明（ERP-009）

> 任务：`ERP-009` 实现库存动作单据（盘点/调整、调拨、销售退货、采购退货）与库存成本基础。
> 范围：`src/ERP.Domain`、`src/ERP.Application`、`src/ERP.Infrastructure`、`src/ERP.Api`、`src/ERP.UnitTests`、`src/ERP.IntegrationTests`、`docs/**`、`.ai/**`。
> 不新增 / 不执行任何 SQL 脚本、不改 `deploy/**`、`release/**`、`checkpoints/**`、`logs/**`、`SeedData*.cs`；生产库、生产 OSS、正式部署与不可逆数据操作仍由 Human Gate 控制（本轮仅由 orchestrator 的真实 Edge 门禁在测试库验证）。

## 1. 背景与结论

ERP-006 审计把「库存动作单据（盘点/调拨/退货）+ 库存成本」判为 **missing**：`Stocks` 只有数量维度，单据只有采购入库 / 销售出库，且既有入库/出库审核只做数量增减、没有任何可审计的移动记录与成本口径。

ERP-009 的落地口径：

1. **四类单据全部由 EF 主子表承载**（`db_owner.StockAdjustments`、`db_owner.StockTransfers`、`db_owner.SalesReturns`、`db_owner.PurchaseReturns` 各自 + `...Details`），沿用报价单 / PI / 订单的既有约定（字轨编号、提交 → 审核、明细整体替换、后端复核合计）。
2. **每一次库存变动都必须有可审计的库存流水**（`db_owner.StockMovements`）：一笔记录 = 一个仓库 + 一个商品的单向变动，持久化成本单价 / 金额 / 移动后结存快照。
3. **销审 = 冲销，不删历史**：原流水标记 `IsReversed`，追加一条 `IsReversal` 红字流水（`ReversalOfMovementId` 指回原流水），库存按原金额还原；不安全的状态（库存已被后续业务占用）直接拒绝销审。
4. **成本口径为移动加权平均法**（moving weighted average），成本基准持久化，估价可逐笔核对：`Stocks.TotalCost` = Σ 流水金额，`Stocks.AverageCost` = `TotalCost / Quantity`。
5. **结构升级幂等**：`SchemaUpgrader.EnsureUpgradedAsync` 第 23 段以 `OBJECT_ID`（建表）+ `COL_LENGTH`（补列）双保险补齐，任一步可重复执行，表缺失时不会中断服务启动。

### 2.2 库存流水 `StockMovement`

| 字段 | 类型 | 说明 |
|---|---|---|
| `MovementDate` / `MovementType` | datetime2 / `InventoryMovementType` | 移动日期与类型（PurchaseIn / SalesOut / Adjustment / TransferOut / TransferIn / SalesReturn / PurchaseReturn） |
| `SourceDocType` / `SourceDocId` / `SourceDocNo` | string(50) / long / string(50) | 来源单据（实体名 + Id + 单号），按单据即可追溯全部流水 |

| `ProductId` / `ProductCode` / `ProductName` / `Spec` / `Unit` | long? / string | 商品信息（按商品 Id 补齐，前端只填名称时也完整） |
| `Direction` / `Quantity` | int / decimal(18,4) | 方向（1 入库 / -1 出库）与数量（恒为正数） |
| `UnitCost` / `Amount` | decimal(18,6) / decimal(18,4) | **成本基准**：本次移动单价与带符号金额（= 方向 × 数量 × 单价） |
| `BalanceQuantity` / `BalanceAmount` / `BalanceAverageCost` | decimal | 移动后结存数量 / 金额 / 加权平均成本快照 |
| `IsReversal` / `ReversalOfMovementId` / `IsReversed` | bit / long? / bit | 红字冲销标记、被冲销的原流水、原流水是否已被冲销 |

### 2.3 库存表成本列（`Stocks` 幂等补列）

| 列 | 类型 | 说明 |
|---|---|---|
| `AverageCost` | decimal(18,6) | 移动加权平均成本单价（历史数据默认 0，不影响既有功能） |
| `TotalCost` | decimal(18,4) | 库存金额（= 数量 × 加权平均成本，出库按该金额核减） |

> 小数位在 EF 模型中用 `HasPrecision` 显式声明（成本 6 位、数量与金额 4 位），与 `SchemaUpgrader` 第 23 段建表脚本一致，避免空库首次 `EnsureCreated` 按默认 `decimal(18,2)` 截断成本。

## 3. 库存成本口径（`InventoryService`，`src/ERP.Application/Services/InventoryService.cs`）

| 场景 | 规则 |
|---|---|
| 入库（调拨入库 / 退货入库 / 盘盈） | `TotalCost += 数量 × 成本单价`；`Quantity += 数量`；`AverageCost = TotalCost / Quantity`（数量为 0 时金额与均价一并归零） |
| 出库（调拨出库 / 采购退货 / 盘亏） | 成本单价缺省取**当前加权平均成本**；`Quantity < 需要数量` 时抛 `RuleConflict`（不落半截流水）；**成本下限保护**：出库成本不得超过该库存行账面金额，出库清零时按账面余额一次性核减，实际核减金额再折算回单价，保证流水金额恒等于库存金额变动（`Σ 流水金额 = Stocks.TotalCost`，账实可核对） |
| 调拨 | 以「调出流水」的成本单价作为「调入流水」的成本单价，因此**调出金额 = 调入金额**、两仓数量与金额双向守恒 |
| 退货成本优先级 | 明细指定 `UnitCost` → 来源单据流水成本（销售退货取来源出库流水、采购退货取来源入库流水）→ 当前加权平均成本 |
| 销审冲销 | 出库流水冲销按原金额加回库存；入库流水冲销按原金额从库存扣除，**数量不足或账面金额不足均拒绝销审**（不出现负库存、不出现负库存金额，`Σ 流水金额 = Stocks.TotalCost` 不被破坏），随后重算均价 |
| 取整 | 金额 4 位小数、成本单价 6 位小数（`MidpointRounding.AwayFromZero`），同一份单据重复计算得到相同结果 |
| 库存行唯一性 | 同一次工作单元（如同一张单据的多行明细）按「仓库 + 商品」复用同一行库存：新建行在 `SaveChanges` 之前先从 EF 变更跟踪器（`Stocks.Local`）复用，避免同仓同商品插入重复库存行、结存快照断裂与「单行库存不足」误判 |

## 4. 接口（`src/ERP.Api/Controllers`）

### 4.1 既有采购入库 / 销售出库的基础单位口径（ERP-023）

- `Stocks.Quantity` 与 `AvailableQuantity` 始终按商品 `BaseProduct.Unit`（基础单位）记账。
- 当入出库明细 `Unit` 等于商品 `PackageUnit` 且两者不同，保存前将 `Quantity × UnitsPerPackage`，并把明细单位改写为基础单位；因此审核、库存不足校验和取消冲回读取的是同一份持久化基础数量，不会二次换算。
- 未配置 `PackageUnit` 的商品、明细已使用基础单位、或历史未知单位均保持原数量，兼容既有数据。
- 明细明确使用 `PackageUnit` 时，`UnitsPerPackage <= 0` 或基础单位为空视为无效元数据并拒绝保存；不允许以错误换算因子静默记账。
- 已审核入库取消前会校验剩余库存是否足够冲回；已审核出库取消则按原基础数量恢复。未审核单据取消不改库存。
- **ERP-025 起**：审核与取消改为统一经 `InventoryService` 记账（见 §9），数量与金额口径不变，取消语义由「原路改库存」升级为「按库存流水生成红字冲销」（无流水可冲销的历史单据仍按原基础数量兜底冲回 / 恢复）。

状态流转规则（四类单据一致）：

- `Pending --提交--> Submitted --审核--> Approved --销审--> Pending`；
- **仅已提交可审核**、**仅已审核可销审**、**仅待提交可修改 / 删除**；已审核不能取消（先销审）；
- 审核带**幂等护栏**：若该单据已存在有效流水（未冲销、非红字），重复审核直接拒绝，保证「已审核单据改库存恰好一次」。

## 9. ERP-025：采购入库 / 销售出库接入库存流水（2026-09-24）

> 任务：`ERP-025`「Record legacy stock in and out in movement ledger」，关闭 ERP-009 遗留的审计缺口：既有采购入库 / 销售出库审核只改 `Stocks`，不写 `StockMovements`，导致这两条最常用的库存路径不可追溯、库存金额也与「移动加权平均」口径脱节。
> 范围：`src/ERP.Api/Controllers`（`StockInController` / `StockOutController`）、`src/ERP.UnitTests`、`docs/**`、`.ai/**`；**不新增 / 不修改任何数据库结构**，未触碰 `SchemaUpgrader.cs`、SQL 脚本、存储过程、`deploy/**`、`release/**`、`appsettings*`。

### 9.1 做法

| 环节 | 口径 |
|---|---|
| 审核（采购入库） | `IncreaseAsync` + `InventoryMovementType.PurchaseIn`，`SourceDocType = StockIn`（单号 / Id / 仓库 / 商品随流水冗余落库），数量取明细**已换算的基础单位数量** |
| 审核（销售出库） | `DecreaseAsync` + `InventoryMovementType.SalesOut`，`SourceDocType = StockOut`，库存不足时由服务抛 `RuleConflict`（**整单不落半截数据**） |
| 幂等护栏 | 审核前 `CountActiveMovementsAsync > 0` 直接拒绝「已产生库存流水，不能重复审核」；单据状态护栏（仅已提交可审核）仍然生效，两层叠加保证「已审核单据恰好改一次库存」 |
| 取消（已审核） | `ReverseAsync`：原流水置 `IsReversed`、追加 `IsReversal` 红字流水（`ReversalOfMovementId` 指回原流水），库存数量与**库存金额**按原流水精确还原；重复取消被「已取消」拒绝 |
| 历史单据兜底 | 本次改造前审核、没有流水的单据：流水冲销返回 0 条时退化为按明细基础单位原路冲回 / 恢复，既不重复改库存，也不改写库存金额 |
| 明细守卫 | 零数量明细（旧版页面允许留空行）不产生库存变动；负数数量按数据错误拒绝（`InvalidParameter`） |
| 流水备注 | 采购入库「采购入库单审核入库（采购订单 Id N）」、销售出库「销售出库单审核出库（销售订单 Id N）」，便于按流水反查订单执行 |

### 9.2 成本口径与已知限制

- 入库明细（`StockInDetail`）与出库明细（`StockOutDetail`）都**没有成本列**，因此成本单价由 `InventoryService` 既有兜底口径决定：入库缺省取当前加权平均成本（首次入库为 0，不臆造采购成本），出库按移动加权平均成本核减并受「成本下限保护」约束。
- 采购订单价格按**包装单位**计价，直接套用会算错基础单位成本（需先按 `UnitsPerPackage` 折算），故本任务**不**从采购订单带入成本；如后续需要采购成本口径，应另立任务并同时定义包装单位折算规则。
- 效果：采购入库增加数量的同时按均价增加库存金额、销售出库按均价核减库存金额，`Stocks.AverageCost` 不再被单边变动拉偏，`Σ 流水金额 = Stocks.TotalCost` 的核对关系对「出入库 + 盘点/调拨/退货」全路径成立（库存行的历史基准金额除外）。
