# 销售交期异常工作台说明（ERP-102）

## 1. 定位

销售订单页新增一个**只读派生**的「销售交期异常」工作台，用既有的订单头交货日期（`SalesOrder.DeliveryDate`）、
明细行交货日期（`SalesOrderDetail.DeliveryDate`，**明细行优先**）与「以本单为来源、未删除、已审核」的
销售出库出货证据（复用 ERP-032），按一个显式的 **as-of 基准日**派生每张订单的交期状态，
帮助运营一眼看出哪些订单逾期、即将到期、已出齐或交期未知。

> **边界（重要）**：本工作台是销售订单的**运营交期视图**，不是排产系统、不是催货 / 交期承诺系统。
> 它不写任何表、不执行迁移 / 生产 SQL / 真实数据库操作 / 部署，也**不改写**订单状态与任何已登记进度
> （出货与收款进度、状态等）。缺日期或出货证据不完整一律按「未知」呈现，绝不当作 0 或正常。

## 2. 接口

- `GET /api/sales-orders/delivery-exceptions?customerId=&asOfDate=&keyword=&page=&pageSize=`
  - 有界分页（`pageSize` 1~200，默认 50），稳定排序（客户 → 订单日期 → 单据 Id）。
  - `asOfDate` 为显式基准日，缺省今天；用于判定「已过 / 临近 / 未到」，不用于过滤订单日期。
  - `customerId` / `keyword`（订单号 / 外销合同号 / 客户 PO 号）可选筛选。
  - 固定次数数据集访问（无逐单查库）；出货数量复用 ERP-032 的同一套权威批量派生。

## 3. 交期状态口径（后端、前端与测试同源）

| 状态值 | 含义 | 判定 |
| --- | --- | --- |
| `fulfilled` | 已出齐 | 已审核且未删除的出库已覆盖订单数量（未出数量为 0；含超发） |
| `overdue` | 逾期 | 交期（明细行交期优先，缺省回落订单头交期）已过 as-of 且未出齐 |
| `due_soon` | 即将到期 | 交期落在 as-of 后 7 天内（含当天与第 7 天）且未出齐 |
| `on_schedule` | 在途正常 | 交期未到、未出齐但尚未进入异常窗口 |
| `unknown` | 未知 | 订单头与明细交期都缺失，或出货证据超过单次派生上限 |

判定顺序固定：**出货证据不完整未知 → 已出齐 → 缺日期未知 → 逾期 / 即将到期 / 在途**。
部分出货（`partial`）仍视为未出齐、继续按日期判定；超发（`over_shipped`）未出数量为 0，视为已出齐。

## 4. 交期与出货证据口径

- **交期判定**：明细行交期优先——有任意明细行交期时取**最早明细交期**作为判定交期；无明细交期时回落订单头交期；
  两者都缺则为未知。
- **出货证据**：复用 ERP-032，已出数量只统计「`StockOut.SalesOrderId` 指向本单、主表未删除、明细未删除、且
  `Status == Approved`」的出库明细数量（明细数量已折算基础单位，与订单明细同口径直接比较）。
- 待提交 / 已提交出库单列为待审数量（`PendingQuantity`），不计入已出；已驳回 / 已取消 / 软删除不计。
- 一页多张订单命中批量派生上限时，无法把截断归因到具体订单，该页相关订单的出货数量与出货状态按「未知」返回，
  绝不静默给出不完整数量。

## 5. 界面

销售订单页工具栏「🚚 交期异常」打开工作台：客户 / 基准日 as-of / 关键字 / 每页条数筛选，
KPI（逾期 / 即将到期 / 已出齐 / 在途 / 未知本页计数）、订单明细表（订单交期、明细交期、判定交期、
已出 / 已订、未出、出货状态、交期状态、说明）与 CSV 导出。未知值在表格与导出中原样显示「未知」。

## 6. 测试

`src/ERP.UnitTests/SalesOrderDeliveryExceptionTests.cs` 覆盖：交期状态派生（逾期 / 即将到期 / 在途 /
已出齐）、明细交期优先于订单头交期、日期边界（含当天与第 7 天）、部分出货仍为未出齐、仅已审核未删除出库计入已出、
缺日期未知、出货证据截断未知、只读不写库、分页有界与稳定排序、客户 / 关键字筛选、批量取数（固定次数数据集访问、
无逐单查库）、接口端点与前端接线契约。全部使用内存数据库，不连接 SQL Server、不启动 API、不执行任何 SQL 或 seed。
