# 代理服务费协议证据说明（ERP-069）

## 1. 背景与定位

**目标**：为**客户侧代理服务**提供一份可审计的**代理服务费协议证据登记册** —— 把授权用户**显式提供**的商业条款
（协议号 / 权威客户 / 生效日期区间 / 币种 / 披露的计费方式与显式费率或固定金额 / 有界的计费依据说明 / 有界备注）
登记为仓库内证据，并可显式登记与作废。

**定位（重要）**：本登记册是**仓库内商业条款证据**：

- **不是**税务发票（不开票、不连税务平台、不作废真实发票）；
- **不是**会计凭证 / 记账分录（不记账、不生成凭证 / 收款 / 付款 / 结算单）；
- **不是**付款授权或资金指令（不授权、不发起、不执行任何付款）；
- **不是**法律意见（不做条款合法性、效力、管辖或税务处理判断）；
- **不构成**服务已交付或已收付款的证明；
- **不提供**任何「不披露 / 账外 / 隐匿佣金」的字段或流程：条款一律以显式、可读、可审计的方式记录。

**与相邻模型刻意分离**：业务员提成报表（`/api/reports/sales-commission`，比例取自系统参数 `SalesCommissionRate`、
按毛利计算）、客户佣金 / 回佣比例（`BaseCustomer.CommissionRatio`）、订单佣金比例快照（销售订单 `CommissionRatio` 列）、
供应商返点比例（`BaseSupplier.RebateRatio`）都是**各自独立的模型**：本登记册既不读取、也不改写、也不派生它们，
登记 / 作废协议**不会改变任何提成报表结果**。

## 2. 新增前的既有模型审计（acceptance criterion 1）

在新增本模块之前，对仓库内既有「客户条款 / 佣金 / 合同字段」逐项审计（只读比对 Domain / Application /
Infrastructure / Api / wwwroot / 测试与 `SchemaUpgrader.cs`），结论如下：

| 既有模型 | 实际口径 | 是否可作为「代理服务费协议」权威模型 |
|---|---|---|
| `BaseCustomer.CommissionRatio`（客户「佣金/回佣比例（%）」） | 客户主数据上的**单一比例设置**，销售订单选客户时带出 | **否**：没有协议身份、生效区间、计费方式、固定金额、计费依据，也无登记 / 作废留痕 |
| `SalesOrder.CommissionRatio`（订单佣金比例快照） | 单据上的比例快照（随订单保存） | **否**：属于订单口径，不是客户协议 |
| `BaseSupplier.RebateRatio`（供应商返点比例） | 供应商主数据上的比例设置 | **否**：供应商侧口径，与客户代理服务费无关 |
| 业务员提成表（`GET /api/reports/sales-commission`） | 内部报表：比例取自系统参数 `SalesCommissionRate`，按毛利计算 | **否**：内部提成核算，不是对外协议，也不得被协议条款反向影响 |
| 业务单据附件引用（ERP-045，分类含「合同 / 协议」） | 只有**元数据**的附件引用（分类 / 显示名 / 不透明引用标识 / 校验和） | **否**：只登记引用，不承载任何商业条款字段，也不做校验 |
| 单证中心 / 客户销项发票证据 / 收款引用 | 出口单证、发票证据、收款引用 | **否**：口径完全不同，本模块不转换、不替换、不自动链接 |

**结论**：仓库内**不存在**「代理服务费协议」的权威模型，也不存在可与协议条款混用的既有字段，因此
**新增一个独立证据模型** `AgencyServiceFeeAgreements`：

- 不替换、不复制、不合并上述任一模型；
- 不再向 `BaseCustomers` / 销售订单 / 供应商加任何列（**无 `ALTER TABLE`**），也不做任何历史回填；
- 与业务员提成报表的口径**物理隔离**（两张表、两套规则、无派生关系）。

## 3. 协议字段与校验口径

| 字段 | 口径 |
|---|---|
| `AgreementNo` | 协议号，必填，≤50 字符，去首尾空白；由用户按真实协议填写，**系统不自动发号、不做格式猜测** |
| `NormalizedAgreementNo` | 规范化协议号（唯一身份判定用，服务端写入）：去掉所有空白与 `-` / `－` / `—` / `_` 后大写 |
| `CustomerId` + `CustomerCode` / `CustomerName` 快照 | 新增 / 修改时客户必须**存在、未删除且启用**；编码与名称快照由**服务端写入**，客户端提交的同名字段不被采信 |
| `EffectiveFrom` | 生效起始日期，必填（**必须显式填写**，系统不按当天 / 订单 / 参数推算），只取日期部分 |
| `EffectiveTo` | 生效结束日期，可空 = **无固定结束日**；填写时不得早于起始日期（不静默调整、不猜续签日期） |
| `Currency` | 币种，必须来自系统币种口径（CNY / USD / EUR / HKD / GBP / JPY），规范化为大写；金额一律以**原币**记录 |
| `FeeMethod` | 披露的计费方式，只允许 `比例费率` / `固定金额`（未知取值一律拒绝） |
| `RatePercent` | 费率百分比：比例费率时必填且 **(0, 100]**，保留 4 位小数（0.5 进位）；固定金额时留 0 |
| `FixedAmount` | 固定金额：固定金额时必填且**按币种精度取整后 > 0**；比例费率时留 0 |
| `FeeBasis` | 计费依据说明，必填、≤200 字符；**只作为人工留痕**，服务端不据此计算金额 |
| `Remark` | 备注，≤500 字符 |
| `Status` | 0 草稿 / 1 已登记 / 2 已作废 |
| `RecordedAt` / `RecordedBy` | 登记时间与登记人：登记时由服务端写入；登记人来自**已认证身份**（缺失记「未知用户」），长度 ≤100 |
| `VoidedAt` / `VoidReason` | 作废时间与原因：作废时由服务端写入，原因必填且 ≤500 字符 |

**读取侧标注（`[NotMapped]`，不落库）**：`CustomerAvailable` / `CustomerAvailabilityText`、`FeeTermsText`、
`EffectiveRangeText`、`BoundaryText`、`CommissionSeparationText` 由服务端生成，与前端同源文案。

## 4. 费用条款：显式、互斥、不派生

| 计费方式 | 必填 | 禁止 | 说明 |
|---|---|---|---|
| 比例费率 | `RatePercent > 0` 且 `≤ 100`（取整 4 位小数） | 同时填写 `FixedAmount`（非 0） | 费率必须来自用户显式提交；系统**不**从业务员提成设置、客户 / 供应商主数据比例、历史订单、自由文本、客户默认值或金额相似度推断 |
| 固定金额 | `FixedAmount` 按币种精度取整后 `> 0` | 同时填写 `RatePercent`（非 0） | 金额一律以协议币种原币记录，不做汇率换算 |

- **不兼容组合一律拒绝**（不静默归一化、不自动取舍、不把金额折算成费率，也不把费率折算成金额）；
- 负数（费率 / 固定金额）一律拒绝；取整后为 0 的金额 / 费率一律拒绝；
- 费率超过 100% 一律拒绝（不自动截断）；
- **不派生**：创建、修改、读取都不访问提成参数或主数据比例；事后修改 `SalesCommissionRate` 或客户
  `CommissionRatio`，协议条款保持不变；
- **不计算**：系统不按费率 × 金额算出任何费用金额、不生成应收 / 应付、不写任何财务记录。

## 5. 客户权威与历史快照

- 新增 / 修改：客户必须**存在、未删除且启用**；不存在 / 已删除 → `NotFound`，已停用 → 规则冲突；
- 客户编码 / 名称以**快照**形式保存在协议行（服务端写入）：客户停用、软删除、改名后历史证据仍按登记当时口径可读；
- 读取时按客户 Id **一次批量装载**客户；不可用时显式标注「已停用 / 已删除」，**绝不回填、绝不改派**；
- 本表**刻意不建**到客户的外键、也没有导航属性（客户可能停用 / 软删除，外键会阻塞或破坏历史可读）。

## 6. 有效身份唯一（重复登记被拒绝）

- 判定键：**同一客户 + 同一规范化协议号**；
- 规范化规则（`NormalizeIdentityPart`，与其它登记册同口径）：去首尾空白 → 去掉所有空白与 `-` / `－` / `—` / `_` → 大写；
- 有效范围：`IsDeleted = 0 AND Status <> 2`（即**未作废**，**草稿同样占用身份**，避免同一协议被重复登记）；
- 重复一律拒绝（`Duplicate`），**不静默合并、不覆盖**、不按费率 / 金额 / 生效日期相似度匹配；
- 已作废记录保留可读但**不占用身份**（作废后可重新登记同一协议号）；不同客户可以使用相同协议号；
- 并发兜底：过滤唯一索引 `UX_AgencyServiceFeeAgreements_ActiveIdentity`（`IsDeleted = 0 AND Status <> 2`）。

## 7. 状态机、冻结与作废保留

```
草稿(0) --登记--> 已登记(1) --作废--> 已作废(2)
   \------------------作废------------------^
```

| 操作 | 草稿 | 已登记 | 已作废 |
|---|---|---|---|
| 修改 | 允许（客户 / 条款 / 日期 / 备注） | **拒绝**（先作废再重新登记） | **拒绝** |
| 登记 | 允许（写入登记时间 / 登记人） | **拒绝**（重复登记） | **拒绝**（不可恢复为已登记） |
| 作废（原因必填） | 允许一次 | 允许一次 | **拒绝**（重复作废） |

- 作废**保留**协议身份、费用条款、客户快照、登记人与时间戳、作废原因与时间；
- **不物理删除、不静默改写**（控制器没有 `DELETE` / `PATCH` 接口），已作废证据默认包含在台账中（显式状态筛选）；
- 作废原因空白 → 参数错误；超过 500 字符 → 参数错误。

## 8. 非变更边界（本模块不改写什么、不做什么）

- **只读写一张表** `AgencyServiceFeeAgreements`；不建第二张关联表、不加列、不建外键；
- **不改写**：客户主数据（含佣金比例、信用额度、信用状态、状态）、销售订单（含佣金比例、金额、状态、明细）、
  装柜与单证、客户收款单及其引用行、客户销项发票证据、库存与库存成本、库存流水、费用与退税记录、结算记录；
- **不做**：开票 / 作废发票、税务申报、记账或凭证、收款 / 付款 / 结算单、任何付款授权或资金指令、任何法律判断；
- **不读**：业务员提成设置（`SalesCommissionRate`）、客户 / 供应商主数据比例、历史订单金额、任何自由文本；
- **无账外字段**：实体与请求模型均**不含**任何「不披露 / 账外 / 隐匿佣金」字段（单元测试以反射黑名单断言），
  也不建模任何佣金取值字段（`CommissionRate` / `CommissionAmount` / `CommissionRatio`）；
- **无历史回填**：既有客户 / 订单 / 发票 / 收款 / 库存数据不因本模块产生任何变化，也不在读取时补写。

## 9. 接口与界面

| 接口 | 说明 |
|---|---|
| `GET /api/agency-service-fee-agreements` | 台账分页（默认 50、单次上限 200）：客户 / 状态 / 币种 / 计费方式 / 生效起始日期区间 / 关键字；默认含已作废历史 |
| `GET /api/agency-service-fee-agreements/{id}` | 详情（含客户可用性标注与同源口径文案） |
| `POST /api/agency-service-fee-agreements` | 新增草稿（协议号 / 客户 / 生效区间 / 币种 / 计费方式与条款 / 计费依据 / 备注） |
| `PUT /api/agency-service-fee-agreements/{id}` | 修改草稿（已登记 / 已作废拒绝） |
| `POST /api/agency-service-fee-agreements/{id}/record` | 登记（写入登记时间与登记人，客户端不能提交登记人） |
| `POST /api/agency-service-fee-agreements/{id}/void` | 作废（原因必填，保留历史） |

- 全部接口 `[Authorize]`；控制器为 `[ApiController] [Route("api/agency-service-fee-agreements")]`；
- 无 `DELETE` / `PATCH` 接口（不提供硬删除与静默改写）；
- **未知筛选取值一律拒绝**（状态 / 计费方式 / 币种 / 超长关键字），不静默忽略筛选条件。

**界面**：`wwwroot/js/agency-service-fee-agreements.js`（列表 / 新建 / 编辑 / 详情 / 作废 五个视图）：

- 入口一：**客户资料工具栏**「🧾 服务费协议」（`extraActions`，始终可见）；
- 入口二：**客户资料行操作**「服务费协议」（`rowActions`，自动以该客户预筛选）；
- 页面顶部与表单内显式声明：不是税务发票 / 会计凭证或记账分录 / 付款授权 / 法律意见 / 服务已交付或已收付款的证明；
  费用条款只保存显式填写的值（不从业务员提成设置、客户比例或历史订单推断），比例费率与固定金额不得同时填写；
  更正走显式作废（原因必填）；未提供结束日期时显示「无固定结束日」。
