# 单证中心：商品明细行快照（ERP-051）

> 任务：`ERP-051`「Add immutable line-item snapshots to Trade Documents」——为既有单证台账（`TradeDocuments`）增加**行级快照证据**子表，
> 让商业发票（CI）与装箱单（PL）能逐行登记商品、数量、单价 / 金额（CI）与箱数 / 净重 / 毛重（PL），并可被核对与追溯。
>
> 本文档与 `docs/单证中心生成与导出说明.md`（ERP-019 / ERP-030 / **ERP-052**）配套阅读：单证的**生成、Excel 导出与共享打印**原口径不变，
> 自 **ERP-052** 起**消费明细行**（由销售订单 / 装柜清单生成时带入行快照、Excel 明细行导出、打印明细区），
> 详见 `docs/单证中心生成与导出说明.md` §11。

## 1. 背景与定位

- 单证台账原本是**单表**结构：一份单证一条记录，装箱单 / 商业发票的商品明细只能写在备注或另存 Excel，无法逐行核对。
- 本轮新增 `TradeDocumentItems`（**单证明细行快照**）：一行 = 一个商品在**制作当时**的记录，可选引用商品资料。
- **它不是**第二套商品主数据、**不是**库存交易、**不是**报关核定价格、**不是**退税或税务依据；
  维护明细行**不会**改写商品资料、销售订单、采购订单、装柜清单、库存与库存流水、发票、退税、费用或财务记录，
  **也不会**回写单证表头（金额 / 状态 / 份数 / 备注）。

## 2. 数据模型与字段口径

| 列 | 类型 | 口径 |
|---|---|---|
| `TradeDocumentId` | BIGINT | 所属单证（外键 → `TradeDocuments`，脚本中**不含级联动作**；EF 侧 `DeleteBehavior.Cascade`：应用层物理删除单证时清理明细）；单证走软删除，软删除后明细仍可读但不允许再维护 |
| `LineNo` | INT | 行序（服务端权威写入：留空 = 既有最大行序 + 1；显式指定时同一单证内不得重复；不填补空洞、不静默重排） |
| `ProductId` | BIGINT | 可选商品资料引用（0 = 人工录入的纯文本行）；**刻意不建**到 `BaseProducts` 的外键 |
| `ProductCode` / `ProductNameCn` / `ProductNameEn` / `Spec` / `Unit` | NVARCHAR | 商品编码 / 中文名称 / 英文名称 / 规格 / 单位**快照**（引用商品资料时由服务端写入权威值） |
| `Quantity` | DECIMAL(18,4) | 数量（必须 > 0，最多 4 位小数） |
| `UnitPrice` | DECIMAL(18,4) | 单价（原币，不能为负，最多 4 位小数；装箱单行恒为 0） |
| `LineAmount` | DECIMAL(18,2) | 行金额（**服务端计算**：数量 × 单价，按币种精度 0.5 进位取整；装箱单恒为 0） |
| `PackageCount` | INT NULL | 箱数（可选；未登记为 **NULL**，不臆造为 0） |
| `NetWeight` / `GrossWeight` | DECIMAL(18,4) NULL | 净重 / 毛重 kg（可选；未登记为 NULL；填写毛重时不得小于净重） |
| `Currency` | NVARCHAR(20) | 币种快照（写入时取自单证台账币种；不做汇率换算） |
| `Remark` | NVARCHAR(500) | 行备注（纯文本，不参与任何金额派生） |
| 审计字段 | — | `CreatedAt` / `CreatedBy` / `UpdatedAt` / `UpdatedBy` / `IsDeleted` / `RowVersion`（继承 `BaseEntity`） |

唯一约束：`UX_TradeDocumentItems_Document_LineNo`（`TradeDocumentId, LineNo`，过滤 `IsDeleted = 0`）——
同一单证内同一行序只能有一条**未删除**行（服务端先行拒绝重复，索引作为并发兜底）。

## 3. 允许的单证类型与状态机

| 维度 | 取值 | 说明 |
|---|---|---|
| 允许明细行的单证类型 | **商业发票**（含单价与金额）、**装箱单**（含箱数 / 净重 / 毛重，不含价格） | 其余类型（报关单 / 形式发票 / 产地证 / 提单 / 订舱确认 / 外汇核销单 / 其他 / 空）**一律拒绝明细行变更**，而不是保存含义不明的记录；清单读取仍可进行，并显式标注「不支持明细行」 |
| 可维护状态（准备状态） | **待制作**、**已制作** | 可新增 / 修改 / 删除明细行 |
| 冻结状态 | **已提交客户**、**已使用**，以及任何未知 / 空状态 | 明细行只读：新增 / 修改 / 删除一律拒绝（已冻结快照不做硬删除、不做静默替换） |

> 状态判定为**白名单式**：不在准备状态白名单内的任何取值都按冻结处理（fail-closed）。

## 4. 校验与服务端计算口径

| 项 | 口径 |
|---|---|
| 数量 | 必须 > 0；最多 4 位小数（超精度拒绝，不静默取整） |
| 单价 | 不能为负；最多 4 位小数；装箱单行只能为 0（含价格即拒绝） |
| 行金额 | **服务端计算**：`数量 × 单价`，按**币种精度**取整（JPY / KRW / VND / IDR 为 0 位，其余 2 位；0.5 进位，确定性）；客户端提交的金额 / 币种一律不被信任 |
| 币种 | 商业发票行必须使用单证台账币种且该币种在系统币种口径内（CNY / USD / EUR / HKD / GBP / JPY），不做汇率换算；装箱单不含价格，只保存币种快照 |
| 箱数 / 净重 / 毛重 | 可选：不能为负、精度 ≤ 4 位、箱数 ≤ 1,000,000；**填写毛重时不得小于净重**；未填写保持 NULL（页面显示为「—」，不显示 0） |
| 文本 | 去首尾空白；超长拒绝（商品编码 50 / 名称与规格 200 / 单位 20 / 备注 500）；拒绝控制字符与 `<` `>`（HTML / 脚本标记字符），导出处按纯文本；未引用商品资料时商品编码与中文名称至少填一项 |
| 行序 | 留空由服务端追加；显式指定必须 > 0 且不与同单证其他未删除行重复（重复 → `Duplicate`） |
| 行数 | 单证最多 200 行（`MaxLinesPerDocument`）；读取单次最多 200 行（超出标记 `Truncated`） |

## 5. 快照语义（写入当时的值，永不自动刷新）

1. **引用商品资料**（`ProductId > 0`）：新增（或修改时**显式改指**商品）时由服务端取商品资料的编码 / 中英文名称 / 规格 / 单位写入快照；
   客户端同时提交的商品文本被忽略（以商品资料为准）。
2. **不静默刷新**：修改行时若商品引用未变化，**保留已登记的商品快照文本**（商品资料改名 / 改规格 / 停用后历史行不变）；只有显式改指商品或清除引用才改变商品身份口径。
3. **清除引用**（`ProductId = 0`）：改为人工录入的纯文本行，写入人工提交的文本（仍受长度与纯文本校验）。
4. **商品不可用**：商品资料被停用 / 软删除后，行仍照常可读，并给出只读标注「商品资料已停用 / 已不存在或已删除：本行快照保持登记当时的值，不会自动刷新」。
5. **来源单据变化**：本表不保存销售订单 / 装柜清单明细，也不随其变化（生成时的来源留痕仍按 ERP-019 写在单证表头）。

## 6. 行合计与差异提示（只读派生，绝不回写表头）

清单接口同时返回：

- `lineAmountTotal`（行金额合计，含 `truncated` 时明确说明只是**部分合计**，不判定差异）；
- `packageCountTotal` / `netWeightTotal` / `grossWeightTotal`：**只累加已登记该值的行**，并同时给出登记行数（`packageCountRecordedLines` / `weightRecordedLines`）；
  没有任何行登记时返回 `null`，**绝不把「未登记」当成 0**；
- `amountMismatch` / `amountMismatchText`：行合计与单证台账金额是否一致。台账金额为 0 时按既有打印口径视为「未填写金额」，**不判定差异**；
  不一致时只提示「请人工核对」，系统**不会**自动改写单证金额。

## 7. 接口清单（`/api/trade/documents`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/{id}/items?take=200` | 明细行清单（只读、有界）：单证信息 + 行清单 + 行合计 + 差异提示 + 可维护性 / 类型支持文案 |
| POST | `/{id}/items` | 新增明细行（准备状态 + 允许类型；金额服务端计算；行序服务端追加） |
| PUT | `/items/{itemId}` | 修改明细行（同一套校验；商品引用未变化时不刷新快照） |
| DELETE | `/items/{itemId}` | **显式删除**一行（软删除，保留审计字段；仅准备状态允许） |

请求体（新增 / 修改共用 `TradeDocumentItemSaveDto`）只接受行内容：
`productId`、`productCode`、`productNameCn`、`productNameEn`、`spec`、`quantity`、`unit`、`unitPrice`、
`packageCount`、`netWeight`、`grossWeight`、`lineOrder`、`remark`。
**不接受** `lineAmount` / `currency` / `tradeDocumentId`（单证 Id 只走路由，金额与币种由服务端权威处理）。

错误码沿用统一口径：参数 / 精度 / 文本问题 → `1001`；单证或明细行不存在 / 已删除 → `1002`；
行序重复 → `1003`；类型不支持、状态冻结、行数上限 → `1004`。

## 9. 数据库与幂等升级

`TradeDocumentItems` 由三处保持一致：

1. **EF 模型**（`ErpDbContext.cs` DbSet + `ErpDbContext.Config.cs` ERP-051 段）：长度 / 精度（数量与单价 DECIMAL(18,4)、行金额 DECIMAL(18,2)）、
   过滤唯一索引 `UX_TradeDocumentItems_Document_LineNo`、与单证主表的级联外键；**刻意不建**到商品资料的外键；
2. **幂等升级**（`SchemaUpgrader.cs` 第 35 段）：`IF OBJECT_ID(...) IS NULL` 建表 + `IF NOT EXISTS (sys.indexes ...)` 建索引 +
   `IF NOT EXISTS (sys.foreign_keys ...)` 建外键，**不含任何数据改写语句**；
3. **接口抽象**（`IErpDbContext.TradeDocumentItems`）与控制器 / 服务读写路径。

> 本任务**不修改** `deploy/**`、`release/**` 与任何 `*.sql`；生产库执行、部署与发布仍受 Human Gate 控制，本文档不声明生产库已升级。
> 历史单证不产生任何明细行（不做回填），读取老单证返回空清单并照实说明「没有明细行」。

## 11. 边界与后续

- **生成 / 导出 / 打印消费明细行已由 ERP-052 交付**（2026-09-25）：
  由销售订单 / 装柜清单生成（或带入预填预览）时按来源明细写入行快照，`GET /api/trade/documents/export-excel?layout=lines`
  按明细行导出（含行合计），共享打印输出类型适配的明细表与合计；映射口径、缺值语义与测试见
  `docs/单证中心生成与导出说明.md` §11；
- **不做价格推断**：不按商品资料现价 / 最近成交价补全历史行单价，也不做汇率换算与跨币种合并（ERP-052 同样遵守）；
- **不作库存与财务动作**：不影响库存与库存流水、不含报关核定价格、不产生退税或税务判断，也不生成任何收付款 / 结算 / 发票记录；
- **无附件**：明细行不含图片 / 附件，附件仍按 ERP-045 的引用登记册单独管理；
- **历史单证不回填**：老单证保持空明细（无生产回填语句），需要时由人工在准备状态补录；老单证照常导出（`无明细行` 一行）与打印（无明细区）。
