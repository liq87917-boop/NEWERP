# 销售订单取消 × 已审核预装柜需求证据护栏（ERP-369）

## 1. 背景与目标

ERP-368 在预装柜明细上新增了显式来源列 `ContainerPreLoadingDetails.SourceSalesOrderDetailId`，把每条预装明细与
**已审核销售订单明细**链接为「需求计划证据」，并在预装柜审核时以来源明细数量为容量上限做累计校验。
但 ERP-347 的销售订单取消护栏只校验出库 / 采购 / 收款引用证据，**没有**校验该链接：
取消来源销售订单会让已审核预装柜所承诺的需求证据失去依据，形成阶段 3 库存闭环的缺口。

ERP-369 在**既有取消路由**（`POST /api/sales-orders/{id}/cancel`）上补齐这一道护栏，并把取消与
预装柜审核 / 取消串行化在同一把上游订单行锁上：

- 存在「未删除、已审核」且明细显式链接本单明细的预装柜单时**拒绝取消**，返回**可执行**的解除要求；
- 显式取消预装柜单即**释放**护栏，且其链接与数量作为历史证据**原样保留**；
- 未链接（`null` 历史遗留）/ 待提交 / 已提交 / 已驳回 / 已删除 / 已取消 / 无关订单的预装柜单**不阻断**；
- 取消动作**不**改动下游库存 / 采购 / 财务 / 单证，也**不**清除任何历史证据。

## 2. 证据口径（有效需求承诺证据）

| 项目 | 内容 |
| --- | --- |
| 判定字段 | `db_owner.ContainerPreLoadingDetails.SourceSalesOrderDetailId`（显式来源销售订单明细 Id，可空，刻意不建外键） |
| 阻断条件 | 父预装柜单 `!IsDeleted` 且 `Status == Approved`，明细行 `!IsDeleted` 且链接指向**本单未删除明细** |
| 不阻断 | 未链接（`null` 历史遗留）、明细已删除、预装柜单已删除、待提交 / 已提交 / 已驳回 / 已取消、链接到**其它订单**明细 |
| 来源解析 | 本单实时未删除明细 Id 一律**从库中实时读取**（不依赖调用方是否加载导航属性），绝不按单号 / 金额 / 相似度猜测来源 |
| 解除路径 | 在「预装柜单」取消该单（只改状态，链接与数量保留）或清除其显式来源链接 |

证据是**需求计划 / 追溯**语义，不是库存预留、不是出运凭证；判定只做有界只读查询，绝不跨币种合计金额。

## 3. 拒绝文案（可执行、有界）

拒绝时返回 `RuleConflict`，文案包含：

- 至多 `SalesOrderCancellationRules.MaxReportedPreLoadingLinks = 5` 张预装柜单号（附链接行数与商品名，
  超出只给「等共 N 张」，绝不无界输出）；
- 解除要求 `SalesOrderCancellationRules.PreLoadingReversalRequirementText`：
  「请先在「预装柜单」中取消该预装柜单，或清除其显式来源销售订单明细链接后再取消销售订单；
  本护栏不改动下游库存 / 采购 / 财务，也不删除任何历史证据（取消预装柜单会原样保留其链接与数量）。」

## 4. 原子性与并发（共享上游订单行锁）

- 销售订单取消在**同一个可串行化事务**内先对订单行加 `UPDLOCK, HOLDLOCK`
  （`PreLoadingSalesOrderLinkRules.LockSalesOrderRowSql`，与 ERP-368 预装柜流程**共用同一常量 / 同一把锁**），
  再执行「身份 / 菜单 / 数据范围 → 实时状态 → 出库 / 采购 / 收款证据 → 预装柜需求证据」判定，最后才改状态；
  任一步失败整体回滚：**订单 / 明细 / 金额 / 状态与历史证据零改动**。
- 预装柜审核 / 链接 / 取消沿用 ERP-368 的确定性锁序：

  ```text
  上游销售订单行（SalesOrderId 升序，UPDLOCK, HOLDLOCK）
      → 订柜信息行
      → 预装柜单行
  ```

  预装柜**取消**也在取得来源订单行锁之后才动状态，因此与来源销售订单取消严格串行化：
  先提交者决定结果 —— 预装柜先取消 → 来源取消放行；来源先取消 → 看到已审核链接而被拒绝并回滚。
- 取消只取上游订单行锁，绝不反向获取下游锁，锁序与既有 ERP-343 / ERP-346 / ERP-347 / ERP-368 完全一致，不引入锁环。

## 5. 授权（真实既有权限，fail closed）

- 身份、账号状态、既有「销售订单」（`sales-order`）菜单与客户数据范围实时解析，缺一即拒绝；
- 特权账号（超级管理员 / 系统内置角色 / 显式特权角色）沿用既有全部访问，**不新增用户授权**；
- 受限业务员按既有口径（登录名 = 员工编码 + 业务员客户归属 + 显式菜单）判定，护栏对其同样生效，
  **绝不**降级为匿名或管理员兜底；菜单回收后立即收敛。

## 6. 非目标（边界）

- 取消只把状态置为 `Cancelled`：不改订单明细 / 金额 / 客户 / 币种，不静默取消预装柜 / 采购，不冲销库存或财务；
- 解除需求证据只走既有显式工作流（预装柜取消或清除链接），本护栏**不删除**任何历史证据；
- 不新增表 / 列 / 菜单 / 权限，不改写预装柜单、商品、客户等主数据，不执行生产库变更。
