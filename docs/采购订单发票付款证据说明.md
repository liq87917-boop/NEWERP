# 采购订单已分配付款引用证据说明（ERP-067）

## 1. 背景与定位

ERP-066 建立了**供应商付款单 → 供应商采购发票**的付款引用（分摊）登记册（`SupplierPaymentInvoiceAllocations`），
让「这张付款单把多少钱指向了哪几张**已登记**采购发票」可被显式登记与追溯；ERP-065 使供应商采购发票登记册具备
发票类型 / 显式到期日 / 付款条件 / 作废留痕；ERP-048 与 ERP-050 已分别在采购订单上暴露只读的**发票证据**
（ERP-043 / ERP-065 的「发票 → 采购订单」关联行）与**付款引用证据**（ERP-049 的「付款单 → 采购订单」引用行）。

在采购与对账的实际操作里，用户还需要在看到订单的**订单金额（已订）**、**收货数量（已收）**、**供应商发票证据（已开票）**
的同时，看到**第四类完全独立的证据：已分配付款引用证据** —— 「付款单按登记指向了本订单关联发票上的多少金额」。

本次（ERP-067）在**既有采购订单列表 / 详情工作流**与**ERP-044 供应商采购发票对账报表**上暴露该证据：

- 有效（未作废、发票仍为已登记、供应商与币种自相一致）引用金额（**发票级**）；
- 其中**可安全归属本订单**的金额（仅当该发票的有效关联行**只指向本订单**时才能归属）；
- 有效引用行条数、付款单张数、关联到本订单的发票张数；
- 参与证据的付款单金额快照合计，以及其中**未指向任何采购发票**的部分；
- 已作废引用行、**发票已失效（草稿 / 已作废）**、无效历史证据（供应商 / 币种 / 快照不一致）、
  无法确认证据（付款单或发票已删除 / 不存在）**单独分桶列出并逐条给出原因**，绝不并入有效合计；
- ERP-044 对账报表中，**订单金额 / 已开票金额 / 付款引用金额 / 已分配付款引用金额**保持**分别标注**的字段。

定位：**采购订单维度的已分配付款引用证据只读呈现**，是**运营性的证据视图**。它**不是**总账或应付账款余额、
**不是**法定供应商对账单、**不是**税务（进项）申报或抵扣判断、**不是**付款授权与付款执行、**也不是**结算确认或账龄表。

> 本说明对应改动**不含**任何数据库结构变更（无新表 / 新列 / 新索引），也不含任何历史数据回填；
> 改动仅限只读派生、接口暴露、界面呈现、文档与单元测试（`SchemaUpgrader.cs`、任何 `.sql`、`deploy/**`、
> `release/**`、`checkpoints/**`、`SeedData*.cs` 均未改动）。

## 2. 金额口径（唯一权威来源）

| 值 | 口径 |
|---|---|
| 有效已分配付款引用金额（发票级） | 只按 ERP-066 的**持久化引用行**合计，且只统计**有效**行：引用行状态 = 有效、付款单存在且未删除、发票存在未删除且状态 = **已登记**、引用行供应商 / 币种与付款单及发票**自相一致**、引用金额为正数且不超过引用行快照上限 |
| 可归属本订单金额 | 上述有效行中，**所在发票的有效关联行只指向本订单**（唯一关联）的部分；其余部分只作**发票级金额**单列 |
| 发票级金额（不按订单拆分） | 有效金额 − 可归属本订单金额；同一张发票被多张采购订单关联时，系统**不按比例摊派、不猜测归属、不重复计入任何订单** |
| 有效引用行条数 / 付款单张数 | 有效行条数与付款单去重计数 |
| 参与证据的付款单金额快照合计 | 有有效行的付款单的**快照金额**去重求和（仅作上下文；不是银行付款金额或应付余额） |
| 未指向任何采购发票的金额 | 参与证据的付款单金额快照合计 − 该付款单侧**全部**有效发票引用行合计（下限 0，仅作上下文） |
| 币种与精度 | 复用 ERP-043 的 `CurrencyAmountRules`（JPY / KRW / VND / IDR 为 0 位小数，其余 2 位，0.5 进位）；**不同币种绝不合并、不做汇率换算** |
| 分桶与资格判定 | 复用 ERP-066 的 `SupplierPaymentInvoiceAllocationRules`（状态机、付款单 / 发票可用性与状态文案）与 ERP-065 的 `PurchaseInvoiceRules`（发票状态、类型与身份文案） |
| 订单可用性 | 复用 ERP-044 的 `available` / `cancelled` / `unavailable` 常量与文案 |
| 发票到期日 | 只回显 ERP-065 的**持久化到期日**；未提供即「未知」，**不**按供应商账期推算，也**不**用于账龄判断 |

**金额直接取自持久化行**：本视图不重算付款金额、不按税率或比例反推、不调整差额、不做汇率换算、不跨币种合并，
也绝不因为「看起来像」就把未分配部分或历史证据改派给任何采购订单或发票。

## 3. 归属规则（为什么会有「发票级金额」）

采购订单只能通过 **ERP-043 / ERP-065 的持久化「发票 → 采购订单」关联行**看到发票，而 ERP-066 的引用行挂在**发票**上，
因此「一笔付款指向了哪张发票」无法在一般情况下被精确拆到订单。本视图采用**保守且可验证**的规则：

| 情形 | 处理 |
|---|---|
| 该发票的有效关联行**只指向本订单** | 该发票上的有效引用金额计入**可归属本订单金额**（唯一被允许的按订单归属） |
| 该发票还被**其他采购订单**关联 | 该发票上的有效引用金额只作**发票级金额**单列（`orderAttributable = false`），并在行说明中写明「系统不按比例摊派、不猜测订单归属」 |
| 发票本身不可用 / 不可确认 | 归入 `invoice_inactive` 或 `unavailable` 分桶，不参与任何归属 |

界面与接口都**分开标注**「订单归属金额」与「仅发票级金额」，使读者不会把发票级金额误当成「本订单已付款」。

## 4. 证据分桶

一条持久化引用行（付款单 → 采购发票）在派生时只可能落进下列一个分桶：

| 分桶 | 命中条件 | 是否计入有效合计 |
|---|---|---|
| `recorded` 有效已分配付款引用证据 | 引用行状态 = 有效，付款单存在未删除，发票存在未删除且状态 = **已登记**，引用行供应商 / 币种与付款单及发票一致，引用金额为正数且不超过引用行付款单金额 / 发票含税总额快照 | **是**（唯一计入的分桶） |
| `voided` 已作废引用行 | 引用行状态 = 已作废（保留身份 / 金额 / 快照 / 作废原因） | 否 |
| `invoice_inactive` 发票已失效 | 引用行仍有效，但引用的发票仍为**草稿**或**已作废**（发票侧证据不成立） | 否 |
| `invalid` 无效历史证据 | 供应商快照与付款单 / 发票不一致、引用行币种与付款单 / 发票不一致、引用金额非正数、引用金额大于付款单金额或发票含税总额快照、状态码无法识别 | 否 |
| `unavailable` 无法确认的证据 | 引用行指向的付款单或采购发票不存在 / 已删除 | 否 |

汇总与详情都会给出各分桶的**金额与条数**，并在说明中点名「为什么这些金额不计入有效合计」，
避免被读成「已经付款所以已经结清」。

## 5. 有界读取与「未知」处理

| 入口 | 有界上限 | 说明 |
|---|---|---|
| 列表批量汇总 | 一次最多 **200 张**采购订单（超出直接拒绝，不静默截断） | 固定 **7 次**数据集访问：订单 + 订单侧关联行 + 发票 + 发票侧关联行 + 持久化引用行 + 付款单 + 付款单侧有效发票引用合计（数据库侧分组聚合），每项含 1 条溢出探测；**无逐行查库 / 无逐行存储访问** |
| 列表批量汇总 | 最多读取 **5000 条**引用行 | 命中上限时本次响应内**全部**订单的金额与计数按 `null`（未知）返回 |
| 单张订单详情 | 最多读取 **500 条**引用行 | 命中上限时金额与计数按 `null`（未知）返回，明细只显示已读取部分 |
| ERP-044 对账报表 | 一次最多聚合 **500 张**发票 | 超出时该批发票的已分配付款引用字段按未知（`null`）显示，报表不给部分合计 |

- 命中上限时**绝不报出部分合计**：接口返回 `truncated = true`，界面显示「未知（超出有界读取上限）」；
- 金额 / 计数为 `null` 一律显示为「**未知**」，**绝不用 0 顶替**；
- 订单**没有任何引用行**：证据短标签为「无已分配付款引用证据」，明确提示
  「不代表未付款、已付款、已结清、逾期或欠款，也不构成应付余额、付款授权或结算依据」；
- 订单**只有历史 / 无效证据**：短标签为「仅有历史 / 无效已分配付款引用证据」，有效合计为 0 但**不显示为未付款**；
- 订单**已取消**：证据照实列出，订单金额仅作历史参考，不推断付款或逾期；
- 订单**不存在 / 已删除**：批量接口仍返回该订单一行（`orderAvailable = false`、订单金额未知），**绝不静默丢行**。

## 6. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/purchase-orders/{id}/invoice-payment-evidence` | 单张采购订单已分配付款引用证据详情（汇总 + 有界逐条明细 + 口径 / 边界 / 维度分离文案） |
| GET | `/api/purchase-orders/invoice-payment-evidence-summaries?ids=1,2,3` | 列表用有界批量汇总：逗号分隔订单 Id（去重、保序，≤ 200 张），非法或超界一律拒绝；空 `ids` 返回空结果且**不访问数据库** |

同时复用（未新增第二套对账引擎）：`GET /api/purchase-invoices/reconciliation`（ERP-044 对账报表）在发票行、

`allocatedPaymentRule` / `allocatedPaymentBoundary` / `fourEvidenceClasses` 文案。

返回内容（两个采购订单接口同源）：有效已分配付款引用金额（发票级）、可归属本订单金额、仅发票级金额与发票张数、
有效引用行 / 付款单 / 可归属发票张数、已作废 / 发票失效 / 无效 / 无法确认的金额与条数、关联到本订单的发票张数、
订单金额与订单可用性文案、`truncated`、短标签 `evidenceLabel`、行级 `evidenceNote`、逐条明细
（付款单号 / 日期 / 状态 / 金额 / 未指向发票金额、发票身份 / 类型 / 开票日期 / 状态 / **显式到期日或「未提供（未知）」** /
付款条件、供应商快照、引用金额、分桶、订单归属标注、登记与作废留痕、原因），以及口径文案
`rule` / `scopeNote` / `boundary` / `separateDimension` 与 ERP-066 同源的
`allocationRule` / `allocationBoundary` / `evidenceDimensionRule`、ERP-043 同源的 `invoiceLinkageRule` / `amountEquation`。

## 8. 边界（明确不做的事）

- **只读**：派生过程只有 `AsNoTracking` 查询，**从不** `SaveChanges`；
- **不改写采购订单**：状态、到货进度、结算进度文本、金额与明细一律不变；
- **不改写采购发票**：类型 / 代码 / 号码 / 日期 / 到期日 / 付款条件 / 金额 / 状态 / 关联行一律不变，
  也不作废、不登记、不自动匹配；
- **不改写付款单与引用行**：审批 / 执行状态、金额、币种、银行账户与备注不变，不自动建立 / 修改 / 作废 / 改派任何引用行；
- **不改写下游记录**：库存与库存成本、库存流水、退税记录、供应商余额、费用与收付款都不受影响；
- **不作财务判断**：不判断是否已付款、是否已结清、是否逾期，不推算账期与到期日、不做账龄分摊与税负计算，
  不产生记账、凭证、收付款或结算单，也**绝不**把四类证据轧差成一个「应付余额」；
- **无回填**：既有采购订单 / 发票在没有引用行时显示「无已分配付款引用证据」，行为与历史完全一致；
- **无结构变更**：不新增表 / 列 / 索引，`SchemaUpgrader` 不变；生产库执行、部署与发布仍受 Human Gate 控制。
