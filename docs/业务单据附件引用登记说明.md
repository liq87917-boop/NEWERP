# 业务单据附件引用登记说明（ERP-045）

## 1. 定位

为**既有**销售订单、采购订单、装柜清单与出口单证（单证中心）登记**仅元数据**的附件引用：分类、安全显示名、
不透明引用标识、可选内容类型 / 字节数 / 校验和、备注，以及**来源授权确认留痕**。

本模块是**引用登记册**，不是文件存储、不是预览 / 下载通道、不是对象存储代理：

- 系统**不上传**、**不下载**、**不预览**、**不抓取**、**不覆盖**、**不删除**任何文件或 OSS 对象；
- 系统**不读取**文件内容，也**不校验**文件是否存在、内容是否安全、是否真实、是否已获下载授权；
- 列表中的每一条都是**元数据引用**，不等于「文件可用 / 已授权下载」的证明；
- 真正的对象存储集成（读写对象、签发下载地址、凭据使用）属于**另行人工审批（Human Gate）**的活动，不在本任务范围内。

## 2. 覆盖的父单据（白名单）

| 父单据类型 | 常量值 | 权威号码字段 | 界面入口 |
|---|---|---|---|
| 销售订单 | `SalesOrder` | `SalesOrders.OrderNo` | 销售订单列表 → 行操作「附件引用」 |
| 采购订单 | `PurchaseOrder` | `PurchaseOrders.OrderNo` | 采购订单列表 → 行操作「附件引用」 |
| 装柜清单 | `ContainerLoadingList` | `ContainerLoadingLists.LoadingListNo` | 装柜清单列表 → 行操作「附件引用」 |
| 出口单证 | `TradeDocument` | `TradeDocuments.DocNo` | 单证中心 → 行操作「附件引用」/ 工具栏「📎 附件引用册」 |

白名单之外的类型（如报价单、入库单等）**一律拒绝**（`InvalidParameter`）。父单据必须**存在且未删除**，
否则拒绝登记（`NotFound`）；父单据号码 / 类型快照由服务端权威写入，父单据改名、停用或软删除都不影响
历史引用可读（快照是登记当时的口径）。

## 3. 登记字段与有界校验

| 字段 | 必填 | 口径 |
|---|---|---|
| `Category` 分类 | 是 | 白名单：`Contract` 合同协议 / `Invoice` 发票 / `PackingList` 装箱单重量单 / `Customs` 报关资料 / `Certificate` 证件证书 / `Transport` 运输单据 / `Photo` 图片影印件 / `Other` 其他 |
| `DisplayName` 显示名 | 是 | 1~200 字符；只作为**纯文本标签**：拒绝控制字符、`<` `>` 标记字符、链接与 `data:` / `javascript:` / `vbscript:` / `file:` 方案 |
| `ReferenceId` 不透明引用标识 | 是 | 1~200 字符：只允许字母 / 数字 / 点 / 下划线 / 加号 / 连字符（首字符为字母或数字，且不含连续 `..`） |
| `ContentType` 内容类型 | 否 | 只接受 `type/subtype` 形态（如 `application/pdf`，≤120 字符）；不接受参数、链接与标记 |
| `SizeBytes` 字节数 | 否 | `0`~`10737418240`（10 GiB），`0` = 未提供 / 未知；负数与超上限拒绝 |
| `Checksum` 校验和 | 否 | 16~128 位十六进制摘要（如 SHA-256）；不接受自由文本 |
| `Notes` 备注 | 否 | ≤500 字符；拒绝控制字符 |
| `SourceAuthorizationAcknowledged` | 是 | 必须为 `true`（显式确认；见 §5） |
| `SourceAuthorizationNote` 授权确认说明 | 是 | 1~300 字符；拒绝控制字符、标记字符与链接形态 |
| `AuthorizedBy` 确认人 / 来源 | 否 | ≤100 字符 |

父单据号码快照 `ParentNo` ≤50 字符（超长父单据号码无法形成有界快照，登记被拒绝）。

## 4. 不透明引用口径（服务端权威校验）

拒绝的引用形态（`InvalidParameter`）：

- 任意 URL：`https://…`、`//host/…`；
- 数据 / 脚本 / 文件方案：`data:`、`javascript:`、`vbscript:`、`file:`；
- 文件系统穿越：`../..\…`、`..\..\…`、`%2e%2e%2f…`；
- 路径形态：`a/b/c`；
- 空白分隔：`att 2026 0001`；
- 查询串：`att-2026-0001?token=abc`；
- HTML / 脚本标记：`<script>…</script>`。

接受的示例：`att-2026-000123`、`9F8E7D6C1234`、`oss_2026.09+01`、`a`。

**读取侧安全标注**：历史或外部写入的不安全值（例如迁移前遗留的 URL）不会被服务端改写，
但接口返回 `referenceAvailable = false` 与 `referenceUnavailableText`，界面**只显示不可用文本**，
绝不把原值拼成链接、图片或框架标签，也绝不据此发起服务端请求（服务端不存在此类抓取代码路径）。

## 5. 来源授权确认

创建引用时必须显式提供：

- `sourceAuthorizationAcknowledged = true`；
- `sourceAuthorizationNote`（授权依据 / 范围）。

该确认**只表示登记人声明其有权引用该来源**，**不**授予系统任何对象存储访问权，
**不**代表系统已认定生产数据合规，**不**替代任何生产数据资格审批。
服务端记录确认时间（`AuthorizedAt`，服务端权威写入）与确认人（`AuthorizedBy`，原样记录）。

## 6. 作废与历史保留

- 作废必须填写**原因**（1~500 字符），否则拒绝（`InvalidParameter`）。
- 作废只改状态：`Status = 1`（已作废）+ `VoidedAt` + `VoidReason`；**原始元数据**（分类 / 显示名 /
  引用标识 / 内容类型 / 大小 / 校验和 / 备注）与**授权留痕**完整保留，`IsDeleted` 仍为 `0`。
- **不提供**硬删除、**不提供**远端对象删除、**不提供**编辑或静默替换接口：
  控制器只有 `GET` 与两个 `POST`（登记 / 作废），没有 `PUT` / `PATCH` / `DELETE`（单元测试以反射守住该契约）。
- 重复作废被拒绝（`RuleConflict`）。
- 台账默认**包含**已作废历史（留痕可读）；可按状态筛选只看有效（`status=0`）或只看已作废（`status=1`）。

## 7. 唯一口径与并发兜底

同一「父单据（类型 + Id）+ 分类 + 引用标识」在**有效**记录内唯一：

- 重复登记一律**拒绝**（`Duplicate`），不静默合并、不覆盖；
- 已作废记录保留可读但**不占用**身份，因此作废后可重新登记同一引用标识；
- 数据库层由过滤唯一索引 `UX_DocumentAttachmentReferences_ActiveIdentity`
  （`IsDeleted = 0 AND Status = 0`）并发兜底；服务端在写入前先行判定，索引只作最后防线。

## 8. 读取口径与有界性

| 场景 | 接口 | 有界口径 |
|---|---|---|
| 台账分页 | `GET /api/document-attachment-references` | 每页 1~200 条（默认 50；传超大值按 200 截断），页码下限 1 |
| 详情 | `GET /api/document-attachment-references/{id}` | 单条 |
| 单据详情清单 | `GET /api/document-attachment-references/by-parent` | 单次最多 200 条（`MaxPerParent`），可传 `status` |
| 父单据候选 | `GET /api/document-attachment-references/parent-options` | 单次最多 200 条（`MaxParentOptions`），只返回未删除单据，关键字只匹配单据号码 |
| 模块元数据 | `GET /api/document-attachment-references/metadata` | 白名单 / 上下界 / 口径文案（接口与界面同源） |

- 台账过滤：父单据类型、父单据 Id、分类、状态、关键字（父单据号 / 显示名 / 引用标识 / 备注，≤100 字符）。
- 父单据可用性**一次批量装载**（每种父单据类型最多一次查询），绝无逐行数据库查询。
- 父单据可用性与引用安全性都是**只读标注**：已删除父单据与历史不安全引用值不改变记录可读性。

## 9. 接口与界面入口

```
GET    /api/document-attachment-references                    # 台账（分页）
GET    /api/document-attachment-references/metadata           # 模块元数据（白名单 / 口径文案）
GET    /api/document-attachment-references/by-parent          # 指定父单据的有界清单
GET    /api/document-attachment-references/parent-options     # 父单据候选（有界）
GET    /api/document-attachment-references/{id}               # 详情
POST   /api/document-attachment-references                    # 登记（仅元数据）
POST   /api/document-attachment-references/{id}/void          # 作废（原因必填）
```

界面：`wwwroot/js/document-attachment-references.js`（在 `index.html` 注册），
入口为销售订单 / 采购订单 / 装柜清单 / 出口单证的列表行操作「📎 附件引用」，
以及单证中心工具栏「📎 附件引用册」；`openDocumentAttachmentReferencesForCurrentModule`
按当前模块编码推断父单据类型。界面所有动态文本经 `darEsc` 转义，**不生成链接、不嵌入图片 / 框架标签、不自行抓取**。

## 10. 与既有数据的关系（历史兼容）

- 单证中心既有的「附件说明 / 存放位置」（`TradeDocuments.FileNote`）**保持原样**：
  **不自动导入**为本模块引用、**不改写**、**不**当作已授权附件（两者是不同口径，FileNote 仍是自由文本说明）。
- 商品图片位（`BaseProducts.Image1~3`）**保持原样**，本模块不读取、不改写、不迁移。
- 已有单据无需任何回填即可使用本模块；没有引用数据时系统行为与历史完全一致。

## 11. 幂等数据结构（SchemaUpgrader 第 32 段）

`SchemaUpgrader` 第 32 段以 `IF OBJECT_ID('db_owner.DocumentAttachmentReferences') IS NULL` 幂等建表并建索引：
**不含任何 `UPDATE` / `INSERT` 回填语句**，也**不**在父单据表上加列或建外键。

| 索引 | 列 / 过滤 | 用途 |
|---|---|---|
| `UX_DocumentAttachmentReferences_ActiveIdentity`（唯一） | `ParentType, ParentId, Category, ReferenceId` WHERE `IsDeleted = 0 AND Status = 0` | 有效身份唯一（并发兜底） |
| `IX_DocumentAttachmentReferences_ParentType_ParentId` | `ParentType, ParentId, Status` WHERE `IsDeleted = 0` | 父单据 / 单据详情有界检索 |
| `IX_DocumentAttachmentReferences_ReferenceId` | `ReferenceId` WHERE `IsDeleted = 0` | 按引用标识检索 |

**生产库结构变更、部署与发布仍由 Human Gate 控制**；本文档不声明生产库已升级或已执行任何脚本。

## 12. 非变更边界

登记、读取与作废引用**只读写** `DocumentAttachmentReferences` 一张表，**不**改写：

- 父单据（销售订单 / 采购订单 / 装柜清单 / 出口单证）的状态、金额、明细、备注、唛头与出运字段；
- 库存与库存成本、`Stocks` / `StockMovements`、入库与出库单据；
- 财务数据（费用单、付款 / 收款 / 结算单、退税记录）与供应商 / 客户主数据；
- 审批状态、到货进度、结算进度与任何既有引用链。

系统也**不**记账、**不**生成凭证、**不**触碰任何对象存储凭据。

## 14. 延后与人工门禁事项

- **真实对象存储集成**（对象上传 / 下载 / 预览 / 签名地址 / 凭据使用 / 对象删除）**未实现**，
  必须作为独立任务并取得 Human Gate 批准后另行设计；
- **浏览器 / UI 验收**按项目策略在开发阶段记为 `browser_deferred`，延后到 `FINAL-UI-ACCEPTANCE`
  阶段用真实 Microsoft Edge 执行（场景：为既有销售订单登记授权后的不透明引用，核对有界元数据且不上传 /
  不抓取文件；尝试不安全 URL / 穿越引用被拒绝，作废有效引用后历史仍可见且父单据无变化）；
- **生产库结构执行**、**生产 OSS 操作**、**部署与发布**仍受强制 Human Gate 控制。
