# 外贸 ERP · 一级/二级菜单与业务流程优化建议

> 版本：V1.0（待确认稿） · 日期：2026-09-18 · 范围：仅**建议**，未改动任何代码/数据
> 适用业务：义乌小商品外贸 —— **工贸一体**（自产自销）与 **纯代理采购**（代客采购组货出口）两种模式

---

## 〇、结论先行（TL;DR）

1. **现有菜单骨架是对的**（询价 → 订单 → 出入库 → 装柜 → 结算 → 报表），但**有 3 个一级菜单命名与实际功能不符**，需要改名与重新归位；「商品资料」被埋在「基础资料」里也偏低（SKU 是外贸系统的核心资产）。
2. **纯代理采购模式的"命门"目前缺席**：采购单不挂客户/销售单、一柜多客户拼柜分摊、代垫货款、**代理费/佣金结算**、供应商档口货源管理 —— 这 5 项不补，代理模式只能靠 Excel 补位。
3. **工贸一体模式的"命门"也缺席**：**没有任何生产/委外/物料模块**，成本核算只有 `CostPrice` 一个静态字段。若真的自己做生产，需要新增「生产管理」一级菜单（可分阶段）。
4. **单证与合规链路空缺**：报关单、装箱单、商业发票、产地证（CO/Form A/Form E）、验货报告、唛头标签、出口方式（一般贸易 0110 / **市场采购 1039** / 跨境电商 9610、9710）都没有落点 —— 其中 **1039 市场采购贸易是义乌特色**，必须支持"不退税/无票采购"场景。
5. **建议一级菜单从 8 个调整为 12 个**（见第三节蓝图），并通过「**业务模式**」系统参数 + 角色权限实现**按模式隐藏不适用菜单**，而不是做两套系统。
6. 落地代价分级：**① 纯菜单调整**（改名/移动/排序/图标，仅改菜单表数据，1 天）→ **② 字段与流程补齐**（每个功能 1~3 天）→ **③ 新增业务模块**（生产、退税、单证等，每个 3~10 天）。建议先做 ①+② 的 P0，再看 ③。

### 1.3 三个"名不对实"的地方（建议改名）

| 现名 | 问题 | 建议 |
|---|---|---|
| **物流管理** | 里面其实是「采购入库 / 销售出库 / 库存查询」，属**库存管理**范畴，真正的物流（订舱、报关、跟踪）在装柜模块 | 改名 **库存管理**，或与装柜合并为 **仓储物流** |
| **装柜管理** | 装柜只是出运链路的一环（订舱 → 拖车 → 报关 → 装柜 → 提单 → 到港） | 改名 **出运管理**（或"出口作业"） |
| **账务管理** | 现有 7 张单据只覆盖"定金/货款/收付款/结算"，缺费用、应收应付、佣金、退税 | 改名 **财务结算**，并扩充 |

另外：**「其他资料」是垃圾桶式命名**，且商品与数据字典（币种/港口/货代/唛头）挤在同一张表用 `InfoType` 区分 —— 建议把商品独立为一级「商品中心」，其他资料拆成「数据字典」（币种汇率、港口航线、运输方式、结算方式、价格条款、唛头模板、品牌、认证、包装单位）。

### 2.2 备选方案 B（更紧凑，10 个一级菜单）

> 如果觉得 13 组太多，可合并为：**首页看板 / 客户与市场 / 采购与供应商 / 询报价与订单 / 商品与库存 / 生产管理 / 出运与单证 / 财务结算 / 报表中心 / 系统设置**
> 代价：「商品」与「库存」同组、「报价」与「订单」同组，二级菜单每组长达 8~12 项，侧栏需要滚动查找（已支持手风琴 + 隐藏滚动条，体验可接受）。

### 2.3 只需要改数据、不需要开发的部分（可立刻做，约 1 天）

| 动作 | 内容 | 实现方式 |
|---|---|---|
| 改名 | 物流管理 → 库存管理；装柜管理 → 出运管理；账务管理 → 财务结算；询价管理 → 询报价管理 | `UPDATE SysMenus SET MenuName=…`（编码不变，前端 `CODE_ICON` 映射不受影响） |
| 移位 | 客户资料 → 客户与市场；供应商资料 → 供应商与采购；商品资料 → 商品中心；采购入库/销售出库 → 库存管理 | 改 `ParentId` + 新建一级菜单行 |
| 排序 | 按业务流排序：首页 → 客户 → 采购 → 询报价 → 订单 → 商品 → 库存 → 出运 → 财务 → 报表 → 系统 | 改 `SortOrder` |
| 图标 | 一级菜单统一 emoji + SVG 图标（现有 `GROUP_EMOJI` 已支持） | 前端映射表 |
| 隐藏 | 按「业务模式」隐藏生产管理（纯代理）或拼柜分摊（纯工贸） | 角色菜单授权 + 模式参数联动 |

> ⚠️ 建议**不要**先建"没有功能的空菜单"（点击会显示"该功能开发中"），应**先开发功能、后上菜单**，或建了先隐藏。

## 三、两种外贸模式的差异（菜单要能"分模式可见"）

### 3.1 业务主流程对比（义乌场景）

**A. 工贸一体**（自己/关联工厂生产，如饰品、袜品、文具厂）

```
客户询盘 → 报价(含退税收益) → 接单/PI/外销合同 → 收定金
   → 原料/辅料采购 → 打样确认 → 排产/生产/委外(镀色·包装) → 成品QC
   → 成品入库 → 客户/第三方验货 → 订舱·拖车·报关 → 出货装柜
   → 收尾款/收汇 → 出口退税 → 售后与返单
```
> 系统关键诉求：**BOM 与物料、生产任务与进度、产成品入库、成本核算（料工费）、退税台账、工厂与车间视角的产能/交期**。

**B. 纯代理采购**（外贸公司/代理，帮外商在国内组货出口）

```
外商询盘/指定采购清单 → 找货比价(多档口·多供应商) → 报价 = 采购成本 + 代理费 + 费用
   → 客户确认 → 收定金或全额代垫 → 分批下采购单(多供应商) → 到货集货(义乌仓)
   → 验货·分箱·贴唛 → 拼柜组柜(LCL/FCL) → 订舱·报关 → 出货
   → 向客户结算(货款+代理费+报关拖车等费用) → 与供应商结算 → 确认代理费/汇差利润
```
> 系统关键诉求：**采购单挂客户、代垫资金追踪、一柜多客户拼柜分摊、费用明细与分摊、代理费/佣金结算、应收账龄（客户赊账）、供应商档口与开票信息**。

### 3.2 能力矩阵（√ 必需 / ○ 有用 / — 不适用）

| 能力 | 工贸一体 | 纯代理采购 | 系统现状 |
|---|---|---|---|
| 客户/供应商主数据 | √ | √（**供应商数量多、以档口为主**） | 有，但缺档口与开票信息 |
| 询价 → **报价单** → PI | √ | √（**报价是核心环节**） | **只有询价，缺报价与 PI** |
| 销售订单（外销合同） | √ | √ | 有，缺 PO 号/条款/佣金 |
| **采购单归属到客户/销售单** | ○ | **√（必需）** | **无归属字段** |
| 供应商比价（一单多询） | ○ | **√** | **无** |
| BOM / 生产任务 / 委外 / 领料 | **√** | — | **完全没有** |
| 成品/半成品入库 | √ | ○ | 只有采购入库 |
| 集货仓（收货→验货→组柜） | ○ | **√** | 收货计划有，缺验货与分箱贴唛 |
| **一柜多客户拼柜 + 费用分摊** | ○ | **√（必需）** | **装柜清单是单客户结构，不支持** |
| 订舱/柜号/封条/箱重体积 | √ | √ | 有（预装柜/装柜清单） |
| **单证中心**（报关单/装箱单/CI/PL/产地证） | √ | √ | **无** |
| 出口方式（0110/1039/9610/9710）与不退税场景 | ○ | **√（义乌 1039 常见）** | **无** |
| 定金/货款/收付款 | √ | √ | 有 |
| **费用单**（报关/拖车/港杂/仓储）与分摊 | √ | **√** | 仅结算单里有"运费/其他费"两个粗字段 |
| **代垫货款追踪（代收代付）** | — | **√（必需）** | **无** |
| **代理费/佣金结算** | ○（给客户回佣） | **√（主要收入）** | **无** |
| 应收账龄 / 客户信用占用 | √ | **√（赊账多）** | 有信用额度字段，无账龄 |
| 供应商应付/对账 | √ | **√** | 无 |
| **退税台账 / 发票管理** | **√** | √（视是否自营出口） | 无 |
| 库存盘点/调拨/预警/多单位 | √ | ○（集货仓为主） | 只有库存查询 |
| 报表（业务/财务/柜量/佣金/退税） | √ | √ | 7 张，偏财务与业务产值 |
| 业务模式切换与菜单可见性 | — | — | **无（建议新增）** |

### 3.3 关键设计建议：一个系统、两种模式

| 建议 | 说明 |
|---|---|
| **系统参数：业务模式** | `BizMode = 工贸一体 / 纯代理采购 / 混合`。影响：菜单默认可见性、单据必填规则（如代理模式下采购单必须选客户）、结算单据类型 |
| **单据字段而非单据类型区分模式** | 销售订单加「业务性质：自营出口 / 代理出口」、采购订单加「采购归属客户」——一套单据两用，避免重复开发 |
| **菜单可见性 = 角色权限 + 模式默认值** | 沿用现有「角色-菜单」授权模型，只把"模式默认可见菜单集"作为新建角色时的预勾选模板，不引入第二套权限体系 |
| **报表按模式拆口径** | 工贸看"料工费与毛利率"，代理看"代理费收入、代垫资金周转、柜量毛利" |

## 四、你可能还没想到的缺口清单（按优先级）

> 说明：P0 = 影响业务闭环/当前必须用 Excel 补位；P1 = 明显提效或风控；P2 = 锦上添花。

### P0（业务闭环缺口，建议优先）

| # | 缺口 | 为什么义乌场景必须有 | 建议落点 |
|---|---|---|---|
| 1 | **报价单（Quotation）** | 现在只有"询价单"，客户要的是**带有效期、条款、港口的正式报价**，且常有 2~3 轮议价与版本 | 新增「报价单」单据（可由询价单一键转报价），含版本/有效期/Incoterms/目的港/佣金 |
| 2 | **形式发票 PI / 商业发票 CI** | 外商下单前几乎都要 PI（用于开信用证、付款申请、配额），出货后要 CI 给客户清关 | 报价单 → PI → 销售订单 一键流转；CI 由销售订单+装柜清单生成 |
| 3 | **采购单归属客户/销售单** | 代理采购的每张采购单都要能回答"这是给哪个客户哪张单买的"，否则无法核算单客户毛利 | 采购订单新增 `CustomerId / SalesOrderId / IsAdvancePayment(代垫)` |
| 4 | **一柜多客户拼柜 + 费用分摊** | 义乌拼箱（LCL）极常见：一个柜 5~20 个客户混装，柜费（拖车/报关/THC/文件费）**必须按体积或金额分摊** | 装柜清单由"单客户"升级为"柜 → 多客户分组明细"，分摊规则可配（按体积/按金额/按箱数/手工） |
| 5 | **费用单（含分摊）** | 报关费、拖车费、港杂费、仓储费、快递费、查验费目前无处录入，只能塞进结算单的"其他费" | 新增「费用单」（单据 + 费用科目 + 归属柜/客户/订单），支持分摊与结转成本 |
| 6 | **代理费/佣金结算单** | 纯代理模式下**这是主要收入**（通常 1~3% 代理费，或按柜固定费用），也包含给客户的"回佣/暗佣" | 新增「代理费/佣金结算单」，可按订单/柜/客户结算，支持明佣暗佣 |
| 7 | **应收账款与账龄** | 客户赊账、柜到港才付尾款的模式极常见；缺账龄就没有催收抓手 | 「应收账款」（按客户/订单/柜）、「账龄分析」（30/60/90/180 天） |
| 8 | **客户/供应商关键字段补齐** | 没有 PO 号、Consignee/Notify、唛头、Incoterms、档口信息、开票税率，做不出给客户和报关行的正式文件 | 见第五节字段清单（改字段 + 页面表单） |
| 9 | **单证中心** | 报关单、装箱单、CI、PL、产地证（CO/Form A/Form E）目前全靠 Word/Excel 手做，易错且慢 | 「单证中心」由装柜清单/销售订单自动生成并可导出 Excel/PDF |
| 10 | **业务模式开关 + 数据字典** | 一本账服务两种模式；币种汇率/港口/结算方式/价格条款/唛头/包装单位现在挤在"其他资料"里，字典不明 | 系统参数 + 「数据字典」统一维护 |
| 11 | **订单执行跟踪** | 一张订单状态 = 已下单/已采购/已到货/已验货/已装柜/已出运/已收汇，业务员和客户天天问 | 订单详情加"执行链路时间轴"（可由采购/入库/装柜/收款自动回填） |

### P1（提效与风控）

| # | 缺口 | 价值 |
|---|---|---|
| 12 | **验货单 QC**（结论 + 缺陷 + 照片 + 是否通过） | 义乌外商会指定第三方验货（SGS/BV）或自己来验；有照片证据能大幅减少索赔纠纷 |
| 13 | **出口方式与不退税场景**（0110 一般贸易 / **1039 市场采购** / 9610·9710 跨境电商 / 买单出口） | 义乌 1039 市场采购"无票免税"是主流玩法之一，报销与退税逻辑完全不同 |
| 14 | **退税台账**（退税率、可退金额、已退、函调状态） | 工贸一体与自营出口的利润里退税占比很大 |
| 15 | **库存盘点 / 调拨 / 预警** | 集货仓最容易"货找不着"；安全库存与呆滞预警能减少压货 |
| 16 | **供应商对账单 / 客户对账单** | 月结供应商（档口多为月结）对账靠 Excel，容易多付 |
| 17 | **物流跟踪**（提单号、船名航次、ETD/ETA/ATD/ATA、到港/清关/派送） | 客户最常问"柜到哪了"；也是延误索赔的依据 |
| 18 | **样品管理**（打样单、样品费、寄样记录、客户反馈） | 饰品/文具/圣诞用品打样频繁，样品费常单独结算 |
| 19 | **审批流**（金额阈值、多级审批：业务员 → 主管 → 财务 → 总经理） | 现在审核是"一次审核"，无金额分级，风控不足 |
| 20 | **发票管理**（增值税专票/普票、出口发票、退税发票关联） | 供应商开票直接影响退税与成本 |
| 21 | **多单位与箱规**（个/打/箱，1 箱 = X 打；外箱体积重） | 报价按"个"、采购按"打"、装柜按"箱"，没换算就只能人工算 |
| 22 | **汇率管理**（每日汇率、锁汇、汇兑损益） | 汇率波动 1% 就可能吃掉代理费 |
| 23 | **供应商比价**（同一需求向 3~5 家询价并比价表） | 代理采购的利润就来自比价，系统里应留痕 |

## 六、需要你确认的问题（决定开发范围与优先级）

1. **业务模式**：你是"工贸一体"、"纯代理采购"，还是两者都有？各占营业额比例大约多少？
2. **生产环节**：是真有自己车间/工人生产，还是主要**外发加工 + 自己组货**？（决定「生产管理」是重度还是轻量）
3. **出口方式**：主要走 0110 一般贸易、**1039 市场采购贸易**，还是**买单出口**？是否需要系统管**退税**？（这决定单证与税务模块的复杂度）
4. **拼柜情况**：是否经常一个柜拼多个客户？费用分摊你希望按**体积**、**金额**还是**箱数**（或可手工调整）？
5. **收款方式**：客户主要是 T/T 定金+尾款、还是 L/C 信用证？平均账期多久？（决定应收与账龄口径）
6. **供应商结算**：档口是**现结**还是**月结**？是否必须提供发票（专票/普票）？
7. **财务边界**：只需"业务台账 + 收付记录"，还是要**完整总账**（科目、凭证、三大报表）？是否需要与金蝶/用友对接？
8. **单证输出**：报关单、装箱单、CI、PL、产地证是要**系统直接导出 Excel/PDF**，还是要对接"单一窗口"等外部系统？
9. **主体数量**：是否有多个公司主体（如"工厂公司 + 代理出口公司"）需要分账套管理？
10. **审批层级**：单据审核是几个人？要不要按金额分级（如 <5 万主管即可、>5 万要老板）？
11. **移动端**：业务员在外是否需要手机查单/下单？仓库是否需要扫码？
12. **能否提供真实单据样本**：报价单、PI、装箱单、对账单各一份（Excel/Word 即可）—— 有样本可以**直接按你们的实际格式**做打印与导出模板，比通用设计更省事。

## 七、建议的实施路线（分 4 阶段，可逐段验收）

| 阶段 | 内容 | 预估工作量 | 影响面 / 风险 |

### 技术风险与注意事项（给开发侧的提示）

| 项 | 说明 |
|---|---|
| 菜单归属改动的连带影响 | `SysRoleMenus` 按 `MenuId` 关联，**新建一级菜单后必须给角色重新授权**，否则用户登录看不到；建议同时提供一段幂等授权 SQL（参考 `init5.sql` 的做法） |
| **菜单编码尽量不改** | 权限码（`PermissionCode`）、打印模板 `BillType`、前端 `CODE_ICON`/`BILL_CODE_MAP`/`EXPORT_MENU_MAP`、钉钉动作码都引用菜单编码 —— **只改名称最安全**，改编码会牵动多处 |
| 商品从「其他资料」拆出 | 该表现在用 `InfoType` 混装了商品与字典，拆分会影响基础资料导入导出、打印设计器字段映射，需要回归测试 |
| 新增必填字段 | 生产库已有历史数据，新字段一律**允许为空 + 后台给默认值**，避免老单据打不开 |
| 数据库升级 | 沿用现有 `SchemaUpgrader`（启动幂等升级）新增表/列；结构性改动（如装柜升级为多客户）建议**单独脚本 + 备份**，不要只靠自动升级 |
| 前端 | 新菜单编码需补 `CODE_ICON` 图标、`GROUP_EMOJI` 分组 emoji；侧栏已支持手风琴与隐藏滚动条，二级菜单变多不会撑破布局 |

## 八、我的推荐结论

1. **先做阶段 0**（纯菜单数据调整，半天）：立竿见影解决"菜单名不达意、商品被埋、客户/供应商藏太深"的问题，且零风险。
2. **紧接着做阶段 1 的 5 件事**（报价单、采购单归属、费用单、应收账龄、字段补齐）—— 这 5 件是"两种模式共用、且现在最靠 Excel 硬撑"的部分。
3. **代理模式优先做拼柜分摊 + 代理费结算**：这是纯代理模式的**利润与对账核心**，也是现有系统最明显的空白；工贸模式的「生产管理」建议单独立项、与你确认工序细节后再动。
4. **不要做两套系统**：一套单据 + 字段区分 + 按模式隐藏菜单，维护成本最低。
