# 装柜出运引用登记说明（ERP-057）

> 任务：`ERP-057` 为**既有**装柜链路记录（订柜信息 / 预装柜单 / 装柜清单）登记一条显式的**出运引用证据**
> （出运方式 / 订舱号 S/O / 提单号 B/L / 起运·中转·目的港 / 计划开船·到港时间 / 承运人 / 货代 / 拖车 /
> 报关行快照），并支持带修订留痕的修订与显式作废。
> 范围：`src/ERP.Domain`、`src/ERP.Application`、`src/ERP.Infrastructure`、`src/ERP.Api`、
> `src/ERP.UnitTests`、`docs/**`、`.ai/**`。
> 不改动任何 SQL 脚本、`deploy/**`、`release/**`、`checkpoints/**`、`SeedData*.cs`；
> **生产库执行、外部承运商 / 海关 / 货代对接、正式部署与发布仍由 Human Gate 控制**。
> 本次未启动 API、未连接 SQL Server、未执行任何 `.sql` / seed / 部署动作、未联系任何外部系统。

## 1. 背景与审计结论（为什么是「一套」而不是「第二套」）

装柜链路在仓库中**已有唯一的持久化引用关系**：

| 关系 | 持久化字段 |
|---|---|
| 预装柜单 → 订柜信息 | `ContainerPreLoading.BookingId` |
| 装柜清单 → 预装柜单 | `ContainerLoadingList.PreLoadingId` |
| 本套跟踪值的权威记录 | `ContainerBooking`（ERP-040 的出运方式 / B/L / S/O / 港口 / ETD·ETA·ATD·ATA / 拖车 / 报关行 / 查验 / 放行列） |

因此 ERP-057 **不**新建出运主数据、**不**复制订柜跟踪列、**不**在装柜三单上加列，也**不**按柜号 /
订单号 / 单证号等自由文本匹配任何记录。新增的只有**一套**登记册：

| 表 | 作用 |
|---|---|
| `ContainerShipmentReferences` | 出运引用证据（显式源记录 + 出运证据快照 + 状态 / 修订 / 作废留痕） |
| `ContainerShipmentReferenceRevisions` | 修订留痕（**只追加**的「修订前原值」快照） |

`ERP.UnitTests/ContainerShipmentReferenceTests.cs` 的
`ERP057审计_仓库只有一套出运引用模型_不改写装柜链路` 用源码 / 反射方式锁定该结论
（`IErpDbContext` 中只有一套「出运引用」模型、装柜三单没有新增任何出运证据列、
幂等升级段内不含任何 `ALTER TABLE` / `UPDATE` / `INSERT` / `DELETE`）。

## 2. 字段与快照口径（`ContainerShipmentReferences`）

| 项 | 口径 |
|---|---|
| `SourceType` | 显式 allowlist：`booking`（订柜信息）/ `pre-loading`（预装柜单）/ `loading-list`（装柜清单）；其他取值一律拒绝 |
| `SourceId` | 显式指向对应类型的一条**未删除**记录；不存在 → 404，已删除 → 400 规则冲突 |
| `SourceNo` / `SourceDate` / `SourceStatus` / `SourceStatusText` / `ContainerNo` | **服务端写入**的源记录快照（客户端提交值不被采信）；订柜信息无柜号 → 空串（= 未知） |
| `ShipmentMode` | `LCL` 拼箱 / `FCL` 整箱 / 空串 = 未知（其他取值一律拒绝，含大小写与首尾空白归一） |
| `ShippingOrderNo` / `BillOfLadingNo` | 用户录入的引用文本（≤ 50 字符）；**不是**订舱确认或提单正本 |
| `CarrierName` / `ForwarderName` / `TruckerName` | 自由文本（≤ 200 字符），仅作联系记录 |
| `DeparturePort` / `TransitPort` / `DestinationPort` | 自由文本（≤ 100 字符），空串 = 未知 |
| `PlannedDepartureAt` / `PlannedArrivalAt` | 可空计划时间（ETD / ETA）；有值时必须在 2000-01-01 ~ 2100-01-01 之间，且**计划开船不得晚于计划到港** |
| `CustomsBrokerId` / `CustomsBrokerName` | 引用「其他资料」中 `InfoType = CustomsBroker` 的字典项 + 服务端写入的名称快照（复用 ERP-040 口径） |
| `Remark` | 有界备注（≤ 500 字符） |
| `Status` | `1` 已登记（可修订 / 可作废）/ `2` 已作废（只读） |
| `RecordedAt` / `RevisionNo` / `LastRevisedAt` / `LastRevisionReason` | 登记时间 / 当前修订号（首次 = 1）/ 最近修订时间与原因 |
| `VoidedAt` / `VoidReason` | 作废时间与必填原因 |

**未知口径（贯穿全模块）**：未填写一律保持空串 / `null` 并显示「未知」，
**绝不**由柜型、体积、客户、航线、单据状态或任何自由文本推断出运方式、港口、日期或报关行。

## 3. 源记录关联口径

| 场景 | 结果 |
|---|---|
| 新增引用：`SourceType` + `SourceId` → 未删除的对应类型记录 | 正常登记，写入服务端快照 |
| `SourceType` 不在 allowlist（含空串 / 自由文本） | 400 参数校验失败（不静默忽略） |
| `SourceId` 指向不存在 / 已软删除的记录 | 404 / 400 规则冲突，不产生任何写入 |
| 同一源记录已有**有效**引用 | 400 重复（提示改为修订或先作废），不静默覆盖 |
| 修订时提交不同的 `SourceType` / `SourceId` | 400 参数校验失败：**不允许改派**（如需指向别的柜请新建引用并作废旧的） |
| 修订时未提交源记录字段 | 视为「保持原样」，不视为改派 |
| 源记录后来被软删除 / 改名 | 历史证据照常可读，`SourceAvailable = false` 且显式标注不可用；快照值不回填、不改写 |
| 按文本匹配（柜号 / 订单号 / 单证号） | **永不发生**：系统只按显式类型 + Id 关联 |

## 4. 修订与作废（可审计的留痕）

1. **修订**（`PUT /{id}`，必填原因 ≤ 200 字符）：服务端先把**修订前的原值逐列**写入
   `ContainerShipmentReferenceRevisions`（含被取代的修订号、时间、原因），再写回新值并把
   `RevisionNo` +1、更新 `LastRevisedAt` / `LastRevisionReason`；校验失败时留痕与新值**都不落库**。
2. **作废**（`POST /{id}/void`，必填原因 ≤ 500 字符）：只改状态与作废留痕，保留全部证据字段、
   源记录快照与全部修订留痕；**重复作废被拒绝**；不提供硬删除。
3. **作废后可重新登记**：过滤唯一索引 `UX_ContainerShipmentReferences_ActiveSource`
   （`SourceType + SourceId`，过滤 `IsDeleted = 0 AND Status <> 2`）只约束**有效**行，
   已作废行不再占用额度，新旧并存可查。
4. 修订留痕表**只追加**：唯一索引 `UX_ContainerShipmentReferenceRevisions_Reference_Revision`
   保证同一引用内修订号不重复，且不提供任何修改 / 删除接口。

## 5. 接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/container/shipment-references` | 出运引用台账（分页，有界）：源记录类型 / Id、状态、出运方式、登记日期区间、关键字过滤 |
| `GET` | `/api/container/shipment-references/{id}` | 详情：当前证据 + 只读标注 + 有界修订留痕（超出显式说明截断） |
| `GET` | `/api/container/shipment-references/{id}/revisions` | 修订留痕（按修订号倒序，最多 50 条） |
| `GET` | `/api/container/shipment-references/source-candidates` | 可登记源记录候选（只读、有界；标注是否已有有效引用） |
| `GET` | `/api/container/shipment-references/customs-broker-options` | 报关行下拉选项（复用 ERP-040 口径，只读） |
| `POST` | `/api/container/shipment-references` | 登记出运引用证据 |
| `PUT` | `/api/container/shipment-references/{id}` | 修订（必填原因，先写留痕再写新值） |
| `POST` | `/api/container/shipment-references/{id}/void` | 作废（必填原因，保留历史） |

**读取性能口径**：台账按页返回（默认 50 / 上限 200）；单页内的源记录可用性、报关行可用性与修订条数
一律**批量装载**（分组计数 1 次 + 按源记录类型最多 3 次 + 报关行 1 次），**无逐行数据库访问**。

## 7. 边界（本任务明确不做的事）

1. **不改写装柜链路**：不改订柜信息 / 预装柜单 / 装柜清单的任何列、状态与工作流，
   不推进装柜状态、不改柜号、不写任何单据号。
2. **不改写任何下游记录**：销售订单、采购订单、库存与库存成本、库存流水、单证中心、
   发票、费用与分摊、收付款、税务与结算记录一概不写。
3. **不触达外部系统**：不调用船公司、海关、报关行、货代或任何跟踪 / 订舱服务，也不做 EDI / API 对接。
4. **不做生产回填 / 迁移**：不为历史订柜补出运引用，不迁移历史单据（历史记录保持可读，可直接登记新引用）。
5. **不新建出运主数据**：不建第二套订柜 / 出运主表，不在装柜三单上加列（审计结论见第 1 节）。
6. **不做推断与派生**：不由柜型 / 体积 / 客户 / 航线 / 单据状态推演出运方式、港口、日期或报关行；
   不由自由文本匹配源记录。
7. **不提供硬删除与静默替换**：更正只走显式修订（保留原值）或显式作废（必填原因）。
