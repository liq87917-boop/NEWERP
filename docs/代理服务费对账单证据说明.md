# 代理服务费对账单证据说明（ERP-070）

## 1. 背景与定位

**目标**：在 ERP-069 代理服务费**协议证据**（商业条款）之上，为**客户侧代理服务**提供一份可审计的
**代理服务费对账单证据登记册** —— 把授权用户**显式提供**的对账内容（对账单号 / 权威客户 / 币种 / 对账日期 /
**可选**到期日 / 服务期间 / 显式关联的协议 / 一条或多条**显式服务来源引用行**）登记为仓库内证据，
并可显式登记与作废。

**定位（重要）**：本登记册是**仓库内操作性费用证据**：

- **不是**税务发票（不开票、不连税务平台、不作废真实发票）；
- **不是**具有法律效力的客户对账单确认（不向客户发出、不取得客户签认）；
- **不是**收入确认（不做收入 / 成本 / 期间归属判断）；
- **不是**付款通知或催款函（不催收、不联系客户、不发送任何消息）；
- **不是**结算 / 核销确认（不改写任何收款、应付 / 应收、余额或结算记录）；
- **不是**会计凭证或总账记账分录（不记账、不生成凭证 / 收付款 / 结算单）。

**与相邻模型刻意分离**：客户销项发票证据（ERP-055）、收款单及其引用行（ERP-046 / ERP-060）、
业务员提成报表（`/api/reports/sales-commission`，比例取自系统参数 `SalesCommissionRate`）都是**各自独立的模型**：
本登记册既不读取、也不改写、也不派生它们，登记 / 作废对账单**不会改变它们的任何结果**。

## 2. 新增前的既有模型审计（acceptance criterion 1）

在新增本模块之前，对仓库内既有「客户对账 / 服务费 / 结算」相关模型逐项审计（只读比对 Domain / Application /
Infrastructure / Api / wwwroot / 测试与 `SchemaUpgrader.cs`），结论如下：

| 既有模型 | 实际口径 | 是否可作为「代理服务费对账单」权威模型 |
|---|---|---|
| ERP-069 `AgencyServiceFeeAgreements` | 客户代理服务费的**商业条款证据**（协议号 / 生效区间 / 币种 / 计费方式与费率或固定金额 / 计费依据） | **否**：它是**条款**，没有对账日期、服务期间、逐笔服务来源、行证据与合计；本模块把它作为**显式关联的只读依据** |
| 客户销项发票证据（ERP-055 `CustomerSalesInvoiceEvidences`） | 销项发票（普票 / 专票 / 出口发票）的**发票证据**与分摊 | **否**：发票口径，不是服务费对账；本模块不开票、不引用发票 |
| 收款单 + 收款引用行（`FinanceReceipts` / `CustomerReceiptAllocations`） | 客户收款与到账引用 | **否**：资金口径，不是费用对账；本模块不收款、不改写 |
| 客户对账 / 账龄工作台（ERP-068 供应商对账为只读派生） | 只读派生报表，无新增表 | **否**：报表不承载逐笔证据与解除留痕 |
| 单证中心 `TradeDocuments` | 出口单证（商业发票 / 装箱单等）的商业文本 | **否**：单证口径，不承载服务费条款与行证据 |
| 业务员提成表（`GET /api/reports/sales-commission`） | 内部报表：比例取自系统参数 `SalesCommissionRate`，按毛利计算 | **否**：内部提成核算，与客户代理服务费对账无关，也不得互推 |

**结论**：仓库内**不存在**「代理服务费对账单」的权威模型，也不存在可与对账行混用的既有字段，因此
**新增一个独立的证据模型**（表头 + 行两张表）：

- 不替换、不复制、不合并上述任一模型；
- 不再向客户 / 销售订单 / 装柜清单 / 协议 / 发票 / 收款 / 库存 / 费用等既有表加任何列（**无 `ALTER TABLE`**），
  也不做任何历史回填；
- 与业务员提成报表、发票与收款口径**物理隔离**（各自的表、各自的规则、无派生关系）。

## 3. 表头字段与校验口径

| 字段 | 口径 |
|---|---|
| `StatementNo` | 对账单号，必填，≤50 字符，去首尾空白；由用户按真实对账单填写，**系统不自动发号、不做格式猜测** |
| `NormalizedStatementNo` | 规范化对账单号（唯一身份判定用，服务端写入）：去掉所有空白与 `-` / `－` / `—` / `_` 后大写 |
| `CustomerId` + `CustomerCode` / `CustomerName` 快照 | 新增 / 修改时客户必须**存在、未删除且启用**；编码与名称快照由**服务端写入**，客户端提交的同名字段不被采信 |
| `Currency` | 币种，必须来自系统币种口径（CNY / USD / EUR / HKD / GBP / JPY）并规范化为大写；金额一律以**原币**记录 |
| `StatementDate` | 对账日期，必填（**必须显式填写**，系统不按当天、订单或来源单据日期推算），只取日期部分 |
| `DueDate` | 到期日，**可选**持久化证据：留空 = **未知**（保持 `NULL`，系统不按客户账期 `CreditDays`、协议文字、对账日期或历史对账单推算）；填写时不得早于对账日期 |
| `ServicePeriodFrom` / `ServicePeriodTo` | 服务期间起止，**均必填**（不按对账日期或行来源日期推算），结束不得早于起始（不静默调整） |
| `AgreementId` + `AgreementNo` / `AgreementCurrency` / `AgreementCustomerId` / `AgreementFeeMethod` / `AgreementTermsText` | 显式关联的 ERP-069 协议证据：必须**存在、未删除且为「已登记」**（草稿 / 已作废拒绝），且**协议客户 = 对账单客户**、**协议币种 = 对账单币种**；协议号 / 条款文案只作**只读快照** |
| `TotalAmount` | **服务端计算**的有效行金额合计（DECIMAL(18,2)，按币种精度对已校验行求和）；请求模型**没有任何合计字段**，客户端无法提交被信任的合计 |
| `Status` | 0 草稿 / 1 已登记 / 2 已作废 |
| `RecordedAt` / `RecordedBy` | 登记时间与登记人：登记时由服务端写入；登记人来自**已认证身份**（缺失记「未知用户」），长度 ≤100；作废不改写它们 |
| `VoidedAt` / `VoidReason` | 作废时间与作废原因（作废必填、≤500 字符）：保留原始行与全部快照，不硬删除、不静默改写 |
| `Remark` | 备注，≤500 字符（仅人工留痕，不参与任何金额派生） |

## 4. 服务来源链接：显式标识符，绝不猜测（acceptance criterion 2）

每一行只按 **来源类型 + 来源记录 Id（持久化标识符）** 引用一条**既有的**服务来源记录：

| 来源类型 | 目标表 | 自带客户 | 自带币种 | 判定口径 |
|---|---|---|---|---|
| `sales-order`（销售订单） | `SalesOrders` | 是（`CustomerId`） | 是（`Currency`） | **客户与币种都会被校验**：与对账单客户 / 币种不一致即拒绝（不做汇率换算） |
| `loading-list`（装柜清单） | `ContainerLoadingLists` | 是（兼容主客户字段 `CustomerId`） | **否**（该表没有币种列） | 客户兼容性按**兼容主客户字段**校验（**不按参与方行推断归属**）；币种校验对该来源**不适用**，照实标注而不替它补一个币种 |

**绝不猜测**：本模块**不**按单号文本、金额、日期或相似度匹配来源，**不**提供「自动关联 / 推荐来源」入口，
**不**把来源单据金额、协议费率或客户默认值折算成行金额；来源不存在 / 已删除 / 已取消一律拒绝（历史行仍可读）。

来源快照（单号 / 日期 / 状态码与状态文案 / 客户 / 币种）全部由**服务端按来源记录写入**，
请求模型不含这些字段（客户端提交的同名字段不被采信）。

## 5. 行证据：显式、有界、不派生（acceptance criterion 4）

| 字段 | 口径 |
|---|---|
| `LineNo` | 行号，服务端按提交顺序从 1 起连续编号（不允许跳号或重复） |
| `SourceType` / `SourceId` | 显式来源类型（allowlist）与来源记录 Id；Id ≤ 0 一律拒绝 |
| `SourceNo` / `SourceDate` / `SourceStatus` / `SourceStatusText` / `SourceCustomerId` / `SourceCustomerCode` / `SourceCustomerName` / `SourceCurrency` | 服务端写入的来源快照（`SourceCurrency` 为空串 = 来源不携带币种） |
| `Description` | 行说明，必填 ≤200 字符（仅人工留痕，服务端不据此计算金额） |
| `BasisQuantity` | 计费基础数量快照，**可选**（DECIMAL(18,4)，4 位小数、0.5 进位）：留空 = **未知**，不从来源单据数量推算；绝对值超上限拒绝 |
| `BasisNote` | 计费基础说明，必填 ≤200 字符（说明数量 / 口径来自哪里，服务端不据此计算金额） |
| `Amount` | 行金额，必填（DECIMAL(18,2)）：按对账单币种精度取整后**必须大于 0**；**只来自用户显式提交** |
| `Currency` | 与对账单币种一致（冗余保存，便于按币种有界检索） |
| `Remark` | 行备注，≤500 字符 |
| `Status` | 与所属对账单同步：0 草稿 / 1 已登记 / 2 已作废 |

**不从任何地方折算费用**（服务端权威）：当前协议费率 / 协议固定金额、客户账期与默认值、来源单据金额、
自由文本、历史对账单、金额相似度都**不会**被转换成行金额；界面上也刻意**不回显来源单据金额**
（避免任何「按相似度猜费用」的暗示）。

## 6. 金额与合计口径（acceptance criterion 5）

- 行金额按**币种精度**取整（见唯一的币种金额口径 `CurrencyAmountRules`：JPY / KRW / VND / IDR 为 0 位小数，
  其余 2 位；固定 0.5 进位）并校验 `0 < 金额 ≤ 上限`；
- **合计由服务端计算**：对**已校验的持久化行金额**按币种精度求和并写入 `TotalAmount`；
  登记时也会按当时持久化的行金额**重算**合计（登记 = 冻结 + 重算）；
- **客户端无法提交合计**：`AgencyServiceFeeStatementSaveDto` 没有任何合计字段，
  `TotalAmount` 与 `TotalAmountText` 都是服务端产物；
- 金额一律**原币**：不做汇率换算、不跨币种合并（跨币种对账必须分别登记）。

## 7. 唯一性与重复计费保护（acceptance criterion 6）

| 规则 | 实现 | 口径 |
|---|---|---|
| 对账单身份唯一 | `UX_AgencyServiceFeeStatements_ActiveIdentity`（`CustomerId, NormalizedStatementNo`，过滤 `IsDeleted = 0 AND Status <> 2`） | 同一「客户 + 规范化对账单号」在**未作废**记录内唯一；**草稿同样占用身份**；不同客户可使用相同对账单号；作废记录保留可读但不占用身份（可重新登记） |
| 对账单**内**重复来源 | 服务层请求内去重（`HashSet` 精确键 `sourceType\|sourceId`） | 同一提交中重复引用同一来源 → `Duplicate` 拒绝（不合并、不忽略） |
| **重复计费证据**（跨对账单） | `UX_AgencyServiceFeeStatementLines_ActiveSource`（`SourceType, SourceId`，过滤 `IsDeleted = 0 AND Status <> 2`）＋ 服务层一次查询预检 | 同一来源同时只能被**一条未作废对账单行**引用；**草稿行同样占用来源身份**，作废后被释放；重复一律拒绝，**绝不改派、不合并、不覆盖** |

## 8. 到期日：可选、持久化、不推算（acceptance criterion 7）

- `DueDate` 是**显式持久化证据**：填写即照实保存（只校验不得早于对账日期）；
- 留空时**保持 `NULL`**，读取侧显式显示「未提供（到期日未知：不由客户账期、协议或对账日期推算）」；
- 服务端**不**读取客户 `CreditDays`、协议文字、对账日期或历史单据来补一个到期日，
  界面上也不预填任何日期。

## 9. 状态机、冻结与作废保留（acceptance criterion 8）

| 状态 | 允许的操作 | 冻结口径 |
|---|---|---|
| 0 草稿 | 修改（`PUT`）、登记（`POST /record`）、作废 | 可编辑；替换行时原草稿行**软删除**（保留可审计痕迹，**不物理删除**），新行重新校验并重新编号 |
| 1 已登记 | 作废 | 表头与**全部行**冻结：不可修改、不可重复登记；登记人 / 登记时间由服务端写入 |
| 2 已作废 | **无**（只读） | 保留对账单身份、全部原始行、来源快照、客户与协议快照、登记人与时间戳、原始金额与合计；作废原因必填 |

- 作废对账单会**同步作废**其全部有效行（行状态 → 2），并**释放来源身份**（该来源可被新对账单重新显式引用）；
- 作废**不**改写原始行金额、不删除记录、不静默替换；重复作废一律拒绝；
- 行与表头的读取侧可用性标注（来源 / 客户 / 协议）都是**只读标注**：来源或协议或客户之后被取消、软删除、
  改名或作废时，历史行仍按登记当时快照可读，**绝不改派**到别的记录。

## 10. 非变更边界（本模块不改写什么、不做什么）

- **只读写两张表** `AgencyServiceFeeStatements` / `AgencyServiceFeeStatementLines`；
  不建第二张关联表以外的对象、不加列、不建外键、不建导航属性；
- **不改写**：ERP-069 协议证据（含费率 / 固定金额 / 状态 / 登记人）、客户主数据（含账期 / 信用额度 / 信用状态 / 佣金比例）、
  销售订单（含金额 / 状态 / 佣金比例 / 明细）、装柜与装柜清单（含柜号 / 状态 / 参与方）、单证中心、客户销项发票证据、
  收款单及其引用行、库存与库存成本、库存流水、费用与分摊、退税、结算与余额记录；
- **不执行**：开票 / 作废发票、报税、记账 / 生成凭证、收款 / 付款、催收 / 联系客户、调用任何外部服务
  （无 HTTP 调用、无消息推送、无 OSS / 税务平台访问）；
- **不做**：法律判断、收入确认、汇率换算、跨客户合并、跨币种合并、按相似度匹配来源或协议。

## 11. 接口与界面

| 接口 | 说明 |
|---|---|
| `GET /api/agency-service-fee-statements` | 台账（分页、有界）：客户 / 协议 / 状态 / 币种 / 来源类型 / 对账日期区间 / 关键字过滤；默认含已作废历史；**列表只返回行数摘要** |
| `GET /api/agency-service-fee-statements/{id}` | 详情（含**全部有界行清单**、来源快照与可用性标注、同源口径文案） |
| `GET /api/agency-service-fee-statements/metadata` | 元数据：来源类型 / 状态白名单、支持币种、有界额度与口径文案 |
| `GET /api/agency-service-fee-statements/source-options` | 来源候选（**有界**）：必须显式给出客户与币种；只返回未删除来源，逐条给出资格文案；关键字只匹配单号；**不回显来源金额** |
| `POST /api/agency-service-fee-statements` | 新增草稿（校验客户 / 协议 / 日期 / 服务期间 / 每条显式来源行 / 行证据，服务端计算合计） |
| `PUT /api/agency-service-fee-statements/{id}` | 修改草稿（已登记 / 已作废拒绝；原草稿行软删除替换） |
| `POST /api/agency-service-fee-statements/{id}/record` | 登记（冻结表头与行、按持久化行金额重算合计、写入登记人与时间） |
| `POST /api/agency-service-fee-statements/{id}/void` | 作废（原因必填；保留原始行与全部快照；同步作废行并释放来源身份） |

界面：`src/ERP.Api/wwwroot/js/agency-service-fee-statements.js` + `modules.js`（客户资料工具栏「📄 服务费对账单」与
客户行操作），入口 `openAgencyServiceFeeStatementRegister(customerId)`；页面含台账、草稿表单（表头 + 行编辑区，
来源候选按类型过滤且不可引用的来源被禁用并给出原因）、详情与作废视图，并在界面显式声明本册的边界与口径。
