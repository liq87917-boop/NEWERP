# 供应商对账与账龄工作台说明（ERP-068）

> 本文档描述 **ERP-068** 交付的**只读**供应商对账与账龄工作台：它在本系统**已经登记**的
> 供应商采购发票证据（ERP-043 / ERP-065）与「付款单 → 采购发票」引用证据（ERP-066）之上，
> 按「供应商 + 币种」给出**含税总额证据 / 有效已分配证据 / 算术剩余证据**，并按**显式到期日**与
> **显式 as-of 日期**计算互斥账龄桶。
>
> 它是**仓库对账口径的证据视图**：**不是**总账或应付账款余额、**不是**经审计的法定供应商对账单、
> **不是**付款授权与付款执行依据、**不是**税务（进项）申报与抵扣判断、**不是**结算确认或核销结果，
> 也**不产生**任何记账、凭证、收付款或结算单。

## 1. 定位与来源

| 维度 | 来源 | 说明 |
|---|---|---|
| 发票证据 | `PurchaseInvoices`（ERP-043 / ERP-065） | 类型 / 代码 / 号码 / 开票日期 / 供应商快照 / 币种 / 净额 / 税额 / **含税总额** / 状态 / **可选显式到期日** / 付款条件 |
| 已分配付款引用证据 | `SupplierPaymentInvoiceAllocations`（ERP-066） | 「某张既有付款单把多少钱指向了这张发票」的持久化引用行（含有效 / 已作废状态与快照） |
| 供应商可用性 | `BaseSuppliers` | 只读标注（存在 / 未删除 / 启用）；快照永远可读，**不回填** |

- 发票 → 采购订单的关联（ERP-043）与付款 → 采购订单的引用（ERP-049）**不参与**本工作台的金额派生：
  本工作台只做「发票维度」的对账（发票含税总额 vs 付款引用到发票的金额），
  避免把不同证据维度的金额相加。
- 本轮**不新增任何表、不新增任何列、不做任何回填**（见 §10）。

## 2. 三类证据与算术口径（严格分列、绝不轧差）

| 证据 | 口径 | 未知处理 |
|---|---|---|
| ① 含税总额证据 | 发票持久化 `GrossAmount`（价税合计，原币） | 发票行本身完整加载，**恒可确认** |
| ② 有效已分配证据 | 只统计**未作废**、且经 **ERP-066 行级资格判定**通过（付款单可用、发票仍为已登记、金额与快照自相一致、币种与供应商一致）的引用行合计；复用 ERP-067 的同一套分桶实现，**不新增第二套对账算法** | 命中系统有界上限时为 `null`（未知），**绝不给部分合计、绝不用 0 顶替** |
| ③ 算术剩余证据 | ① − ②（原币）；只有①与②都可确认时才给出 | ②未知 → ③未知；②&gt;① → 按**无效证据**显示，③未知（**绝不轧为 0、绝不视为已结清**） |

- 没有任何持久化引用行的发票 = **证据缺口**（`none`），显示为「无」而不是「未知」，
  也**不代表**未付款、已付款、已结清、逾期或欠款。
- 历史 / 无效 / 无法确认的引用行（已作废 / 发票失效 / 供应商或币种或快照不一致 / 付款单或发票已删除）
  一律**保持可见**（条数与金额单独成列），**绝不并入有效合计**，也**不被修复、改派、重算或合并**。
- 草稿与已作废**发票**单独标注，且其金额**不参与**任何有效应付证据合计与账龄桶合计；
  发票仍为草稿 / 已作废时，指向它的引用行按「发票已失效」单列。

## 3. 账龄口径（只按显式到期日与显式 as-of 计算）

- 账龄**只对登记了显式到期日**的发票计算；逾期天数 = **as-of 日期 − 到期日**（按日期，不按时分秒）。
- 五个桶**互斥且完整**（边界取含，即 30 / 60 / 90 天归入本桶，次日起归入下一桶）：

| 分桶 | 判定 | 文案 |
|---|---|---|
| `not_due` | 逾期天数 ≤ 0（as-of ≤ 到期日，含恰好到期当天） | 未到期（as-of ≤ 显式到期日） |
| `overdue_1_30` | 1 ≤ 逾期天数 ≤ 30 | 逾期 1 ~ 30 天 |
| `overdue_31_60` | 31 ≤ 逾期天数 ≤ 60 | 逾期 31 ~ 60 天 |
| `overdue_61_90` | 61 ≤ 逾期天数 ≤ 90 | 逾期 61 ~ 90 天 |
| `overdue_over_90` | 逾期天数 &gt; 90 | 逾期 90 天以上 |

- as-of 日期是**显式参数**（界面提供「账龄基准日」输入；未提供时取当天）；年份 &lt; 1900 的取值直接拒绝。
  同一个 as-of 下结果可**逐张复算**（每行回显逾期天数与分桶文案）。
- 账龄桶合计**只统计计入有效应付证据合计的发票**（草稿 / 已作废不进桶）。
- 典型示例：`asOfDate` 前一天到期 → 逾期 1 天（`overdue_1_30`）；到期日为 as-of 之后 5 天 → 未到期且回显「尚有 5 天」。

## 4. 「未知到期日」独立分组

- 到期日为空 → 账龄**不计算**：该发票进入**独立的「未知到期日」分组**（仍按「供应商 + 币种」隔离），
  分组给出张数、含税总额、有效已分配、算术剩余与发票身份清单（有界：只含本次返回页）。
- 系统**绝不**按开票日期、付款条件（自由文本）、供应商默认账期或历史发票**推算**到期日，
  也**不把**未知到期日当作「当天到期」或「已逾期」。
- 未知到期日的发票**不并入**任何账龄桶合计；到期日区间筛选**只命中**登记了到期日的发票
  （未知到期日的发票既不在区间内、也不在区间外 —— 属口径内行为，界面显式提示）。

## 5. 分配状态：派生行状态与可用筛选

| 状态 | 含义 | 可作为筛选 |
|---|---|---|
| `none` | 没有任何持久化引用行（**证据缺口**） | ✅ |
| `historical_only` | 没有有效引用行，但存在历史 / 无效引用行（保留可见） | ✅ |
| `partial` | 0 &lt; 有效引用行合计 &lt; 含税总额 | ✅ |
| `full` | 有效引用行合计 ≥ 含税总额 | ✅ |
| `over_allocated` | 有效引用行合计 &gt; 含税总额（与源规则矛盾 → **无效证据**，剩余按未知） | ❌ 仅行状态可见 |
| `unknown` | 命中系统有界上限，聚合不完整（金额与计数按未知） | ❌ 仅行状态可见 |

- 筛选全部**只用持久化字段**（含税总额与持久化引用行的状态 / 金额 / 存在性）在数据库侧判定，
  **无逐行查库**；`over_allocated` 与 `unknown` 需要 ERP-066 行级资格判定与有界上限判定，
  因此只作为**读取时派生的行状态**出现，不提供为筛选（口径与《供应商付款关联采购发票说明.md》同源）。

## 6. 币种隔离（绝不合并、绝无跨币种总额）

- 所有金额（含税总额、有效已分配、算术剩余、账龄桶合计）一律按**原币**分别成行：
  分组键 = 「供应商 + 币种」，币种汇总每个币种一行。
- **不存在**任何跨币种总额字段：接口模型与界面都不提供「全部币种合计」，也**不**使用当前汇率或猜测汇率
  （只有源证据本身已持久化的权威换算才会被采用；本工作台不使用任何换算）。
- 同一供应商的不同币种**分别成组**，互不相加、互不折算。

## 7. 授权与 fail closed（明细）

打开单张发票的对账与账龄证据明细（`GET /api/purchase-invoices/reconciliation-aging/invoices/{invoiceId}`）时：

1. **身份**：缺少登录用户 Id → 未认证错误（`2000`），不返回任何证据；
2. **模块授权**：复用**既有**的「角色 → 菜单」口径（`SysUserRoles` → `SysRoleMenus` → `SysMenus.MenuCode`，
   忽略按钮型菜单与被删除的授权），本轮要求 `purchase-order`（采购订单模块，与 ERP-061 ~ ERP-067 的工作流同源）；
   未获授权 → 权限不足（`2002`），不返回任何证据；授权每次请求都**重新查询**，回收后立即收敛；
3. **来源**：发票必须存在且未删除；不存在 / 已删除 → 不存在错误（`1002`），**不做修复、不改派、不编造**；
4. 明细行与列表行**完全同源**（同一派生方法），因此界面在列表与明细之间不会出现两套口径。

以上任一条不满足都**不返回部分证据**（fail closed）；界面在拒绝时只显示拒绝原因与 fail-closed 说明。

## 8. 接口与前端入口

| 项 | 内容 |
|---|---|
| 报表 | `GET /api/purchase-invoices/reconciliation-aging?supplierId=&currency=&invoiceId=&invoiceStatus=&allocationState=&invoiceDateFrom=&invoiceDateTo=&dueDateFrom=&dueDateTo=&asOfDate=&keyword=&page=&pageSize=` |
| 明细 | `GET /api/purchase-invoices/reconciliation-aging/invoices/{invoiceId}?asOfDate=`（重新校验身份与模块授权，fail closed） |
| 授权 | 与供应商采购发票登记册相同：控制器的类级 `[Authorize]`（JWT）+ 上文的模块授权复核；未提供任何匿名入口 |
| 前端 | `wwwroot/js/supplier-reconciliation-aging.js`（工作台页）、`index.html`（脚本注册）、`modules-doc.js`（采购订单工具栏「🧮 对账与账龄」）、`modules.js`（供应商行操作「对账与账龄」，按该供应商预筛选） |
| 导出 | 前端 CSV 导出（`exportSraCsv`）与屏幕**同一份数据**：同一筛选、同一分页、同一币种隔离、同一「未知到期日」分组；**不含**跨币种总额，也不写「应付 / 欠款 / 逾期确认 / 已对账」等法律或账务断言 |

## 9. 有界读取与性能口径

- 单页最多 **200** 张发票（默认 50）；关键字 ≤ 50 字；供应商 / 币种 / 发票状态 / 分配状态 / 日期区间
  的非法取值**一律拒绝**（不静默忽略筛选条件）。
- 每次查询为**固定 7 次数据集访问**：发票（筛选与分页共用 1 次 + 本页装载 1 次）、本页供应商、
  ERP-066 引用行、发票、付款单、付款单侧有效引用合计（后 4 次来自 ERP-067 的复用入口）；
  **与发票张数 / 引用行数无关，无逐行查询（N+1）**。
- 命中系统有界上限（单页发票 &gt; 500 张或引用行 &gt; 5000 条）时，分配证据金额与计数一律按「未知」返回，
  **不给部分合计**，并在报表文案中说明原因（含税总额因发票行完整加载仍可确认）。
- 全程只读：没有一次写入（单元测试断言 `SaveChanges` 调用次数为 0，并对来源表做前后快照比对）。

## 10. 数据库与幂等升级

- 本轮**不改动数据库结构**：不新增表、不新增列、不新增索引、不做任何回填，也**不修改** `SchemaUpgrader`。
- 只读取既有 `PurchaseInvoices`、`PurchaseInvoiceAllocations`、`SupplierPaymentInvoiceAllocations`、
  `FinancePayments`、`BaseSuppliers`、`SysUserRoles` / `SysRoleMenus` / `SysMenus`。
- 生产库的任何变更、执行与发布仍受 Human Gate 控制（见《部署交付文档.md》）。

## 12. 明确的边界（不得越界使用）

- **不是**总账 / 应付账款余额：本工作台不判断是否欠款、不产生凭证或记账；
- **不是**法定供应商对账单：未经供应商确认，也不构成任何法律意义上的对账结论；
- **不是**付款授权或付款执行依据：「剩余证据」「逾期天数」都**不得**作为付款、拒付或催收的依据；
- **不是**税务申报 / 抵扣判断：不做进项认证、税负计算或抵扣判断；
- **不是**结算确认或核销结果：不核销发票、不结清任何单据，也不改写任何来源记录；
- 「未知」与「无效」是**如实呈现的证据状态**，**不是**「未付款」「已付款」「已结清」「可抵扣」的同义词。
