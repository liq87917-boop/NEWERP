# 销售退货订单影响（ERP-101）说明

## 1. 目的

销售订单退货影响是一个**只读派生**视图：针对一张销售订单，按**显式链接链**派生「毛出货 / 有效退货 / 净出货」的运营证据，用于判断退货对该订单已出货数量的影响。

显式链接链（不按单号文本、金额或相似度推断）：

- 销售退货 → 来源销售出库单：`SalesReturn.SourceStockOutId` → `StockOut.Id`
- 销售出库单 → 销售订单：`StockOut.SalesOrderId` → `SalesOrder.Id`

## 2. 接口

- `GET /api/sales-orders/{id}/return-impact`（行操作「退货影响」）
- 只读：仅有 `GET`，不写任何表、不执行迁移 / 生产 SQL / 真实数据库操作 / 部署，不改写订单任何已登记进度（出货与收款进度等）。

## 3. 派生口径

### 3.1 毛出货（GrossShipped）

只统计「以本单为来源、未删除、已审核」的销售出库明细数量，与 ERP-032 出货口径一致：

- `StockOut.SalesOrderId == 本订单` 且 `!IsDeleted` 且 `Status == Approved` 的出库明细数量，按商品汇总；
- 待提交 / 已提交出库不计入；已驳回 / 已取消 / 已删除不计入。

### 3.2 有效退货（ValidReturned）

只统计「来源出库单属于本单且未删除、退货已审核、客户与本单一致」的销售退货明细数量：

- `SalesReturn.SourceStockOutId` 指向本单的**未删除**出库单；
- `SalesReturn.Status == Approved`；
- `SalesReturn.CustomerId == 本订单.CustomerId`。

### 3.3 净出货（NetShipped）

`净出货 = 毛出货 − 有效退货`，**不静默钳制**：

- 退货超过出货时净额为负，并标记「超退」异常（`over_return`）；
- 零与未知严格区分：零是真实 `0`；未知是 `null`（命中派生上限），绝不回落为 0。

## 4. 异常退货（不计入净额）

以下退货一律作为异常**单列**，绝不推断为对某个商品 / 单据的扣减：

| 分类 | 代码 | 判定 |
| --- | --- | --- |
| 未审核 | `non_approved` | 来源出库单存在且未删除，但退货本身未审核（待提交 / 已提交 / 已驳回 / 已取消） |
| 客户不一致 | `wrong_customer` | 退货已审核但客户与本单客户不符 |
| 来源已删除 | `missing_source` | 退货的 `SourceStockOutId` 指向本单的已删除出库单（链接悬空） |
| 来源不属于本单 | `unmatched` | 退货的 `SourceStockOutId` 指向其它订单的出库单 |
| 未关联来源 | `unlinked` | 退货的 `SourceStockOutId` 为空，无法按显式链接归属 |

## 5. 有界读取

单张订单固定 7 次数据集访问（订单 / 出库单 / 出库明细 / 关联退货 / 异常退货 / 退货明细 / 客户名称），无逐单、逐行查库。命中集合上限（出库单 / 退货各 200，明细各 2000）时，数量一律返回 `null`（未知），并置 `Truncated = true`。

## 6. 边界

- 不是库存成本、库存台账或应收账款结论：不改写库存、库存流水、出货进度或收款记录；
- 不改写订单任何已登记进度字段；
- 不执行迁移 / 生产 SQL / 真实数据库操作 / 部署。

## 7. 测试

`ERP.UnitTests/SalesOrderReturnImpactTests.cs` 覆盖：毛出货 / 有效退货 / 净出货派生、链接状态、审核状态、删除、超退不钳制、客户不一致、来源已删除 / 来源不属于本单 / 未关联来源的异常、只读不写库、订单不存在、接口端点、路由只读、前端接线、有界读取。
