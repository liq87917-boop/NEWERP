# 代理服务费收款分摊证据说明（ERP-071）

## 1. 背景与定位

系统里已经有客户**收款单**（`FinanceReceipt`：收款单号 / 日期 / 客户 / 金额 / 币种 / 付款方式 / 银行账户 / 状态），
也有 ERP-070 的**代理服务费对账单证据**（`AgencyServiceFeeStatements` + `AgencyServiceFeeStatementLines`：对账单号 /
权威客户 / 币种 / 对账日期 / 可选到期日 / 服务期间 / 显式关联的 ERP-069 协议 / 显式服务来源行 / **服务端合计**）。
但两者的权威口径里都**没有**任何「收款 → 对账单」的持久化引用：

- ERP-070 对账单证据只有客户、服务来源与合计，**没有任何收款级引用**；
- ERP-053 的 `CustomerReceiptAllocations` 是**收款单 → 销售订单**的引用（另外一套维度），
  与代理服务费对账单口径不同（引用对象、金额含义与判定资格都不同）。

因此用户没有任何办法**显式登记**「这笔收款对应哪几笔代理服务费对账」。

**ERP-071 的审计结论（对应验收项 1）**：仓库里既有的客户收款证据（`FinanceReceipt`）与 ERP-070 对账单证据
**都不含**收款 → 对账单的持久化引用，`SchemaUpgrader` 中也不存在第二套同类结构；本任务只新建**一套**
「收款 → 代理服务费对账单」分摊模型，并**复用**既有收款单主数据与既有对账单登记册：

- **一个收款主数据**：`FinanceReceipt` 原样使用，本模块**不加列、不改写**；
- **一个对账单登记册**：`AgencyServiceFeeStatements` / `AgencyServiceFeeStatementLines` 原样使用（ERP-070），不改写；
- **一个显式分摊模型**：`AgencyServiceFeeCollectionAllocations`（本模块唯一新增的表）。

定位：**代理服务费收款分摊登记册**。它**不是**银行入账 / 到账凭证、**不是**应收账款台账或余额、
**不是**货款核销、**不是**客户对账单（statement of account）、**不是**收入确认、**不是**税务（销项）判断、
**不是**结算确认，也**不是**会计凭证或总账记账分录。登记 / 作废一行都**不会真的收款或付款、不会移动资金、
不会把对账单标记为已收款或已结清**，也不引入第二套账务引擎（不记账、不生成凭证 / 结算单、
不改写客户信用额度或信用状态）。

## 2. 命名口径：为什么用 `Collection` 而不是 `Receipt`

ERP-053 的单元测试
`CustomerReceiptAllocationTests.ERP032审计_收款单只有客户级引用_仓库只有一套收款引用模型` 锁定了一条审计契约：
`IErpDbContext` 中「名字同时含 `Receipt` 与 `Allocation`」的 DbSet **只能有一套**（`CustomerReceiptAllocations`），
以此证明「仓库只有一套『收款单 → 销售订单』收款引用模型」。

本模块虽然同样以客户收款单为**来源**，但引用对象是**代理服务费对账单**，属于另一套独立证据维度，
因此类型名与 DbSet 名刻意采用 `Collection`（收款）而不是 `Receipt`：
`AgencyServiceFeeCollectionAllocation` / `AgencyServiceFeeCollectionAllocations`。
这样既保持语义准确（客户收款 = collection；行 = 分摊证据行），又**不破坏** ERP-053 已审计锁定的命名契约 ——
本模块**不需要**修改任何既有测试。

## 3. 字段与快照口径

| 字段 | 口径 |
|---|---|
| 对账单 | 必须**存在、未删除且已登记**（草稿 / 已作废拒绝）；只保存**服务端快照** |
| 对账单快照 | 对账单号 / 对账日期 / 状态 / 状态文案 / **服务端合计** / 币种 / 关联协议 Id 与协议号（只读留痕） |
| 收款单 | 必须**存在、未删除且未取消**（`DocumentStatus.Cancelled` 拒绝）；本册只读它 |
| 收款单快照 | 收款单号 / 收款日期 / 状态 / 状态文案 / **收款金额**（原币，写入时按币种精度取整，作为有效行合计上限） |
| 客户快照 | 客户 Id + 编码 + 名称（服务端写入；客户停用 / 删除 / 改名后历史证据仍可读，绝不回填） |
| 分摊金额 | 原币（与收款单 / 对账单币种一致），`DECIMAL(18,2)`；**按币种精度取整后必须大于 0** |
| 备注 | 有界（≤ 500 字符），只作为登记说明，不参与任何金额派生 |
| 登记人 / 登记时间 | 服务端按已认证身份与服务器时间写入（客户端不能提交） |
| 状态 | `1` 有效 / `2` 已作废（作废 = 保留原始值 + 作废时间 + 作废原因） |

**币种精度**复用仓库唯一权威实现 `CurrencyAmountRules`（与装柜费用分摊 ERP-042、供应商发票 ERP-043、
供应商付款引用 ERP-049、客户收款引用 ERP-053、对账单 ERP-070 同一套）：

- 无小数币种（JPY / KRW / VND / IDR）为 **0 位**，其余（含未知币种口径）为 **2 位**；
- 取整一律 **0.5 进位**（`MidpointRounding.AwayFromZero`，不使用银行家舍入）；
- **原币存储**：不做汇率换算、不跨币种合并、不按金额相近猜测对账单；
- 收款单或对账单币种不在系统币种口径内（`CNY / USD / EUR / HKD / GBP / JPY`）时，登记新分摊一律拒绝。

## 4. 权威资格与双向金额校验（服务端）

登记一行分摊时按下列顺序校验，任一不满足即拒绝并给出可读原因（**不静默合并、不自动调整差额**）：

| 校验 | 口径 |
|---|---|
| 显式标识符 | 对账单 Id 与收款单 Id 都必须由用户**显式选择**（非正即拒绝；系统不按单号文本 / 金额 / 相似度匹配） |
| 对账单存在 | 不存在 / 已删除 → 数据不存在（404 语义） |
| 对账单已登记 | 草稿 / 已作废 → 业务规则冲突（只有**已登记**的对账单证据可以承接收款分摊） |
| 收款单存在 | 不存在 / 已删除 → 数据不存在（404 语义） |
| 收款单未取消 | 已取消 → 业务规则冲突（历史分摊仍可读） |
| 币种口径 | 两侧币种必须在系统币种口径内 |
| 客户一致 | 收款单客户 Id 必须等于对账单客户 Id（**不转换、不改派**） |
| 币种一致 | 收款单币种必须等于对账单币种（**不做汇率换算、不跨币种合并**） |
| 客户可用 | 客户必须存在、未删除且启用（历史分摊不因停用被改写） |
| 分摊金额 | 按币种精度取整后必须 **> 0**（例如 100.005 USD → 100.01；0.004 USD → 拒绝） |
| 备注 | ≤ 500 字符 |
| 单侧有效行上限 | 单条对账单 / 单张收款单各自最多 50 条**有效**分摊行（超限拒绝，不静默截断） |
| 重复对 | 同一「对账单 + 收款单」只允许**一条有效分摊行**（重复提交 → 数据重复语义） |
| 收款单可分摊余额 | `收款金额（按币种精度取整） − 本维度有效分摊合计`，分摊金额不得超过它 |
| 对账单未分摊额 | `对账单服务端合计 − 本维度有效分摊合计`，分摊金额不得超过它 |

> **双向可用金额都是「本维度」口径**：只扣减 `AgencyServiceFeeCollectionAllocations` 的**有效行**，
> **不**扣减 ERP-053 的销售订单收款引用，也**不**与它相加（见第 7 节）。
> 两侧未分摊金额分别展示、**绝不被静默核销或改派**，也**不**表示已付 / 已结清 / 逾期 / 已确认收入 /
> 已记账状态或应收未收余额。

## 5. 重复、一对多 / 多对一与部分分摊

- **部分分摊**：一行可以只分摊收款金额（或对账单合计）的一部分；两侧未分摊金额分别可见；
- **一对多**：一张收款单可分别分摊到多张已登记对账单（每张一张有效行）；
- **多对一**：一张对账单可分别接收多张收款单的分摊（同一对账单内每个收款单一行有效行）；
- **全额分摊**：本维度有效行合计**恰好等于**基准金额时才显示「已全部分摊」（等于或超过都不可能，因为超额被拒绝）；
- 未分摊金额只是**算术证据**，缺失即「无」，**绝不**被解释为未付 / 已付 / 已结清 / 逾期 / 收入确认 / 记账状态。

## 6. 作废与历史（不可硬删除）

- 作废必须填写**原因**（必填、≤ 500 字符），写入 `VoidedAt` / `VoidReason`；
- 作废**保留**原始分摊金额、对账单 / 收款单 / 客户快照、登记人与时间戳，**不物理删除、不改派、不静默金额替换**；
- **重复作废被拒绝**；已作废行不再占用两侧额度，因此**同一「对账单 + 收款单」可以重新登记**一条新的有效行
  （新旧并存可查）；已作废历史**永不并入**有效合计，只单独计数与列出；
- 有效行唯一性的数据库兜底是过滤唯一索引 `UX_AgencyServiceFeeCollectionAllocations_StatementReceipt`
  （`IsDeleted = 0 AND Status <> 2`），与模型配置同名同过滤条件。

## 7. 证据维度分离（与 ERP-053 / ERP-055 绝不相加）

| 维度 | 模型 | 含义 |
|---|---|---|
| 客户收款 → 销售订单 | `CustomerReceiptAllocations`（ERP-053） | 「这笔收款指向哪几张订单」 |
| 销项发票 → 销售订单 | `CustomerSalesInvoiceAllocations`（ERP-055） | 「这张发票分摊到哪几张订单」 |
| **客户收款 → 代理服务费对账单** | **`AgencyServiceFeeCollectionAllocations`（ERP-071）** | **「这笔收款分摊到哪几条代理服务费对账单」** |

- 三个维度**互相独立**：模型、金额含义与判定资格都不同；
- 系统**绝不**把三个维度的金额相加，也**绝不**把它们当作「几张不同的收款单」；
- 任意一个维度的变动都**不影响**其它维度的数值（本模块只读写自己的一张表）；
- 本模块派生的「可分摊余额 / 未分摊额」只属于**本维度**。

## 8. 只读派生（两侧汇总与有界候选）

| 视图 | 口径 |
|---|---|
| 对账单侧汇总 | 对账单快照 + **本维度有效行**已分摊金额 / 未分摊额（下限 0）/ 有效行数 / 已作废行数 + 有界逐行明细 |
| 收款单侧汇总 | 收款单快照 + **本维度有效行**已分摊金额 / 可分摊余额（下限 0）/ 有效行数 / 已作废行数 + 有界逐行明细 |
| 关联状态 | `unallocated` 本维度尚未分摊 / `partial` 部分分摊 / `fully_allocated` 已全部分摊（等于基准金额时才是全额） |
| 可分摊收款单候选 | 只列**同客户 + 同币种 + 未删除 + 未取消**的收款单（单次 ≤ 200 条），附本维度已分摊、可分摊余额与资格文案（已占满 → 不可分摊） |
| 可承接分摊的对账单候选 | 只列**同客户 + 同币种 + 未删除 + 已登记**的对账单（单次 ≤ 200 条），附本维度已分摊、未分摊额与资格文案；草稿 / 已作废**不出现** |
| 台账 | 分页（默认 50 / 上限 200 条），可按对账单 / 收款单 / 客户 / 状态 / 币种 / 登记时间区间 / 关键字过滤；默认包含已作废历史 |

**查询有界、无逐行查库**：台账每页只做「列表计数 1 次 + 本页 1 次 + 收款单 1 次 + 对账单 1 次」批量装载；
对账单侧汇总为「对账单 1 次 + 分组统计 1 次 + 明细装载（3 次）」；收款单侧汇总同口径；
收款单候选为「客户 1 次 + 收款单 1 次 + 有效行分组 1 次」；对账单候选为「客户 1 次 + 对账单 1 次 + 有效行分组 1 次」；
访问次数与页大小、单据数量**无关**，也**不随行数变化**。

## 9. 非变更边界（登记 / 作废都不改写既有数据）

- **收款单**：状态、金额、币种、付款方式、银行账户、客户、备注、软删除标记**全部不变**（本册只读它）；
- **对账单证据**：对账单号、合计、到期日、服务期间、状态、登记人、行清单**全部不变**（本册只读它）；
- **客户资料**：信用状态（正常 / 预警 / 暂停）、信用额度、账期、结算方式、备注**全部不变**；
- **ERP-069 协议证据**、**销售订单**（含出货进度 / 金额 / 明细 / 交期 / 合同）、**装柜与装柜清单**、**单证中心**、
  **客户销项发票证据**、**库存与库存成本**、**库存流水**、**费用与分摊**、**退税**、**结算与余额记录**：
  不受影响，也**没有任何请求期回填**；
- **ERP-053 收款引用行与 ERP-055 发票分摊**：不受影响（维度分离）；
- 登记 / 作废**不执行任何收款 / 付款 / 记账 / 核销 / 结算 / 催收动作**，也不生成任何财务单据，也不调用任何外部服务。

## 10. 数据库与幂等升级

`AgencyServiceFeeCollectionAllocations` 由三处保持一致：

1. **EF 模型**（`ErpDbContext.Config.cs`，ERP-071 段）：长度 / 精度（`DECIMAL(18,2)`）、
   过滤唯一索引 `UX_AgencyServiceFeeCollectionAllocations_StatementReceipt`，以及
   `IX_..._StatementId_Status` / `IX_..._ReceiptId_Status` / `IX_..._CustomerId_Status` / `IX_..._Status_AllocatedAt`；
2. **幂等升级**（`SchemaUpgrader.cs` 第 44 段）：`IF OBJECT_ID(...) IS NULL` 建表 +
   `IF NOT EXISTS (sys.indexes ...)` 建索引，**不含任何 `ALTER TABLE`、UPDATE / INSERT / DELETE**；
3. **DbSet 与接口**（`ErpDbContext.Entities.cs` / `IErpDbContext.cs`）各新增一个 `DbSet`。

关键设计：

- **刻意不建任何外键与导航属性**（收款单 / 对账单只做软删除、客户可能被停用 / 改名）：本表只保存服务端快照，
  历史分摊证据必须始终可读，也不参与收款单与对账单的任何计算；
- 既有收款单、对账单、协议、客户表**没有任何列变更**，因此历史单据在不登记任何分摊时行为与升级前完全一致；
- 生产库执行、部署与发布**仍受 Human Gate 控制**，本文档不声明生产库已升级。

## 11. 接口与界面

| 接口 | 说明 |
|---|---|
| `GET /api/agency-service-fee-collection-allocations` | 收款分摊台账（分页 + 多条件过滤，默认含已作废历史） |
| `GET /api/agency-service-fee-collection-allocations/metadata` | 支持币种、有界额度与同源口径文案 |
| `GET /api/agency-service-fee-collection-allocations/receipts` | 可分摊收款单候选（**必须**显式给出客户与币种，单次 ≤ 200） |
| `GET /api/agency-service-fee-collection-allocations/statements` | 可承接分摊的对账单候选（只列已登记，单次 ≤ 200） |
| `GET /api/agency-service-fee-collection-allocations/receipts/{receiptId}/summary` | 收款单侧汇总（本维度已分摊 / 可分摊余额 + 有界明细） |
| `GET /api/agency-service-fee-collection-allocations/receipts/{receiptId}/allocations` | 指定收款单的分摊行清单（可按状态筛选） |
| `GET /api/agency-service-fee-collection-allocations/statements/{statementId}/summary` | 对账单侧汇总（本维度已分摊 / 未分摊额 + 有界明细） |
| `GET /api/agency-service-fee-collection-allocations/statements/{statementId}/allocations` | 指定对账单的分摊行清单（可按状态筛选） |
| `GET /api/agency-service-fee-collection-allocations/{id}` | 分摊行详情 |
| `POST /api/agency-service-fee-collection-allocations` | 登记分摊（登记人由服务端按已认证身份写入） |
| `POST /api/agency-service-fee-collection-allocations/{id}/void` | 作废分摊（原因必填，保留历史） |

界面：`src/ERP.Api/wwwroot/js/agency-service-fee-collection-allocations.js` + `modules.js`
（客户资料工具栏「💰 服务费收款分摊」与客户行操作 `openAgencyServiceFeeCollectionAllocationForCustomer(customerId)`），
入口 `openAgencyServiceFeeCollectionAllocationRegister(statementId, customerId)`；ERP-070 对账单详情页也提供
「💰 收款分摊」按钮直达本工作台。

页面含台账（多条件过滤 + 状态含已作废历史）、**对账单视角**工作台（对账单合计 / 本维度已分摊 / 未分摊额、
可分摊收款单候选、显式金额、分摊行清单与作废）、**收款单视角**（收款金额 / 本维度已分摊 / 可分摊余额与历史行）
与作废视图（原因必填、明示保留原始值），并显式声明本册的边界、双向金额口径与证据维度分离口径。
